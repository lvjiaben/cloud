# 用户偏好与产品体验入口

此文件只保留通用偏好和定位方法。业务决定的完整原文已按主题搬到[偏好索引](../memory/preferences/index.md)，不要求每次全读；按[上下文规则](context-loading.md)检索并读取与任务有关的完整条款。原文中的旧流程要求由当前`AGENTS.md`和`openspec.md`替代，业务语义不变。

## 通用偏好

- 全程中文，回复直接、明确；实际排查、修复和验证，不只给建议。需要下一步时给具体操作。
- 本地数据库、接口和真实测试数据允许用于开发与排查；不因假设的数据风险拒绝本地工作。未经用户明确要求，不提交`Git`、不推送、不创建`PR`。
- 面向普通运营人员和客户，用户界面使用自然业务语言；不得直接展示内部参数、原始`JSON`、堆栈或开发术语。错误提示应给出可操作的原因和恢复方式。
- 只对会改变业务结果、权限、费用、数据归属或主要操作流程的真实歧义询问用户。内部命名、代码组织和等价实现自主处理。加载、重复点击保护、关闭、权威状态刷新和失败恢复等基础交互沿用既定稳妥方案。
- 不用总体方向、竞品、旧实现或个人猜测替代业务确认。用户确认后，更新对应主题及受影响规范，再实现；最新确认优先。
- 前端问题用真实浏览器检查，行为改变补匹配自动化验证。内部工具和纯文档不运行无关页面测试。
- 完成汇报说明实际变化、验证和剩余问题，不列无关规则加载过程或重复检查清单。

## 读取与更新

1. 先用`.agents/CONTEXT.md`选择领域；关键词检索会同时定位偏好、规范和任务。跨模块变化补读相关边界，不只看一个插件。
2. 修改业务前阅读命中条款全文及其明确依赖。一般不读取历史归档、外部资料笔记、无关阶段和全部偏好。
3. 生产、第三方写入、本机与浏览器操作先核对相应授权条款；历史授权只适用于原确认范围，不构成新的扩大授权。
4. 新确认的长期结论合并到`.agents/memory/preferences/`对应主题。新增主题同步`index.md`和领域导航；已被新决定替代的条款标明替代关系，避免并存的相反命令。
5. 主题文件只保存长期业务决定、资料入口和授权边界，不写入密码、密钥、令牌、许可证或私钥。参考文档不是操作授权，不能覆盖已确认规则。
