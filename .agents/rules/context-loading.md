# 上下文定位与读取规则

## 质量优先与完整目标

按需读取优化的是信息获取，不是推理深度、任务范围或交付标准。先恢复用户完整目标、最新反馈、已确认边界和未完成项，再选择当前步骤；步骤完成不等于目标完成。简单修正直接处理，跨模块或多阶段任务利用现有任务记录保留进度与验收，不另造重复业务正文。

- 读取是否充分，以能否解释目标行为、调用与数据链路、失败原因和验收依据判断，不以文件数、字符数或调用次数判断。搜索无命中、条款矛盾、故障复发、结果与预期不符或依赖不清时，扩大相关搜索与读取，直到证据支持结论或定位到真实阻断。
- 按行为影响确定范围：改入口需查调用方和实际提交结果；删除能力需查注册、装配与仍保留的使用路径；修共享契约需查消费者。不是每次全仓审计，也不能仅因文件属于另一模块就跳过必要依赖。
- 用户要求继续、完整修复或主动检查时，持续完成已授权目标及必要依赖。无关问题另记；目标内问题必须修复或明确真实阻断，不能借“局部验收”“独立问题”缩小授权范围。用户新反馈默认补充当前目标，不能抹掉前面未完成的要求。
- 完成前将用户期望逐项对应到当前实现与证据，区分源码修好、构建通过、实际运行生效和业务链路验证。有依赖的失败不能称为范围外；模拟通过、页面可打开或任务勾选不能单独证明真实业务可用。证据不足时继续验证，真实阻断仅暂停依赖部分。
- 用户要求多轮检查时，每轮选择尚未覆盖的风险或不同证据来源，例如先沿契约与状态转换检查，再验证失败、乱序或重试的可观察结果；后轮依据前轮发现调整。保留仍有效证据，不以重复运行相同测试代替复查，不为凑轮次或发现数量改动正确实现。这不是所有任务默认多轮审计的要求。

## 启动与渐进读取

首次进入任务先读`AGENTS.md`和`user-preferences.md`，当前上下文已提供的正文不再用工具重读。纯交流、解释和方案讨论直接回答；结论需要仓库证据时只查相关内容，不自动收集状态、枚举变更或启动实施与审查。用户要求修改时再进入下列定位流程。需要定位时查`.agents/CONTEXT.md`；按实际修改范围加载领域规则、业务条款、技能和规范。禁止用`cat`拼接全部规则、偏好、技能或整个`openspec/`。

## 定位顺序

1. 准备修改时先用`go run ./.agents/tools/context.go status`查看全局计数、目录分组和活跃变更，再用`status <仓库相对路径>`查看本任务具体文件。也可内部收集完整Git状态后返回同类摘要；不把数百条全局清单输出到上下文。状态清单是候选，不等于本次审查范围；其他任务的文件不得覆盖。
2. 根据问题中的插件、页面、接口、错误或业务词，用`rg --files`、`rg -n`或上下文工具找路径和标题；索引只负责导航。
3. 先读目标源码和当前任务，再读匹配的完整业务条款、`Requirement`及其`Scenario`，需要决策背景时才读对应设计章节。跨模块或依赖不清时扩大到相关边界。
4. `contextFiles`和产物依赖是候选路径，不能解释为全量正文加载要求。优先当前任务和直接依赖，不默认读取全部历史任务、全部设计或全部能力。
5. `archive/`、`evidence/`、外部资料和历史执行报告默认不读；当前问题确需历史证据、审计、迁移或授权核实时显式定位后读取。

## 完整性与复用

- 搜索片段、标题、索引和摘要不算读完规范。相关条款必须完整读取，明确的依赖继续补读；不能因上下文预算忽略权限、资金、秘密和失败语义。
- 大文件先查标题和行号，只读相关完整条目、任务或章节；输出过大时拆成相关逻辑单元，不能截断后宣称已完整读取。
- 遇到超长单行或广泛命中时，先用有界`locate`定位，或用`rg -l`只找文件、按目标文件查标题；不要直接输出整个目录的匹配正文。检索片段仅供定位，随后仍读完整相关条款。
- 同一任务、同一内容版本、正文仍在当前上下文时，可在实现、反馈和审查之间复用。文件变化、范围扩展、新会话或压缩后正文已不可用时，仅重读受影响条款；旧会话摘要不能替代当前权威正文。
- 验证证据可复用，但必须仍覆盖当前改动、相关依赖与验证环境。用户报告复发、并行改动、数据/配置/运行版本变化或覆盖不足时，重新核查受影响证据；不能仅凭目标文件未变化复用旧结论。已通过且仍有效的检查不反复运行。
- 领域规则的相关条款及其共同门禁仍必须遵守；未命中的领域可合并写一条无影响说明，不自动扩成全项目审计。

## 维护约束

- `AGENTS.md`只放短入口、边界和加载矩阵；用户偏好入口只放通用偏好。业务细节写到主题文件，不无限追加到入口。
- 工作流门槛以`openspec.md`为唯一来源，技能只负责动作顺序；命令提示只路由到技能，禁止复制整个技能。
- 长变更保留原始状态和验收记录，通过关键词、标题或任务ID定位；不得为减小文件自动删除已完成记录、改任务状态或自动归档。
- 同一事实只维护一个当前权威正文。迁移业务记忆时保留来源和完整性证据；旧治理条款明确标记已由当前规则替代，不能重新成为全量读取命令。

## 输出与任务边界

- 命令执行前确定所需结果：找路径用`rg --files`或`rg -l`，找位置限定目录和关键词，读正文按完整条款。不要依赖工具截断保护来控制输出；截断后按相关范围重新查询。
- 默认状态摘要只计数和分组，目录分组与活跃变更各最多列12条，并报告省略数量；指定范围只列该范围总数和最多12条文件，不重复全局分组与变更清单。需要更多时缩小路径或定向执行Git命令，不能把省略当作没有改动。重命名按新旧路径匹配，生成产物也计入状态。
- 测试与构建需要保留长日志时写入临时文件，默认只返回命令、退出状态、结果摘要和相关失败片段；发现新错误再定向读取。失败、跳过和未执行必须如实说明。
- 一个连续任务保留完整目标与未完成项，沿用仍有效的插件、任务ID、相关条款和验证范围。反馈、依赖或反证改变影响范围时及时扩大；不机械重扫整个项目，也不把原范围当作禁止继续排查的上限。
- 沟通只报告新增结论、变化、验证和阻断，不重复加载清单或无影响类别；不为交流或局部修正额外建立计划、交接文档或重复业务正文。
- 排查先确定当前问题、已有证据和下一项待证事实；独立的定向读取或只读查询合并执行，有依赖的步骤仍顺序进行。不要每读一个文件就发起一轮调用，也不要为批量化加载无关文件。
- 相同查询或轮询连续两次未增加证据时，检查任务状态、日志、退出码或其他证据来源，再决定下一步；有明确运行信号的长任务继续有界等待并报告进度。已结束、失败或需要登录等外部条件时立即说明真实状态与下一步，不能继续描述为“正在处理”，也不因减少调用而跳过必要验证。
- 读取其他会话先取状态、近期目标和最后结论；接管时继续恢复原始目标、后续确认、未完成项和关键验证，摘要不足就读取相关历史，不能把最后答复当作完整需求。需要执行记录时提取相关命令、结果或计数。工具的单项字符限制不等于总输出限制，返回内容需在工具内筛选后再输出；不得把整份会话、原始会话日志或图片编码当文本回传。
- 已完成目标后的独立需求建议使用新会话，并只交接当前目标、关键路径、有效证据和待解决条件。当前连续任务仍完成已授权工作，不擅自创建会话、跨会话发消息或中断任务；新会话仍需读取相关权威条款，简短交接不能代替正文。
- 实施时明确用户完整目标下的本次验收结果，后续修复、回归和汇报围绕可观察结果；目标内遗漏和影响正确性的依赖持续补齐，真正无关的问题才另行记录。用户要求全面处理时按授权覆盖，不能只选一个局部结果；局部反馈则不机械重验无关变更。已有任务可用`handoff <变更> <任务ID>`生成不超过4 KiB的完整任务交接，不自动重做已完成项。
- 订单、付款与开通排查优先使用`order --order <订单号>`统一只读摘要；由`LINA_DIAG_TOKEN`或显式`--session-file`提供当前本地会话。查询失败、缺少权限或超过三条履约任务均报告证据不完整，不拼临时SQL绕过授权，不因未知结果重放开通。
- 检查会话开销使用`audit --thread <会话ID>`或`audit --file <JSONL>`获取有界计数，图片、缓存和文本分列，不复制历史正文或将累计输入当作费用。重复读取热点只用于定位，不能自动认定为无效工作。
- 组织验证优先使用`check --path <本次路径> --change <相关变更>`；可用`--plan`预览。明确选本次范围，不自动采用全部工作区；保留完整日志，失败、超时与未覆盖类别仍须处理，工具的自动检查不能替代领域门禁。操作与限制见[工作流工具说明](../tools/workflow/README.zh-CN.md)。

## 快速命令

```bash
go run ./.agents/tools/context.go status
go run ./.agents/tools/context.go status apps/lina-plugins/idc-payment
go run ./.agents/tools/context.go audit --thread 01a1533d-0a8d-7dd3-a0bb-c6b704a6716a
go run ./.agents/tools/context.go check --path .agents/tools --change streamline-agent-context
go run ./.agents/tools/context.go handoff streamline-agent-context 6.1
go run ./.agents/tools/context.go order --order ORD_example --session-file <私有会话JSON>
go run ./.agents/tools/context.go locate 退款
go run ./.agents/tools/context.go locate --limit 20 idc-payment refund
go run ./.agents/tools/context.go read .agents/memory/preferences/36-refunds.md
go run ./.agents/tools/context.go read openspec/changes/add-idc-server-operations-platform/tasks.md FB-52
# 大文件先列标题，再按任务ID或完整章节读取。
rg -n '^#{1,6} ' openspec/changes/add-idc-server-operations-platform/design.md
go run ./.agents/tools/context.go read openspec/changes/add-idc-server-operations-platform/tasks.md 1.7
```

工具默认只检索当前规则、偏好和OpenSpec正文，最多输出12条定位结果。`read`输出完整选中块；超过12 KiB或选择存在歧义时拒绝全量输出，并要求按章节、任务ID或`@行号`缩小范围。也可用`rg`与普通文件工具按完整逻辑单元读取。工具是辅助入口，不替代权威规则或业务判断。
