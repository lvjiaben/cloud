## 当前运营重点与性能基线

- 用户当前后台高频操作主要是魔方云自动开通、产品暂停和工单回复，首版必须优先优化这些路径的效率与异常处理。
- 当前魔方财务最严重问题是购物车和结算性能，单个商品从提交到付款页可能耗时约十分钟；新系统必须把商品配置、实时报价、创建订单和进入付款页的端到端性能作为首版硬性验收指标。必须使用版本控制的 benchmark manifest 固定硬件、数据库规模、购物车项目数、每项配置数、并发、冷热缓存、查询上限和数据脚本，创建订单并返回付款选择页的本地接口达到`p95≤2`秒、`p99≤5`秒，并输出可复查分段计时、错误率和数据库查询预算证据。
- 旧魔方财务结算源码会在返回付款结果前同步执行购物车钩子，并通过名为`asyncCurlMulti`的函数发起阻塞式站内`HTTP`调用；其耗时探测路径还存在未可靠设置超时的问题。这是旧系统结算长时间卡顿的高概率原因，后续只能通过运行时分段计时确认，不得直接照搬该实现。
- 新系统的报价和结算请求只允许执行本地校验、批量读取、价格快照、订单与账单事务以及事务内`Outbox`写入；通知、插件钩子、支付渠道网络调用、上游开通、`AI`调用及其他外部副作用必须在事务提交后由任务系统执行，不得阻塞进入付款页。
- 商品、配置项、价格、库存和上游状态装配禁止前端瀑布式调用、逐配置同步远程调用和随配置项数量增长的`N+1`查询。
- 商品目录由`idc-core`独占写入：分类和商品身份允许可恢复软删除，发布版本、插件配置、价格、简单库存、成本和履约绑定保留显式历史。金额只保存逐币种最小货币单位整数，不使用浮点或跨币种兜底；每个发布版本最多冻结一个自动化接口实例。服务器资源池只属于服务器插件内部，通用商品核心不保存或解释资源池编号。
- 历史“Provider 快照生成商品草稿”方向已经由`FB-52`废止，不得继续实现、恢复或作为验收依据。服务器供应商容量只能留在服务器插件内部，以有界持久任务和安全投影支持异步履约判断；它不得创建或修改通用商品草稿、商品库存、商品销售状态、报价或结账事实，也不得把 Provider 编号、状态、余量、成本、凭据或原始投影交给商品域。
- 后台客户列表和客户`360°`必须使用有界、集合化装配：主体页采用`created_at + id`稳定游标；外部游标使用有版本的 URL 安全不透明编码，绑定规范化筛选和页大小，并在后续页查询前按`tenant_id + id + customer_no + created_at`校验权威边界，不依赖单机内存、不为 GET 写状态。个人/企业实名、等级、标签及后续订单、账单、服务等摘要按领域固定批量查询，禁止逐客户查询。普通列表只返回显示安全的状态与摘要，法定姓名、证件/登记标识、查重摘要、认证案例和凭据不得进入列表响应。
- 后台客户列表与客户`360°`路由只能读取已经由独立后台受众装配流程建立的直接活动员工受众；普通`GET`请求禁止调用`EnsureCurrentStaff`或以读操作顺带创建、重绑永久员工身份。页面分页只能使用后端返回的不透明上一页/下一页游标，不伪造总数、页码跳转或把内部主键暴露给浏览器。
- 后台客户列表的分组与标签筛选必须使用有效关系上的集合化`EXISTS`查询，并把精确分组/标签业务编号绑定进不透明游标；禁止先拉取客户后在内存筛选、按客户查询关系或接受归档/撤销关系扩大结果。
- 后台分组与标签筛选控件不得一次加载完整字典；必须按当前界面语言使用索引化名称前缀远程搜索和有权威边界的不透明 keyset 游标，每次候选最多 25 条。候选游标绑定类别、语言、规范化前缀和页大小，空业务编号或跨条件复用失败关闭。
- 批量客户标签写入必须同时保留客户级审计可检索性和集合化数据库性能。现有单事件审计接口不能通过逐客户循环调用来伪装批量实现，也不能只写一条无法按客户检索的总事件；实施批量写前必须先提供受硬上限约束、同事务、集合化持久化的批量审计边界。
- 批量客户标签已确定为每次最多 100 个客户、20 个标签，仅允许`assign/revoke`。每个命令只写一条封印审计事件和一组不可更新/删除的客户检索链接，审计签名绑定客户数量与集合摘要；随后用单次集合化 SQL 变更关系。同一幂等键重放只返回原审计结果，不重复写入。
- `idc-core`的审计重放摘要、完整性签名和秘密信封包装必须使用部署注入的版本密钥环`LINAPRO_IDC_CORE_SECURITY_KEYRING`。稳定`reservation_key`与版本根密钥不得相同；各版本根密钥通过 HKDF-SHA-256 分别派生`audit/replay`、`audit/integrity`和`secret/envelope`实际密钥。轮换时新版本作为活密钥，旧版本保留审计验证和信封解包装能力，退役前必须完成有界重包装与全量认证；缺失、格式错误、未知字段或活动版本缺失时启动失败关闭，不允许随机、数据库或硬编码回退。
- 源码秘密能力采用`core`单 owner 声明、`resource`启动冻结和显式工厂装配，不提供运行期全局`Resolve/Get`。`resource`必须按渠道引用的不可逆摘要派生独立 owner/scope，并只把该 callback accessor 与加密输出 sink 注入对应 Provider 实例；不同渠道不得共享可互读秘密的宽 scope。读取只允许已审查的`provider.*`或`resource.*`用途；scope manager 的创建/替换只接受同步单次 producer，不提供列表或 handle 发现。后台管理 API 仍必须额外执行最近重新认证、精确权限、数据范围和审计，动态插件明文 bridge 继续关闭。
- 智简魔方库存首版使用一次有界的`GET /clouds/create_page`区域、节点和存储嵌套图生成候选并通过快照指纹保护跨页一致性；现有`GET /stores`证据仅确认按节点过滤，取得全节点批量契约前不得通过逐节点调用补齐库存，也不得宣称该端点已接入。
- 资源插件的渠道和资源池采用可恢复软删除；渠道秘密绑定、资源映射、资源任务、上游任务绑定以及能力、库存、成本、余额、到期和健康观测必须保留显式生命周期或不可变历史，不得用软删除抹去对账证据。渠道秘密表只保存`core secretcap`不透明引用且仅 resource owner 构造边界可读取，列表、API、日志和审计不得暴露；停用渠道不得构造 Provider 或接收新任务。
- Provider 出站网络只能使用 resource owner 注入的安全客户端：精确绑定渠道 HTTPS origin、禁止重定向和 Host 覆盖、正常校验证书，每次拨号重新解析并直接连接已校验公网 IP；DNS 结果只要混入私网、回环、链路本地、共享、基准测试、文档、组播或保留地址就整体拒绝，适配器不得自建裸 HTTP 客户端或提供跳过 TLS 校验开关。
- 异步资源任务的开通/重装输入秘密与控制台/重装输出秘密不得进入任务参数 JSON；resource owner 必须使用独立任务秘密绑定历史保存`secretcap`不透明引用、输入/输出方向、一次性凭据或短期票据策略与到期/揭示/撤销状态，引用本身不得进入列表、API、日志或审计。
- 已被上游接受的资源任务必须使用独立只读观察租约收敛：领取和回报以 PostgreSQL 时间及任务号、状态、随机令牌、版本、有效期完整栅栏，并以固定有界集合查询装配上游任务绑定。`QueryTask`返回的任务号必须与权威绑定精确一致；查询失败或上游返回未知时保留最后已知`accepted/running/result_unknown`状态并延后观察，绝不能退回写队列或重复提交上游操作。
- 智简魔方登录令牌属于秘密且是缓存敏感状态。单机可以使用同一 Provider 实例内的短期缓存；集群模式必须由`resource`所有者提供共享、可失效且不泄露明文的认证会话能力，或让适配器拒绝启用，禁止把仅进程内令牌缓存当作集群完成态。
- 公开购买流程和移动端购买流程必须进行真实浏览器验收，不能只验证管理后台。
