## 本地合规网关业务请求认证长期规则

- 本地插件与本地网关之间需要跨进程认证时使用安装期本地生成的版本化签名凭据，签名帧必须绑定安装实例、当前密钥、服务端预期操作范围、方法、规范路径/查询、真实载荷摘要、数据库校验时间窗、256 位随机数和 256 位业务幂等键；禁止依赖平台销售注册、JSON 字段顺序、客户端时钟结论或客户端自行声明的操作范围。
- 防重放随机数和业务幂等必须是两个独立围栏。随机数原文不落库，同一实例重复随机数只有完全相同签名帧才能恢复；业务幂等键原文只计算用途隔离 HMAC，同一实例内改变范围或内容必须冲突，不能产生第二次供应商写入。
- 业务内容摘要有意排除密钥代次、时间、随机数和签名，使响应丢失或密钥轮换后可以用同一业务幂等键和新签名恢复，但必须继续绑定同一实例、操作范围、方法、路径、查询和载荷。
- 安装标识固定由安装器首次生成`linst_`前缀加 256 位随机值，并同时写入插件和本地网关的私有配置。原实例备份恢复必须保留该标识；克隆为新商家或新实例时必须重新生成，禁止复用来源实例标识。
- `10.6`形成的进程认证基线只包括通用签名/验签、数据库围栏，以及既有`GET /internal/v1/installation`按服务端固定`installation.read`范围接线；腾讯业务路由由`10.8`在复用该基线、完成官方契约实现和测试后逐项静态注册，诺诺业务路由在`10.4.c`与`10.10`门禁完成前继续关闭。
- 每个签名帧都必须携带 256 位业务幂等键。只读请求只持久化随机数防重放围栏；写请求才同时持久化业务幂等围栏，并在同一业务键改变范围、方法、规范目标或规范载荷时返回冲突。
- `application/json`请求体必须先按`RFC 8785`规范化再计算真实载荷摘要；非`JSON`载荷只有在服务端路由显式声明原始字节模式时才可按原始字节计算摘要。规范化不得接受重复`JSON`对象成员。
- 请求路径和查询只能发送唯一规范形式：路径拒绝百分号别名、点段和歧义编码；查询名称和值按`RFC 3986`百分号编码，按编码后的名称排序，每项固定使用`name=value`，拒绝重复参数名、空参数名和非规范输入。
- 进程认证有效期由部署配置显式注入且硬上限为 60 秒；签发时间最多允许比 PostgreSQL 权威时间快 30 秒。客户端时间不能作为验收结论，过期、超窗或未来偏移超限都必须失败关闭。
- 进程签名密钥的生成、轮换和撤销在当前阶段只通过安装器或运维命令行完成，不提供管理页面；浏览器永远不得接触进程密钥。未来管理页面最多展示不含秘密的状态和当前活动密钥编号。
- 实例和操作级限流必须使用 PostgreSQL 权威时间与持久状态，不能把单进程内存计数当集群真相；真实窗口、上限和策略版本由部署权威显式注入，不能在代码中猜测商家的生产额度。
- 供应商写熔断按供应商和操作范围保存持久`closed/open/half_open`状态，半开只允许一个数据库围栏探测。只有真实越过供应商边界的写尝试可观察`succeeded/definitive_failure/result_unknown`，本地认证、权限、额度、参数或构造失败不得计为供应商故障。
- 当前安装环境内的每个业务请求在数据库中最多只能创建一条供应商写尝试，不能通过更换供应商或操作范围取得第二张写租约。首次租约提交后，任何相同业务恢复都只能返回原尝试且明确禁止再次调用供应商；本地凭据撤销阻止新租约，但已越过供应商边界的在途尝试仍允许记录精确结果。
- `result_unknown`立即打开供应商写熔断且不允许自动重发；早期并发调用的迟到成功只能收敛自身业务请求，不能关闭更新代次的熔断。开放期结束后只允许一个数据库围栏的半开探针，探针超时必须把原尝试和业务请求原子标记为结果未知并重新开放熔断，后续由只读主动查询或证据驱动人工接管处理。
