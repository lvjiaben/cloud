## 前端与真实验证偏好

- 本地已安装`Chrome`组件和`Playwright`。
- 前端需求和`Bug`优先使用`Chrome`真实页面直观排查。
- `Playwright`用于自动化回归测试。
- 所有前端问题修完后，必须再次用`Chrome`真实访问页面，逐处检查交互、样式、弹窗、表格、提示是否合理。
- 不能只靠类型检查或代码推断就结束前端问题。
- 表格页必须避免`vxe-table`无限高度、无限滚动和内容错位问题。
- 所有后台业务页面统一遵循现有`Vben Admin`页面结构：列表和设置内容放入普通`Card`，表格占满页面剩余可用高度并在表格内部滚动，不能因为`Page`与`VxeGrid`高度组合而只显示一行；禁止使用渐变大横幅、巨型页面标题、自绘透明弹窗或会污染宿主布局的全局样式。简单的新增和修改使用`Modal`，字段多、步骤多或需要较大操作空间的编辑使用大尺寸`Drawer`，只有真正需要完整工作区的复杂编辑器才允许独立页面。菜单必须按客户、商品、资源、订单财务、工单内容、通知营销、合规与平台能力等业务类别组织一级菜单和二级功能，并在中文界面完整显示中文、英文界面完整显示英文，禁止把所有 IDC 功能堆进一个一级菜单。通知模板按渠道或业务类别使用页签分组，模板列表在固定高度区域内滚动。服务器批量操作不设置独立控制台菜单，必须并入服务器管理列表的多选批量操作。
- 客户编号使用从`10000`开始、只增不减且删除后不复用的纯数字短编号；超过五位后自然增长，不补长随机前缀。后台客户列表必须直接展示手机号，支持按客户编号、手机号和姓名搜索，操作列必须完整可见；重复手机号或邮箱必须明确提示“手机号已存在”或“邮箱已存在”，不能笼统显示客户资料无效。后台客户管理必须提供重置登录密码操作，直接创建的客户立即处于可登录状态，首次登录后按既定规则修改初始密码；单商家模式不要求客户选择租户，也不能以空租户列表阻断登录。
- 后台直接创建客户时，使用手机号创建就必须把管理员输入的手机号原样作为登录名；国际区号只作为联系方式结构化信息保存，不能偷偷拼到登录名中。商品分类后台必须提供列表、新建、编辑、删除和恢复，删除使用可恢复软删除，不能只提供新建入口。
- 需要精确选择客户的后台表单，例如协助报价，不允许手工输入客户编号；必须使用可输入搜索的下拉框，候选项同时展示客户姓名、手机号和短客户编号，并在服务端按当前员工数据权限返回有界结果。
- 第十一阶段及以前的后台页面必须做整体一致性验收，不能只修用户逐页指出的位置：搜索区、表格、操作列、必填星号、普通`Card`、刷新入口、`Modal`/`Drawer`、空状态、错误提示、中文菜单和菜单分组都要按同一套 Vben 标准检查。`marketing-header`、渐变大横幅、巨型标题和同类装饰结构一律删除，刷新按钮放在当前内容`Card`右上角；工单工作台、工单设置、隐私治理、红字任务、服务器附属资源等页面不例外。
- 用户反馈某一页面出现表格裁切、内容不可见、缺少`Card`、弹窗或抽屉不清晰、深色`hero`大模块、按钮看不清、原始`JSON`或内部字段直接展示、简单功能缺少完整增删改查等问题时，必须把第十一阶段及以前所有同类页面作为同一轮反馈范围主动扫描并一次性修复，不能只改截图中的单页或单元素。只有同类问题全部完成代码、类型、双语、权限、相关测试和真实浏览器逐页验收后，才能向用户汇报“已修复”或“已完成”；处理中可以报告明确根因和进度，但不得用编译通过、局部接口成功或单页截图冒充整轮完成。
- 用户可见内容只能展示短客户编号、公开业务号、名称和业务状态；`CUS_`、`CTC_`、`ctg_`、`ver_`、数据库主键及同类内部关联编号可以作为服务端关联键或前端控件内部值，但不得出现在表格、卡片、抽屉、错误提示、下载或其他可见文案中。面向客户的资料接口不得返回客户或联系人内部关联编号。个人账号进入只适用于企业的功能时，页面必须先按客户类型判断，禁止先调用必然失败的企业接口；应隐藏无效操作并用普通话说明该功能只适用于企业账号。
- `web-customer`的资料、购物车、订单、财务、合同、发票、地址、数据权利、工单和通知等日常功能页统一使用普通 Vben `Page + Card`工具栏和清晰的小标题；禁止使用功能名加`hero`的深色大模块、渐变横幅或巨型`h1`。支付结果、身份验证结果等确实需要强调结果的独立流程页也不得泄露内部编号或原始载荷。
- 后台插件和`web-customer`的可见组件统一按“Vben 官方封装组件优先、Vben 没有时使用 Ant Design Vue、两者都没有时才允许自建”的顺序实现。列表必须使用 Vben 官方`VxeGrid/useVbenVxeGrid`封装，搜索区必须使用 Vben Form，按钮必须使用官方按钮组件；所有列表的操作列固定在最右侧并在横向滚动时持续可见。页面字体必须继承 Vben 主题字体和字号，不得在业务页面或插件根容器另设`Inter`、等宽字体或其他整套字体栈；只有代码、指纹等明确的技术值允许局部等宽字体。后台所需的 Vben 接入能力必须由一个独立、可复用的插件拥有，其他业务插件也通过该插件使用同一套适配契约；不得把适配代码、业务页面或业务依赖写入`web-antd`宿主。商品分类固定为“商品与定价”下独立二级菜单的完整列表页，提供搜索、新建、编辑、可恢复删除和恢复，不得继续藏在商品管理弹窗中。客户后台菜单必须按客户任务形成固定展开的分组和二级功能，分组标题不可折叠、不可收起，禁止把全部页面平铺为一级菜单，也禁止显示没有实际客户操作价值的菜单。
- GoFrame 请求 DTO 的数组、切片和对象列表不得使用只适用于字符串字符数的`length/min-length/max-length/size`标签校验元素数量。集合数量边界必须由明确的集合校验或进入业务前的显式`len`校验完成，并逐个校验元素格式；相关接口测试必须经过真实 HTTP 参数绑定和校验层，至少覆盖最小值、最大值、低于最小值和超过最大值。每次发现此类框架校验误用时必须扫描全部 IDC 插件的同类型字段并一次性修复，不能只改用户点名的一个接口。
- 不得只根据截图中的重复提示、页面外观或点击结果猜测故障原因。必须先按用户说明复现真实操作，再核对浏览器请求、后端日志和权威数据；例如用户多次点击后出现多条提示，不得擅自解释成页面自动重试。首次改密的完成标准是新密码确实保存成功、首次改密门禁确实清除并实际进入可用的客户中心，不能以按钮可点击、接口开始请求或页面跳转尝试代替。
- 通知模板页面必须真实显示按渠道分类的`Tab`，模板列表在固定高度内容区内滚动；通知渠道页面必须让管理员能找到并配置已实现的腾讯短信、邮件、微信公众号、企业微信等商家自有渠道。腾讯电子签和诺诺电子发票的入口固定在合规中心各自页面；尚未取得权威外部能力或商家配置不完整时，要显示缺少什么和如何检查，不能只报“服务暂时不可用”或隐藏配置入口。
