## 通用试用资格长期规则

- 试用次数按“客户 + 商品”累计，不按商品版本、插件配置或接口实例变化重置；商家发布新版本或调整配置，都不能让同一客户重新取得已经用完的试用资格。商品计费规则中的`trial_quantity`表示该客户对该商品最多可试用的购买数量，不代表服务器台数。
- 匿名公开商品可以稳定展示“需要客户上下文”状态，但不能猜测客户历史试用次数。游客购物车不得加入试用项；客户购物车和后台协助报价都必须基于目标客户的权威资格投影生成最终报价，并把当时的上限和既往占用次数冻结到报价与订单快照。
- 试用订单必须整单只包含试用项且所有安装费、周期费、折扣、税额和应付金额都精确为零，禁止把付费商品、余额、优惠或其他支付来源与试用混装。试用不得创建渠道支付交易、支付分配、账本交易、余额快照或占用客户余额。
- 结账事务必须按稳定顺序锁定“客户 + 商品”资格范围，并按订单项购买数量创建唯一试用资格占用；报价可以过期，真正的并发防重必须以结账时的权威`held + consumed + 本次购买数量 <= 冻结上限`为准。两个独立有效报价并发结账时只能有满足剩余资格的一方成功，后续履约任务粒度仍由冻结插件契约决定。
- 结账先把试用资格置为`held`，统一财务结清在同一事务重新校验当前有效实名、订单账单归属、订单项数量、冻结规则和不可变摘要，再把资格原子转为`consumed`并生成唯一`financially_settled`事实与`Outbox`。后台协助的零金额试用订单也必须走相同目标客户资格和统一结清，不能由员工直接标记已支付或可履约。
- 待付款试用订单取消时释放仍处于`held`的资格；因付款期限到期取消时记录为`expired`。已经`consumed`的资格永久计入客户商品累计，不因订单取消、商品换版本或后续交付变化恢复。资格范围、订单项与购买数量以及`hold/consume/release/expire`变动链必须由数据库约束保持投影闭合且历史不可修改。
