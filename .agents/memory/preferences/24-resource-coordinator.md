## 资源任务执行协调器

- Provider 写任务只能在 resource owner 先以整批集合查询把本地资源号解析为当前渠道与资源池下的权威上游资源号后调用；开通可暂时没有上游资源号，其他能力缺失映射时必须在调用前失败关闭，禁止直接把本地资源号当作上游编号；同一任务批次内每个渠道只构造一次 Provider。
- 只有明确证明没有调用上游，或上游明确拒绝且未接受请求，才允许在尝试预算内自动重试；原始错误、超时和不合法响应都必须冻结为脱敏的结果未知，先查询对账，禁止重放写请求。
- Provider 返回的输出秘密必须只以`secretcap`不透明引用保存，并与任务状态、上游任务绑定和输入秘密撤销在同一事务提交；开通映射、无任务号查询、证据和秘密孤儿补偿尚未完成时，不得把执行协调器注册为生产 worker。
- 无上游任务号的未知结果只能通过当前活跃的本地资源、渠道和资源池精确映射执行只读`QueryResource`核对；快照必须产生于本次观察租约之后。只有启动、停止、暂停、恢复和终止可凭精确目标状态收敛，重启、重装、变配、换`IP`和重置密码必须使用专用结果证据或人工核对。任务结案、拥有方状态证据和脱敏 Provider 证据必须同事务写入不可变历史，禁止保存原始响应或秘密引用。
- 开通同步成功或异步任务成功必须先在 resource owner 同一事务内创建或激活“本地资源 + 渠道 + 资源池 + 唯一上游资源号”映射，再保存脱敏 Provider 证据并结案任务；上游资源已被其他本地资源占用、映射目的地不一致或缺少上游资源号时必须整体回滚，跨 owner 回报只能发生在该事务成功之后。
- 魔方云换`IP`写接口没有可靠上游任务号时，只允许用本次观察租约后的实例详情白名单投影对账；实际`ip_count`必须与任务规范化参数中的期望`ip_num`精确一致，并把实际数量作为不可变证据与任务结案同事务保存。仅看到实例运行、数量缺失或数量不一致都不得判成功，也不得自动重放换`IP`写请求。
- 魔方云供应商容量观测必须合并单次有界`/clouds/create_page`嵌套创建图与单次有界`/stores?list_type=all&enable=1`顶层存储列表，共用全局候选上限、字段白名单、稳定去重和覆盖双源的跨页指纹；禁止为补齐存储按节点扇出请求。
- Provider 容量观测只能由`idc-resource`在插件内部暂存：页大小、下一游标和页计数需要持久化以支持重启核对，每页批量写入且有总页数/总条数硬上限；只有终页事务可以替换上一份完整观测，任何部分失败、重复页、跳页或畸形页都不得影响当前完整观测。该数据不能进入商品库存、生成商品草稿或改变商品发布状态。
- 无上游任务号的资源观察租约必须用 PostgreSQL 时间写入独立领取时间业务字段并原样返回执行器；快照新鲜度以该字段为下界，禁止拿 ORM 自动维护的`updated_at`冒充领取时间。
- 历史`resource`库存快照自动生成商品草稿方向已经停止。资源插件不得自动创建、修改或同步商品库存和商品草稿，也不得通过`catalogcap`把供应商容量写入商品域；服务器供应商容量如需观测，只能留在服务器插件内部作为异步履约判断，不改变通用商品可售数量。
- 插件不得自行、定时或依据供应商容量自动创建或导入商品草稿。管理员可以在服务器自动化接口详情中主动选择上游商品执行导入；连接器只提供有界只读商品资料，商品拥有方据此创建未上架草稿，并自动填写连接器、接口实例及其声明的产品配置。导入后仍由管理员在商品管理中核对资料和价格，选择“按上游价格加价”或“自行填写最终售价”，再走商品核心唯一发布流程手动上架；系统绝不自动发布。发布前由商品核心集合校验中英文销售资料、显式价格、税务、简单库存、插件配置、履约方式和单一接口实例冻结证据。服务器插件内部的资源池候选只属于其私有履约契约，不得进入通用商品字段。
- 商品版本行是该版本插件配置、价格、计费、简单库存、履约方式和单一接口实例绑定的统一并发写栅栏；任何商品图修改服务必须先锁定对应版本行，再修改子图。发布事务先锁版本和商品再重检冻结证据，禁止未来子图写服务绕过该锁序。
- `FB-52`确认后的商品配置契约不得再把固定套餐、服务器组件或`component_type_code + normalized_value`当作通用商品模型。插件分别声明接口配置、后台商品配置和客户购买配置；核心只理解版本化字段声明、受限条件、类型化不透明值及其冻结快照，不解释`CPU`、内存、证书、域名、手机、物流或未来商品字段。
- 通用配置字段首版固定支持单行文本、多行文本、整数、小数、开关、单选、多选、日期、日期时间、密码或密钥、树选择、国家省市区地址联动和受治理文件上传。手机号、邮箱、域名和网址属于文本字段的宿主白名单校验格式，不另建商品类型。三类配置表面共用同一基础协议但按场景限制：密码或密钥只允许接口配置并通过`secretcap`保存且永不回显；后台商品配置和客户购买配置不得收集接口秘密；地址、树选择和文件上传只能使用宿主治理的数据源、上传能力、大小类型限制和权限边界。
- 单选、多选、树选择和地址联动既可使用插件声明的有界双语静态候选，也可通过插件逐项声明并获授权的版本化候选查询方法读取；服务端必须限制数量、稳定排序、绑定声明修订并防止`N+1`。用户只看到双语标签与安全值，不看到稳定字段键、原始枚举、内部编号、任意`JSON`或插件私有错误。
- 动态候选首版固定使用一次有界批量协议：单次请求最多包含 128 个字段，并携带目标字段、父级路径和当前选择；每个字段最多返回 512 个候选，整份响应最多 1 MiB，候选只包含目标字段、安全候选值、父级安全值和中英文标签。宿主必须拒绝未知字段、重复字段、重复候选、越界数量和不匹配的父级关系；缓存只能使用“精确插件版本 + 授权方法 + 完整输入摘要”作为键并设置短时有界有效期，不得跨版本、方法或选择复用。
- 配置联动只允许受限声明式规则：等于、不等于、包含、数值比较、为空和非空，可在有界深度内使用`AND/OR`组合；结果只允许显示、隐藏、必填、禁用、过滤候选以及`requires/excludes`。禁止脚本、任意表达式、跨字段计算、动态执行代码或由插件在同步报价请求中实时计算金额。所有声明和提交值必须在接口保存、商品配置保存、发布、公开配置、报价及开通边界重新校验，不能信任前端状态。
- `requires`引用多个值时必须全部满足，不能把“满足任意一个”当作通过；`excludes`引用多个值时只要命中任意一个就构成冲突。前后端和所有保存、发布、报价、订单、服务与履约边界必须复用这一套语义。
- 受治理文件字段必须由插件声明结构化策略：最大文件数量、单文件大小、总大小、允许的 MIME 类型、允许的扩展名以及是否要求安全扫描。匿名官网只展示这些要求并引导登录，不得返回上传地址或文件令牌；登录后的用户中心必须按“预留上传 → 私有存储上传 → 服务端检查 → 可用令牌”完成，检查通过前不得保存为有效购买配置。
- 文件令牌只允许精确的上传登录账号使用，即使属于同一企业客户也不得由其他账号直接复用。以后如需企业内共享，必须另建明确授权流程，不能扩大首版令牌权限。文件令牌、对象存储凭据、真实存储路径和扫描原始结果不得进入公开商品接口或插件页面。
- 文件上传预留必须在 1 小时内完成；服务端检查通过后的未下单文件令牌有效 7 天，可由原上传账号在同一商品版本和配置修订下反复用于配置、报价和加入购物车。正式下单时令牌必须原子绑定该订单并转为永久历史证据，不得再用于创建另一笔订单；商品版本或配置修订失效、原上传账号主动撤销时必须立即停止新使用。报价和加入购物车本身不得提前消费令牌，历史订单证据不得因令牌到期、撤销或插件生命周期变化删除。
- 配置对价格的影响只能进入核心拥有、明确币种、整数最小货币单位、正式发布并随商品版本冻结的显式价格方案；插件不得同步远程询价、临时改价、跨币种兜底或把供应商价格直接作为客户应付金额。接口秘密只冻结引用和秘密修订证据，不复制明文到商品版本、订单、服务或履约快照。
- 商品复制早期“不复制接口绑定、要求重填销售摘要”的决定已由[商品业务与插件交付](75-product-commerce.md)中`2026-10-14`用户确认替代，以该主题为当前权威。仍保留新身份、不可售草稿、零库存、不复制成本和交易历史、不复制旧服务器配置图的边界；交付绑定与冻结配置在当前精确授权及插件接受新业务的前提下重建，仍须重新通过唯一发布门禁。
- 后台手工创建分类与商品必须使用不同的精确员工权限，并且仅接受直接员工、默认商家及全局或本商家数据范围。商品分类只是商家自定义目录，分类名称不得决定或限制商品种类；创建商品时在同一事务生成新的商品身份及`manual + draft`版本 1，商品当前版本指针保持为空，插件配置、价格、接口绑定和发布状态均不得自动生成。分类/商品写入与业务审计必须同事务，审计失败整体回滚。
- 商品正式发布只有一个状态切换服务。所有`manual`、`copy`、`migration`和插件迁移来源版本都必须经过同一套双语销售文案、冻结插件配置声明与类型化值、受限联动规则、启用计费规则逐币种显式价格、税务和履约绑定完整性门禁；人工商品可以没有接口绑定，自动商品至多绑定一个可接受新业务的接口实例。发布、旧版本转`superseded`、商品当前版本指针和业务审计必须同事务提交，任何插件或旧 Provider 入口都不能保留第二套发布写路径。
- 商品计费周期必须原样保存“单位 + 正整数数量”：一次性固定为 1 次，小时最多 87,600、天最多 3,650、月最多 120、年最多 10，十年不得折算成含糊月数。新购最低周期与单次续费最高周期独立配置；安装费只进入首购，不进入续费；续费必须使用显式续费金额。阶梯和按量首版只使用从数量 0 开始、连续、无重叠且最终无上限的分段累进区间。按量规则必须声明权威计量单位、采集周期、整数舍入、保底、封顶和缺失数据策略；缺失时只能待补算，或明确使用上一完整周期暂估并标记为 estimated，不能把未知用量返回成 0 元。试用报价必须取得权威历史试用次数，达到商家配置上限就拒绝。所有金额和分段计算只用最小货币单位整数并做溢出保护。
- 商品币种可售性只能来自当前版本该币种的显式价格。对每个启用计费规则，所选币种必须同时具备基础价、全部必需配置项价格及合法完整阶梯；任一维度缺失或畸形，该币种不得出现在公开可售币种中，也不得报价或下单。后台可以看到按计费规则和配置项定位的缺失/畸形问题，公开端只消费可售结论。禁止把小写或模糊币种自动改成另一个配置、禁止从其他币种兜底、禁止引入实时汇率或浮点金额；精确价格读取只按“计费规则 + 大写三字母币种 + 基础/选项”命中。发布必须校验所有已配置币种，而不能悄悄忽略其中不完整的币种。
- 商品新单只读取商品版本的本地简单库存设置和当前有效预留，不得在列表、报价或结账中调用插件或供应商。服务器插件自己的资源池库存、故障切换和刷新策略不得进入通用商品核心；需要时由服务器插件在单一接口实例内部负责。
- 每个已发布商品版本最多绑定一个自动化接口实例。负载均衡、多供应商切换、资源池选择和供应商故障切换如有需要，由该插件在接口实例内部负责，通用商品版本不得直接绑定多个资源池或多个接口。
- 后台商品工作台列表必须使用直接活动员工、默认商家、精确`idc:admin:catalog:product:list`权限和可表达的数据范围。单次响应最多 100 个商品且不超过 1 MiB，以`sort_order + id`不透明 keyset 游标分页；游标必须使用部署密钥派生的独立用途密钥加密边界和筛选摘要，禁止仅用可逆 Base64 暴露内部主键，并绑定名称前缀、商家分类、状态、最新版本来源和页大小。名称前缀中的`%`、`_`和反斜杠按字面匹配。商品、最新版本、配置、启用计费、显式币种、简单库存和成本必须围绕当前页用固定次数的本地 PostgreSQL 集合投影完成，禁止前端逐商品补查或在工作台请求中调用插件或供应商。
- 后台商品最新版本详情必须使用独立于列表的`idc:admin:catalog:product:query`权限，列表权限不能替代；每次打开详情只调用一次有界本地接口，以固定查询次数返回配置、计费、逐币种价格、简单库存、成本和履约绑定，不得同步调用插件或供应商。详情必须中英文展示业务枚举，禁止暴露数据库主键、上游原始载荷、凭据或秘密；插件清单、权限或翻译资源变化必须提升插件版本并通过正式升级路径验证，不能依赖同版本热覆盖。
- 后台商品发布必须使用独立的`idc:admin:catalog:product:publish`权限，列表和详情权限都不能替代。界面只对最新草稿显示发布入口并要求二次确认、提交中按版本禁用；服务端必须复用唯一事务发布服务，重新锁定并校验双语文案、插件配置、所有配置币种价格、简单库存和履约接口冻结证据，原子切换旧发布版本、当前指针及员工业务审计。前端确认不构成授权或完整性证据，任何绕过页面的直接请求仍需失败关闭。
- 商品发布预览必须与发布动作使用同一精确权限，只返回固定有界、由前端本地化的稳定检查码：生命周期、启用分类、双语销售资料、配置声明与值、受限联动、逐币种价格、税务和履约接口。未全部通过时界面必须禁止提交；预览仅解释当前状态，不能成为授权或可发布凭证，真正发布必须重新读取权威数据执行全部门禁。任何插件或供应商核对不得泄露私有配置，也不得在预览中产生外部副作用。
- 后台分类候选、分类创建和商品创建必须使用三项互不替代的精确员工权限；候选只返回本地启用分类并设置固定数量和响应大小上限。手工创建商品原子生成商品、`manual + draft`版本 1 和该版本的简单库存设置，不自动生成插件配置、价格、履约接口、发布状态或合同要求。
- 后台插件商品配置编辑必须使用独立精确员工权限，并只允许修改仍为草稿且来源允许人工维护的版本。写入必须先锁父版本，设置字段、选项、规则、文件和响应大小硬上限，并与业务审计同事务。管理端完全按冻结的插件双语声明渲染宿主标准组件，不提供任意`JSON`、原始字段键、原始枚举或代码编辑器；保存后、发布前及履约前由服务端按同一声明修订重新校验。
- 后台计费规则和价格方案必须分别使用`idc:admin:catalog:billing:write`与`idc:admin:catalog:price:write`精确员工权限，且只允许修改`manual`、`copy`或`migration`来源的草稿。计费规则复用报价域唯一校验；价格以一个“计费规则 + 基础商品或规格项 + 精确大写三字母币种”的完整方案一次原子提交，阶梯从 0 开始、区间连续、末段无上限，续费价与相位一致。金额只保存整数最小货币单位，不自动转换币种代码、不换算、不跨币种继承，也不覆盖既有同维度方案；两类写入共享版本父锁并与业务审计同事务。
- 通用配置联动规则必须使用独立`idc:admin:catalog:compatibility:write`精确员工权限并共享版本父锁，只允许从插件冻结声明提供的受限操作符、条件和结果中选择。字段引用必须属于同一声明修订，隐藏或禁用字段不得凭客户端残留值绕过校验；规则写入、容量与深度检查、冲突拒绝和员工业务审计必须同事务，并与公开配置、报价、发布和履约门禁共用唯一校验语义。服务器插件可在自己的契约中声明服务器选项关系，但核心不得把服务器关系类型固定为所有商品的公共枚举。
- 通用商品库存是新增、编辑商品版本时直接维护的简单设置：是否跟踪库存和非负可售数量。库存不绑定插件、供应商、资源池，不需要审批、原因或库存审计；报价必须扣除当前有效预留，结账继续用数据库锁防止超卖。商品版本成本也是商家直接维护的通用设置，按币种和周期追加或更新，不携带 Provider 或资源池字段。
- 服务器插件可以在自己的后台页面维护资源池、新单路由、维护模式和故障切换，但这些能力不得成为商品核心页面、通用 API 或通用库存的必填字段。商品核心只保存一个已校验的接口实例引用；目录插件不得读取服务器插件数据库，也不得解释或信任客户端提交的资源池编号。
- 服务器插件可以提供独立的“供应商容量”观测页，但它不是商品库存管理，也不得自动创建商品、商品草稿、商品库存或销售审核。该页面只服务服务器插件自己的异步履约和故障判断，不出现在通用商品编辑器；不得返回 Provider 游标、指纹、端点、凭据或原始错误。
- 供应商容量观测如需分页、同步和重试，必须保持有界、幂等并在插件内部完成；结果只表示供应商侧当前容量，不改变商品版本库存，不触发商品停售，也不要求普通商品运营人员填写原因或完成库存审计。
- 公开销售目录只展示`active`商品指向的当前`published`版本，列表每页最多 24 条并使用绑定全部筛选条件的不透明 keyset 游标；列表、详情和筛选候选只读本地 PostgreSQL，不调用 Provider。匿名投影不得包含商品/版本内部编号、数据库主键、资源池、成本、Provider 身份、凭据或快照指纹，只能展示双语销售资料、完整可售币种和由商品版本简单库存得出的`available/unavailable`结论。目录摘要永远不能冒充报价；在插件配置方案和权威价格构成完成前，用户端只能提示“配置后确认准确价格”。
- 公开商品配置器只读取当前正式版本，以部署密钥派生的 HMAC 不透明修订绑定公开 slug、内部版本、插件发布与配置声明修订；匿名声明只含双语标签、说明、宿主控件类型、受约束安全值、公开候选和允许的受限联动结果，不得返回内部版本、稳定字段键、原始枚举、任意`JSON`、价格成本、资源池、供应商或数据库主键。完整选择必须由服务端按冻结声明权威校验，隐藏、禁用、失效候选和客户端本地状态都不能成为报价或下单授权。
- 正式配置图的进程内 LRU 最多 256 项，PostgreSQL 始终是权威源；每次校验先读取当前商品、启用分类和正式版本并核对修订，所以版本切换或停用没有陈旧窗口。多节点不共享图内容，缓存遗漏、驱逐、重启或损坏只回退数据库重建，并提供命中、未命中、写入、驱逐和损坏计数；缓存不得保存价格、原始规范、成本或 Provider 数据。

- 最终结算报价必须重新批量校验购物车，公开价格解释和购物车缓存金额都不能直接成为锁价；商品、插件配置、精确价格、通用库存、履约接口、风险、税务、客户资格与优惠事实全部进入不可变快照，报价同步路径禁止调用插件或供应商。服务器资源池选择如存在，只能成为服务器插件自己的不透明证据。
- 最终报价统一按未税净额核算，含税商品先按冻结税策反推未税金额，优惠后再计算税额；所有金额只用整数最小货币单位并满足`小计－优惠＝净额`、`净额＋税＝总额`及头/项目/构成/调整各层求和不变量。
- 营销优惠按整笔报价一次确定性评估和预占，再稳定分配到适用项目；当前没有正式代理关系与代理价来源时必须明确记录无代理调整，禁止用客户价冒充代理价。报价、优惠预占和购物车最新报价指针必须同事务成功或整体回滚。
