## Provider 上游工单长期边界

- 智简魔方公有云管理员`v1`的冻结契约没有工单端点，`idc-zjmfcloud`必须把`server.upstream-ticket`声明为明确不支持；执行该能力时必须在本地失败关闭且零网络调用。
- 旧魔方财务系统的上游工单使用独立的`/zjmf_api_login`或`/resource_login`登录，以及`/ticket/department`、`/upload_image`、`/ticket/create`和`/ticket/reply`；它属于财务/资源渠道协议，禁止与管理员`v1`混用认证、客户编号、实例编号或任务语义。
- 实际上游工单转发归工单域所有，必须独立完成管理员选定字段、附件脱敏、部门映射、本地/上游编号映射、回复同步和内部备注隔离；不得为了复用通用 Provider 能力把未经验证的工单端点塞入魔方云资源适配器。
- 旧魔方财务上游工单连接固定由`idc-core`工单域拥有独立渠道配置：端点、`zjmf_api_login`或`resource_login`认证模式、账号秘密句柄、上游部门映射和渠道状态不得复用魔方云管理员`v1` Provider 配置。工单域只保存由所关联长期权益的业务拥有方提供的不透明上游关联引用，不把`dcimid`、服务器服务号或其他供应商内部编号做成通用字段，也不要求管理员手填这些编号。秘密只通过`core secretcap`保存和短暂访问，普通配置、任务、日志、审计和接口响应不得保存或回显原文；未配置、停用、版本不兼容或缺少权威权益映射时转发入口隐藏并在直接请求中失败关闭。
