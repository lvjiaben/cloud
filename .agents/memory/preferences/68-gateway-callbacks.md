## 本地合规网关回调与对账长期规则

- 本地供应商回调必须分为供应商专用验签适配器和供应商中立收敛核心；核心只接受验签器一次性同步产出的已验证事件，不接受普通 JSON、自报实例/商家/主体或“已验签”布尔值。腾讯回调路由由`10.9`按当时官方精确通知与验签契约实现并验证后开放，未完成前不影响`10.8`通过主动查询实现可恢复流程；诺诺精确验签字段和密钥轮换契约未核实时不开放生产回调路由。任何供应商都不得自创通用`HMAC`冒充官方验签。
- 回调原始请求体最多 256 KiB，只有供应商专用验证器确认参与签名的有界请求头可以和原始字节一起进入加密证据；未签名候选头不得保留。外部事件精确重放必须恢复原证据、原投递号、原投递版本和当时投影，任何关联、载荷或规范状态变化都冲突；数据库必须强制证据、路由与投递版本一致且一个证据最多形成一个投递。
- 每个真实供应商写租约必须在同一事务创建唯一的本地回调路由。外部对象号使用独立 HMAC 精确查询并加密保存；回调只能按既有外部对象绑定，或按被供应商签名覆盖的本地尝试关联值首次绑定，实例和业务归属始终由 PostgreSQL 权威关系派生。
- 回调与主动查询原始证据必须用独立 AES-256-GCM 密钥加密，外部事件号使用供应商隔离 HMAC 去重。重复或乱序事件保留证据但不能让终态倒退；相互冲突的终态进入只读主动查询，不能按最后到达结果覆盖。证据、路由、投递版本与证据摘要必须由数据库复合外键锁定一致，一个证据最多形成一个投递；本地业务只接收单调版本、规范状态和脱敏证据摘要。
- 本地主动查询只能领取已经绑定加密外部流程号的路由，必须使用 PostgreSQL 权威时间、有界批量、`SKIP LOCKED`、256 位精确租约和有上限指数退避。外部流程号只在路由保护器同步回调内交给启动期冻结的供应商专用只读查询器；失去租约的迟到结果不能覆盖回调，原始响应只保存为加密证据，自由文本错误不得持久化。权威查询确认现有终态可以清除对账待办，相反终态继续保持冲突等待人工接管；查询不得绕过领域服务直接改写商家业务请求。
- 本地人工接管只能由当前`IDC`商家的受权员工把运行中、结果未知或存在终态冲突的路由推进为`manual_takeover`并停止自动化，不得提供强制成功、强制失败或危险重发。每次接管必须带近期完整认证、精确乐观版本、封闭原因和 1 至 16 条同一路由既有不可变证据；存储层集合核对并摘要证据，将接管记录、关联、加密决定证据、路由版本和本地投递在同一事务提交，只有完全相同的用途隔离操作键重放可以恢复。
- 主动查询只允许领取`running/result_unknown/reconciliation_required`路由，使用 PostgreSQL 时间、随机租约、状态和版本完整围栏；查询失败只延后并保留未知，不得调用供应商写接口。人工接管只接受当前商家员工权威能力、最后读取版本、封闭原因及一至十六条本路由既有证据，不允许自由文本、强制成功/失败、覆盖外部编号或危险重试。
- 本地人工接管的封闭原因固定为`result_remains_unknown`（结果仍不明确）、`terminal_result_conflict`（成功与失败证据冲突）、`query_reference_missing`（缺少只读查询所需编号）、`supplier_query_unavailable`（供应商只读查询暂不可用）或`compliance_security_review`（需要合规或安全复核），禁止自由文本。提交接管要求当前员工最近五分钟内完成完整登录。后续管理页面默认勾选最近且与当前待办最相关的安全证据，员工可以确认或调整，最终提交一至十六条；页面只显示时间、来源、规范状态和本地不透明编号等安全元数据，不显示供应商原文、密文、摘要、外部编号或秘密。
- 腾讯已有合同模板首次同步到`LinaPro`时，如果腾讯接口不能可靠提供本地所需的适用客户、签署顺序或模板语言，必须标记为“待补充设置”，不得猜测或自动扩大适用范围；管理员补充这三项后才允许在本地启用。
- 腾讯模板后续被停用或不再返回时，必须保留本地映射、历史合同和不可变版本，标记腾讯已停用或已下线，并禁止新合同继续使用；不得因供应商状态变化删除历史。
