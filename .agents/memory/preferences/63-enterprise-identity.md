## 企业实名认证长期规则

- 所有客户账号必须先完成个人实名认证，提交本人姓名和身份证并由服务端权威确认；个人实名认证完成前不得发起企业认证。完成个人实名认证后，同一个账号可以继续申请企业认证，不另建登录账号或客户主体。
- 企业认证提交后，在待审核、补材料或驳回期间，账号继续按已完成个人实名的个人客户使用；只有后台批准并完成企业法定投影事务后，同一账号才升级为企业客户。企业认证失败、驳回或撤回不得取消既有个人实名结果。
- 企业认证材料原件、拟变更法定资料和材料永久访问地址只归`idc-compliance`及插件作用域私有对象存储所有，不得进入`idc-core`普通表、日志、审计正文、任务载荷或任何`AI`输入。核心域只保存批准后的法定投影、键控查重摘要和不透明合规案件号。
- 企业认证必须使用独立的用途告知与同意。客户身份由当前登录主体推导，不得从请求接收客户号或租户号；法定资料变更复核使用的同意必须发生在该变更申请之后。
- 已认证企业修改法定名称或登记标识时，必须先创建只含变更字段类别、原认证案件号和原投影版本的核心法定资料变更单，再精确绑定一个新的合规复核案件。复核中或驳回时继续保留原已认证投影；只有批准事务可以替换投影并关闭变更单。
- 企业登记标识查重必须使用安装实例密钥生成用途隔离的键控摘要，并由数据库唯一索引处理并发竞争。批准路径不得借本次复核修改变更单未声明的法定字段；案件、投影、变更单和审计任一写入失败都必须整体回滚。
- 企业认证原件上传固定采用“两步式服务端预约 + 原始内容写入”：先用 JSON 命令提交材料类型和随机幂等键，由服务端生成不透明材料编号；再以该编号向固定原始内容端点发送 PDF、JPEG 或 PNG。原件上传请求不得使用 multipart、客户端文件名、客户端对象路径、永久地址、自定义幂等请求头或材料类型请求头，避免框架临时明文文件及请求头追踪泄漏。
- 企业认证材料和法定资料快照必须先在可清除缓冲中完成类型、容量与业务规则校验，再使用安装实例本地`secretcap`生成密钥的 AES-GCM 信封加密，只把密文写入插件作用域私有对象存储并回读确认。普通数据库只允许保存不透明对象引用、密文摘要、密钥代次码、容量和状态；密钥明文、密文、秘密句柄、对象引用和永久访问地址不得进入客户响应、日志、审计正文、任务或`AI`。
- 企业认证经办人姓名、证件号和授权材料只在申请人角色明确为授权经办人时收集；法定代表人直接申请时必须拒绝多余经办人身份字段和经办材料。所有法定资料明文只进入案件专属加密快照，并在服务返回前清除调用方可清除缓冲。
- 企业认证客户入口只返回案件号、材料号、稳定状态、材料类型、媒体类型和大小等安全投影；不得返回私有对象引用、密文摘要、密钥代次、秘密引用、原始幂等键或内容指纹。材料查看和下载必须留给后台独立精确权限、最近重新认证、短期单次访问票据及逐次查看审计闭环。
- 企业认证后台列表必须使用有界、无精确总数的稳定游标分页；详情默认只返回脱敏法定资料和有界材料元数据。后台批准只能消费服务端认证过的加密法定资料快照，请求不得提交或覆盖法定资料；驳回只能使用面向客户的封闭可操作原因码。
- 企业认证原件访问必须复用核心近期完整登录证明：独立精确权限、直接员工和数据范围先行，证明必须签名、绑定当前会话与精确案件/材料、短期有效且由 PostgreSQL 单次消费。每一次真正放行原件都必须先在同一事务写入不含对象路径、摘要、证明或身份明文的不可变业务审计；证明签发不产生永久地址。
- 企业认证批准必须在同一事务锁定并重新核对服务端权威法定资料快照和最多八份材料，禁止用事务外预检代替最终门禁；后台按客户筛选的有界案件目录必须有与稳定游标顺序匹配的数据库索引，不能退化为全表扫描。
- 企业登记标识重复时批准事务必须整体回滚，再在新事务把案件置为`review_required`并记录稳定重复风险原因；不得强制覆盖另一客户的核心法定投影。重审中的已认证企业只有最终批准能替换原投影，驳回继续保留原认证结果。
