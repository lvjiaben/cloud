## 原子结账与库存预留规则

- 客户结账只消费当前活动客户自己的最终报价；原始幂等键只计算摘要后落库。相同客户、相同幂等键和相同报价必须复用首单，同键换报价或同报价换键必须拒绝，不能靠重复点击生成多单。
- 结账锁序固定为“幂等作用域、报价、购物车、客户、排序后的商品版本简单库存、营销预留”。报价必须仍是购物车最新报价，客户版本和状态未变化，报价及购物车未过期；任何变化都要求重新报价。通用结账不得锁定、读取或解释服务器插件资源池和供应商容量。
- 所有商品库存都只由商家在商品新增、编辑和版本设置中直接维护，结账读取并冻结商品库存结果。通用商品库存与自动化插件、供应商接口和资源池无关，不产生插件库存扩展点、自动库存同步、独立库存审核、确认权限、原因说明或审计流程。服务器插件可以在自己的履约边界内判断供应商容量是否足够，但不得反向修改或冒充通用商品库存；不得用风险审核或履约审核伪造库存事实。
- 订单、订单项、原始待付账单、账单明细、库存预留、通用配置快照、营销名额核销、购物车关闭和订单 Outbox 必须在同一个本地 PostgreSQL 事务提交。任一步失败整体回滚；同步结账不得创建服务器专用履约单元，也不访问支付渠道、自动化插件、通知、合同、税务发票或`AI`，不提前写支付或资金账本。每个订单项后续统一形成一份交付记录；履约意图是在权威结清并满足所选履约方式后，按照冻结插件契约声明的`per_order_item`或`per_quantity_unit`粒度持久化创建。
- 单次结账最多处理 100 个报价项目；订单项数量和后续按件履约意图总量使用独立硬上限，但不得把数量预先展开成服务器专用履约单元。账单明细金额必须逐字段复制不可变订单项并由数据库提交约束复核；订单、账单和预留使用同一个数据库时间基准计算付款/持有截止时间。
