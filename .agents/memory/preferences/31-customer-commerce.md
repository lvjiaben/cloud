## 客户交易门户与后台订单目录规则

- 客户购物车、报价、结账、付款准备、取消、订单列表和详情接口只从当前活动客户主体派生所有权，任何客户接口都不得接受或回传`customer_no`。后台订单目录必须使用与客户读模型分离的服务，并分别校验`idc:admin:commerce:order:list`和`idc:admin:commerce:order:query`精确权限；直接员工、默认商家和可表达数据范围之外一律失败关闭。
- 客户与后台订单列表不返回昂贵总数，使用部署密钥独立派生的 AES-GCM 游标封装`created_at + id`边界，并绑定客户、后台/客户入口、全部筛选条件和页大小。客户单页最多 50 条、后台最多 100 条；游标被篡改、跨客户、跨筛选或跨入口复用都必须拒绝。
- 订单详情必须由一次服务调用在本地 PostgreSQL 只读可重复读事务中聚合订单、账单、最多 100 个项目、有界通用交付记录与履约意图、1000 条库存事实、取消、最多 100 条审核及付款准备，禁止前端逐行补查。长期服务权益只在冻结插件契约声明持续管理能力且真实创建后显示；响应不得包含数据库主键、内部摘要、接口秘密、Provider 凭据或原始载荷。
- 所有 HTTP 金额使用十进制最小货币单位字符串，前端用`BigInt`格式化，不得转成 JavaScript 浮点数；时间点统一使用 Unix 毫秒。取消、付款和风险动作是否可用必须由服务端当前事实投影，未知资金、资源或履约结果时不提供危险快捷操作。
- `web-customer`用户中心对结账和取消等业务动作使用浏览器生成的随机 UUID 幂等键，并在同一会话的重试和刷新恢复中稳定复用；禁止用订单号、报价号或用户编号构造可预测幂等键。订单创建后结账按钮立即锁定，页面刷新重试仍由后端返回首次提交结果，不能诱导客户重复下单。
- 后台订单详情只读投影即使显示待风控，也不得伪造`evidence_digest`来调用批准或驳回。缺少完整证据审核流程时入口必须禁用并解释原因；后续启用仍需沿用批准/驳回两项独立权限、服务端证据重检和原子业务审计。
