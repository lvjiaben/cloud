## 服务期限与续费履约长期规则

- 所有已进入履约的订单项都必须保留通用交付记录，用于展示交付进度、结果和后续人工处理；但不能因此一律创建长期服务权益。只有插件冻结契约明确声明该商品需要持续管理、续期、状态查询或客户后续操作时，履约成功后才创建长期服务权益。手机、普通实物和一次性人工服务等一次性交付商品默认只保留交付记录；`SSL`证书、云服务器等需要持续管理的商品由插件契约声明长期服务能力。通用核心不得按商品分类、名称或服务器字段猜测。
- 开发数据迁移只允许为具有精确冻结通用履约意图的旧订单服务补建交付记录、长期权益和同事务`Outbox`。当前`090-generic-delivery-entitlement-backfill.sql`必须按这一证据边界执行；缺少精确意图的活动旧服务必须失败关闭，先提示导出需要保留的开发数据，再按当前模型重建，绝不能伪造插件契约、业务拥有方或长期权益。
- 续费入口只对已经创建长期`service_entitlement`，且冻结插件契约明确声明持续管理、续期支持与到期管理语义的权益开放。一次性交付、实物和一次性人工服务没有续费入口；系统不得按商品名称、分类、插件 ID 或服务器字段猜测续费能力。
- 冻结业务拥有方契约明确声明由外部供应商确认续期时，续费必须通过版本化拥有方接缝和持久异步任务执行，只有权威任务成功并与本地权益收敛后才能推进新到期日。契约明确声明期限只由本地权益管理时，才允许在财务结清后原子推进本地期限，且不得伪造外部任务、到期快照或供应商对账证据。
- 续期支持或到期管理能力缺失、未知、条件不满足、冻结契约不一致或证据失效时必须失败关闭并进入人工处理，不能按插件名称推断，也不能静默降级为本地续费。服务器插件若使用 Provider 续期，只是该业务拥有方的一种实现，不得成为所有商品的通用规则。
- 新购和续费价格必须保存不可变权益价格快照，冻结商品版本、配置快照、计费周期、币种、税务、价格构成、原到期日、预计新到期日、业务拥有方、契约版本和续费模式。头部金额与完整构成必须同事务匹配，后续改价、改配置、换接口实例或调整插件内部资源池不得覆盖历史。
- core 只拥有长期服务权益、续费策略、续费操作和冻结契约引用；各业务拥有方独占自己的运行状态、外部任务、资源映射和供应商证据，core 只能保存不透明引用和脱敏状态，禁止跨插件直接读写数据库。服务器运行状态和 Provider 资源事实继续只属于服务器插件，不得扩展成所有长期权益的共同字段。
- 新购服务器开通采用“core 先提交业务终态、resource 再幂等接收结果回执”的跨插件收敛：core 只保存资源任务不透明编号、渠道编号和脱敏证据摘要；resource 只有收到与任务、请求和证据完全一致的成功回执后才把初始密码标为可领取，失败回执必须吊销密码，人工处理必须保持不可领取。`result_unknown`是需要继续权威查询的非终态，core 只能把运行态投影为未知并继续只读轮询，不得发送终态回执、释放库存或停止收敛。回执暂时失败只能重试同一冻结回执，不能回滚已经提交的 core 终态或重复创建、查询 Provider 任务。
- 多台服务器共用的库存预留必须保存已消耗数量和已释放数量。所有履约单元终态后，全部成功为`consumed`、全部失败为`released`、成功与失败混合为`partial`；结果未知或人工处理不得提前释放库存，也不能把部分成功伪装成整单成功。
- 自动续费的报价/账单冻结窗口与手动续费分离；下一次余额重试必须早于账单截止时间和能力证据到期时间，任一窗口不足时形成已耗尽事实并提醒，禁止保存一个必然无法执行的重试时间。
- 到期自动化采用按服务冻结的不可变生命周期策略。主节点调度只创建带服务版本、原到期日和策略版本栅栏的提醒、宽限、到期、暂停、恢复或终止任务，不直接覆盖服务三维状态，也不在扫描事务调用 Provider；续费成功后旧到期任务必须失效，已权威暂停但尚未终止的服务只创建一次恢复任务。
- 自动恢复必须证明服务当前最后一次业务操作仍是那次权威成功的生命周期暂停；商家人工暂停、安全暂停或滥用处置不能因为历史上曾自动暂停而被续费流程自动解除。
- 到期自动终止只允许作用于运行中、已关机或已暂停三个稳定运行态；开通中、恢复中、变更中、终止中、已终止和运行状态未知时禁止自动回收。终止与仍在执行或待人工确认的续费互斥。
- 终止前必须冻结原运行态。Provider 明确失败，或明确报告能力不可用且能够证明尚未创建上游写任务时，恢复原运行态并记录确定失败；是否写入未知时保持终止中并转人工，禁止盲目重试。
- 生命周期审计元数据与真正发给 Provider 的参数必须分开保存；内部任务号、服务版本、到期栅栏、能力摘要和幂等摘要不得混入上游参数。跨插件失败码在进入 core 前规范化为小写稳定码，原始 Provider 错误文本不得进入客户事实或日志。
- 生命周期跨插件依赖必须走版本化`lifecycleresourcecap`和声明期 SPI：resource 声明并拥有 Provider 任务来源，core 在作业装配时冻结工厂并显式注入处理器。提醒 Outbox 由 core 拥有，必须与生命周期处理器共享同一 core 数据库实例并作为强制构造参数传入；禁止隐藏全局服务定位、跨插件数据库读写或为测试放宽生产依赖。
