# 变更审查

在`openspec.md`规定的实现、反馈完成及归档节点，或用户明确请求审查时使用。领域规则唯一来源为`AGENTS.md`及其引用文件；技能仅负责编排，不新增领域门禁。

## 确定范围

- 任务或反馈审查限定本任务修改、创建和生成的文件；归档审查覆盖该变更全部内容；手动审查按用户指定范围，未指定时使用工作区变更。
- 用`git status --short`、`git diff --name-only`、`git diff --cached --name-only`和`git ls-files --others --exclude-standard`收集候选，再按任务归属过滤，不能将其他任务的工作区改动自动纳入。
- 范围必须包含本任务未跟踪文件。未跟踪目录展开为具体文件；涉及子仓库时进入子仓库收集同类状态并补父路径前缀。生成流程产物即使没有差异也需纳入相应验证范围。
- 涉及插件时检查并读取该插件根目录`AGENTS.md`；涉及活跃变更时用`openspec status --change "<name>" --json`确认状态。

## 读取与验证

1. 按`AGENTS.md`判断命中规则域，依据`.agents/rules/context-loading.md`读取相关完整规则章节和完整`Requirement`及其`Scenario`。禁止以检索摘要代替正式结论。
2. 同一任务内未变化、已读正文仍在上下文中的规则与证据可复用。跨会话、正文丢失、内容变化或范围扩展时重新读取必要内容，避免实施到审查重复全量加载。
3. 对当前范围检查契约、实现、测试、规范和任务状态；影响分析与强制验证命令遵循`.agents/rules/openspec.md`及实际命中领域规则，不在本技能维护命令清单。
4. 验证证据必须覆盖当前内容。已通过且覆盖内容未变化的本次证据可复用；新增/变化路径、失败或未覆盖项需要补验证。记录外部依赖阻断、替代验证和剩余风险，不能把未执行当作通过。
5. 缺失规则、不可调和冲突或缺少强制门禁证据属于阻塞问题；不得据此完成任务或归档。仅检查相关类别，不擅自修复范围外文件。

## 输出

简述范围与来源、读取规则、验证证据和结论。发现项必须包含文件路径、行号、规则来源及影响；严重问题阻塞完成，警告说明风险。无问题时写明“未发现阻塞问题”，保留实际验证缺口。无需重复空章节或逐域模板。
