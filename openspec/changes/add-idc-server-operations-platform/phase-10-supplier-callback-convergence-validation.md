# 第十阶段供应商回调收敛验证记录

## 1. 范围与结论

本切片完成任务`10.6.e.2`的供应商中立回调收敛核心，包括启动期注入的供应商专用验证器、失败关闭注册表、原始字节与签名头边界、事件去重路由、乱序状态机、加密证据和版本化实例投递。

本记录形成时尚未冻结腾讯电子签与诺诺电子发票生产回调的精确签名字段、证书或密钥轮换、时间窗和事件类型契约，因此没有注册生产回调`HTTP`路由，也没有把通用`HMAC`或测试替身冒充供应商验签器。腾讯验证器现由`10.9`按当时官方精确通知与验签契约实现，诺诺继续等待正式契约；只有逐项验证后才能在启动装配层注入对应验证器并开放其精确路由。

## 2. 信任、证据与路由边界

- `SupplierCallbackService`只接收原始请求体和有界候选头；普通调用方不能提交预构造的已验证事件。验证器必须在返回成功前同步调用一次且仅一次`yield`，缺失验证器、零次或多次产出、非法事件、缺失签名头和越界材料全部失败关闭。
- 原始请求体最多 256 KiB，候选头最多 32 个/32 KiB，参与签名的头最多 16 个/16 KiB，单头值最多 4 KiB。证据只保留原始请求体和验证器声明的已签名头，未签名候选头不会进入加密证据。
- 证据帧最多 282624 字节，AES-GCM 密文最多 282652 字节；数据库约束接受精确最大值并拒绝超限值。证据密钥、路由加密密钥、路由查询 HMAC 和事件 HMAC 均要求互不复用。
- 回调归属只由供应商、既有外部引用 HMAC、供应商签名覆盖的中央尝试号或已存在事件 HMAC 推导。查询通过三个精确索引候选的`UNION`最多返回两条路由以发现冲突，不读取回调自报实例、商家、客户或主体，也没有循环查询和`N+1`。

## 3. 去重、乱序与投递不变量

- `provider_code + external_event_hmac`是事件唯一围栏。相同事件、相同路由、相同证据摘要、相同规范状态和相同外部引用为精确恢复；关联、载荷或状态变化返回稳定冲突，不覆盖原证据。
- 精确重放在路由后续发生变化时仍恢复原证据对应的投递号、投递版本和当时的规范投影，不会把旧投递号与当前路由版本拼接。
- `running`只可进入成功、失败或结果未知；结果未知可被后续权威终态收敛；终态不被处理中或结果未知倒退。相反终态只把对账投影置为`query_required`，不采用最后到达结果。
- 证据、路由投影与投递在一个 PostgreSQL 事务内提交。数据库以复合外键强制`evidence_no + route_no + route_version + evidence_sha256`与投递完全一致，并以唯一约束保证一个证据最多形成一个投递。
- 回调不会直接改写商家实例的业务请求状态。实例后续只消费中央投递中的路由、请求、规范投影、中央版本和证据摘要。

## 5. 规则域与依赖来源

- 架构与依赖注入：存储、路由保护器、证据保护器、事件摘要器和每个供应商验证器均由构造函数逐项注入并在构造期冻结；当前没有生产路由和运行期服务图，因此没有临时`New()`、全局注册表或缓存实例。未来启动装配是唯一 verifier owner。
- 数据库：变更只含当前未发布迭代的 PostgreSQL DDL，无 Seed 或 Mock DML；最新 SQL 已直接二次执行验证幂等。事件、外部引用、尝试和投递均使用唯一或精确索引，单次回调查询数为常数。
- 数据权限：没有客户或员工`HTTP API`。实例归属由已持久化写尝试和路由复合外键派生，回调不能提交所有权字段；因此不接入后台角色数据范围，也没有对象存在性接口。
- 安全：原始请求、签名头、外部事件号和外部对象号不进入日志、错误或普通投影。只保存密文、用途隔离摘要和规范状态。
- 缓存、前端、`i18n`与 E2E：均无影响；本切片不新增缓存、页面、用户可见文案、接口文档或可访问路由，因此使用 Go 单元/集成测试而不是浏览器 E2E。

## 6. 剩余边界

- 本切片没有注册腾讯与诺诺供应商专用验证器及生产`HTTP`路由；腾讯后续由`10.9`实现，诺诺继续受外部证据门禁。
- 主动查询领取、结果回报与退避由`10.6.e.3`完成，平台授权和证据驱动人工接管由`10.6.e.4`完成；它们各有独立验证记录，不属于本回调切片。
