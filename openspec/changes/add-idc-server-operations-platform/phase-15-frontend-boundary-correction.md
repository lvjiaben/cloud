# 第十五阶段前端边界纠偏

## 结论

本文件冻结官网、客户后台和管理后台的最终边界。它纠正此前把官网与客户后台合并成 Nuxt 应用的错误方向，但不改变当前仍应按顺序完成第十阶段的要求。

| 边界 | 最终位置 | 技术与责任 |
|---|---|---|
| 管理后台 | `apps/lina-vben/apps/web-antd/` | LinaPro 现有 Vben 管理工作台，不承载客户业务页面 |
| 客户后台 | `apps/lina-vben/apps/web-customer/` | 以`web-antd`为母版的 Vben/Vite 第二应用，承载登录、账户、购物车、结算、订单、财务、服务器、合规和售后 |
| 官网生态 | `apps/lina-websites/` | 独立官网契约、开发`SDK`、起步模板、默认 Nuxt 官网、开发文档和动态官网包交付 |

## 问题原因

此前为了让官网具备服务端渲染和`SEO`，直接把`web-customer`改成 Nuxt`app/`结构。该做法错误地让官网技术栈覆盖了客户后台技术栈，违反“客户后台必须与`web-antd`一比一使用 Vben 写法”的用户要求，也使第三方官网开发者必须进入`lina-vben`。

## 客户后台允许差异

`web-customer`必须复制并持续跟随`web-antd`的目录和基础设施。只允许以下差异：

| 允许不同 | 原因 |
|---|---|
| 包名、应用名、图标和品牌值 | 区分客户后台与管理后台 |
| 开发端口`6677` | 与管理后台`6666`隔离 |
| 偏好与持久化命名空间 | 防止主题、布局、水印和状态互相污染 |
| 客户业务路由、接口、状态和页面 | 两个应用面对的使用者和业务不同 |
| 构建产物和发布路径 | 保持独立升级与路由边界 |

除上述项目外，`src/`、Vite、TypeScript、`src/app.vue`、`src/main.ts`、`src/bootstrap.ts`、`src/preferences.ts`、`src/router/`、`src/api/request.ts`、`src/store/`、`src/locales/`、`src/layouts/`、`src/adapter/`、`src/components/`、`src/views/`、共享包、页面容器和交互写法均以`web-antd`为准。客户后台禁止使用 Nuxt 文件路由、Nuxt 状态、Nuxt 请求层或另一套偏好系统。

## 官网开发与交付

`apps/lina-websites/`至少包含以下项目：

| 路径 | 用途 |
|---|---|
| `sites/default/` | 随系统交付的默认 Nuxt 官网 |
| `packages/site-contracts/` | 品牌、内容、商品、价格、购物车交接和`SEO`的稳定类型 |
| `packages/site-sdk/` | 对版本化公开接口的安全封装 |
| `templates/nuxt-starter/` | 第三方开发者可复制到独立仓库的起步项目 |
| `docs/` | 中英文开发、调试、测试、打包、安装、升级和安全说明 |

第三方官网不需要访问或修改`lina-vben`、客户后台或插件后端源码。官网只能调用版本化`public`接口；客户后台只通过统一 Vben 请求层调用当前客户的`account`接口。

## 动态官网包

开发者完成官网后生成标准预编译`.zip`。压缩包必须包含已经构建好的服务端产物、静态资源和不可变清单，不得要求商家重新编译 LinaPro，也不得在安装时联网执行`npm install`。

后台动态安装流程如下：

1. 有独立权限且完成重新认证的管理员上传官网`.zip`。
2. 本安装实例流式写入暂存区，检查文件数量、压缩前后大小、路径穿越、绝对路径、符号链接、重复文件、清单、摘要、兼容版本、路由和所需能力。
3. 校验通过后解压到按官网、版本和内容摘要隔离的不可变目录。
4. 使用安装包内置的锁定运行时，以低权限独立进程启动候选版本；候选进程只获得公开接口地址、站点修订和最小运行目录。
5. 健康检查、服务端 HTML、静态资源、双语、路由和`SEO`预检通过后，才允许管理员打开专用预览。
6. 发布时原子切换当前版本指针和路由目标，不重编译，不覆盖旧目录，也不重启`web-antd`或`web-customer`。
7. 切换失败继续服务上一个健康版本；管理员可以一键回滚。

## 路由与购物车交接

| 路由范围 | Owner |
|---|---|
| `/`、`/products/*`、新闻、公告、知识库、下载、联系和公开协议 | 当前已发布官网包 |
| `/auth/*`、`/account/*`、`/cart`、`/checkout/*`和支付返回 | `web-customer` |
| `/admin/*` | `web-antd` |
| `/api`、`/x`和`/x-assets` | LinaPro 与源码插件后端 |

官网加入商品时只提交商品和配置选择，后端重新计价并保存权威购物车。官网只把不透明购物车引用交给`web-customer`；不得通过 URL、本地存储或前端包传递权威价格、客户号、购物车快照或支付结果。

## 迁移与删除门禁

此前错误 Nuxt`web-customer`中的公开商品展示和配置器应迁入默认官网；购物车、订单、财务、个人实名和企业认证应按 Vben 页面规范迁入重建后的`web-customer`。旧`idc-portal/portal`也按同一归属拆分。

只有默认官网和 Vben 客户后台的类型、双语、路由、安全、真实浏览器、适用的`SSR/SEO`和构建门禁全部通过，才能删除旧 Portal 源码、生成物、锁文件、构建配置和测试副本。禁止先删后迁，也禁止长期保留两套可编辑实现。

## 后续执行顺序

本纠偏先停止继续扩展错误 Nuxt`web-customer`，保留并迁移已有工作，再建立 Vben 客户后台基线和官网开发边界。完成纠偏后，主任务仍回到`tasks.md`当前未完成的第十阶段；不得因为修正了第十五阶段前端边界而跳过第十至第十四阶段。

## 当前实施状态

截至`2026-08-13`，错误 Nuxt 源码已整体迁到`apps/lina-websites/sites/default/`，原路径已按`web-antd`母版重建为 Vben/Vite `@lina/web-customer`，并通过结构一致性、类型、双语和依赖构建门禁。独立官网工作区已经建立契约、`SDK`、Nuxt 起步模板和中英文开发文档，类型和生产构建通过。

这不是第十五阶段完成证明。旧 Portal 仍保留，客户业务页面尚未迁入 Vben，默认官网仍暂存客户专属页面，官网生产打包器、后台上传安装器、低权限运行监管、预览、原子切换和回滚均未实现。上述任务继续保持未勾选，按阶段顺序回到当前第十阶段后再实施。
