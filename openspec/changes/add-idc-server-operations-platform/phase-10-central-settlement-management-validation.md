# 第十阶段中央结算管理验证记录

> 状态：本文件只保留历史技术验证证据。其平台操作者、预付、后付、价格发布和计费开关能力已被[完整独立交付边界纠偏记录](phase-10-independent-delivery-correction.md)废止，不得继续装配或扩展。

## 1. 任务范围

本记录对应`10.7.b`，实现中央服务内部的平台操作者结算管理能力：

- 预购账户创建与正向入账；
- 关联既有同账户流水的预购或后付纠正；
- 后付账户首次审批、限额和有效期续批；
- 一至十六项供应商价格的草稿写入与原子发布封口；
- 供应商与操作范围维度的本地计费可用性开关；
- 全部动作的用途隔离幂等、近期完整认证、不可变审计和类型化历史结果快照。

本任务没有注册公共管理`HTTP`路由，没有把管理服务装配到中央进程启动图，也没有调用腾讯、诺诺或开放供应商业务路由。安装实例、商家、商家客户和普通后台员工均不能直接取得该内部服务；未来平台运营入口必须注入实现五项精确方法的平台权威。

## 2. 权威与幂等边界

`ManagementAuthority`为预购入账、账户纠正、后付审批、价格发布和供应商计费开关分别定义方法。一项授权不能替代另一项，也不存在接收任意动作名称和任意字段的通用危险写入口。服务先校验未信任请求，再由权威精确回显全部业务字段并补充操作者引用、完整认证时间和授权证据`SHA-256`；任何金额、币种、账户、版本、关联流水、价格项、供应商范围或原因漂移都会在进入存储前拒绝。

调用方只提交带`liop1_`版本的 256 位高熵操作键。`OperationDigester`使用独立 256 位密钥并把动作类型纳入域分离`HMAC-SHA-256`；相同原始键在不同动作中不会产生相同数据库键。原始操作键不写日志或数据库。存储层使用 PostgreSQL`clock_timestamp()`要求完整认证不在未来且不超过十分钟。

## 3. 原子领域行为

### 3.1 账户操作

预购入账按“商家 + 币种”取得事务级范围锁。账户不存在时只创建同币种预购账户，随后用同一事务追加`prepaid_fund`账本并更新账户投影；账户已存在时只允许未关闭的预购模式。账户纠正要求账户编号、商家、币种、模式和期望版本完全匹配，并必须关联同账户既有流水；预购纠正只改变可用额，后付纠正只改变未结金额，任何负余额、金额上限或后付限额越界都会失败。

后付审批同样按“商家 + 币种”串行化。首次审批只在该币种没有账户且期望版本为零时创建后付账户；续批只允许未关闭后付账户，并拒绝把限额降到“已预占 + 未结”以下。续批只更新限额和有效期，不自动清除`debt_blocked`或`suspended`状态。

### 3.2 价格与供应商门禁

价格发布先写不可变管理操作，再批量写入最多十六项草稿，最后在同一事务执行唯一`draft -> published`封口。数据库要求版本头绑定完全匹配的平台管理证明；发布后继续新增、更新或删除价格项都会失败。

供应商计费门禁以“供应商 + 操作范围”唯一，首次创建要求期望版本为零，后续更新必须命中当前版本。门禁投影的每次变化都通过延迟约束匹配同事务管理操作。缺少门禁或门禁为`disabled`的失败关闭准入由`10.7.c`接入；当前`enabled`仅表示平台本地运营决定，不表示供应商生产能力或套餐余额。

## 4. 不可变审计与精确恢复

`007-settlement-management.sql`新增：

- `idc_gateway_settlement_management_operation`不可变管理操作；
- `idc_gateway_settlement_management_account_result`账户历史结果；
- `idc_gateway_settlement_management_price_result`价格发布历史结果；
- `idc_gateway_settlement_management_gate_result`门禁历史结果；
- `idc_gateway_provider_billing_gate`当前供应商计费门禁；
- 价格和管理账本对精确管理操作证明的数据库约束。

管理操作、结果快照和资金账本都不可更新或删除。账户结果使用“流水 + 账户”复合外键，不能把其他账户流水冒充本次结果。精确重放先按动作域操作摘要加事务级 advisory lock，再比较完整规范请求摘要并读取不可变结果表；因此后续余额、限额或门禁变化不会污染旧响应。相同摘要下请求内容变化返回冲突，不会重新执行。

## 5. 性能、数据权限和运行时影响

- 单次管理动作只锁定一个商家币种账户、一个账户、一个价格版本或一个供应商范围；跨商家和跨范围可以并行；
- 价格明细使用一次`unnest`批量写入，最多十六项，不产生随明细数增长的数据库往返；
- 读取只使用唯一键、主键或有界结果快照，没有列表、导出、聚合或`N+1`路径；
- 当前没有生产查询入口或公共路由，数据范围由未来平台权威提供，商家实例不能提交平台余额、后付资格或供应商开关真相；
- 没有缓存、页面、菜单、API 文档、运行时用户可见文案或语言资源变化，因此无缓存和`i18n`影响，不触发 E2E；
- 没有修改宿主、商家插件运行图、开发工具、构建脚本或跨平台入口。

## 6. 自动化覆盖

单元测试覆盖精确授权漂移在进入存储前拒绝、动作域幂等隔离和重复价格代码拒绝。真实 PostgreSQL 集成测试在随机`linapro_gateway_management_*`隔离 schema 中覆盖：

- 两次预购入账、关联纠正和不可变历史；
- 首次后付审批与按版本续批；
- 两项价格原子发布和精确恢复；
- 供应商门禁启用、停用和旧启用结果恢复；
- 旧入账在账户后续变化后仍返回原余额与原版本；
- 八个并发入账共同竞争同一账户且最终金额和版本守恒；
- 过期完整认证失败关闭；
- 迁移首次应用、幂等`Apply`、最新 SQL 重入和 PostgreSQL 标识符长度。
