# 第十阶段安装独立性验证记录

## 1. 已验证基线与外部阻断

本记录证明任务`10.6.a`、`10.6.b.1`、`10.6.c.1`、`10.6.d.1`、`10.7.a`、`10.7.b.1`、`10.7.c`和`10.7.d.1`已经形成可复用的本地化基线。`10.6.b.2`后续完成的签名帧与持久围栏证据见[本地进程认证闭环验证记录](phase-10-process-authentication-validation.md)，生产用量装配的后续闭环证据见[本地供应商用量运行闭环验证记录](phase-10-local-supplier-usage-runtime-validation.md)。本记录形成时尚未完成的供应商主体加密生命周期、持久限流/熔断、回调复合约束和主动查询租约已由各自后续记录验证，但生命周期执行服务仍未完成，因此本记录本身不证明`10.6`、`10.7`或`FB-11`完成。本记录形成时腾讯`10.4.b`与诺诺`10.4.c`均未完成；`2026-08-14`后腾讯已转为官方契约和购买方运行时门禁并由`10.8`实现，诺诺仍受外部证据阻断。

## 2. 本地进程身份基线与中央身份删除

- 安装期密钥工具生成当前安装唯一的进程认证密钥环，活动密钥签发新请求，上一代只在轮换窗口验签，撤销后不再保留秘密材料。
- 请求签名绑定方法、完整请求目标、Unix 毫秒时间、密钥编号、三十二字节 nonce 和正文`SHA-256`；数据库原子消费 nonce，过期、篡改和重放均失败关闭。
- 合规插件提供本地签名端，网关提供验签端；互操作测试使用同一密钥环验证，不需要授权码、平台销售记录、远程注册令牌或软件提供方网络服务。
- 商家插件的`gatewayenrollment`服务、DAO/DO/Entity、迁移、注册秘密 scope 与网关远程注册/身份包已删除。最终数据库由迁移`008-retire-remote-identity.sql`删除注册、实例、实例密钥、跨客户主体绑定和回调投递表。
- `10.6.b.2`已经在后续闭环中绑定安装实例、服务端预期范围、规范目标、规范载荷、PostgreSQL 权威时间、256 位随机数与 256 位业务幂等键，并分离读取随机数围栏和写入业务幂等围栏；精确实现与验证范围见[本地进程认证闭环验证记录](phase-10-process-authentication-validation.md)。

## 3. 商家自有供应商配置门禁基线

- 只允许`tencent_essbasic`与`nuonuo_invoice`两个安装内目标；不存在平台代接或中央代理 provider code。
- 查询、写入和证据检查分别使用`idc:admin:compliance:supplier:query`、`write`、`validate`精确权限，授权目标固定为当前安装内的供应商配置号。
- 写入要求当前单商家租户员工在最近五分钟内完成宿主完整登录。创建后记录是安装级单例，只能由同一精确权限和数据范围读取；不存在列表、跨租户或跨安装查询，因此不适用部门行级过滤，但仍由宿主 Authorizer 执行租户、直接员工、角色与目标可见性检查。
- 商家主体只保存`msub_<32位小写十六进制>`不透明本地引用；凭据进入独立`compliance.local-supplier-credential`的`secretcap` scope，API、审计和数据库业务列不返回明文、密文或秘密引用。
- 两阶段变更先把配置置为`updating`且适配器关闭，再更新秘密，最后提交`configured_blocked`。数据库约束只允许`external_confirmation_required`且强制`adapter_enabled=false`；证据检查只追加本地阻断审计，不触网、不启用客户端。
- `msub_*`当前只是插件侧不透明引用，不等于本地网关已经实现主体专用`AES-256-GCM`、查重 HMAC、身份操作幂等 HMAC、单一活动绑定和撤销后重开；这些缺口由`10.6.c.2`、`10.6.c.3`继续处理。

## 4. 回调、主动查询、证据与人工接管策略基线

- 本地策略图只接受腾讯、诺诺显式注册的验签器或查询器；缺少客户端时返回`adapter disabled`，没有软件提供方回退路径。
- 回调先完成供应商验签，主动查询先经过本地熔断门禁；原始回调、外部引用和查询证据只进入当前安装的密封器，Store 只能收到稳定状态和密文、事件 HMAC、载荷摘要与本地密钥版本。
- 本地数据库保存操作、回调、证据、熔断和接管记录，不含远程实例父级或投递路由。回调、证据和接管历史由触发器禁止更新或删除。
- 人工接管请求不能提交操作者身份；权威身份由当前安装会话派生，必须是当前商家员工且五分钟内完成完整认证。测试证明软件提供方平台操作者投影被拒绝。
- 当前只完成策略接口和基础表，不具备每业务请求单一写租约、按操作范围持久熔断、256 KiB 回调原文上限、证据/路由/投递复合外键、`SKIP LOCKED`查询租约或 1 至 16 条证据集合核对；这些缺口由`10.6.d.2`至`10.6.d.4`继续处理。

## 5. 中央结算删除与本地只读投影基线

- `internal/settlement`生产代码及测试已删除，不保留兼容 API、视图或运行时装配。
- 历史迁移`006`、`007`只为升级校验账本保留；迁移`010-retire-central-settlement.sql`删除`idc_gateway_price_*`、`idc_gateway_settlement_*`、`idc_gateway_provider_billing_gate`及对应函数。
- PostgreSQL 实迁移测试在隔离 schema 连续应用全部十二个迁移并再次幂等应用，最终确认中央身份、价格、余额、授信、计费门禁与结算表均不存在。
- 本地替代只保存供应商权威套餐、用量、费用证据、预算阈值与告警、有界对账及 SLA 快照。金额使用原币种最小单位，数量使用整数分子/分母，不跨币种合并，也不创建软件提供方对购买方的余额、授信、统一价格或代付账本。
- `localusage`只提供四次有界本地读取，单次用量最多二百行、窗口最多四百天；没有写入、支付或中央服务方法。
- 本记录形成时尚未把供应商套餐/用量采集、预算告警、对账和`SLA`装配到生产运行图；后续本地生产闭环见[本地供应商用量运行闭环验证记录](phase-10-local-supplier-usage-runtime-validation.md)。真实供应商契约未确认时仍必须继续关闭，不能把只读投影底座或关闭状态解释为真实供应商接口已启用。

## 6. 独立运行与生命周期

- 运行配置结构只有当前安装的数据库 DSN 文件与进程密钥环文件；依赖图测试禁止宿主和腾讯、诺诺 SDK，真实供应商客户端与业务路由均未装配。
- 软件提供方业务服务不可用不会影响本地进程启动、迁移、存活、就绪、进程认证、配置、证据、查询投影或灾备；商业授权只在另行冻结的软件使用权边界生效。
- 组件包双语生命周期手册给出商家/供应商/软件提供方责任矩阵，以及备份、隔离恢复、服务终止、供应商撤权、证据导出、法律保全、分类留存删除和卸载顺序。
- 数据库新增分类留存策略、法律保全事件、证据导出记录、供应商授权事件和恢复验证记录；恢复验证约束供应商写操作保持关闭。
- 当前没有供应商授权撤销、受控证据导出、法律保全和分类型留存删除的执行服务或恢复演练，因此只完成`10.7.d.1`数据与文档底座。

## 8. i18n、数据权限与性能影响

- `i18n`：新增供应商配置 API 文档和稳定错误码均提供中英文资源；英文继续以 API 源文为准，中文 API 文档覆盖测试通过。
- 数据权限：供应商配置是租户`0`当前安装单例，无列表或客户行数据；所有读写仍执行宿主精确权限、当前商家员工、租户和目标检查，写入另加近期完整认证与审计。网关内部用量投影没有公开 HTTP 路由，只能由后续受进程认证的本地路由装配。
- 性能：供应商配置查询按`tenant_id + provider_code`唯一键读取；本地用量固定四次查询，使用 provider/时间索引、限制二百行和四百天窗口，不存在按返回行逐条查询的`N+1`路径。
