# 阶段 6.8 财务、续费与逾期回归验证

> **`FB-52`部分失效声明：**账本、余额、账单和资金守恒回归仍可保留；旧服务续费、Provider 确认和服务器到期生命周期的回归不能证明当前长期权益续费完成。续费必须按`service_entitlement`冻结的业务拥有方与契约重新验证，一次性交付没有续费入口。

## 交付结果

本切片把金额守恒、并发余额、账单合并拆分、人工收款、自动续费和逾期调度六类高风险不变量整理为专门的真实 PostgreSQL 回归组，并完成 20 轮随机顺序执行。测试直接使用生产迁移和领域服务，不用内存数据库、Mock SQL 或弱化约束的测试专用实现。

首轮高并发执行发现测试夹具允许过多并行隔离 schema 同时执行`DROP SCHEMA ... CASCADE`，导致 PostgreSQL 共享锁表耗尽。修复在测试夹具中增加最多 4 个隔离 schema 的并发闸门，仍保持每个用例独立 schema 和测试级并发，同时消除测试基础设施资源争用。修复后账务组和续费/逾期组均连续通过 20 轮，插件后端全量真实 PostgreSQL 回归、Go 静态检查和插件治理也全部通过。

## 不变量覆盖矩阵

| 风险域 | 权威验证 |
| --- | --- |
| 金额守恒 | 每笔账本交易借贷总额相等，账户快照链可从不可变分录重建；账单付款、退款、冲回、坏账、减免和人工收款分配与账单头金额精确一致；溢出、负数和跨币种输入失败关闭 |
| 并发余额 | 两个不同幂等键同时消费同一可用余额时只有一个成功，另一个得到余额不足；同一充值或付款 8 路并发只产生一个交易；冻结余额不可被可用余额消费绕过 |
| 账单合并拆分 | 合并仅接受同客户、同币种、可转换且尚无资金活动的账单；来源保持不可变并关闭支付入口，派生明细与总额守恒；拆分要求每个完整明细恰好出现一次，目标账单总额之和等于来源 |
| 人工收款 | 收款与减免使用不同账务语义；未配置或超过阈值时先进入待复核，申请人不能自审；拒绝不产生账本事实，批准只入账一次；8 路并发重放只创建一个申请 |
| 自动续费 | 余额不足不写账本且保留可重试账单；并发执行只创建一个续费尝试和一个结算事实；零金额续费不伪造资金交易；不同币种余额不可混用，价格变化不改写旧报价 |
| 逾期调度 | 8 路并发调度保持批量上限且每个提醒、宽限、暂停、恢复和终止任务只创建一次；续费推进到期日后旧任务失效；人工暂停不自动恢复，不稳定运行态不自动终止，明确失败安全恢复原运行态 |

## 测试隔离修复

- `configureBillingServiceIntegrationDB`在读取到真实 PostgreSQL DSN 后取得包级容量为 4 的测试闸门，并通过`t.Cleanup`释放。
- 清理顺序利用 Go 测试清理函数的后进先出语义：先完整关闭连接并删除当前独立 schema，再释放名额，不允许下一个测试在旧 schema 尚未清理时挤入。
- DSN 未配置时仍直接跳过，不占用名额；数据库创建、迁移或测试中途失败时`t.Cleanup`仍会释放名额，不形成死锁。
- 改动只位于`_test.go`，不影响生产连接池、事务并发、调度批量或业务吞吐。
