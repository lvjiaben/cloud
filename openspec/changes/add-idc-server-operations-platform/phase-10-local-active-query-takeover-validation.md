# 第十阶段本地主动查询与人工接管验证记录

## 1. 任务结论

任务`10.6.d.4`已完成安装环境内的只读主动查询和证据驱动人工接管领域能力。主动查询使用 PostgreSQL 权威时间、有界批次、跳过已被其他进程锁定的路由、一次性随机租约、固定失败分类和封顶退避；人工接管只接受当前商家受权员工、近期完整登录、精确路由版本、固定原因、同一路由既有证据和用途隔离操作键。

本记录形成时腾讯与诺诺真实查询客户端均未装配，生产运行时使用空查询器和空回调验证器集合，不启动查询作业、不开放公开回调或人工接管路由，也不回退到软件提供方服务。`2026-08-14`后腾讯查询器改由`10.8`按官方公开契约和购买方运行时能力门禁实现，诺诺仍受`10.4.c`外部证据阻断。人工接管页面和宿主员工权限适配器属于后续管理接线；本任务交付的是不能绕过授权边界的领域服务和数据库不变量。

## 2. 根因与修正范围

任务`10.6.d.3`已经完成回调收敛，但当时没有保护供应商外部流程号、没有跨进程主动查询租约、没有查询失败退避，也没有可持久审计的人工接管事务。旧`internal/localops`仅为早期非生产策略骨架，不能证明 PostgreSQL 领取、回调竞态、证据归属、操作幂等或不可变接管记录已经完成。

本轮新增迁移`016-local-active-query-takeover.sql`和`internal/suppliercallback`中的权威实现，并保留`internal/localops`作为不参与生产装配的历史策略骨架。实现没有引入平台销售注册、远程实例身份、跨客户路由、中央结算、平台操作者或软件提供方业务服务依赖。

## 3. 冻结实现

### 3.1 只读主动查询

- 外部流程号最多 512 字节，使用独立`AES-256-GCM`密钥加密，并使用另一套版本化`HMAC-SHA-256`密钥建立供应商隔离的唯一查询索引；活动和保留密钥版本一次有界核对，数据库不保存流程号原文。
- 每批最多领取 50 条路由，查询使用`FOR UPDATE SKIP LOCKED`和 PostgreSQL 当前时间。租约令牌为 256 位随机值，调用方只持有一次性原文，数据库只保存`SHA-256`摘要；租约固定 60 秒并同时围栏路由版本、供应商和操作范围。
- 单进程最多并发 4 条查询，作业启动后立即处理一批，随后每 10 秒轮询。单次供应商读取固定 50 秒超时，为租约内的本地证据事务保留 10 秒；服务退出会取消并等待查询作业，之后才关闭运行时数据库。
- 只有`running`、`result_unknown`或`reconciliation_required`且已经保护外部流程号的路由可领取。查询器只有同步只读接口，没有创建、签署、开票、红冲或其他供应商写能力。
- 失败只允许`transport_unavailable`、`timeout`、`malformed_response`、`reference_mismatch`和`provider_rejected`五类固定码；退避依次为 1、2、4、8、16、30 分钟，后续始终封顶 30 分钟。失败只追加加密证据并释放租约，不伪造终态。
- 查询结果必须通过路由版本、租约摘要和数据库到期时间围栏，再复用回调状态收敛事务。回调先提交后，迟到查询稳定返回租约丢失，不能覆盖回调或业务终态。

### 3.2 当前商家员工人工接管

- 权限精确固定为`idc:admin:compliance:route:manual-takeover`。可信权威适配器必须证明当前商家员工、权限已授予、目标数据范围匹配和最近五分钟完整登录；数据库时间同时拒绝过期认证和超过 15 秒的未来时间。
- 请求只接受最后读取的精确路由版本、256 位用途隔离操作键、1 至 16 条同一路由既有证据，以及`result_remains_unknown`、`terminal_result_conflict`、`query_reference_missing`、`supplier_query_unavailable`或`compliance_security_review`之一。
- 操作键使用独立版本化 HMAC 密钥族，保留版本可精确恢复同一请求；相同操作键改变版本、原因、员工或证据集合时返回冲突。
- 一个 PostgreSQL 事务按业务请求、路由和证据集合顺序加锁，保存证据集合摘要、不可变接管记录、不可变证据关联、加密决定证据、`manual_takeover`路由版本和本地版本化投递，同时清除查询租约并停止后续自动查询。
- 接管输入和数据库结构均没有自由文本、强制成功、强制失败、外部流程号覆盖或危险重试字段。既有成功或失败发生冲突时，接管只停止自动化并保留权威业务终态。

### 3.3 密钥、装配与交付

回调对账密钥环现有五个相互独立的版本化用途：证据加密、外部事件摘要、外部流程号加密、外部流程号查询摘要和人工接管操作摘要。构造函数逐项接收数据库、当前安装标识、密钥环、只读查询器集合或员工权威能力；生产运行图的查询器集合为空，人工接管服务也不会在缺少可信宿主员工权威适配器时被装配。

双语根说明和安装说明已同步租约、退避、密钥、监管、备份与恢复边界。Windows 和 Linux 发布包各包含 25 个受清单`SHA-256`保护的文件，并包含迁移`016-local-active-query-takeover.sql`；清单继续明确`SupplierClientsIncluded=false`和`BusinessRoutesEnabled=false`。

## 5. 规则影响判断

- API：未新增或修改公开 HTTP API、DTO、OpenAPI 元数据或路由；生产回调和人工接管入口保持关闭。
- 数据权限：人工接管在进入事务前要求可信权威能力返回当前商家员工、精确权限和目标数据范围；缺少任一证明均失败关闭。

- 开发工具：没有修改 Makefile、脚本或 CI；发布工具只复用既有迁移收集机制并通过双目标实际构建。

`lina-review`复核了安装所有权、用途隔离密钥、数据库时间、领取上限、租约原文保护、超时与退避、回调竞态、错误分类、员工权限、数据范围、近期认证、操作重放、证据归属、事务锁顺序、不可变记录、运行期退出和发布清单。

复核期间修正了四类问题：冻结设计仍残留中央平台表述；供应商读取原本没有小于租约的执行超时；HTTP 服务异常退出时查询作业可能晚于数据库关闭；少量哈希写入和 SQL 行关闭错误未被显式处理。修正后补充真实超时测试并重新通过全部门禁。

最终没有遗留阻断`10.6.d.4`的`P0`、`P1`或`P2`问题。本记录当时列出的腾讯外部阻断已被`2026-08-14`用户决策和`10.4.b`官方契约记录解除，腾讯实现转入`10.8`；诺诺`10.4.c`仍是外部阻断。父任务`10.6.d`按精确子任务原则继续保持未勾选。
