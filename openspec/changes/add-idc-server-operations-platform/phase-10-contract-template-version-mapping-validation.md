## 腾讯模板与本地版本映射

| 要求 | 实现与验证 |
| --- | --- |
| 一个腾讯模板对应一个本地模板 | 以腾讯返回的不透明模板编号生成稳定本地模板编号，同时由数据库唯一约束锁定`provider_code + provider_template_ref`，重复同步不能形成第二个本地模板。 |
| 腾讯内容不变时不重复建版本 | 同一份完整快照再次同步时，服务端按快照摘要识别已有版本；真实 PostgreSQL 验证结果为`newVersions=0`，本地模板编号和版本号都不变。 |
| 腾讯内容变化时追加本地版本 | 名称、腾讯版本、更新时间或签署控件快照变化后，在同一个本地模板编号下追加`version_no + 1`；旧版本保留，不改名、不改腾讯版本，不被覆盖。 |
| 新快照阻止旧版本继续用于新合同 | 如果旧版本正在启用，同步到新快照时先把旧版本停用，再追加“待补充设置”的新版本；历史合同仍引用原版本。 |
| 同步不产生逐行查询 | 腾讯完整快照先批量写入临时表，再在一个事务内集合化更新、追加版本和标记下线，没有按模板逐条查库的`N+1`路径。 |

关键数据库保护包括：

- 本地模板编号唯一；腾讯来源与腾讯模板编号组合唯一。
- 同一个本地模板的快照摘要唯一，防止相同腾讯快照重复建版本。
- 本地版本号与本地模板编号组合唯一。
- 已提交、已启用和已停用版本只能改变允许的状态字段，不能退回草稿或改写正文映射。
- 合同通过外键固定引用精确模板版本，已被合同使用的版本不能删除。

## 固定范围和签署顺序

适用范围只有以下三项：

- `personal`：个人客户。
- `enterprise`：企业客户。
- `all_customers`：全部客户。

签署顺序只有以下三项：

- `customer_first`：客户先签。
- `merchant_first`：商家先签。
- `parallel`：双方同时签。

这两组固定值同时由服务端校验、数据库约束和插件前端下拉选项限制。新增测试逐项确认九种合法组合全部接受，并确认`individual`、`company`、`all`、`sequential`、`merchant_and_customer`、`any`等未定义值全部拒绝。

## 复制行为

复制动作固定执行以下行为：

1. 服务端先按管理权限检查来源模板和精确版本。
2. 新建一个不同本地模板编号、版本号为`1`、状态为“草稿”的本地模板。
3. 只复制名称、适用范围和签署顺序，不复制腾讯模板编号、腾讯状态、腾讯版本、使用次数、腾讯正文或旧字段位置。
4. 同一个重试编号重复提交只返回同一个新草稿，不重复创建。
5. 复制事务只追加新模板和审计记录，不更新来源模板；真实 PostgreSQL 比较确认来源版本在复制前后完全一致。
6. 插件前端收到新草稿后直接打开编辑器。真实 Chrome 验证确认名称、范围和签署顺序已经带入，正文与字段为空，管理员从新草稿继续编辑。
