# 第九阶段上游用户映射验证记录

## 验证范围

本记录覆盖任务`9.4.b`：`resourcecap`可选上游用户契约、智简魔方公有云`v1`用户名查重与创建适配，以及`idc-resource`拥有方的耐久映射状态机。本轮只读取生成式文档和旧连接器证据；没有向生产实例发起用户创建、修改或删除请求，也没有保存线上凭据、令牌、用户编号或原始响应。

## 契约与状态机

- `PrincipalProvider`只提供精确查重和创建两个窄方法；用户名、密码、电话、邮箱、实名名称都只能通过`secretcap.Handle`进入适配器。
- 智简魔方适配器将`POST /user/check`的明确`id=0`解释为不存在，正整数解释为已存在；畸形、超时和传输故障从不产生创建资格。
- 创建固定提交`state=1 + username + password`，不接受普通参数中的客户资料。随机密码由`core secretcap`拥有方按固定 256 位 URL-safe 策略在加密边界内幂等生成，并发或进程恢复只得到原句柄；创建响应编号必须由后续精确查重确认后才能发布本地映射。
- 初次查重明确不存在后才进入创建；创建未知或租约过期永久进入只读核验，不会重新获得写资格。已认证写请求收到`401`不会刷新后自动重发，而是失效令牌并形成结果未知。明确未接受的创建也要先经过一次新的精确查重，且总写入领取最多三次。
- worker 每次只推进一条任务，过期租约每轮最多恢复 32 条，主节点作业每轮最多处理 8 条；领取索引覆盖 tenant、状态、到期时间和稳定主键，不存在按客户集合逐项查询的`N+1`。
- 成功映射只保存客户不透明编号、渠道、上游用户编号和脱敏证据摘要，随后撤销用户名与密码句柄。人工核对前先撤销随机密码，只保留渠道加密用户名句柄供操作员执行精确查重。

## 数据与边界

- 新表`plugin_idc_resource_principal_task`是耐久异步状态，不使用软删除；历史结果以终态、尝试次数、结果未知栅栏和摘要保留。
- 迁移只包含 DDL，使用存在性保护并可连续执行；对当前迭代内演进的状态约束和部分索引采用显式删除后重建，重复执行结果一致。
- `core`新增`039-generated-secret-policy.sql`，只扩展已有秘密请求操作与版本栅栏约束并同步列注释；旧`002-secret-envelope.sql`保持原迭代语义。新迁移在隔离 schema 和专用 codegen 数据库中均连续执行两次，标准 DAO/DO/Entity 随后重新生成。
- DAO/DO/Entity 由插件官方`make dao`生成；资源迁移测试在隔离 PostgreSQL schema 中连续应用全部迁移两次。
- `core`仍拥有客户与秘密信封，`resource`唯一拥有上游映射和任务，`zjmfcloud`只负责协议适配；没有跨插件数据库外键或内部实现导入。
- 本切片把核心插件提升到`v0.1.52`、资源插件提升到`v0.1.4`并把最低核心依赖收紧到`>=0.1.52`、魔方云适配器提升到`v0.1.1`，确保升级路径会交付迁移和契约变更。

## 规则域影响

- 架构、插件、后端、数据库和测试：命中并已按规则验证；生产依赖从启动装配层显式注入，任务查询和租约恢复均有固定上限。

## Lina 审查摘要

任务级审查发现并修复三类阻断问题：第一，通用认证方法会在写请求收到`401`后刷新令牌并重发，可能重复上游变更；现已拆分只读与单次写路径，写入只失效令牌并进入未知结果。第二，调用方生成随机密码后以确定性幂等键写入秘密服务会在并发或崩溃恢复时生成不同明文并冲突；现由`secretcap`拥有方以固定策略只生成和加密一次，重放只恢复句柄。第三，生成密码约束最初被追加到旧`002`迁移；现恢复旧迁移并新增`039-generated-secret-policy.sql`，通过真实 PostgreSQL 重复执行和官方 DAO 生成闭环。

修复后复核确认秘密明文不离开回调边界、写入无同调用重放、任务领取与恢复均有硬上限、插件依赖版本覆盖新增公开契约，且没有宿主目录、前端、公开 HTTP、缓存或运行时`i18n`变化。当前严重问题 0 个、警告 0 个；快照、备份、安全组、`NAT`、虚拟介质、流量包和上游工单仍属于父任务`9.4`的明确未完成边界。

任务`9.4.b`的公开契约、适配器、拥有方状态机、生产装配和真实 PostgreSQL 回归已经闭环。快照、备份、安全组、`NAT`、虚拟介质、流量包和上游工单仍未完成，因此父任务`9.4`保持未勾选；可信生产`HTTPS`入口仍未具备，本轮不执行生产写测试，也不影响任务`9.7`继续阻断。
