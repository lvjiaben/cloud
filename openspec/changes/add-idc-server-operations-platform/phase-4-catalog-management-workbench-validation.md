# 第四阶段后台商品工作台验证记录

> **`FB-52`部分失效声明：**商家分类、通用商品资料、计费、逐币种价格、税务和唯一发布服务可以保留；固定服务器配置、资源池候选与绑定、Provider 成本和旧发布检查不是通用商品工作台能力，不能作为当前阶段完成证据。现行工作台只维护商品版本简单库存、履约方式、一个兼容自动化接口实例和插件声明的结构化配置。

## 结论

`4.6`的商品列表、最新版本只读详情、可解释发布预览、版本发布、分类与空白商品草稿创建、配置组与类型化规格项追加、计费规则与明确币种完整价格方案追加、兼容规则追加、本地成本观测、既有资源池新单路由策略，以及资源拥有方候选建绑定十一个纵向切片已经完成：后台现在拥有相互隔离的列表、详情、发布、分类候选、分类创建、商品创建、配置写入、兼容规则写入、计费写入、价格写入、成本写入和资源池写入权限，配套管理读模型、版本化 HTTP API、插件菜单和双语 Vben 页面。分类候选以一次有界本地查询支撑创建表单；分类写入与商品加首个空白草稿版本都复用既有事务服务和员工业务审计，不会自动定价、绑定资源池或发布。草稿编辑器既能以 13 类类型化表单追加配置，也能创建有方向且数量明确的`requires/excludes/allows`兼容边、五类计费模型，并把一个规则、基础商品或规格项和精确币种的完整价格阶梯一次原子提交。对已绑定资源池可追加明确币种和周期的本地成本观测，也可调整可恢复的新单路由策略；新绑定只能从资源拥有方的启用、同服务器类型候选建立，并在提交时按不透明池号、类型和修订指纹权威重检。所有入口都不能编辑自动库存、换池、删除绑定或冒充 Provider 成本。

真实 PostgreSQL、两插件全量后端、Go lint、插件治理、前端类型检查、生产构建和 Chromium `TC002`均通过。截图审查发现并修复了标准视口横向溢出、抽屉或弹窗动画未完成即截图、菜单加载提示未收口、语言切换后数据遮罩尚未退出、七项发布检查在单列弹窗中超出标准视口、配置下拉浮层残留、父子翻译键冲突、阶梯金额控件未显式导入导致只显示标签、连续选择两个规格时误命中前一个退出浮层，以及候选选择器与地区字段挤压的问题。Lina 审查还发现原 Base64 游标会暴露内部边界、同版本覆盖新增翻译资源不会触发已安装实例升级、候选查询缺少匹配排序的专用索引和新建接口前端返回类型过宽；均已修复。独立自动库存运营页仍待后续切片，因此`4.6`顶级任务保持未完成。插件自身中英文资源覆盖通过；仓库级`i18n`仍只被无权修改的宿主通知预览页 6 个既有缺失键阻断。

## 实现范围

- 新增`GET /admin/catalog/products`，权限为`idc:admin:catalog:product:list`。接口只接受直接活动员工、默认商家及全局或本商家数据范围；授权在筛选解析和数据库读取前完成。
- 新增`GET /admin/catalog/products/{productNo}`，权限为`idc:admin:catalog:product:query`。列表权限不能查看详情，畸形商品号在身份和权限依赖读取前失败关闭，隐藏目标与不存在目标统一为不可访问。
- 新增`POST /admin/catalog/product-versions/{versionNo}/publish`，权限为`idc:admin:catalog:product:publish`。列表和详情权限不能替代；路径参数在接口层限制为必填且最多 128 字符，生产授权器继续在访问目标前校验稳定业务号、直接员工、默认商家和数据范围。
- 新增`GET /admin/catalog/product-versions/{versionNo}/publication-preview`，复用精确发布权限，以固定七项检查码返回生命周期、分类类型、双语销售资料、配置兼容、逐币种价格、新单资源池和来源审核状态。响应不携带底层异常或自由文本，前端负责双语解释；预览只提供建议，不写目录状态，也不能替代正式发布时的权威重检。
- 新增`GET /admin/catalog/categories`、`POST /admin/catalog/categories`和`POST /admin/catalog/products`，分别使用分类查看、分类创建和商品创建精确权限。分类候选只做一次显式字段查询，最多 500 项和 512 KiB；创建商品从候选分类推导类型，并只生成商品与`manual + draft`版本 1。
- 新增`POST /admin/catalog/product-versions/{versionNo}/configuration-groups`和`POST /admin/catalog/product-versions/{versionNo}/configuration-groups/{groupNo}/options`，共同使用独立`idc:admin:catalog:configuration:write`权限。授权先于请求规范化和数据库读取；列表、详情、商品创建、复制和发布权限均不能替代配置写入权限。
- 配置写事务统一按“版本→商品→配置组”锁序执行，与发布重检共享父版本并发栅栏；只允许`manual`、`copy`或`migration`来源的`draft`，Provider 导入继续通过不可变审核物化链路。配置组与规格项分别最多 20,000 行，容量检查和写入由同一版本锁串行保护。
- 配置组写入校验选择方式和上下限；固定配置强制`single + 1..1`，且每组只允许一个启用、最小/最大/默认数量相同的固定规格。规格项只接受地域、机房、线路、CPU、内存、系统盘、数据盘、带宽、流量、IP、备份、镜像和其他组件的类型化字段，保存确定性规范 JSON，拒绝任意 JSON 和跨类型夹带字段。
- 新增`POST /admin/catalog/product-versions/{versionNo}/compatibility-rules`，使用独立`idc:admin:catalog:compatibility:write`权限。授权先于规范化；服务共享版本父锁，以一次集合锁定读取两个同版本规格，启用规则不能引用停用规格，非排斥规则不能越过目标规格数量边界。
- 兼容规则复用管理写与发布门禁的唯一`ValidateCompatibilityRule`：`requires`最小目标数量至少为 1，`excludes`固定为零且无最大数量，`allows`必须显式设置最大数量；来源与目标不能相同，同版本同类型同方向边不能隐式覆盖。单版本最多 8,000 条，插入与员工审计同事务。
- 新增`POST /admin/catalog/resource-pool-bindings/{bindingNo}/cost-observations`，使用独立`idc:admin:catalog:cost:write`权限。授权在请求规范化和目标读取前完成；接口只接受既有绑定、原样大写三字母币种、整数最小货币单位金额、明确周期及可选未来有效期。
- 成本事务锁定目标绑定，以 PostgreSQL `CURRENT_TIMESTAMP`记录观察时间，每个绑定最多保留 100,000 条不可变历史；只写`source=manual`且上游快照号为空的记录并追加同事务员工审计。该入口可以记录已发布或暂停新单绑定的实际运营成本，但不能改商品图、覆盖成本历史、伪造 Provider 来源或编辑自动库存。
- 新增`PUT /admin/catalog/resource-pool-bindings/{bindingNo}/policy`，使用独立`idc:admin:catalog:resource-pool:write`权限。请求完整替换优先级、权重、停新、状态、维护模式、最低可售量和库存不确定策略；范围与库存路由读取模型及数据库约束一致。
- 资源池策略事务锁定既有绑定，只更新七个可恢复的新单字段并写包含前后策略快照的高风险员工审计。请求没有版本、资源池、地区、线路或库存字段，也不提供删除；真实 PostgreSQL 证明不可变绑定身份保持原值，历史服务器不会被迁移。
- 新增`GET /admin/catalog/product-versions/{versionNo}/resource-pool-candidates`与`POST /admin/catalog/product-versions/{versionNo}/resource-pool-bindings`，复用精确`idc:admin:catalog:resource-pool:write`权限。授权先于目标读取；候选只来自启用渠道下启用、未删除且与云服务器或裸金属类型一致的资源拥有方池，最多 500 项、512 KiB，并且不包含端点、凭据或原始上游载荷。
- `core`只声明请求方端口和冻结式 SPI，`resource`使用一次集合查询实现端口，不形成反向数据库读取或 Provider 调用。候选携带渠道号、资源池号、服务器类型、Provider 身份和双方版本派生的 SHA-256 修订指纹；提交时资源拥有方直接重读精确候选并常量时间比较指纹。商品事务再次锁定`manual/copy/migration + draft`父版本，原子创建不可变池身份、初始新单策略和高风险员工审计；新绑定没有库存快照，自动路由继续失败关闭。
- 新增`POST /admin/catalog/product-versions/{versionNo}/billing-rules`，使用独立`idc:admin:catalog:billing:write`权限；复用权威计费校验创建一次性、周期、阶梯、按量或试用规则，单版本最多 256 条。新增`POST /admin/catalog/product-versions/{versionNo}/billing-rules/{billingRuleNo}/price-schedules`，使用独立`idc:admin:catalog:price:write`权限；配置、列表、详情和发布权限均不能替代二者。
- 计费与价格写入共享版本父锁，只允许`manual/copy/migration + draft`。价格服务锁定规则与可选规格项，一次提交一个“规则 + 基础商品或规格项 + 精确大写币种”的完整方案；阶梯必须从 0 开始、连续且末段无上限，续费价与价格相位一致。金额只用整数最小货币单位，不自动转换币种代码、不按汇率换算、不跨币种继承，也不覆盖已存在的同维度方案。
- 单次价格方案最多 1,024 阶梯，单版本最多 20,000 个价格行；服务在固定查询次数内完成容量、维度冲突和完整性校验，以 256 行固定批次写入并在同一事务追加员工业务审计。审计只记录规则、定价目标存在性、币种和阶梯数量，不复制价格金额。
- 发布 API 只委托唯一的统一发布服务：同一事务内锁定草稿版本与商品，重新校验双语销售资料、配置和兼容规则、所有配置币种基础/选项/续费价格、启用新单资源池及 Provider 物化证据，再切换旧发布版本、商品当前版本指针并追加员工业务审计。确认或审计失败全部回滚。
- 详情以固定 8 次本地集合查询装配最新版本头、配置组、配置项、兼容规则、计费规则、逐币种价格、资源池最新库存及各池币种最新成本；各集合独立限量，总计最多 20,000 行、序列化最多 4 MiB，不调用 Provider。
- 详情时间统一为 Unix 毫秒，不返回数据库主键、上游原始载荷、凭据或秘密。Vben 宽抽屉每次打开只发起一个详情请求，并按当前语言展示配置、价格、供给、成本和业务枚举。
- 名称前缀最多 128 个 Unicode 字符，并把`%`、`_`和反斜杠转义为字面匹配；类型、状态和最新版本来源只接受稳定枚举。默认每页 25、最多 100，响应序列化后不得超过 1 MiB。
- 不透明游标以部署安全根派生的独立用途密钥执行 AES-256-GCM 加密，密文内绑定`sort_order + id`边界及规范化筛选摘要；调用方不能从 Base64URL 传输值读取内部主键，篡改、修改名称/类型/状态/来源/页大小或部署密钥轮换后的旧游标都会失败关闭。
- 单条 SQL 先以`MATERIALIZED`页集合和`LATERAL`索引读取每个商品最新版本，再围绕当前页集合聚合配置组、启用选项、启用计费规则、显式价格币种、资源池绑定、每池最新库存和成本观测。响应已经包含页面全部摘要，前端不发起逐行详情请求。
- `015-catalog-management-read-indexes.sql`增加通用 keyset、类型、状态、类型加状态及中英文名称和公开 slug 前缀索引；真实 PostgreSQL 在禁用顺序扫描后证明类型加状态的有界列表使用专用索引。
- Vben 页面使用`Page + useVbenVxeGrid`，提供四项筛选、不透明前后游标、商品版本、配置、价格、资源池可售性、成本观测和本页关注指标。页面容器限制在工作区宽度内，表格自行处理横向内容，不再把指标与筛选撑出 1280×720 视口。
- 发布入口只对具备发布权限的最新草稿显示；点击后只发起一次预览请求，七项检查全部通过才允许提交一次发布写请求，成功后重新查询本页。前端禁用状态和预览结论都不替代服务端授权与完整性校验。
- 新建分类与新建商品使用相互隔离的双语 Vben 弹窗。商品表单以响应式双列布局完整显示在 1280×720 视口；普通商品合同开关默认关闭，创建成功后只刷新一次当前列表。
- 商品行只对同时具备任一草稿子图写权限和详情读取权限的员工显示编辑入口，且只对可编辑来源草稿开放。宽抽屉一次读取现有有界详情，展示配置组、规格项、兼容边和计费规则；配置、兼容、计费和价格按钮各自按精确权限显示。兼容表单使用可搜索规格候选并按规则类型规范数量；计费表单覆盖五类模型并清空无关字段；价格表单支持基础价或规格项加价、精确币种、续费价及完整连续阶梯。
- 核心插件版本提升到`v0.1.17`，资源插件提升到`v0.1.2`；通过正式升级路径应用候选/绑定 API、菜单文案、双语资源、端口装配和专用候选索引。直接修改同版本清单、翻译或迁移不会被宿主错误地当成已升级。
- 插件 E2E 目录增加最小 ESM 边界，避免 Playwright 将插件测试按 CommonJS 转译后加载宿主 ESM 固件失败。

- **已修复**：新建绑定前端调用最初把精简创建响应声明成包含库存字段的完整资源池详情，可能误导后续调用者读取并不存在的快照字段。现改为逐字段匹配 HTTP 响应的独立结果类型，类型检查与生产构建通过。
- **已修复**：请求方端口注册器的重复声明与冻结后拒绝仅依赖代码审阅。现新增并发安全 registrar 单测，明确验证只接受一个非空 factory、冻结保留快照且冻结后永久拒绝声明。

- **已修复**：插件 E2E 缺少 ESM 包边界，Playwright 把测试依赖图按 CommonJS 处理并在宿主`auth-state.ts`触发`exports is not defined`。插件内最小`hack/tests/package.json`使测试清单和实际执行恢复。
- **已修复**：初版表格最小宽度把工作台整体撑出视口，第四个指标和来源筛选不可见。页面现在限制自身及 Grid 容器宽度，指标使用自适应列；修复后截图已人工复核。
- **已修复**：初版截图在路由根节点出现后立即执行，顶部仍显示“加载菜单中”。页面对象现在同时等待宿主路由加载和菜单提示隐藏。
- **已修复**：英文切换后的断言可在 VXE 数据遮罩退出前成立，造成截图整体灰化。插件页面对象现在在进入页面和截图前统一等待可见数据遮罩彻底退出，TC-2i 复跑及 1280×720 截图复核均通过。
- **已修复**：详情抽屉最初只等待内容节点可见，截图可能发生在右侧进入动画尚未结束时，造成抽屉看似被裁切。页面对象现同时等待详情数据完成和内容进入视口，并以大于 800 像素的对话框宽度作为浏览器门禁。
- **已修复**：动态业务枚举词条首次写入清单后，本地实例已安装同一个`v0.1.4`，宿主不会重复导入同版本资源，详情暴露翻译键。插件提升到`v0.1.5`并走正式升级路径后，中英文详情均无翻译键；测试还验证关闭抽屉、切换语言和再次打开后的完整英文枚举。

- **已修复**：第一列表切片的少数 API、控制器、游标和持久化 Go 文件缺少文件职责注释，不符合后端文件治理要求；本轮审查已补齐且不改变运行语义。

- 已确认一个列表请求只执行一条有界 SQL，聚合 CTE 仅连接当前页商品，不存在随返回行数增长的 HTTP 或数据库查询次数。

- 已确认分类查看、分类创建与商品创建权限互不替代；分类查询显式投影并设置数量和响应大小上限，所有写请求继续委托既有事务管理服务。HTTP 控制器不直接写表，商品创建不自动生成配置、价格、资源池、合同要求或发布状态。
