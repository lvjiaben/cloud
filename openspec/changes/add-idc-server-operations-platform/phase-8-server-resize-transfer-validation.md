# 第八阶段服务器变配与所有权转移验证记录

## 完成范围

本记录覆盖任务`8.9`。客户服务器详情已经提供服务别名、备注、流量只读展示、自动续费入口和退款关联；服务所有权转移由转出方申请、接收方在`24`小时内通过本人邮箱确认，且不会转移原客户的历史账单、合同、发票和工单。通用旧变配入口失败关闭，客户只能使用本阶段的权威选项、报价和结算流程。

服务器升级按剩余服务期使用整数向上取整计算补差，付款并收到`financially_settled`后才提交 Provider；降级不退款，在下一个续费周期生效；磁盘缩容和 Provider 未声明的参数始终拒绝。成功后保存新的配置快照、版本和续费价格基线。明确失败的收费升级复用统一退款流程，结果不明保持锁定并转人工处理，禁止重复提交或重复退款。

## 关键修复

- `067-server-resize-transfer.sql`把`resize`纳入统一业务操作约束：收费升级必须绑定不可变价格快照，免费降级必须不带收费快照，错误组合由数据库直接拒绝。
- 隔离 PostgreSQL 回归发现`067`最初重建约束时缩窄了`057`已有集合，会误拒绝重启等普通操作，并会把免费配件或免费换 IP 错判为必须带价格快照。现已完整保留`057`的全部操作类型和价格快照语义，只新增`resize`；迁移测试清单也按真实依赖补齐`066 → 067 → 068`。
- Provider 明确失败时创建唯一退款交接记录，由现有统一退款 worker 重新核对订单、账单、单项、资金来源和可退金额，再创建、批准并执行退款；佣金回退事件完成后才把订单、变配意图和业务操作收敛到最终状态。
- 修复账单项编号直接扫描到字符串切片导致空列表、进而误报“退款事实已变化”的问题。
- 退款成功和人工处理的每个状态更新现在都必须精确影响一行；任何陈旧状态或并发漂移会让整个事务回滚，不会追加伪成功事件。

## 边界与影响

- 后台宿主：没有修改`web-antd`；客户功能只在`web-customer`。
- 资金：不新建第二套退款通道，不直接修改余额；全部复用账单拥有方的资金来源、退款执行和结果不明保护。
- 数据权限：沿用当前客户与服务所有权检查，接收邮箱查询不暴露账号是否存在。
- 性能：到期降级和退款交接均有批量上限、稳定索引和行锁，不按页面行数调用 Provider。
- `i18n`：客户变配与转移已有中英文资源；本轮退款加固没有新增用户文案。
- 缓存与工具：没有新增缓存，也没有修改构建、测试或跨平台脚本。
