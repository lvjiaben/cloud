# 第四阶段公开配置权威报价验证记录

> **`FB-52`失效声明：**旧通用公开配置报价建立在服务器固定配置图之上，相关路由已经删除。本记录仅用于迁移对账，不能作为当前商品配置或报价完成证据；现行配置和价格必须由冻结插件结构化契约与通用商品计费共同提供。

## 结论

`4.7.c`已完成。公开商品配置器现在会在服务端确认组合有效后，请求当前正式版本的权威价格构成；Portal 不保存或推导价格，也不会把当前构成冒充后续结算事务中的锁价报价。

## 权威边界

- 新增`POST /public/catalog/products/{publicSlug}/configuration-quotes`。请求只接受公开 slug、43 字符不透明修订、原样大写三字母币种和完整规格选择。
- 服务端先重新校验当前正式配置图，再以固定查询读取最多 256 条启用计费规则、100,000 行该币种启用价格和唯一税务策略，最后再次证明商品仍指向同一正式版本。
- 基础商品与每个已选规格分别返回周期费、安装费和构成合计；税务快照包含含税语义、税务处理、税率基点、税收分类、舍入范围、模式和最小单位粒度。
- 逐项舍入和汇总舍入分别执行；含税价格反推税额，未税价格在净额上计税。有理数计算使用整数与`math/big`，全部加法、乘法和舍入结果执行溢出保护。
- 按量方案返回`pending_usage`，试用方案返回`requires_customer_context`，两者都不返回伪造金额。缺价、非法组合、旧修订、重复税务策略、畸形规则或溢出全部失败关闭。
- 计费方案号使用版本绑定的 HMAC 不透明令牌；响应不暴露内部版本号、计费规则号、数据库主键、成本、资源池或 Provider 身份。
- 报价最多 4,096 条价格构成，连同响应信封不超过 1 MiB。金额在 HTTP 边界以十进制整数字符串传输，Portal 使用`BigInt`只做格式化，避免 JavaScript 安全整数精度丢失。
- 全链路只读本地 PostgreSQL，不调用资源插件或 Provider，也不创建订单、购物车、报价快照或审计写入。

## 审查结论

- 数据权限：接口是有界匿名销售投影，不接收客户或商家身份，不暴露内部对象存在性之外的资料；后台精确权限和数据范围没有变化。
- 性能：配置、计费、价格、税务与最终版本复核均为固定集合查询；没有逐规格数据库查询，价格构成在创建前执行全局行数硬上限。
- 一致性：公开修订和计费方案令牌都绑定部署密钥、公开 slug 与正式版本；返回前的当前版本复核消除发布切换竞态。
- 缓存：只复用此前已验证的正式配置图 LRU；价格和税务始终从 PostgreSQL 读取，不进入跨请求报价缓存。
- i18n：新增 Portal 可见文案和公开错误均提供中英文镜像；金额与业务状态不依赖前端硬编码价格。
