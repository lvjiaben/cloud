# 第六阶段信用审批与额度使用服务验证记录

## 当前结论

任务`6.11.a`、`6.11.b`、`6.11.c.1`和`6.11.d`在本记录形成时完成；后续`6.11.c.2`、`6.11.e`及仓库级多语言门禁也已收口，最终结论见[信用账单还款 Owner 接线验证记录](phase-6-credit-repayment-owner-validation.md)和[公共门禁复核记录](phase-6-gate-revalidation.md)。`idc-core`已实现逐币种信用政策、申请、连续审批、最终开户、额度占用、未出账完整释放、账单开立、账单还款、未出账预还款、逾期登记、宽限冻结、耐久服务处置任务、违约费用、坏账核销/收回、人工恢复和有界信用对账的内部权威服务，并完成后台与客户 HTTP、隔离读模型、精确权限、业务审计和最近重新认证门禁。

## 审批与激活

- 政策按币种追加不可变版本，明确最高额度、双人复核阈值、账单日、还款期、宽限期和逾期费；原始幂等键只派生不透明业务号，不落库。
- 高额申请允许第一名员工在独立事务提交同意票并继续保持`pending_review`。第二名不同员工可以批准或拒绝；只有全部同意后才在同一事务创建客户信用账本账户、信用账户、不可变条款和首条额度授予流水。
- 员工申请禁止自审。政策、申请和审批重放必须匹配原内容，同一幂等身份改金额或同一审批人改证据均失败关闭；风险材料只保存`private:`引用和摘要。

## 额度占用与释放

- 占用先锁定“客户 + 币种”信用账户并重新校验客户状态、账户状态、有效期、币种、投影守恒和数据库当前可用额；不同币种、未激活、冻结、到期或额度不足均不能使用。
- 新占用在一个事务内创建不可变敞口、扣减可用额、增加未出账本金并追加完整前后快照流水。业务来源构成稳定重放身份，同来源改金额、订单/账单归属或证据摘要会冲突。
- 未出账取消只完整释放尚未出账且未还款的敞口，恢复同币种可用额并追加反向流水。已出账、部分还款或已还款退款不进入此接口，等待专门退款分配流程。
- 账户行锁和版本条件更新共同防止并发超用；真实 PostgreSQL 并发测试中，两笔各占用 6,000、总额度 10,000 的请求只能成功一笔，最终投影保持 4,000 可用和 6,000 未出账。

## 账单与还款

- 信用账单按商家`IANA`时区校验账户条款账单日，拒绝未来、重叠或超过 62 天的账期。单张最多 10,000 条未出账敞口，明细和敞口使用有界集合写入，账户只推进一次版本并追加一条账单汇总流水。
- 账单到期日严格等于数据库开立时间加条款还款天数。相同幂等键只能重放完全相同的账户与账期，改账期或用另一幂等键创建重叠账单都会冲突。
- 已确认还款必须引用同币种正式账本交易，并核对交易类型、业务来源、借贷总额和应收贷记；在线支付与人工收款必须有等额商家现金借记，客户余额还款必须有对应客户余额借记，支付清算和佣金分录不能冒充到账。账单还款先分配费用再分配本金，只有本金按账单明细顺序恢复额度；部分还款保持应收，足额还款结清账单和敞口。
- 未出账预还款只分配到指定同币种敞口，减少未出账本金并恢复额度。账本金额不一致、超过剩余本金、跨币种或改确认凭据重放全部失败关闭。

## 逾期、宽限与服务处置

- 逾期案件起点固定为账单到期时刻，宽限截止严格等于到期时刻加冻结条款天数。数据库当前时间只判定是否已经到期并记录实际检测时间；作业晚扫、停机恢复或重复执行不会重新赠送宽限期。
- 逾期登记在一个事务内把账单标记为`overdue`、增加账户逾期本金、追加`delinquency`流水并创建唯一案件。已因其他账单冻结的账户仍可登记后续到期账单，坏账账户则失败关闭。
- 宽限期结束后在同一事务冻结信用账户、追加`freeze`流水、把案件推进到`service_action_pending`并通过异步任务 owner 创建唯一脱敏任务。任务只保存案件、账单、信用账户、客户和币种业务号，不创建`business_operation`、不写服务运行态、不调用 Provider。
- 异步任务新增显式数据库事务入口，避免领域服务持有的数据库实例与全局默认 DAO 事务分离；任务创建失败会与账务状态一起回滚。未来任务处理器必须重读案件，已还清的案件不得继续限制服务。
- 逾期部分还款同步减少案件本金、账单应收和账户逾期本金；足额还款把案件金额归零并标记`resolved`。账户保持`frozen`，只能通过后续受控人工恢复，防止待执行任务与自动解冻发生竞态。

## 违约费用、坏账和信用对账

- 违约费用按到期后的完整`24`小时计日，日费以当前未偿本金乘条款日基点后按最小货币单位向上取整，并受条款累计上限限制。每次调度和逾期还款前都从最后计费截止日补齐；费用通过新的不可变账单明细、案件金额和`late_fee`流水追加，不改本金或信用余额。
- 坏账核销要求不同申请人/复核人、精确待核销金额、规范原因、批准摘要，以及等额坏账费用借记和应收贷记账本交易。核销把本金从已出账移入已核销、账单进入`written_off`且账户进入`bad_debt`；普通账单还款不能再作用于该账单。
- 坏账收回使用专用`bad_debt_recovery`还款与`written_off_recovery`分配，账本必须借记真实商家现金或对应客户余额并贷记坏账费用，禁止支付清算、佣金或应收冒充。部分收回按费用后本金分配，全部收回也不复活原账单、不自动解冻账户。
- 人工恢复要求账户版本栅栏、稳定来源、原因、证据摘要和直接员工，并重新确认逾期本金、已核销本金及全部未解决案件均为零；成功后清除冻结证据、按有效期进入`active/expired`并追加唯一`unfreeze`流水。
- 信用对账使用单条集合 SQL 按账户号 keyset 每批最多扫描`100`个账户，同时核对账户与敞口汇总、活动逾期案件和最新流水。一个批次的所有差异合并为一个优先级`100`的脱敏耐久任务，相同差异指纹稳定重放，不按账户产生查询或任务`N+1`。

## 影响判断

- 接口与权限：内部领域服务已通过`6.11.e`接入相互隔离的后台与客户 HTTP、读模型和命令服务。客户身份只从当前活动主体派生；后台按申请、账户、账单和政策拆分八项精确权限，并拒绝模拟身份或不可表示的数据范围。政策变更、申请复核和客户余额还款使用绑定完整规范化预览的一次性最近重新认证凭证，执行时重新授权，业务事实与审计同事务提交。坏账核销、收回和人工恢复在独立审批证据 owner 尚未对外组合前不开放 HTTP。
- 外部系统：无 Provider、支付渠道、智简魔方或其他外部调用。信用还款只消费本地正式账本中的已确认证据；支付、余额和人工收款 owner 的生产接线尚未完成，服务不会自行声明渠道成功，也没有把佣金作为资金来源。逾期升级只创建内部耐久任务，实际服务处置处理器尚未接线。
- 性能与并发：开户按单申请常数次查询；占用与释放按单账户、单敞口常数次查询和写入，没有列表装配或`N+1`读取。账户锁是同客户同币种的串行化边界，不会跨币种互相阻塞。
- 多语言与前端：未新增用户界面、菜单或运行时可见文案，无新增翻译资源；后续 HTTP/UI 切片必须补充双语 API 文档与页面文案。
