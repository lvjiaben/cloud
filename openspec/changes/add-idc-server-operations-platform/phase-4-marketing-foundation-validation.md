# 第四阶段营销数据底座验证记录

## 结论

任务`4.8`已完成。`idc-core`新增迁移`020-marketing-foundation.sql`和 18 组 GoFrame DAO/DO/Entity，为动态分群、优惠券、代金券、积分、充值赠送、返现和限时活动建立可并发执行的数据底座。本切片只建立事实与约束，不提前实现`4.9`的核销服务或`4.10`的管理页面。

## 分群与活动快照

- 既有客户分组继续用于人工 CRM 归类；新的营销分群独立保存`static/dynamic`模式、双语名称、定义摘要、刷新间隔和版本，禁止复用分组冒充动态分群。
- 动态条件只接受固定事实、运算符和值类型。支持等级、标签、客户/实名类型、地区、注册时长、消费金额、服务数量、续费期限、工单、渠道和风险；金额条件必须明确大写三字母币种，不保存或执行任意 JSON。
- 当前成员是可撤销投影；活动目标使用独立完整快照，快照绑定分群版本、定义摘要、成员数量和内容摘要。活动通过`目标快照 + 目标分群`复合外键防止串用其他分群快照。
- 分群条件、集合值、成员、快照和快照成员均有稳定集合索引，后续刷新和读取可以批量执行，不需要逐客户 N+1 查询。

## 促销、券与并发名额

- 活动显式保存类型、时间窗、优先级、叠加策略、叠加组、商品范围、状态和版本；权益规则分别表达固定金额、比例、代金券、积分、充值赠送、返现和客户价，并保存币种、最低消费、封顶、新购/续费和首期/循环次数。
- 活动类型与权益类型由复合外键和组合约束绑定；券实例再绑定活动、权益编号和权益类型。代金券只能使用正面值，优惠券才允许固定金额或比例，不能用代金券外壳引用比例折扣。
- 领取码只保存 32 字节 HMAC 摘要，不保存明文。券实例、保留记录、客户和币种由复合外键绑定，不能把 A 客户或 A 币种的券保留到 B 客户或 B 币种。
- 活动总名额、逐客户名额和券使用次数分别保存`reserved + consumed <= limit`计数。真实 PostgreSQL 中每类均由两个并发 worker 争抢最后一个名额，连续 20 轮都只有一个条件更新成功；直接写入超额消费被数据库约束拒绝。
- 通用活动保留记录精确绑定活动、权益、客户、报价、币种、权益摘要和过期时间，覆盖没有独立券实例的限时价、客户价、积分、赠送与返现；后续核销服务可以依据同一事实执行核销、释放或过期回收，而不是只剩无法解释的计数器。

## 积分、赠送与返现守恒

- 积分账户只保存可用、冻结和欠积分投影；积分批次保存`available + frozen + consumed + expired + reversed = original`，全部分桶非负。批次状态必须与剩余分桶一致。
- 积分流水是追加事实，获取、冻结、释放、消费、过期、欠积分和还欠积分均有明确增减方向；一个业务操作用行号跨多个到期批次分配，不会被错误幂等约束限制为单批次。
- 充值赠送和返现先进入营销权益，而不是实充资金账本。权益增加`pending`分桶，入账前后始终满足`pending + available + frozen + consumed + expired + reversed = original`；充值赠送在数据库层强制不可提现。
- 赠送/返现流水明确表达待入账转可用、冻结、释放、消费、过期和冲回。权益与流水通过`权益 + 客户 + 币种`复合外键绑定，积分冲回也必须属于原客户，跨客户或跨币种引用被数据库拒绝。
- 金额列全部使用`BIGINT`整数最小货币单位；营销表不含`deleted_at`，历史批次、流水、快照和保留记录不依赖软删除。

## 审查结论

- 数据权限：本切片未新增 API、服务或页面，无新的运行时数据暴露；后续`4.9/4.10`仍必须在目标存在性查询前接入直接员工/客户身份、精确权限和可表达数据范围。
- 性能：动态规则和值、成员、快照、活动、范围、权益、客户名额、券、积分批次和价值权益均按未来批量筛选及稳定分页路径建立索引；并发争抢是单行条件更新，不需要全表锁或逐候选查询。
- 一致性：活动/权益类型、分群/快照、券/客户/币种、积分批次/客户、价值权益/客户/币种均由复合外键证明；名额和金额守恒由 PostgreSQL 直接约束。
- i18n：无运行时用户可见文案、API 文档或菜单变化，因此本切片无 i18n 资源影响；双语名称是业务数据字段，不是硬编码界面文案。
- 缓存：无影响；PostgreSQL 是唯一事实源，本切片没有引入缓存。
- 插件版本：`idc-core`提升到`v0.1.23`，使正式升级路径执行新迁移。
- Git：未提交、未暂存、未推送。
