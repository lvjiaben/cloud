# 第 17 阶段魔方财务同行接口纠偏记录

## 用户确认结论

- 智简魔方公有云`KVM`和资源生命周期对接保持现有管理员`v1`契约不变。
- 本系统与魔方财务做同行上下游对接时，禁止使用已知有问题的`idcsmart_api`插件式`V1`接口。
- 魔方财务适配器固定使用其原生供应商接口，先登录获取`Bearer JWT`，再调用已验证的商品、账务、订单和服务路由。
- 首版新增`LinaPro`对接`LinaPro`适配器，直接复用通用下游`API`与签名`Webhook`契约。

## 源码复核结果

本轮只读复核了本地合法隔离样本`zjmfmangerbetaV3.7.6.zip`，压缩包`SHA-256`为`ECFF5F41B2C604CB7FD823AC33ACBB56FEFD8EE64BFCE30576135A0AE339E6BC`。源码同时包含两类完全不同的对接路径：

| 路径 | 源码行为 | 本项目结论 |
|---|---|---|
| 插件式`V1` | `modules/addons/idcsmart_api/api.php?action=/v1/...`，使用`apiname/apikey` | 已知有问题，不得用于魔方财务同行对接 |
| 原生供应商接口 | `POST /zjmf_api_login`获取`JWT`，后续以`Authorization: Bearer <jwt>`调用`cart/*`、`host/*`、`provision/*`、`upgrade/*`与`dcim/*` | 魔方财务适配器的唯一允许基线 |

样本的`app/zjmf.php`中，`zjmfCurl`负责原生供应商登录、`JWT`缓存、`Bearer`请求和过期后的单次重新登录；`app/common/logic/Host.php`展示了通过该通道执行购物车结算、服务查询、取消和续费。插件式`V1`则是另一套认证、路由和错误语义，两者不能混用。

## 后续实施门禁

1. 第`17.7`必须以上述隔离样本和可用正式文档冻结魔方财务原生供应商契约，不得把插件式`V1`当作候选或降级通道。
2. 第`17.11`对魔方财务的每个最小子集动作必须有原生供应商路由的契约样本与失败语义；未验证动作保持关闭。
3. `LinaPro`对接`LinaPro`使用通用下游契约，不建立特权内网通道、站内`HTTP`回环或第二套交易真相。
4. 第`9`阶段智简魔方公有云适配器不受本纠偏影响；不修改已冻结的`phase-9-zjmfcloud-v1-contract.md`。

## 影响评估

- `i18n`：本轮只更新中文治理文档，无运行时用户可见文案变化。
- 缓存：本轮不实现`JWT`缓存，第`17`阶段实现时必须单独冻结过期、失效和多实例行为。
- 数据权限：本轮不改变运行期数据访问；后续仍由渠道主体、商品范围和服务归属门禁控制。
- 开发工具：本轮不修改脚本、构建或代码生成。
- 测试：本轮使用源码静态复核和`OpenSpec`严格校验；运行期契约测试归入第`17.7`、`17.11`和`17.13`。
