# 第十阶段供应商写熔断验证记录

## 1. 任务结论

任务`10.6.d.3`已经完成中央合规网关内部的供应商写尝试租约、PostgreSQL 持久熔断、单次结果观察和并发半开探针。任务`10.6.d`由此完成。当前仍不开放注册之外的业务 HTTP 路由，不装配腾讯或诺诺客户端，也不执行任何真实供应商请求。

## 2. 写租约与幂等边界

- 每个已认证业务请求在数据库中全局最多只有一条供应商写尝试。首次取得租约的调用方收到`call_supplier=true`；响应丢失或进程恢复后只返回相同尝试号和`recovered=true`，并固定`call_supplier=false`，不得再次跨越供应商写边界。
- 尝试号、业务请求、实例、供应商、操作范围、熔断修订号和探针标记一经写入不可更改。把同一业务请求错误路由到另一个供应商或操作范围时返回`request_conflict`，数据库唯一约束同时禁止第二条尝试。
- 租约事务重新锁定活动实例和权威业务请求。实例撤销后不能取得新租约；已经取得租约并真实越过供应商边界的在途调用仍可记录一次精确结果，避免丢失外部事实。

## 3. 熔断与结果观察

- 熔断状态按供应商和操作范围维护`closed/open/half_open`、策略版本、连续失败数、开放截止时间、唯一探针号和单调修订号，所有时间判断使用 PostgreSQL 权威时间。
- 关闭状态下只有供应商真实可用性失败才能增加确定失败计数；达到阈值后进入开放状态。`result_unknown`表示供应商是否受理无法证明，会立即开放熔断且绝不自动重发。
- 开放期未结束时返回稳定`supplier_circuit_open`和有界重试间隔。到期后并发请求中只有一个事务可创建半开探针，其余请求继续失败关闭且不创建写尝试。
- 探针成功才能关闭同一修订代次的熔断；探针失败或结果未知会重新开放。探针超过策略超时时，下一次准入在同一事务把旧尝试和旧业务请求标记为`result_unknown`并重新开放熔断，不会重放旧写请求。
- 每次尝试只能从`admitted`单向观察为`succeeded`、`definitive_failure`或`result_unknown`。完全相同结果可恢复，不同结果冲突；较早并发尝试的迟到成功只收敛自己的业务请求，不能关闭已经进入新修订代次的熔断。

## 4. 自动化验证

```text
GOWORK=off go test ./... -count=20 -shuffle=on
GOWORK=off go vet ./...
GOWORK=off golangci-lint run --config E:\golang\cloud\.golangci.yml ./...

LINAPRO_IDC_COMPLIANCE_GATEWAY_TEST_DSN=<disposable-dsn> \

PASS
```

真实 PostgreSQL 用例覆盖首次租约、响应丢失恢复、跨供应商误路由拒绝、确定失败阈值、开放期拒绝、探针成功关闭、结果未知立即开放、迟到成功不能关闭新代次、并发请求只有一个探针、遗弃探针原子冻结，以及实例撤销阻止新租约但保留在途结果观察。迁移用例同时验证熔断和尝试表约束、不可删除、身份不可变与受控状态迁移。

当前环境固定`CGO_ENABLED=0`，因此`go test -race`被 Go 工具链以`-race requires cgo`拒绝；并发正确性由真实 PostgreSQL 行锁、唯一约束和十轮乱序并发测试覆盖，未把未执行的 race 门禁记为通过。

## 5. 规则域与审查

- 架构与插件：实现闭环在`idc-compliance/central-gateway`独立模块，没有修改`lina-core`、`lina-vben`或商家插件运行时。
- API 与数据权限：未新增 HTTP 路由或请求 DTO；服务只接收已通过`10.6.d.2`认证的内部准入结果，并在事务中重新核对实例、请求和操作范围。认证成功仍不等于未来合同或发票业务授权。
- 数据库与性能：单次获取或观察只锁定一个业务请求、一个尝试和一个供应商/操作熔断行，全部使用唯一索引和精确查询，无列表、扫描、缓存或`N+1`。
- 安全与审计：不保存供应商原始错误、响应、密钥、主体原文或业务载荷。结果只使用三个封闭类别和安全不透明引用；本地认证、权限、额度、参数或构造失败不能作为供应商故障样本。
- 前端、宿主、缓存与`i18n`：无影响。仓库宿主页面的既有门禁按用户要求不在本任务处理，也不影响本独立模块验证结论。

`lina-review`复核了全局单写租约、事务锁顺序、实例撤销竞态、熔断策略版本、开放与半开转换、并发探针、遗弃探针、迟到结果和持久约束。审查期间把原“请求 + 供应商 + 操作”唯一约束收紧为每个业务请求全局唯一，并补充跨供应商误路由、服务返回形状和存储规范值的失败关闭校验；最终没有遗留阻断`10.6.d.3`的`P0`、`P1`或`P2`问题。
