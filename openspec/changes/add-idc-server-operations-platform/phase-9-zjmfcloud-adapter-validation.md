# 第九阶段智简魔方适配器验证记录

> **`FB-52`范围纠正：**智简魔方 Provider 能力与安全失败关闭规则仍是服务器连接器的契约依据；本文若依赖内置源码插件、通用商品资源池字段或旧服务编号，只能用于迁移对账，不能证明当前托管动态连接器已经完成。最终实现必须由服务器插件拥有业务页面与资源语义，智简魔方作为可管理的托管动态连接器通过版本化服务器扩展点接入。

## 验证范围

本记录覆盖`idc-zjmfcloud`当前离线适配器切片，并核对任务`9.1`冻结契约、Provider 增量规范和用户决策记录。插件根目录不存在独立`AGENTS.md`，因此使用项目顶层规范。

本轮没有访问生产写接口，没有创建、修改、暂停、重装或删除任何用户与实例，也没有把线上凭据、令牌、资源编号或原始响应写入仓库。

## 已验证实现

- 登录严格使用无查询参数的`POST /login`表单，访问令牌只进入`Access-Token`请求头；只读请求的`401`允许刷新并重放一次，已发送写请求的`401`只失效令牌并形成结果未知，禁止同一次调用自动重发。
- Provider 设置使用带单位的`time.Duration`字符串，未知字段、越界值和可能被资源契约识别为凭据的配置形状均拒绝。
- 适配器强制`HTTPS`、证书链和主机名匹配，拒绝重定向，并再次核对响应请求地址、路径和查询串。
- 并发、响应体、令牌、游标页数和创建候选数量均有固定上限；区域、节点、镜像、`IP`组和创建图只保留字段白名单。
- 每个计划库存逻辑页固定读取一次`GET /clouds/create_page`区域→节点/存储嵌套图和一次`GET /stores?list_type=all&enable=1`顶层存储数组，在统一 20,000 个候选上限内执行字段白名单、稳定去重和排序；跨页指纹覆盖两个来源，任一来源畸形或变化都拒绝发布。
- 写操作不会因传输超时、未知状态或缺少任务编号而盲目重试；任务查询同时校验任务编号与资源编号。
- `resource`拥有方使用独立的只读观察次数记录任务与资源查询，每次领取通过 PostgreSQL 权威时间递增；下一次查询采用 5 秒至 5 分钟的有界指数退避和按任务号确定的抖动，状态推进或终态收敛时归零，且绝不改变 Provider 写入尝试次数。
- 适配器保护窗口只阻止新的上游写入；精确的`GET /tasks/:id`与`GET /clouds/:id`继续用于对账，库存、列表和其他非对账流量在保护窗口内保持关闭。
- 开通和重置密码只通过`secretcap`句柄读取秘密；重装凭据和控制台票据只通过资源所有者的加密输出边界返回。
- 救援进入与退出分别作为`server.rescue.enter`和`server.rescue.exit`能力发布；进入只接受`linux/windows`并把当前操作的`temporary_password`秘密句柄一次性映射为`temp_pass`，退出不接受参数或秘密，两者缺任务编号时均进入结果未知保护。
- 安全组只开放当前实例的绑定和解绑；绑定按实例`user_id/type`一次性核对安全组唯一归属，解绑按当前`security`关系核对。无任务号的同步或歧义结果只有回读精确达到目标关系才成功，共享组/规则删除、批量和强制参数保持关闭。
- 控制台地址只接受`https`或`wss`，拒绝用户信息、片段、非法端口和未在 Provider 入口主机或精确白名单中的目标。

## 审查中已修复的问题

1. 登录测试夹具曾要求无契约依据的`a=a`查询参数，导致真实请求偏离冻结的`POST /login`契约；现已删除并加入无查询参数断言。
2. 令牌缓存、请求超时和熔断时长曾使用秒数整数；现已改为`login_cache_ttl`、`request_timeout`和`circuit_open_duration`带单位字符串，并覆盖格式、类型和边界失败路径。
3. 原`token_cache_*`配置名会触发`resourcecap`凭据扫描，导致合法 Provider 配置在进入适配器前被拒绝；现改用`login_cache_ttl`并增加公开 Provider 配置校验测试。
4. 创建图候选上限曾只在完整区域处理后检查；现改为每次追加前检查，并验证拒绝项不会污染去重集合且其临时数据会被清除。
5. 计划库存曾只消费`/clouds/create_page`并把嵌套存储当成完整候选，遗漏公开前端实际消费的顶层`/stores`来源；现每页固定合并两个来源，禁止逐节点扇出，并补充顶层来源畸形与跨页变化的失败关闭测试。
6. 真实本地 E2E 发现库存同步审计缺少精确权限和空的变更前快照，并把业务状态`accepted`误写成审计结果；人工接管也把`manual_takeover`误写成审计结果。审计服务因此按安全规则回滚了本来成功的业务事务。现统一使用审计结果`succeeded`，业务状态只保留在变更后快照，库存同步同时补齐精确权限和空的变更前对象，并增加 Go 回归断言。
7. 任务详情没有未回收资源时，响应层可能省略空数组；页面原来直接读取`.length`，导致抽屉无法展示。现在初次加载和人工接管返回都统一把省略的证据、残留资源数组归一为空数组，真实`TC-1b`至`TC-1d`已验证详情和接管链路。

## 规则域结论

- 架构与插件：适配器代码闭环在`idc-zjmfcloud`，只依赖`core`的`secretcap`和`resource`的`resourcecap`公开契约；退避状态由资源拥有方`idc-resource`维护，未修改宿主目录。每个计划库存逻辑页固定两次远程读取且不按节点调用`stores`，远程调用次数不随区域、节点或候选数增长，不存在动态`N+1`。
- 后端与测试：当前切片编译、重复乱序测试和定向静态检查通过；适配器单元测试通过不安全字段夹具证明附属目录不会泄露共享安全组引用、规则、凭据或原始路径。真实本地 E2E 的每个用例都生成独立随机业务号，不依赖其他用例顺序；事实表按产品规则保持追加不可变，测试只允许在明确隔离、可整体重置的本地 E2E 数据库执行。
- 缓存与派生状态：Provider 认证会话、写健康窗口、阈值和跨节点保护均以 PostgreSQL 为权威源，秘密明文仍由`secretcap`拥有；单机和集群走同一路径，`401`按实际代次失效，数据库或秘密能力不可用时失败关闭。本轮 E2E helper 与投影测试不新增缓存或失效路径。
- 文档：中英文`README`同步维护，OpenSpec 严格校验通过。
- `i18n`：本轮没有新增运行时页面、菜单、按钮、接口文档、错误资源或翻译键，因此运行时资源无影响；E2E 复用既有中英文页面文案，真实浏览器执行通过。
- 数据权限：真实 E2E 只模拟宿主用户信息投影来稳定展示已有管理员入口，资源库存、任务详情和人工接管业务请求全部进入真实本地后端，继续由后端校验登录、精确权限、租户和目标对象范围；夹具使用随机不透明编号且只写隔离 E2E 数据库，不形成生产旁路。
- 数据库：本轮不新增或修改迁移。真实 E2E helper 只向现有资源拥有方表写入最小白名单事实，SQL 已在本地 PostgreSQL 事务中完成插入、读取和整体回滚验证；正式执行时事实按产品不可变规则保留，由隔离 E2E 数据库的整库重置负责清理，不允许指向生产数据库。
- `DI`：未新增运行期接口依赖；现有启动期`taskStore`作为唯一资源任务 owner 同时承担写入、任务观察和资源观察，`Executor`仍由`registerJobs`显式构造并复用同一实例。
- 前端、`E2E`和开发工具：详情接口在没有未回收资源时会省略空数组，页面原先直接读取`.length`导致抽屉渲染失败；现已在生产页面统一把省略的证据和残留资源数组归一为空数组，初次加载与人工接管返回都走同一处理。新增插件本地真实 E2E helper，并扩展既有`TC001`四个场景；当前真实运行时四项全部通过。

## `9.3.a`反馈闭环与影响分析

- 根因：原计划库存只读取`/clouds/create_page`嵌套图，遗漏已安装版本公开`SPA`通过`list_type=all&enable=1`消费的顶层`/stores`数组，导致候选来源不完整。
- 实现：每个逻辑页固定执行两个有界只读调用，合并后再统一排序、分页和计算内容指纹；顶层存储只投影编号、名称、状态、类型和可选剩余容量，未知字段与秘密字段在响应清理时丢弃。
- 性能：远程调用次数固定为两个，不随区域、节点、存储数或页大小增长；两个数组及合并结果共用 20,000 个候选的硬上限，不引入逐节点`N+1`。
- 数据权限：这是 tenant 0 平台渠道内部 Provider 读取，不新增 HTTP 入口、外部对象编号入口或用户数据范围；资源拥有方发布快照时仍需执行自身权限边界，本切片没有绕过路径。
- `DI`、API、SQL、缓存、`i18n`与开发工具：没有新增运行期依赖、构造函数、路由、DTO、数据表、缓存、用户文案、语言资源、脚本或构建入口；运行时`i18n`无影响。

## `9.2`共享认证会话收口

- 根因：`resource`的`ConstructSession`按每个有界调用创建全新 Provider，而旧适配器把令牌、到期时间和单次登录协调锁保存在 Provider 实例内。实例之间不共享，多个应用节点更无法协调，因此会重复登录；一个实例收到`401`也只能清理自身令牌。
- 实现：`resourcecap.ProviderEnv`新增资源拥有方认证会话能力。`plugin_idc_resource_provider_auth_session`只保存渠道、单调代次、状态、到期时间、刷新租约摘要、加密秘密的不透明引用和失效时间，不保存令牌明文。刷新领取和发布使用 PostgreSQL 权威时间、`FOR UPDATE`、256 位随机租约摘要、150 秒有效期和代次围栏；真实登录在事务外执行。Provider 不再保存实例级令牌，所有读取和失效都经过注入能力。
- 一致性：PostgreSQL 是唯一会话权威源，`secretcap`是唯一令牌明文加密权威源。共享状态不依赖`cluster.enabled`分支或进程广播，单机与集群使用相同路径；进程崩溃后由租约到期恢复。最大可接受陈旧时间沿用渠道配置的`login_cache_ttl`，范围为 1 分钟至 1 小时；任一已认证请求收到`401`即按代次立即失效。数据库或秘密能力不可用时认证失败关闭，不退化为本地缓存。
- 安全：旧`401`只能失效其实际使用的代次，不能清除后来发布的新令牌。只读调用只有在共享失效成功后才允许重新认证并重试一次；写调用仍不刷新、不重放。数据库只出现`secretcap.Handle`的不透明引用和租约摘要，测试同时检查令牌原文未落库。
- 性能：一个 Provider 会话首次访问固定执行一次精确渠道行事务和一次秘密访问；并发等待只轮询同一主键，不按资源、任务或库存条目产生查询。表以`channel_no`为主键，租约恢复索引覆盖`tenant_id + status_code + lease_expires_at + channel_no`。
- 验证：资源迁移真实 PostgreSQL 隔离 schema 连续十轮通过，覆盖两个独立会话实例并发只登录一次、共享复用、失效后刷新、旧代次失效不能清除新代次、秘密引用不含令牌和租约清理。智简魔方适配器十轮乱序全量测试覆盖全新 Provider 实例共享一次登录和既有写`401`不重放。两个插件普通全量 Go 测试与官方`lint.go`均通过，`golangci-lint`和`staticcheck U1000`为零问题。
- 规则影响：本轮没有新增 HTTP API、页面、菜单、权限对象、数据范围入口、用户可见文案或 E2E 行为，因此 API、前端、运行时`i18n`、数据权限和 E2E 无影响；中英文插件说明已同步。本次新增 SQL 只有 DDL，带完整插件 ID 前缀和幂等存在性保护，会话状态不采用软删除。
