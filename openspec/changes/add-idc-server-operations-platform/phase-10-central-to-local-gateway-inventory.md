# 第十阶段中央网关实现本地化盘点记录

## 1. 盘点边界

任务`10.6.a`覆盖`idc-compliance/central-gateway`嵌套模块、商家插件内`gatewayenrollment`运行时、插件迁移`006-central-gateway-enrollment.sql`及对应生成模型。分类标准不是文件名，而是数据所有者、授权来源和是否依赖软件提供方业务服务。

## 2. 可直接保留的进程与交付基础

以下能力不携带销售、客户实例、平台操作者或中央结算语义，可以在名称和错误文案本地化后直接保留：

- 独立 Go 模块、独立进程、上下文取消和优雅关闭；
- 有界监听地址、请求头和超时配置；
- `no-store`、`nosniff`、禁止嵌入和最小 CSP 等运维响应头；
- 配置只引用秘密文件、秘密文件大小与 Unix 权限检查、内存清零；
- PostgreSQL 连接启动检查、迁移校验和事务级 advisory lock；
- 可复现跨平台构建、逐文件`SHA-256`和禁止覆盖既有发布目录；
- 仅返回稳定状态码和安全构建元数据的存活/就绪探针。

## 3. 必须改造为当前安装所有权的安全组件

下列算法目标仍有效，但现有记录以`instance_no`、`merchant_ref`、中央主体或中央路由为父级，不能原样上线：

| 现有组件 | 可保留目标 | 必须删除或替换的中央字段/权威 |
|---|---|---|
| `request*`、`operation.go` | 幂等摘要、有界载荷、防重放、持久限流 | 远程实例密钥、跨实例所有者和实例级路由 |
| `circuit*` | 供应商写熔断、结果未知保护、数据库权威状态 | 平台按购买方实例统一控制；改为当前安装自己的供应商渠道 |
| `callback*`、`event_digest.go` | 回调验签、事件去重、单调状态收敛 | 中央实例投递和跨客户回调转发；改为供应商直达本地公开入口 |
| `query*` | 主动查询、只读证据、未知结果收敛 | 平台代查与跨实例路由；改为当前安装自己的供应商账号 |
| `takeover*` | 证据约束、封闭人工接管、禁止强制成功 | 平台操作者权威；改为当前商家近期完整认证的精确权限员工 |
| `evidence_crypto.go` | 用途隔离的证据加密与摘要 | 跨客户路由引用；改为当前安装本地秘密和本地业务对象 |

上述组件必须先去除远程实例父级和平台权威，再接回本地数据库；仅保留测试通过的算法不等于任务完成。

## 4. 必须删除的中央身份与跨客户路由

以下实现没有本地化保留价值，必须删除而不是兼容：

- 嵌套模块`pkg/identityprotocol`、`pkg/registrationapi`、`internal/identity/token.go`、注册服务和`internal/app/registration_runtime.go`；
- `idc_gateway_registration_token`、`idc_gateway_instance`、`idc_gateway_instance_key`、销售记录唯一约束和远程注册 HTTP 路由；
- `idc_gateway_subject_binding`中的跨实例供应商主体绑定；每个安装只配置自己的供应商主体和凭据；
- `idc_gateway_instance_delivery`以及向购买方实例转发回调的投递模型；供应商回调直接进入当前安装；
- 商家插件`gatewayenrollment`服务、远程 HTTPS registrar、`central_instance_no`、`central_key_no`、销售记录引用、注册令牌秘密范围及对应 DAO/DO/Entity；
- 任何商业授权码、平台销售记录或软件提供方网络服务参与业务签名、供应商主体、回调或人工接管的路径。

替代边界是安装时在当前环境生成的用途隔离进程密钥环：活动密钥只签新请求，上一代只在轮换窗口验证，撤销密钥立即拒绝；插件和网关不需要远程注册，也不产生跨安装身份编号。

## 5. 归属任务`10.7`的中央结算删除范围

以下内容只记录在本盘点中，不由`10.6.a`误判为可复用：

- `internal/settlement`全部代码和测试；
- `006-central-settlement-foundation.sql`、`007-settlement-management.sql`；
- `idc_gateway_price_*`、`idc_gateway_settlement_*`、`idc_gateway_provider_billing_gate`；
- 平台预付余额、后付审批、统一价格发布、平台额度门禁和`operator_settlement`权限模型。

本地替代只能是当前商家对自己供应商套餐、用量、费用和预算的只读证据与告警，不建立软件提供方对购买方的余额、授信、代付或价格账本。

## 6. 删除和迁移顺序

1. 先冻结本地组件包、配置和运行边界，保持供应商客户端关闭。
2. 删除商家插件远程 enrollment 和网关注册路由，建立安装期本地进程身份。
3. 将请求安全、回调、主动查询、熔断、证据和人工接管改为当前安装单一所有权。
4. 删除中央结算代码与迁移，新增本地供应商用量/费用只读投影和灾备责任边界。
5. 以全仓静态扫描、单元/数据库测试、双平台组件构建和“软件提供方业务服务不可用”验证证明不存在中央依赖。

该顺序不触碰`web-customer`或旧 Portal，也不开发真实腾讯/诺诺客户端。

## 7. 执行结果

上述顺序已在任务`10.6.b`至`10.7.d`执行完成：远程 enrollment、中央身份、跨客户路由与中央结算生产代码均已删除；历史迁移只作为升级校验账本保留，并由`008`和`010`在最终 schema 中删除对应对象。本地进程身份、商家自有供应商秘密门禁、回调/查询/证据/员工接管策略、本地套餐/用量/费用/预算/对账/SLA 投影和生命周期模型已通过单元、静态、隔离 PostgreSQL 迁移及 Windows/Linux 构建验证，详见[第十阶段安装独立性验证记录](phase-10-local-independence-validation.md)。本记录形成时腾讯与诺诺真实客户端均保持关闭；`2026-08-14`后腾讯客户端转由`10.8`按官方契约实现，诺诺继续因`10.4.c`外部证据缺失保持关闭。
