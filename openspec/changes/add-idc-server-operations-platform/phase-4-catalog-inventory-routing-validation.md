# 第四阶段本地库存与资源池路由验证记录

> **`FB-52`失效声明：**本记录把服务器资源池、供应商库存和新单路由写进了通用商品与报价模型，原结论已经失效，不能继续作为当前实现正确或阶段完成的验收证据。现行模型中的商品库存只是商家在商品版本内维护的简单库存；资源池和供应商容量只属于服务器插件内部异步履约。下文仅用于清理旧表、旧接口、旧测试和开发数据时迁移对账，不能恢复兼容层。

## 结论

原`4.5`实现只代表历史服务器中心模型曾经落地，不代表`FB-52`后的通用库存已经完成。服务器插件仍可保留多资源池选择、容量未知失败关闭、创建前故障转移和创建后绑定冻结，但这些能力必须从商品核心迁入服务器插件，并在财务结清后的持久异步履约中使用。

数据库迁移、最新快照读取、确定性路由、冻结边界、插件后端、代码质量和插件治理门禁均通过。插件新增枚举与错误消息覆盖通过；仓库级`make.cmd i18n.check`仍仅被无权修改的宿主通知预览页 6 个既有缺失键阻断，因此任务暂不勾选。

## 实现范围

- `014-catalog-inventory-routing.sql`为资源池绑定增加`normal/drain/maintenance`维护模式、最低可售数量阈值和`stop_sale/manual_confirmation`不确定库存策略，并提供 2 组、5 项中英文字典。
- 库存快照新增非空`source_completed_at`，证明商品投影只消费已完成来源；来源完成时间必须不早于观察时间且早于过期时间。
- `available/limited`必须同时有观察量和可售量，并满足`可售量 = max(观察量 - 安全余量, 0)`；`unavailable`的两个数量固定为零；`unknown/stale`的数量必须为空，禁止未知库存伪装为零库存或可售库存。
- 库存快照使用数据库触发器拒绝更新和删除，修正只能追加新快照；资源池配置保持可修改，只影响后续新单。
- 路由用一条`CTE + DISTINCT ON`查询读取精确版本、地区、线路的最多 1,024 个绑定和每个绑定最新快照；候选数量超过边界失败关闭，不存在按资源池逐条查库存的`N+1`。
- 新鲜度使用查询返回的同一个 PostgreSQL `CURRENT_TIMESTAMP`。缺快照、观察时间或来源完成时间在未来、已过期、`unknown`或`stale`均视为不确定，不从应用节点本地时钟猜测。
- 只有启用新单、状态有效、维护模式正常、权重大于零且可售量同时达到资源池阈值和请求量的候选可以自动履约。不确定候选按资源池策略停止销售或转人工确认，并返回稳定排序的刷新绑定号供后台异步调度；路由本身没有外部网络依赖。
- 自动候选先取最小优先级组，再使用“版本、地区、线路、订单项路由键”的`SHA-256`摘要按权重稳定选择。输入顺序变化不改变结果，返回值包含资源池绑定、快照号、来源指纹、观察/过期时间和可售量证据。
- 上游尚未创建资源时，可携带失败绑定号重新路由并排除该绑定；一旦上游资源已创建，只返回原绑定的`frozen`结果，不受新单停用、维护或优先级变化影响。资源拥有方`pool_no`保持不透明，不套用商品内部编号格式。
- 返回投影对可空数量和时间做深复制，调用方修改输入集合不会改变已经产生的路由证据。

## 任务级审查

- **已修复**：初版冻结查询没有把原绑定提升到有界集合首位；大量新单候选可能使高优先级数值较大的历史绑定落在`LIMIT`之外。现查询始终把精确原绑定排在首位，创建后冻结不受新单候选数量影响。
- **已修复**：初版把资源拥有方的`pool_no`错误套用商品内部业务号正则，会拒绝合法的不透明编号。现只检查非空、已规范化和数据库字段长度，不解释其格式。
- **已修复**：初版只校验来源完成时间不早于观察时间，未把晚于数据库当前时间的完成时间视为时钟异常。现该情况与未来观察、过期和未知状态一样失败关闭并请求刷新。
- **已修复**：路由 SQL 初版在有界 CTE 中使用`SELECT *`。现只投影路由与最新库存所需字段，查询稳定性和数据最小化门禁通过。
- 已确认最低优先级组之外的池不会参与权重选择；同一输入在候选顺序反转后仍返回同一绑定。
- 已确认不确定库存只返回空绑定的人工确认或不可售结果，不会把候选池误当成已承诺履约池；新鲜但明确无库存的快照不会触发同步上游探测。
- 已确认路由服务没有 Provider、HTTP、缓存或资源插件依赖；后台刷新号是后续本地异步调度输入，不包含上游编号、秘密或原始响应。
- 严重、外部既有阻断：`apps/lina-vben/apps/web-antd/src/views/system/message/notice-preview-modal.vue`引用的 3 个宿主键在`en-US`和`zh-CN`均缺失。当前仓库没有`.contributing`，本任务无权修改宿主目录，不能把仓库级 i18n 门禁标记为通过。
