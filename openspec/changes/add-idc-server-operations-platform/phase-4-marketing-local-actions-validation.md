# 第四阶段营销本地管理动作验证记录

## 范围

本记录覆盖任务`4.10.b.2.2.1`：`idc-core`后台优惠资产发放、未预占资产撤销、人工积分赠送和按原始奖励来源冲正积分。四项操作都不触碰客户真实资金余额。充值赠送与返现权益的入账、冲正和高风险审批仍依赖后续财务分层账本契约，记录在`4.10.b.2.2.2`，因此父任务`4.10.b.2.2`保持未完成。

## 实现证据

- 四项动作分别使用`idc:admin:marketing:asset:issue`、`idc:admin:marketing:asset:revoke`、`idc:admin:marketing:points:credit`和`idc:admin:marketing:points:reverse`。授权器先验证默认商家、直接活动员工、可表达的数据范围和精确权限，再解析未信任输入；任一读取权限或其他写权限都不能替代目标权限。
- 资产发放只接受处于有效时间窗的优惠券或代金券活动、有效权益规则和有效客户；有目标快照时，客户必须存在于冻结快照。资产编号由稳定请求号确定性派生，重复请求返回同一资产，改变绑定活动、权益或客户会冲突。
- 资产撤销先锁定目标行，只允许`issued/active`且`reserved_uses = 0`的资产，并要求客户端提交接口返回的毫秒级`updatedAt`。服务端按同一毫秒契约比较后，仍以数据库原始时间完成条件更新，避免时间精度丢失导致正常界面请求被误判为冲突。
- 积分赠送只追加正数`manual`来源批次；积分减少不提供任意负数调整，而是要求精确的原始来源类型、来源引用和正数冲正数量，复用既有积分批次、流水、守恒和欠积分处理能力。
- 每个动作使用最长 128 字符的稳定请求号、固定原因码和有界数量，在权威 PostgreSQL 事务中同步追加不可变员工业务审计。审计证据携带动作对应的精确权限；审计失败时资产或积分写入整体回滚。重放审计快照不依赖后续账户余额，避免同一请求因可变投影产生不同指纹。
- 四个后台 HTTP 接口只返回业务编号、结果状态、Unix 毫秒时间和有界积分投影，不返回数据库主键、凭据或任意内部 JSON。简体中文 API 文档翻译和中英文运行时错误消息同步维护。
- LinaPro 营销工作台按精确权限分别显示操作入口，统一弹窗生成 UUID 请求号并强制选择固定原因。活动详情可预填活动与权益；资产撤销携带当前更新时间；积分冲正只能从具体批次发起。详情抽屉中的动作会等待抽屉完成关闭后再打开弹窗，避免弹层遮挡。
- 插件版本提升为`v0.1.31`。本切片没有新增数据库迁移、Seed、Mock 或缓存。

## 审查结论

- 数据权限：所有动作在目标存在性和字段校验前完成直接员工身份与精确权限检查；客户身份、代理、跨商家及不支持的数据范围失败关闭。目标不存在、状态不允许和并发版本不一致统一使用冲突语义，不扩散对象存在性。
- 一致性：资产/积分事实和审计证据在同一事务内提交。真实 PostgreSQL 回归证明重复请求不会重复发放或记账，审计失败不会留下孤立事实。
- 财务边界：积分保持非货币语义；当前接口没有充值赠送、返现、余额增加、余额扣减或伪造财务入账路径。真实价值调整继续由财务账本所有者负责。
- 性能：每个动作只锁定单个客户、资产、积分账户或来源批次并使用已有唯一索引定位，不扫描目录、不逐行补查，也不调用 Provider 或远程服务。
- 前端：操作入口与权限一一对应，固定原因码代替自由文本，列表刷新使用现有有界接口。稳定测试标识替代“行内唯一按钮”假设，新增操作后不会让详情定位歧义。
- `i18n`：新增页面文案、原因码、错误消息和简体中文 API 文档均有治理资源；英文 API 文档继续使用 DTO 源文本。
- 缓存：无影响；所有写后读取仍以 PostgreSQL 为唯一事实源。
- Git：未提交、未暂存、未推送。
