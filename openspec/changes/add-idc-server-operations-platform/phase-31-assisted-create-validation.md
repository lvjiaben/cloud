# 协助报价创建闭环验收

## 范围与根因

`FB-117`按`lina-feedback`的`openspec-existing`路径补齐“后台协助创建订单”既定需求。原页面只有列表和审批动作，没有新建入口；创建接口遗漏配置值，正式装配下审批没有冻结配置，下单会被配置门禁拒绝。真实接口验收又发现创建缺审计前快照，且四种动作误把业务状态作为审计结果，导致正式审计服务拒绝事务；现补齐前快照并统一成功结果，业务状态保存在后快照。修改范围为`idc-core`插件的协助报价页面、配置适配、创建接口、审批与配置归属、权限校验、迁移及对应测试。不纳入此前运营数据、工单和其他对话的工作区改动。

## 实现边界

- 从真实客户候选及已发布商品目录选择，商品搜索分页为每页`24`项，单申请最多`8`项；复用公开配置评估及报价接口。金额通过整数最小货币单位传递，不使用浮点金额。
- 新建要求创建权限及客户列表、详情权限；后端继续拒绝非员工、模拟身份、非默认租户和不可表达的数据范围。全部数据范围不等于操作授权，各动作校验独立权限。
- 保留固定优惠、原因、有效期和双人审批。提交失败保留输入，相同内容重试沿用幂等键；修改内容产生新键。不会直接付款或开通服务。
- `114`迁移保存不可变配置意图，无演示数据、软删除或手写自增编号。以租户和明细为主键，以租户和申请为查询索引；读取采用集合查询，逐项重校验与冻结限定最多`8`项。
- 普通固定商品仍按权威购买解析器校验；有配置声明的商品必须冻结配置。旧申请缺失配置意图或旧批准报价缺失快照时明确要求重新发起，不猜测历史配置。
- 配置所有者为申请员工，实际下单审计为下单员工；不伪造客户上下文。客户文件上传仍只允许客户本人，后台禁用文件输入并说明限制，必填文件阻止提交。
- 依赖由插件`backend/plugin.go`在启动期创建，`commerceSvc`绑定同一个目录冻结器和文件消费服务，再传给`NewAssistedQuoteService`；本次复用既有依赖图，无新增宿主能力或请求期服务实例。没有新增缓存、失效协议和第三方写入。
