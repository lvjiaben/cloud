# 第三阶段后台客户列表基础验证记录

## 范围与完成判断

本记录覆盖任务 3.4.a、3.4.b.1、3.4.b.2a、3.4.b.2b 和 3.4.c：后台客户列表的员工授权、稳定分页、基础筛选、固定批量投影、客户 360° 本地域只读底座，以及批量标签的客户级可检索审计、API、权限目录和双语页面。任务 3.4 仍包含跨领域摘要、完整分组/标签分配明细、备注、跟进和黑名单等未完成能力，父任务保持未完成。

在列表基础上，任务 3.4.b.1 已提供客户 360°的本地域只读底座。详情使用独立的`idc:admin:customer:query`权限；只有列表权限不能打开详情。目标客户编号在授权之后校验，不存在或格式错误的编号返回统一不可访问结果。

后台读取使用独立的`customermanagement.Service`，不复用客户自助服务。请求必须先满足直接活动员工受众以及`idc:admin:customer:list`、宿主通配权限或平台管理员证据，再接受当前可由单商家查询表达的全量或商家数据范围。部门、本人、零值和未知范围失败关闭，且授权拒绝发生在参数校验与数据库访问之前。

服务已装配到`GET /admin/customers`和`GET /admin/customers/{customerNo}`。Controller 使用启动期注入的同一服务图，直接传递服务生成的不透明游标；路由分别绑定`idc:admin:customer:list`和`idc:admin:customer:query`，服务层仍进行独立员工受众、权限和数据范围校验，避免把路由中间件当成唯一授权边界。

插件清单发布独立的`IDC Operations / IDC 运营`目录和`Customer Management / 客户管理`菜单，不依赖宿主不存在的固定父菜单键。新增菜单通过插件版本`v0.1.1`的运行期升级落地；页面关闭 VXE 内建页码器，只提供由服务端不透明游标驱动的上一页/下一页，筛选改变时清空游标栈。

## 查询与投影边界

主体列表固定`tenant_id = 0`，只读取客户编号、类型、状态、展示名称、国家、语言、版本和时间，不读取个人姓名、证件、企业登记标识、摘要、认证案例或凭据。排序使用`created_at DESC, id DESC`，后续页使用相同复合边界，避免偏移分页在并发新增时重复或跳行。

名称前缀在服务端进行统一小写与空白规整，数据库`LIKE`参数按字面量转义反斜杠、百分号和下划线。页大小默认 25、绝对上限 100，序列化响应默认限制 512 KiB、绝对上限 4 MiB。

分组与标签筛选只接受`GRP_`或`TAG_`加 32 位小写十六进制的精确业务编号。主体查询分别使用有效分组/标签关系上的索引化`EXISTS`子查询，不先拉取关系到内存、不按客户逐条查询，也不把已撤销关系算入结果；名称、类型、状态、分组、标签和页大小共同进入游标摘要，任何跨筛选复用均拒绝。

筛选候选由`GET /admin/customer-segments`按`group/tag + zh-CN/en-US + 字面名称前缀 + 页大小`返回活动定义。候选使用本地化名称和内部主键升序的索引化 keyset 分页，后续页先校验真实边界；不透明游标绑定类别、语言、规范化前缀和页大小，空业务编号、未知字段、跨语言或跨前缀复用均失败关闭。页面每次最多请求 25 条候选，输入 250ms 防抖后远程搜索，不加载完整分群到浏览器。

每页投影使用固定数量的集合查询：

| 查询 | 最大次数 | 投影字段 |
| --- | ---: | --- |
| 客户主体页 | 1 | 非法定基础摘要和稳定游标 |
| 个人实名状态 | 1 | `customer_no + identity_status_code` |
| 企业实名状态 | 1 | `customer_no + verification_status_code` |
| 当前等级分配 | 1 | `customer_no + level_no` |
| 等级定义 | 1 | 编号、代码、双语名称和优先级 |
| 活动标签聚合 | 1 | `customer_no + COUNT(*)` |

## 批量标签写入与审计边界

`POST /admin/customers/tags/batch`使用独立权限`idc:admin:customer:tag:batch`，服务层仍重新校验直接活动员工受众、权限和当前可表达的全量/商家数据范围。命令只接受`assign/revoke`，最多 100 个规范客户编号、20 个规范标签编号、256 字符原因和一个 8—128 字符 ASCII 幂等键。服务按稳定顺序锁定客户与标签，拒绝不存在、已匿名化客户或已归档标签。

每个非重放命令只写一条封印审计事件，然后以单次集合写入把所有客户编号关联到`business_audit_customer_link`。链接行只允许在事件封印前插入，更新或删除由数据库触发器拒绝；审计事件签名内容包含客户数量和稳定集合摘要，搜索、检索和重放都重验实际链接。审计成功后标签关系使用一条集合化 SQL 写入，同一幂等键重放只返回原审计结果并跳过关系变更。

审计重放摘要与完整性签名不使用进程随机回退。部署必须通过`LINAPRO_IDC_CORE_SECURITY_KEYRING`注入规范 JSON 密钥环：稳定保留查找根密钥与版本化签名根密钥必须不同，重放和完整性通过 HKDF-SHA-256 分离用途。最多保留 8 个版本；缺失、非规范 Base64、未知字段、非法版本或用途复用都使路由装配失败关闭。

首屏最多 6 次客户投影查询；后续页先增加 1 次索引化权威边界校验，确认游标中的`tenant_id + id + customer_no + created_at`仍对应同一真实记录，再执行相同投影。游标采用有版本的 URL 安全不透明编码，绑定规范化名称、类型、状态和页大小；错误编码、跨筛选复用、跨页大小复用和不存在的边界均拒绝。它不依赖单机内存或部署密钥、不产生 GET 写入，集群节点可一致校验；查询次数不随客户行数、标签数或等级数增长。

没有等级的客户返回空等级，未分配活动标签的客户返回 0；客户主体缺少对应类型的实名投影、存在重复当前等级或引用缺失等级定义时失败关闭，不返回部分拼装结果。

## 客户 360°本地域边界

本地域详情复用同一主体、实名和等级白名单投影，增加最多 20 条分组与标签预览；超过预览上限只返回`HasMore`，完整明细必须由后续有界分页接口获取。详情不返回联系人地址内容、自定义字段值、备注和跟进正文、附件对象路径、黑名单证据、风险证据、法定身份字段或任何凭据。

联系人、地址、活动自定义字段、活动备注、计划跟进、可用附件、生效黑名单、未关闭风险、活动分组和活动标签十类数量使用一次固定`UNION ALL`集合查询完成，不产生逐类型或逐记录查询。订单、账单、交易、服务器、合同、发票、工单、通知和审计属于其他领域，必须通过各自所有者发布的批量摘要能力装配；本地客户服务不得跨插件直读其数据表。

## Lina 审查结论

- 审查范围覆盖后台客户服务、授权、校验、DAO 批量投影、单元/真实 PostgreSQL 测试、任务状态、验证记录和用户偏好；仓库其他既有改动不属于本子任务。
- 已按插件边界、数据权限、后端显式依赖、集合化查询、测试独立性、OpenSpec 和文档规则审查；插件根目录没有局部`AGENTS.md`，仓库根目录没有`.contributing`，未修改宿主受保护目录。
- 当前完成态包含后台只读列表、有效分组/标签候选分页、客户 360°本地域只读底座、批量标签的集合化写入与客户级审计、精确权限目录、API、菜单和双语页面。客户分配明细完整分页、客户 360°跨域摘要以及备注、跟进和黑名单动作仍是明确缺口，因此任务 3.4 与 3.4.b 保持未勾选；独立子任务 3.4.b.2b 与 3.4.c 已完成。
- 审查后未发现阻断问题或警告。客户查询固定商家条件，授权先于查询和参数校验，实名资料采用字段白名单，批量装配不存在请求行数驱动的数据库调用；测试与文档状态和实际交付范围一致。
- 客户 360°复审曾发现标签预览和集合计数在默认读已提交隔离下进行跨查询相等比较，合法并发标签调整可能被误判为损坏并短暂返回不可用；已移除不提供安全收益的跨快照相等断言，各投影继续独立校验并在后续刷新自然收敛。修正后 20 轮真实 PostgreSQL 测试、`go vet`、插件 lint 和 OpenSpec 严格校验再次通过。
- 真实浏览器首次验收曾被临时 fixture 使用非法`CUS_E2E...`编号触发领域校验失败；根因是验收数据违反`CUS_ + 32位小写十六进制`契约，不是生产投影缺陷。fixture 改为合法编号后首屏、筛选和 360°均通过，随后已精确清理全部临时数据与受众记录。
- 批量标签复审发现重放判定之前就重新校验客户和标签的当前业务状态，导致原命令成功后客户匿名化或标签归档时无法返回原结果。已把客户锁定与状态校验分离：先按稳定顺序锁定客户并通过封印审计识别重放，重放直接返回；只有新命令才校验客户状态、锁定标签并执行写入。新增真实 PostgreSQL 回归后复审未发现新问题。
