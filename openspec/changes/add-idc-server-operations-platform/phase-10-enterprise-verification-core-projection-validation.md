# 第十阶段企业认证核心投影验证记录

## 完成范围

任务`10.3.a`完成企业认证在核心客户域内的窄能力边界。合规插件可以证明当前企业客户、记录企业认证专用同意、验证可选的法定资料变更申请，并发布首次认证或重审结论；核心域仍不接收营业执照、法人证件、代理人证件或其他材料原件。

本切片没有开放 HTTP 接口或用户页面。企业资料上传、后台人工审核和前端工作流继续由`10.3.b`至`10.3.d`实现，父任务`10.3`保持未完成。

## 冻结业务语义

- 首次企业认证从`unverified/rejected/expired`进入独立待审案件，批准后才写入核心已认证投影。
- 已认证企业修改法定名称或登记标识时，必须先存在核心域的类别型法定资料变更单；核心域不保存拟变更值或证明材料。
- 重审进入`under_review`和被驳回时，原已认证企业投影保持不变。只有批准事务才能一次性替换法定投影并关闭变更单。
- 每个变更单只绑定一个新的不透明合规案件号；旧认证案件号、原投影版本和新复核案件号共同形成并发围栏。
- 未声明变更法定名称或登记标识时，批准请求不得借本次复核替换对应值。

## 数据库与敏感数据边界

迁移`041-enterprise-verification-projection.sql`新增企业认证专用同意类型、企业登记标识键控摘要唯一索引，以及法定资料变更单的`review_verification_case_no`不透明案件引用。迁移重复执行通过。

核心企业投影只接收批准后的法定名称、登记国家、登记标识、脱敏登记标识、行业编码和验证时间。法定名称与登记标识使用调用方拥有的字节缓冲，能力返回前主动清零；材料原件、私有对象地址和拟变更内容不进入核心域。登记标识使用安装实例密钥计算用途隔离的 HMAC-SHA256 摘要，并由数据库唯一索引处理并发重复。

## 权限、状态与事务

客户准备入口不接受客户号，通过当前登录主体推导企业所有权，并只接受该企业最新且在法定资料变更申请之后发生的有效同意。投影能力仅通过核心插件向`idc-compliance`提供的源码级运行时装配，不注册动态插件桥或 HTTP 服务。

首次认证投影、企业投影版本围栏、法定资料变更状态、新复核案件绑定和最终处理结果在同一 PostgreSQL 事务内更新。调用方存在外层事务时自动加入外层事务；并发唯一索引冲突在外层事务场景返回专用错误，要求合规域回滚后另起事务记录人工复核结果。

## 影响分析

- `i18n`：无用户可见文案、API 文档或前端资源变化；内部英文错误保持不可直接呈现。
- 数据权限：有影响。客户准备入口先证明当前企业所有权；管理审核权限和目标数据范围将在`10.3.c`的合规管理服务中接入，不能由本源码能力替代。
- 性能：单目标流程使用固定次数的索引查询和带版本条件更新，不存在随材料数量增长的查询循环。
- 缓存一致性：无影响。认证投影、同意和变更单完全以 PostgreSQL 为权威，不新增缓存。
- SQL：有影响。迁移为增量文件，DDL 已验证幂等，模型由仓库代码生成入口生成。
- 开发工具：无工具源码变化。Windows 环境没有 GNU Make，使用插件`Makefile`所调用的同一仓库内置`linactl dao`入口完成生成。

## 强制审查结论

本切片按`lina-review`对照 OpenSpec、架构、插件、后端、数据库、数据权限、测试、i18n 和文档规则完成审查。审查发现并闭环以下问题：

- 新复核案件最初只由合规域持有，核心变更单无法阻止另一案件重放；已新增不透明复核案件号及状态约束。
- 非终态输入可以携带未绑定操作者的决策原因；已改为待审和过期状态必须同时拒绝操作者与原因字段。
- 已认证结果没有提前拒绝不递增的有效期，且状态机函数复杂度超过仓库门禁；已补显式时间校验，并将开始复核、驳回和批准拆成独立处理函数。
- 批准路径可能替换变更单未声明的法定字段；已按类别逐项比对当前投影并失败关闭。

当前`10.3.a`范围没有遗留高、中或低优先级审查发现。企业材料私有存储、逐次查看审计、后台精确权限和页面验收属于后续未完成子任务，不能据此视为已交付。
