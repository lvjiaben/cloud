# 客户管理简化与交互验收

## 范围与根因

本轮按`lina-feedback`纳入现有活跃变更，只审查客户添加、重置密码、账号列表、客户详情和协助下单。依据用户于`2026-10-12`的具体确认、客户账户规范完整条款，以及本轮开始时的`temp/20261012/103017-customer-before`快照，过滤其他对话的商品定价、代理销售及宿主变更；不把整个工作区作为本轮成果。

旧页面并存邀请与直接开户两条入口，默认首次改密与用户确认不符；详情残留重复统计和失效跳转；商品追加在模板直接引用`crypto`导致操作失败。新增操作记录接口曾固定请求五十条，超出本地审计配置上限，已改由审计拥有方决定有界数量。

## 实现与边界

- 入口和提交按钮均为“添加”。邮箱／手机至少填一项，允许同时填写；浏览器使用安全随机数生成密码，失败重试保留同一密码和请求键，成功后展示及复制。仅填手机用手机号登录，同时填写用邮箱登录；创建与重置均不强制首次改密。真实身份和密码散列仍由既有宿主公开用户能力管理。
- 账号列按两行显示已有手机、邮箱，去标签数量。重置只有确认，无密码或原因表单。详情改为“查看详情”，删掉卡片头、运营足迹和重复业务汇总，保留真实业务页签及精确权限。
- 编号为蓝色下划线复制按钮，状态使用彩色标签，封禁与解封有确认。备注只填内容，列表不重复显示正文；备注、操作记录留在详情内。分组和标签可选择已有项、新建并关联、移除关联。
- 详情宽度固定，宽表格仅在其内部滚动。协助下单追加商品放到脚本方法，不可用问号改为简短可见说明，保持费用与原有下单结果。

新接口为`GET /admin/customers/{customerNo}/audit-records`、`POST /admin/customers/{customerNo}/segments`、`DELETE /admin/customers/{customerNo}/segments/{segmentNo}`。客户可见性、直接员工、租户和精确权限均在拥有方校验；删除仅撤销关联。操作记录只投影编号、操作、结果与毫秒时间，不返回秘密快照。联系方式在既有集合查询中增加邮箱投影，没有逐行补查。没有新增数据表、迁移、缓存或跨插件私有访问，也没有改动宿主或魔方云／证书插件的安装逻辑。

运行期审计依赖由`backend/plugin.go`启动创建的`auditSvc`经`BindCustomerAudit`传给后台控制器，复用相同实例与权限边界；不在请求内另建服务。分组标签复用客户修改服务及同一事务审计写入。

## 连续模拟登录插件闭环（2026-10-12）

此前失败根因仍为：后台立即撤销旧协助身份，客户中心路由守卫在交换新口令前读取旧身份，普通失效处理清理登录状态并跳到登录页。旧记录中的宿主补丁没有应用，用户明确禁止宿主修改；此次改为完全在`idc-core`内利用现有公开能力完成。

客户详情按钮读取公开插件状态中的版本，把原短期、单次交接口令转到插件声明的版本化静态交接页。交接页只把插件自有口令和会话号存入当前标签页的短期`sessionStorage`，清除地址栏片段，再进入原`/account/assistance`。第一次直接成功后，公开页头插槽清理待交接信息；旧登录状态失效时，由宿主原流程清理，公开登录插槽恢复一次交接并立即移除口令，不修改宿主访问令牌、路由守卫或认证流程。成功的新会话还会清理上一会话遗留的过期提示，避免已登录页面仍提示重新登录。插件停用时，插槽按宿主正常治理隐藏。

此次只修改插件前端辅助文件、静态资源、公开插槽、客户详情点击处理及插件内`TC020b`。没有修改`apps/lina-core/`、`apps/lina-vben/`或根`hack/`，没有运行时补丁、复制宿主实现、私有存储访问、后端身份签发变化或延迟旧会话撤销。静态页不含新增可见业务文案；本地交接配置错误复用本轮新增双语简短提示。
