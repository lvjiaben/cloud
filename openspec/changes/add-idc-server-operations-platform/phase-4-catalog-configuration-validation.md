# 第四阶段商品配置图契约验证记录

## 结论

> **FB-52 纠偏说明：** 本记录只证明当时服务器专用配置图的实现和迁移来源，不再作为通用商品配置完成证据。0.10 使用插件声明的十三类宿主管理字段、受限条件和类型化值协议；旧`component_type_code + normalized_value`只读保留到服务器插件迁移对账完成。

`4.2.a`当时完成了服务器专用插件内实现。固定套餐与可配置套餐共享商品版本、配置组和选项模型；13 类服务器组件使用类型化输入和确定性规范 JSON，未知、歧义、越界或不属于当前组件类型的字段都会被拒绝。该结果不得继续扩张为商品核心模型。

同一配置图校验已经接入 Provider 商品草稿接受、物化和发布完整性检查，避免人工商品与 Provider 导入商品形成两套语义。插件自身的运行时多语言和消息覆盖门禁通过；仓库级`make.cmd i18n.check`仍仅被无权修改的宿主通知预览页 6 个既有缺失键阻断，因此子任务暂不勾选。

## 实现范围

- 商品组件字典扩展为地区、线路、机房、处理器、内存、系统盘、数据盘、带宽、流量、`IP`、备份、镜像和附加项 13 类；真实 PostgreSQL 迁移测试要求字典集合精确一致。
- 每类组件使用受约束的类型化输入，并生成键顺序稳定的规范 JSON。地区、线路、机房和镜像使用小写规范代码；处理器、内存、磁盘、带宽、流量、`IP`、备份及附加项分别使用明确的单位、范围和枚举。
- 已存 JSON/JSONB 采用禁止未知字段的严格解码并重新规范化比较，拒绝尾随 JSON、额外字段和非规范语义；业务写入不接受任意 JSON 作为组件值。
- 固定与可配置套餐共享配置组和选项验证器。验证器限制最多 20,000 个组和选项，检查引用唯一性、选项归属、数量上下界、启用选项及选择模式。
- 固定套餐要求每组单选且`min=max=1`，恰有一个启用选项，启用选项的最小、最大和默认数量必须相同且为正数；可配置套餐允许多选和数量范围，但必须能满足组级选择约束。
- Provider 草稿完整性检查改为复用共享验证器，并逐个验证启用选项的规范组件值；接受、物化和发布前均会重新读取并校验真实商品图。
