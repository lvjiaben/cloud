# 第十阶段本地供应商主体保护验证记录

## 1. 范围与结论

本记录只验收任务`10.6.c.2`及其`10.6.c.2a`至`10.6.c.2d`。本轮没有实现腾讯或诺诺真实客户端，没有开放供应商主体`HTTP`路由，没有进入`10.6.c.3`、`10.6.d`或第十五阶段，也没有修改`web-customer`或删除旧 Portal。

任务`10.6.c.2`已完成：本地合规网关现在拥有独立供应商主体密钥环、PostgreSQL 主体生命周期契约和只供进程内部装配的主体服务。主体原文只在调用方可清除输入、供应商专用规范化器输出和同步回调缓冲中短暂存在；普通数据库、身份操作记录、接口、日志、用量与发布清单均不保存主体原文。

## 2. 根因与纠偏

迁移`008-retire-central-control-plane.sql`已经删除旧的中央实例和中央主体绑定模型，但本地运行时此前只有安装标识与进程认证密钥环，没有当前商家自有供应商主体的独立密钥、查重、撤销和重新开通能力。若复活旧表或等待软件提供方统一注册，会重新引入被禁止的平台销售注册、远程实例身份和跨客户中央路由。

本轮因此新增安装本地模型，不恢复任何中央表、中央注册服务或中央业务依赖。`central-gateway`目录名继续只作为历史源码路径存在；实际运行产物和数据库所有权均属于每套安装的本地合规网关。

## 3. 已冻结并实现的业务细节

| 细节 | 本轮实现 |
|---|---|
| 私有密钥 | 一个独立私有版本化文件，分别保存主体`AES-256-GCM`、主体查重`HMAC-SHA-256`和身份操作幂等`HMAC-SHA-256`三套随机密钥族；任意活动或保留密钥材料重复时拒绝加载 |
| 版本轮换 | 三套密钥族分别维护一个最新活动版本和最多七个历史版本；新写只用活动版本，历史解密、查重和重放覆盖所有保留版本；工具不提供未经迁移或留存核验的撤销、销毁入口 |
| 主体规范化 | 核心只调用已注册的供应商专用规范化器，不自行猜测空白、大小写或`Unicode`规则；生产运行时使用空注册表，腾讯和诺诺均失败关闭 |
| 唯一绑定 | 数据库强制每个安装对每个供应商最多一个活动主体，并以版本化查重摘要强制同一数据库可见范围内同一供应商主体最多属于一个活动实例；不同独立数据库之间没有中央查重表 |
| 撤销与重开 | 首次绑定、撤销和重新开通是独立操作；当前安装已有撤销历史时不能伪装为首次绑定，重新开通必须精确引用当前安装同一供应商的已撤销旧绑定并创建新绑定 |
| 固定原因 | 撤销只接受`subject_replaced`、`supplier_authorization_revoked`、`security_compromise`、`instance_revoked`；重新开通只接受`replacement_approved`、`supplier_reauthorized`、`security_recovered` |
| 实例撤销 | 单个本地事务把实例和全部活动主体改为撤销，级联停用查重摘要并阻止新操作；密文历史、身份操作和密钥版本不删除 |
| 明文边界 | 密文附加认证数据绑定安装标识、绑定号、供应商、密文格式和密钥版本；同步回调返回或异常后清零明文缓冲，输入主体和原始幂等键在服务返回前清零 |
| 当前接口 | 只装配内部服务和启动就绪检查；路由表仍只有健康检查与既有安装信息读取，没有主体绑定、撤销、重新开通或读取接口 |

同一身份操作原始幂等键在一个安装内只能用于一个精确请求。换成另一种操作、另一份内容或另一原因会冲突；轮换后仍会使用全部保留幂等密钥版本恢复原结果。

## 4. 数据库与运行时实现

迁移`013-local-supplier-subject.sql`新增四个本地表：

- `idc_gateway_local_supplier_instance`保存当前数据库可见的安装生命周期；
- `idc_gateway_local_supplier_subject`只保存主体密文、随机数、格式、密钥版本和追加式绑定历史；
- `idc_gateway_local_subject_lookup`保存各保留查重密钥版本对应的不可逆摘要；
- `idc_gateway_local_identity_operation`保存不含主体原文和原始幂等键的追加式操作结果。

部分唯一索引、复合外键、检查约束和触发器共同阻止重复活动绑定、跨安装或跨供应商引用、无效重开来源、活动实例之外的新主体、虚假身份操作、历史更新和物理删除。启动时只为当前安装创建本地实例，并为最多两个供应商的活动主体补齐新保留版本查重摘要；检测到第三条异常活动主体时失败关闭。

运行时新增必填`LINAPRO_COMPLIANCE_GATEWAY_SUPPLIER_IDENTITY_KEYRING_FILE`。数据库 DSN、安装标识、进程认证密钥环和供应商主体密钥环必须是四个不同的绝对路径；Windows 上路径比较不区分大小写。就绪检查同时要求三套主体密钥族均有活动版本。

运行依赖由`localRuntime`统一拥有。`buildLocalRuntime`在启动迁移和数据库连接完成后只读取一次主体密钥文件，构造一份`Ring`和一份`Service`，分别保存在`localRuntime.supplierIdentityKeyring`和`localRuntime.supplierIdentity`。服务复用同一个启动数据库连接池、当前安装标识和密钥环，不在请求路径临时调用`New`，也不通过全局查找器取服务；`Ready`复用这份实例检查三套活动密钥，`Close`统一清除内存中的密钥材料。

## 7. 规则与影响审查

- 已读取并遵守`AGENTS.md`、插件边界、OpenSpec、文档、架构、后端 Go、API、数据库、数据权限、测试、开发工具与国际化规则；插件目录没有更近的`AGENTS.md`。
- `API`与数据权限：本轮没有新增`HTTP`接口、请求 DTO、响应 DTO 或权限入口；近期完整登录和精确权限仍明确留给`10.6.c.3`，因此没有把内部服务误当作可直接调用的管理功能。
- `i18n`：没有新增运行时页面、菜单、接口文档源文本或语言资源；运维能力以中英文镜像运行说明交付，命令参数保持跨平台稳定标识。
- 缓存：主体、唯一性、撤销和幂等全部以本地 PostgreSQL 与私有密钥环为权威，没有新增缓存。
- 性能：每实例最多两个活动供应商主体；启动补摘要为一次有界查询和每主体最多八个摘要写入，没有随客户数或历史记录数线性装配。
- 跨平台：新增工具使用 Go 标准库，不依赖 PowerShell、Shell 或`CGO`；Windows 与 Linux 无`CGO`构建均已实际通过。Unix 私有文件拒绝组和其他用户权限，Windows 依赖安装目录访问控制。

## 9. Lina 审查结论

本轮按任务边界审查 26 个文件，并再次核对共享工作区状态；其他未提交文件、`web-customer`和旧 Portal 均未纳入修改。插件目录没有更近的`AGENTS.md`，`apps/lina-plugins`当前也不是独立 Git 工作区。

审查中发现数据库原先允许在主体仍活动时直接把查重标记改为已撤销，数据库层的防重复约束可能因此被绕弱。迁移触发器现已要求父主体先处于已撤销状态，并新增真实 PostgreSQL 绕过测试。审查同时补齐异常回调清零测试、调用方不得留存明文的契约说明、文件职责注释和运行依赖来源记录。修正后没有遗留严重问题或警告。

本任务有内部可执行行为变化，因此已用单元测试和真实 PostgreSQL 集成测试覆盖成功、冲突、绕过、轮换、撤销、重开和异常路径。它没有新增或修改页面、路由、用户可见交互、`HTTP`接口或 E2E 资产，故不触发 E2E 质量审查与截图验证。插件虽启用`i18n`，本轮没有运行时文案或接口文档源文本变化，双语运维文档已成对维护，不新增翻译资源。

本地网关最近的`go.mod`不依赖 GoFrame，它是已经冻结的安装本地独立进程，沿用自己的`database/sql`迁移边界；本轮没有修改宿主 API、GoFrame Controller、DAO、DO、Entity 或代码生成输入，因此不执行`make ctrl`或`make dao`。发布工具为跨平台 Go 工具，Windows/amd64 与 Linux/amd64 的真实组件包及逐文件哈希均已验证。
