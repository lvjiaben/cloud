# 第三阶段客户数据基础验证记录

## 范围与结论

- 本记录覆盖任务 3.1 的数据基础：个人与企业资料、联系人、地址、开票资料、等级、分组、标签、自定义字段、同意证据、备注、跟进、附件、黑名单和风险记录。
- `003-customer-account.sql`包含 23 张插件自有表、136 个数据库`CHECK`约束和 54 个显式索引；其中新增的中英文分组/标签候选复合索引使用`CREATE INDEX IF NOT EXISTS`，没有跨插件外键，也没有访问宿主或其他插件的内部表。
- 本阶段同时交付了客户本人基础资料查询和修改的领域服务，用来验证数据模型、所有权门禁、幂等与审计事务闭环；后台管理、法定资料变更复核、注销、导出和完整客户接口仍分别属于任务 3.2 至 3.7，不能据此视为完成。
- 独立审查在真实`PostgreSQL`中复核全部表、约束、字典、生成类型、索引计划和服务事务，最终结论为`P0=0`、`P1=0`、`P2=0`。

## 数据模型与留存边界

| 数据组 | 表与关键边界 |
| --- | --- |
| 法定资料 | 个人和企业资料分表保存；认证状态进入`verified`时要求案件号、认证时间和全部必要法定资料同时完整 |
| 联系与通知 | 联系人、联系人角色、通知偏好和地址分别建模；角色撤销和资料归档保留历史状态 |
| 经营分层 | 等级、分组、标签及其分配关系使用独立生命周期，不把不同业务语义合并为一个通用关系表 |
| 自定义字段 | 字段、选项、标量值和多选关系分离；类型、客户范围、可见性、敏感级别、长度和数值边界由数据库约束 |
| 证据与运营 | 同意、备注、跟进、附件、黑名单和风险记录保留来源、操作者、状态与时间线，不使用无差别物理删除 |
| 开票资料 | 只保存客户开票抬头与收件资料；税务发票业务、发票开具和腾讯电子签不在本表组内提前耦合 |

23 张表全部使用`plugin_idc_core_`完整前缀，并固定`tenant_id = 0`，落实“一个安装实例只服务一个 IDC 商家”的边界。客户资料引用核心`customer_no`，不创建跨插件或宿主数据库外键；删除、归档、撤销、隔离和匿名化按记录责任分别表达。

## 法定资料与敏感信息

- 个人认证完成必须同时具备法定姓名、掩码姓名、证件掩码、证件检索摘要、认证案件号和认证时间；企业认证完成必须同时具备企业法定名称、登记标识原文、登记标识掩码、检索摘要、认证案件号和认证时间。
- 独立测试逐字段移除上述 12 个必要值，确认任何不完整组合都无法进入已认证状态；完整个人和企业资料能够正常写入。
- 面向普通客户的企业资料投影不返回登记标识原文，只返回掩码值；服务层没有按明文证件号或企业登记号查询的入口。
- 个人证件和企业登记标识的查询索引均以`tenant_id + digest`开头并排除空摘要。对每类表填充 10,000 行后，查询计划仍命中摘要索引，避免按租户扫描全部客户。
- 附件只记录私有对象编号、摘要、大小、扫描状态和可见性；数据库不保存公开下载地址，具体对象访问仍须由后续受控下载能力实施。

## 精确类型与生成代码

- 插件级`hack/config.yaml`显式纳入 23 张新表；同一次`linactl dao`生成流程产出对应公开`DAO`、内部`DAO`、`DO`和`Entity`，没有手写生成文件。
- `NUMERIC(30,9)`及可空数值统一映射为字符串指针，真实数据库往返`123456789012345678901.123456789`时字节级保留精度，不使用浮点数承载金额或高精度配置。
- 可空`DATE`映射为`*time.Time`：数据库`NULL`读取为`nil`，`2040-02-29`按`YYYY-MM-DD`日历语义完整往返，不把纯日期误判为固定时区时间点。
- 可空文本、整数、布尔、日期、日期时间和数值值均使用指针表达缺失，避免把`NULL`静默折叠成零值。

## 字典与国际化

- 本阶段新增 32 个独立字典类型和 136 个稳定字典值；与第一阶段 14 个类型和 54 个值合并后，`idc-core`当前共有 46 个类型、190 个值。
- 数据库`CHECK`内的 46 组稳定枚举语义均与 SQL 字典、中英文`dict.json`逐值对照；`en-US`和`zh-CN`的类型、值集合完全一致。
- 黑名单风险等级和客户风险等级虽有相似值，但保持独立字典，允许两者将来分别演进；发票抬头类型也使用独立的个人、企业字典，不复用客户主体类型。
- 本阶段没有新增前端页面、菜单或`HTTP API`文案。插件新增资源自身通过国际化检查；仓库级门禁仍被禁止修改的宿主页面缺少 6 个既有键阻断，因此任务 3.1 暂不勾选。

## 服务与数据权限验证

- 客户本人读取和更新在进入数据库前先校验当前`customer`受众绑定，并固定使用绑定中的`customer_no`；请求体不能指定其他客户编号，越权对象统一不可见。
- 本人更新只允许显示名、国家/地区和语言等普通资料；客户不能自行修改类型、状态、法定资料、认证状态、等级、分组、标签、风险或黑名单。
- 更新使用版本号进行乐观并发控制，并以“调用方范围 + 幂等键摘要 + 请求摘要”持久化幂等结果；16 路同键并发只产生一次版本推进和一次审计事件。
- 客户更新、幂等结果和脱敏业务审计位于同一数据库事务。审计写入失败时，资料更新和幂等记录一起回滚；相同幂等键改变请求语义时返回冲突。
- 企业法定登记标识原文不进入普通客户投影或审计快照；测试对序列化结果执行了原文泄露断言。
