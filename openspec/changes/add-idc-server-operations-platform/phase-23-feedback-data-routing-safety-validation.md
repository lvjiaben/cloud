## 三轮复审

### 第一轮：真实数据、接口与错误路径

- 核对商品目录、资源池、渠道、服务器和组织数据之间的编号、外键、所有权与路由关系；修复截图型演示数据进入真实流程后失败的问题。
- 用真实 PostgreSQL 覆盖资源池创建成功、目标不存在、越权和事务回滚，确认修复不是前端吞错。
- 扫描服务日志中的`pq:`、参数绑定、对象不存在和插件命名空间错误；修复后本轮运行日志未发现同类错误。

### 第二轮：菜单、抽屉、动态页与响应式体验

- 在真实浏览器检查系统配置目标抽屉、SSL 证书、通知公告、部门管理、供应商容量、上游渠道健康和财务工作台。
- 部门页面显示七条组织数据；容量和健康表格均有固定可视高度；财务五个页签反复切换后页面与表格高度不增长。
- 客户桌面侧栏固定 204 像素且正文不被遮挡；移动端不强塞桌面侧栏。中文状态、菜单与按钮不再暴露内部枚举或英文占位。

### 第三轮：安全、重启与全量门禁

- 客户协助`TC022`覆盖有效口令、失效口令和英文移动端；客户控制台`TC029`覆盖桌面布局、英文移动端溢出与后台自定义外链菜单，合计 6 项通过。
- 执行普通停止、完整生产构建和启动，6030、6031、6032 全部恢复监听；25 个插件无一丢失安装或启用状态。
- 组织表统一为`plugin_org_core_*`，当前数据库有七条部门数据，旧`plugin_linapro_org_core_*`对象数量为零；DAO、SQL、卸载脚本和代码生成配置保持一致。
