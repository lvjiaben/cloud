## 2. 根因与冻结决策

复核发现原有`10.6.b.1`只提供了基础进程密钥环、签名和随机数防重放能力。共享协议已出现部分扩展，但插件签名端、网关处理器、数据库围栏和测试仍使用旧帧或旧表语义，无法同时证明安装实例绑定、服务端固定范围、规范载荷、数据库权威时间和独立业务幂等。继续按旧实现补写会产生多种合理但未确认的协议，因此先暂停并由用户逐项选择。

用户最终冻结以下决策：

- 首次安装由安装器生成`linst_`加 256 位随机安装标识；同实例恢复保留，克隆为新实例重新生成。
- 当前只接线`GET /internal/v1/installation`，服务端固定范围为`installation.read`；腾讯与诺诺业务路由关闭。
- 每个签名帧携带 256 位业务幂等键；读取只持久化随机数围栏，写入同时持久化业务幂等围栏。
- `application/json`按`RFC 8785`规范化并拒绝重复成员；只有服务端声明的非`JSON`路由允许原始字节模式。
- 请求目标只接受唯一规范形式；路径拒绝别名和歧义编码，查询按`RFC 3986`编码后按名称排序且拒绝重复名称。
- 认证窗口由部署显式配置并受 60 秒硬上限约束；签发时间最多领先 PostgreSQL 权威时间 30 秒。
- 生成、轮换和撤销只提供安装器或运维命令行入口，浏览器不接触密钥。

长期结论已经先写入`.agents/rules/user-preferences.md`，并同步到`design.md`、本地合规网关增量规范和`tasks.md`，之后才继续实现。

## 3. 实现证据

### 3.1 安装身份与运维入口

- 密钥工具首次执行时以排他创建方式同时输出私有安装标识和进程密钥环，拒绝覆盖、相同路径和相对路径。
- 轮换保留安装标识与独立业务幂等 HMAC 秘密，只产生新的活动签名密钥；撤销必须伴随已有活动替代密钥。
- 插件签名端和本地网关分别从同一安装的独立私有文件读取安装标识、密钥环及显式认证窗口。
- 组件包配置模板和中英文运维说明包含首次安装、同实例恢复、新实例克隆、轮换与撤销边界。

### 3.2 规范签名帧

- 帧绑定协议版本、安装标识、服务端预期范围、方法、规范目标、载荷模式、规范载荷摘要、业务内容摘要、密钥编号、签发与到期毫秒、随机数和业务幂等键。
- `RFC 8785`处理等价`JSON`表示并拒绝重复对象成员；显式`empty`、`json-rfc8785`和`raw`模式不能互相替代。
- 内部路径必须使用受限 ASCII 唯一形式；查询固定为`name=value`，使用大写百分号编码、编码后名称排序，并拒绝空名称、重复名称、`+`别名、小写百分号编码和非规范顺序。
- 验签使用 PostgreSQL 的`CURRENT_TIMESTAMP`，拒绝过期、超过部署窗口、超过 60 秒硬上限或领先数据库 30 秒以上的帧。

### 3.3 独立持久围栏

- 读取认证事务只写`idc_gateway_process_nonce`，`request_no`保持为空；完全相同帧可以恢复，同一随机数对应不同帧时冲突。
- 写入认证事务先按`installation_id + idempotency_hmac`注册`idc_gateway_local_business_request`，再写关联随机数；同键同规范业务内容恢复原`request_no`，同键改变范围、方法、规范目标或载荷时冲突。
- 数据库只保存随机数摘要、帧摘要、业务幂等 HMAC 和内容摘要，不保存随机数或业务幂等键原文。
- 随机数与业务幂等唯一约束相互独立；读取围栏不会创建伪业务写记录。

### 3.4 首个固定路由

- 插件端`SignInstallationRead`只允许精确`GET /internal/v1/installation`并固定使用`installation.read`。
- 网关端不信任客户端选择范围，以同一固定范围、空载荷模式和规范目标验签；在进入数据库认证前拒绝查询参数和任何请求体，重复认证头、篡改、过期和随机数冲突均失败关闭。
- 成功响应只暴露本地范围、当前活动密钥编号以及`SupplierClientsEnabled=false`、`BusinessRoutesEnabled=false`安全投影。

### 3.5 依赖来源与启动装配

- 运行期依赖 owner 是随安装交付的本地合规网关进程。进程入口通过`LoadConfig`读取当前安装私有文件路径和认证窗口，`Run`在启动期只调用一次`buildLocalRuntime`创建 PostgreSQL 连接池、安装标识和密钥环。
- `Run`把同一个`localRuntime`实例通过`WithLocalRuntime`传给唯一 HTTP 处理器；请求路径只复用该启动期共享数据库连接池和密钥环，不调用`New`临时创建服务图，也不使用全局服务定位器。
- 插件侧`localgatewayauth`是显式构造的签名契约。当前切片提供`LoadFromEnvironment`与`New`，但尚未向插件启动图新增调用网关的运行期服务；后续业务调用方必须在其启动装配中创建并复用同一`Signer`，不能在请求内重新加载秘密。
- 新增的`RFC 8785`库只承担确定性纯函数载荷规范化，不持有运行时状态；`sqlmock`只用于测试，不进入生产依赖图。

## 5. 影响判断

- `i18n`：本任务只修改内部进程协议、命令行运维说明和 OpenSpec 文档，没有新增运行时用户可见文案、菜单、API 文档源文本或语言资源，无资源变更。
- 前端与`E2E`：未修改页面、路由、组件或浏览器工作流，不触发前端或`E2E`用例；已有`web-customer`和官网基线保持不变。
- 数据权限：新路由仅是同机进程认证后的本地安装安全投影，不接收租户或操作者身份，不暴露业务数据列表；后续供应商业务接口仍需独立执行精确权限和数据范围门禁。
- 缓存一致性：没有新增缓存、派生状态、订阅状态或节点内权威快照；时间、随机数和业务幂等均以当前安装 PostgreSQL 为权威，无缓存规则变更。
- 性能：每次认证使用一个串行化事务、一次数据库权威时间读取、一次有唯一键保护的围栏写入，冲突恢复最多追加一次精确唯一键查询；不存在按返回行数增长的查询或`N+1`路径。
- 跨平台：私有文件权限在 Unix 强制拒绝组和其他用户访问，Windows 依赖受限安装目录权限；Windows 与 Linux 无`CGO`组件包均已真实构建。
