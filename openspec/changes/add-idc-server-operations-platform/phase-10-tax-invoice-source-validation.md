# 第 10 阶段发票来源能力验证记录

## 记录范围

- 日期：2026-08-17
- 对应任务：`10.11.a`
- 本记录只证明核心插件已经向合规插件提供安全、只读、当前客户隔离的发票来源能力。
- 本记录不证明发票申请已经落库，也不证明后台审核、供应商提交、退款红冲、客户页面或诺诺真实接入已经完成；这些分别属于`10.11.b`及后续任务。

## 已冻结的业务规则

- 客户可以保存多个常用发票抬头；申请时选择其中一个，本次申请冻结所选抬头的准确版本。
- 客户可以选择一张或多张已付款账单，并分别填写本次开票金额；每笔金额不得超过该账单的剩余可开票金额。
- 浏览器只能提交账单编号、所选抬头编号和每张账单的本次申请金额，不能提交税额、税率、税收分类或销售方主体。
- 每项含税金额、未税金额和税额都由服务端根据订单或续费时已经冻结的税务事实计算。
- 客户提交后的下一状态固定是待后台审核；申请落库与状态机属于`10.11.b`，本任务没有提前实现。

## 实现与边界

### 核心插件拥有的公开能力

- `idc-core/backend/cap/taxinvoicecap`定义发票来源公开契约、有限投影、调用上限和启动声明。
- 该能力只允许调用方插件 ID 为`idc-compliance`。
- 抬头列表投影不包含银行秘密引用，并且列表查询本身也不读取银行秘密引用；只有准备具体申请时才读取客户所选的那一条抬头记录。
- 银行账户只向合规插件提供不透明的本地秘密引用，不提供明文。

### 启动装配与依赖来源

- 核心插件启动时声明唯一发票来源工厂；合规插件启动装配冻结该声明后加载，运行期间不能替换。
- 工厂从宿主授权能力构造当前登录主体读取器，并使用安装实例共享数据库实例；没有在请求方法里临时创建独立服务图。
- 当前客户身份来自宿主授权上下文，浏览器不能指定客户编号。
- 核心插件只读取自己的客户抬头、商家主体、已付款账单、账单明细、退款分配、订单税务事实和续费价格快照。
- 合规插件未来通过`AllocationUsageReader`返回已占用开票额度；核心插件没有读取合规插件内部表、DAO、模型或服务。
- 合规插件已在`plugin.yaml`和`go.mod`声明对核心插件的明确版本依赖。

### 数据权限与金额安全

- 抬头和账单查询都在数据库条件中绑定当前客户编号，不先查全量再在内存过滤。
- 提交准备阶段按稳定排序锁住所选账单行，拒绝其他客户、未付款、已取消、重复选择、金额小于等于零、超过剩余额度和混合币种。
- 已退款金额和既有开票占用会同时扣除；逐项占用必须与总占用一致。
- 拆分账单沿不可变来源链回到原订单或续费价格快照取得税务事实。
- 金额分摊使用整数运算并检查溢出；舍入余数按稳定顺序补到仍有容量的最后项目，保证总含税金额始终等于未税金额加税额。

### 性能边界

- 常用抬头最多`50`条、账单候选最多`50`条、单次选择最多`20`张账单、合计明细最多`200`项。
- 列表路径使用固定次数的批量查询；提交准备路径使用固定次数的批量查询和一次合规占用读取。
- 不在账单或明细循环中执行数据库查询，也不逐项调用其他插件。
- 所有数据库查询只选择当前投影所需字段，没有`SELECT *`。

### 排查过程中的非本任务失败

- 顶层`go.work`当前未包含这些插件，所以插件测试必须显式使用`GOWORK=off`；这不是用跳过测试替代验证。
- 使用容器主机名`postgres`时，本机无法解析；使用容器凭据连接本机 PostgreSQL 时认证失败。最终改为只在测试进程内读取本地开发配置，真实 PostgreSQL 用例通过，且连接内容没有写入文件或输出日志。
- 曾对核心插件全部“真实数据库可选用例”统一注入同一 DSN，暴露了其他既有测试夹具缺少合同策略新列、内容中心拒绝默认`public` schema、通知测试缺少宿主字典表等独立问题。这些失败不在本任务文件和职责内，没有通过修改无关模块掩盖；本任务自己的真实 PostgreSQL 用例与两个插件的正常完整回归均已通过。
- 排查中发现身份服务公开宽接口未直接声明`CurrentCustomer`，启动装配已改为显式能力断言，缺失时安全失败。
