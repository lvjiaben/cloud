# 资源任务执行协调器验证记录

## 完成范围

本轮完成任务 8.5.c.1，只交付可测试、尚未注册生产作业的 Provider 写执行与`QueryTask`观察协调器。任务 8.5.c 和 8.5 顶级项继续保持未完成；资源映射最终收敛、无任务号`QueryResource`核对、脱敏证据持久化、秘密句柄孤儿补偿、具体能力参数编排、跨 owner 回报和`pluginhost.Jobs`启动装配仍在 8.5.c.2。

- 协调器显式注入完整任务服务、冻结 Provider 构造函数和 resource owner 批量资源映射解析器，不访问运行期全局注册表。
- 写任务先解析权威上游资源号，再构造对应启用渠道的 Provider；除开通外，映射缺失或请求校验失败时不会发出上游写请求。
- 资源解析或 Provider 构造失败能够证明“尚未调用上游”，合法的已知未接受错误能够证明“上游拒绝请求”；只有这两类结果可在尝试预算内进入`retry_wait`。
- 原始 Provider 错误、超时、不合法返回、任务或资源编号不匹配都转换为固定脱敏的`result_unknown`，原始错误文本不会进入任务持久层。
- 协调器使用领取时由 PostgreSQL 计算的租约到期时间安排下一次尝试或观察，应用节点时钟不会改变租约判断。
- 写结果通过完整`OperationResult.ValidateFor`校验；输出秘密只允许开通、重装或控制台能力规定的策略，最多 16 个且名称唯一。
- 上游已返回任务号但省略资源号时，任务绑定沿用写请求中已经解析并校验的权威上游资源号；上游返回冲突资源号时冻结为结果未知。
- 任务状态、上游任务绑定、输入秘密撤销和输出秘密引用在同一个任务租约事务提交。输出表只保存`secretcap`不透明引用、策略和可选到期时间，不保存明文。
- `QueryTask`查询失败或返回不合法结果时只释放观察租约并延后查询；合法结果继续由现有持久层精确核对任务号与资源号后原子收敛。
- 每轮最多领取 32 条；领取和秘密输入装配继续使用固定次数集合查询，外部调用数量受批次硬上限约束。

## 依赖注入记录

- `resourcetask.Service`所有者是 resource 插件启动时构造的`resourcetask.Store`，生命周期为插件运行期单例。
- `ProviderConstructor`的生产来源固定为启动期冻结声明后构造的`composition.ProviderRuntime.Construct`。
- `ResourceResolver`的生产来源必须是 8.5.c.2 实现的 resource owner 映射服务；一次接收完整有界批次，并按本地资源号、渠道号和资源池号集合化解析上游资源号，除开通外不允许缺失结果。
- 协调器实例最终只能由 resource 插件启动装配创建并传给`pluginhost.Jobs`托管作业；当前因映射、最终收敛和补偿边界未完成而没有注册生产 worker。

## 验证结果

- 单元测试覆盖：正确构造外部资源请求并转交秘密输入、已接受结果保存任务绑定和输出秘密、原始错误转固定未知结果、已知未接受错误按预算重试、查询失败安全重排、终态观察收敛，以及输出秘密的状态、能力、策略和唯一性门禁。
- 真实 PostgreSQL 隔离 schema 测试验证：迁移可重复执行；已接受任务的上游绑定、输入秘密撤销、输出秘密引用与任务状态同事务持久化；随后`accepted → running → succeeded`观察收敛继续通过完整租约栅栏。
- 资源任务单元测试连续 20 轮随机顺序通过，资源插件全后端测试通过。

## 影响判断

- `API`：没有新增或修改 HTTP API、DTO、路由、权限标签或公开响应。
- 数据权限：这是 resource owner 托管作业内部边界，固定处理本插件任务；未新增任何接收用户任务编号、资源编号或渠道编号的查询/执行入口，也未绕过对象可见性校验。
- SQL：没有修改迁移、表、字段、索引、Seed 或 Mock 数据；只使用既有任务秘密绑定表保存输出引用，因此无需重新生成 DAO/DO/Entity。
- 缓存：没有新增缓存、快照、失效路径或进程内权威状态；任务与租约仍以 PostgreSQL 为准。
- `i18n`：没有新增用户可见文案、错误响应、API 文档、菜单、字典或翻译资源。
- 开发工具与跨平台：没有修改构建、生成、CI 或脚本；验证使用现有 PowerShell、Go 和 OpenSpec 入口。
- 测试与 E2E：没有页面或用户可观察前端变化，不触发 E2E 与 Chrome 页面验收；内部状态行为由单元测试和真实 PostgreSQL 集成测试覆盖。
- 性能：数据库领取和秘密输入保持集合化；每轮任务数硬限制为 32，整批只调用一次映射解析，同一渠道只构造一次 Provider，每个任务输出秘密硬限制为 16，不存在随未限定结果集增长的数据库装配循环。

## 剩余门禁

- 以集合化查询实现本地资源到上游资源的权威映射解析，并把开通同步成功或任务终态成功与映射、服务回报原子收敛；映射完成前不得把当前协调器注册为生产 worker。
- 对没有上游任务号的`result_unknown`调用`QueryResource`只读核对，无法证明结果时进入人工接管，不重复写请求。
- 持久化经过白名单和大小限制的 Provider 证据，并为秘密 sink 已成功但任务事务失败产生的孤儿句柄提供可审计补偿。
- 完成开通、续期、暂停、恢复、开关机、重启、重置密码、控制台、重装、变配、换`IP`和终止的具体参数编排及跨 owner 回报。
- 通过 resource 插件启动装配创建协调器并用`pluginhost.Jobs`注册托管作业，不自行启动根级 goroutine。

## 完成后审查

按`lina-review`对任务状态机、未知结果、秘密边界、数据装配和启动可用性重新审查。审查发现两项实现问题并已在本轮修复：一是上游已返回任务号但省略资源号时，最初实现没有把请求中已核验的上游资源号带入绑定；二是逐任务资源解析接口会诱导随批次数量增长的数据库查询。修复后改为请求资源号回填、整批一次映射解析和每渠道一次 Provider 构造，并增加回归测试。复核未发现当前 8.5.c.1 完成范围内仍存的 P0/P1；生产作业装配仍受上述 8.5.c.2 门禁明确阻止，不把待实现能力降级成审查通过。
