用户提供的旧魔方财务连接器在`DcimCloud.php`中精确证明：先从`GET /clouds/:id`取得实例`node_id`与当前`iso`，候选使用`GET /node_isos?id=:node_id&type=node`并遍历`data[].info[]`的`id/name`；挂载和卸载分别使用`POST/DELETE /clouds/:id/iso`且表单字段为`iso`。`2026-08-12`尝试通过用户授权 Chrome 对真实`3.9.14 beta`生成文档作第二来源逐项只读核对时，文档页面交互超时；没有据此伪造额外响应字段或任务号语义，实施以可定位旧连接器证据和受控假服务为准。浏览器只发生文档页面操作，没有调用任何线上 ISO 或实例写接口。

## 实现边界

- `server.virtual-media`声明为`conditional`，只公开`action=mount/unmount`和条件使用的`image_ref`。挂载只接受两个字段，卸载只接受`action`；未知字段、调用方卸载编号和`force`在认证前拒绝。
- 挂载前读取一次实例详情，要求`node_id`有效且当前`iso=0`；随后读取一次节点 ISO 分组，分组数和全部候选都受 10,000 全局硬上限保护，逐项编号必须合法且目标编号唯一。任何已有挂载都必须先显式卸载。
- 卸载前读取一次实例详情并要求当前`iso`为正整数；适配器把该真实编号映射为请求表单，不相信调用方旧编号。未挂载实例不会发送写请求。
- 挂载只发送一次`POST /clouds/:resource_ref/iso`，卸载只发送一次同路径`DELETE`，表单均为`iso=:observed_or_requested_ref`。
- 写响应携带真实`taskid/task_id`时返回`accepted`。没有任务号的 2xx 普通成功或空响应、`401`及传输歧义都只读回查一次实例详情；仅当`iso`精确等于挂载目标或卸载后的`0`时返回成功，否则保持不可重试的结果未知。明确`400/403/404/405`保持确定失败。
- 每个调用最多一次写入；写`401`只失效旧令牌，回读可以安全刷新令牌但不得重放写入。

## 测试与规则域

受控 TLS 假服务覆盖挂载/卸载精确方法、路径、表单、节点 ISO 查询、任务号受理和同步回读。失败路径覆盖未知动作、缺少/多余字段、`force`、隐式替换、未挂载卸载、目标缺失/重复/畸形、普通成功无法证明、写`401`不重放和传输断线后精确回读。测试自包含且可乱序运行，不访问生产 Provider。

- 架构与插件：实现闭环在源码 Provider 适配器，只消费`resourcecap`既有公开契约；没有宿主修改、新抽象或服务定位。
- 性能：挂载固定两次写前读取、一次写入，无任务号时一次回读；卸载固定一次写前读取、一次写入，无任务号时一次回读。调用次数不随 ISO 数量增长，候选有全局 10,000 硬上限，不存在逐项远程`N+1`。
- 数据权限：没有新增公开 HTTP 入口；`ResourceRef`仍必须由资源拥有方按本地资源与渠道映射后传入，客户/后台权限和数据范围入口尚未实现。
- API、数据库、缓存、前端、E2E、开发工具与运行时`i18n`：无影响。没有路由、DTO、SQL、缓存、页面、运行时文案、脚本或工具变化；中英文技术`README`同步维护。
- 安全：没有隐式替换、陈旧卸载引用、批量或强制路径；歧义写绝不重放，只有真实任务号或精确后置状态可收敛。
