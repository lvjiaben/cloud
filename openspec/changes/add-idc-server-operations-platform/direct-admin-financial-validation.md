# 后台人工财务操作简化验收

## 用户确认与范围

2026-10-18，用户确认“**一起简化，有操作权限即可处理**”。本次采用`lina-feedback`的`openspec-existing`路径，实施任务为`DIRECTFIN1`至`DIRECTFIN3`。当前权威业务结论记录在偏好主题`33`、`35`、`37`和`38`的当日替代条款。

取消人工充值、赠送、扣减、账单减免与营销价值入账、冲正的强制第二人流程；后台财务、授信与退款处理不再强制额外认证，相关原因和证明材料选填。客户授信申请保留一次有对应权限员工的业务决定。原申请人有处理权限时可以完成历史待办；不自动批量批准历史记录。

## 根因及实现

- 原币种复核策略缺省即要求复核，营销价值操作另外强制复核。新操作直接通过既有不可变调账和账本所有者入账，不再读取旧阈值决定是否等待。
- 原服务与数据库同时禁止申请人与处理人相同。新迁移`133-direct-admin-financial-actions.sql`同步修改相关约束与信用校验函数，保留历史申请、审批、账本及其证据。历史授信已有第一票时，原审批人可以完成激活且安全重试。
- 人工说明缺省时保存机器动作原因和操作请求摘要。证明引用保持空值，不伪造外部付款证明；有输入时继续校验格式。人工收款结清验证接受缺省材料。
- 后台页面直接提交当前动作，不再先请求重新认证凭证；旧凭证入口保留，主动提供凭证时仍验证其绑定。客户支付及还款的认证边界未改变。
- 营销直接入账、冲正与权益投影、审计在同一事务提交，重放不生成新账本交易。
