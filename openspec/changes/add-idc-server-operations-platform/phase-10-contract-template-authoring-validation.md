# 第十阶段合同模板本地编辑与腾讯提交门禁验证记录

## 结论

`10.8.c.2`的本地合同模板编辑能力已经在`idc-compliance`插件内实现并通过真实 PostgreSQL、Go 门禁、插件构建、类型检查和真实 Chrome 验证。管理员可以使用在线编辑器或上传`.doc`、`.docx`、`.pdf`、`.html`正文，保存新的不可变正文修订，生成带哈希的不可变`PDF`，主动确认预览，再把固定变量和双方签章位置拖入`PDF`页面并保存。

本项仍不勾选完成。腾讯当前公开接口可以上传“模板用途”文件，但没有公开把该文件、签署方和控件组合成企业可用模板的创建接口；企业模板管理只支持删除、启用、停用和只改名称的复制。因此“提交腾讯”继续明确失败关闭，本地草稿不会被伪装成腾讯模板，也不能启用。全仓双语和全量 E2E TypeScript 编译还另有本项之外的既有阻断。

页面归属没有变化：IDC 合同模板编辑器只在`apps/lina-plugins/idc-compliance/frontend/`，通过插件机制显示在 LinaPro 管理后台；`apps/lina-vben/apps/web-antd/`没有本项 IDC 业务改动。客户合同与签署页面仍由`10.12`直接进入`apps/lina-vben/apps/web-customer/`。

| 预览确认 | 管理员必须打开并主动确认精确当前`PDF`；任何新正文或新`PDF`都会清除旧确认和当前字段指针。 |

## 本轮发现的真实问题

真实 PostgreSQL 首次执行“保存在线正文”时失败。根因是服务端计算下一条正文修订号时，用了只适合结构体或列表的数据库读取方法来接收单个数字；GoFrame拒绝该类型，随后公共错误被安全映射成“服务暂不可用”。此前只有 HTML、字段和加密算法单元测试，没有跑通完整正文数据库工作流，所以页面和局部测试没有暴露该问题。

修复后改为读取单个数据库值，再转换为下一修订号。新增真实 PostgreSQL 工作流验证以下完整链路：

1. 创建本地草稿并保存在线正文修订。
2. 使用同一请求键重试不生成重复修订。
3. 生成严格校验的一页`PDF`并追加新的源文件加`PDF`修订。
4. 以查看权限解密并核对精确当前`PDF`摘要，写出后立即清空内存字节。
5. 主动确认预览，保存客户手写签名和商家企业印章。
6. 服务端判定本地内容和签章位置就绪，但腾讯提交仍不可用，直接启用被拒绝。
7. 切换为上传`PDF`后追加第三条正文修订，旧预览确认和当前字段指针失效；旧修订和字段记录仍保留。
8. 私有对象只包含认证加密信封，不出现正文或`%PDF-`明文。

## 尚未通过的门禁

- 外部能力：腾讯当前公开契约不能完成本地正文到企业模板的创建，因此真实“提交腾讯”没有实现，`10.8.c.2`不能完成。
- 全仓双语：此前全仓检查仍被`idc-core`、核心业务错误翻译和`web-antd`通知预览既有缺口阻断；本轮没有新增用户文案，合规插件合同语言包中英文键仍保持一致。
- 全量 E2E TypeScript：此前仍被本项之外的资源模拟、宿主角色测试和宿主字典测试类型问题阻断；本项定向编译和 5 条真实 Chrome 用例通过。

这些阻断不授权修改`web-antd`、不允许伪造腾讯成功，也不妨碍继续开发不依赖真实模板提交的第十阶段后续任务。

## `2026-08-22`官方资料复核

腾讯最新官方资料仍只形成“上传模板用途文件”和“管理已有模板”两段能力，没有公开把上传文件、参与方、填写控件和签章控件组合成一个新企业模板的创建接口：

- [上传文件](https://cloud.tencent.com/document/api/1323/73066)明确允许`BusinessType=TEMPLATE`并返回短期文件资源号；这只证明模板用途文件可以上传。
- [企业模板管理](https://cloud.tencent.com/document/api/1323/117837)仍只提供删除、启用、停用和复制，复制只能改名称，其他模板内容必须到腾讯控制台处理。
- [API 概览](https://cloud.tencent.com/document/api/1323/70378)仍未列出从上传文件创建企业模板的接口；文件直接发起合同和使用已有模板发起合同是另外两条流程，不能冒充模板创建。

因此`10.8.c.2`的本地编辑部分继续有效，真实“提交腾讯”仍受外部接口能力阻断，`10.8.c.2`、`10.8.c`保持未勾选。
