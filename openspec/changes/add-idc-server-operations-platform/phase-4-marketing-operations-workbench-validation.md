# 第四阶段营销运营工作台验证记录

## 范围

本记录覆盖任务`4.10.a`：`idc-core`后台只读营销运营总览、独立精确权限和 LinaPro 中英文工作台。分群、活动、券、积分及赠送/返现权益的分页管理和写操作，以及曝光、订单、实收、退款、成本和净收益等效果数据源仍属于`4.10.b`，因此`4.10`顶级任务保持未完成。

## 实现证据

- `backend/internal/service/marketing/marketing_management.go`提供专用聚合读模型。一次请求在`READ ONLY + REPEATABLE READ`事务内固定执行 5 次本地 PostgreSQL 查询，返回非货币汇总、数据库快照时间、逐币种权益分桶、最近 12 条活动和最近 12 条权益，不调用 Provider 或其他远程服务。
- 投影最多包含 128 个显式币种并限制为 512 KiB。服务端校验大写三字母币种、非负计数和金额、活动时间窗、最近记录时间及响应大小；构造器拒绝普通和有类型的`nil`依赖。
- `backend/internal/service/marketing/marketing_management_authorizer.go`在任何营销数据读取前验证默认商家、直接非代理身份、活动员工、可表达的数据范围及精确`idc:admin:marketing:overview`权限；平台管理员和宿主通配权限沿用宿主授权语义。
- `GET /admin/marketing/overview`只返回有界业务投影和 Unix 毫秒时间，不返回数据库主键、原始营销条件、外部凭据或秘密。积分字段保持非货币数量，赠送与返现只在各自币种的整数最小货币单位内汇总。
- 运行期依赖来源完整闭环：`backend/plugin.go`在启动装配层复用宿主共享`BizCtx`、`principal`、`Authz`和`g.DB()`创建授权器与读服务，再显式传入唯一后台控制器；服务和控制器构造器都拒绝普通或有类型的`nil`并返回初始化错误，请求路径不会临时创建服务图。
- `frontend/pages/marketing-management.vue`提供分群、活动、券资产、积分、营销同意、逐币种权益和最近记录的响应式运营视图，具有加载、失败、空数据和刷新状态；中文和英文资源镜像维护。插件版本提升为`v0.1.28`。
- `TC003-marketing-operations.ts`使用同一有界总览接口覆盖中文经营信号、人民币与美元隔离、刷新无瀑布请求和英文切换。

## 审查结论

- 授权先于持久化读取；只读总览不会创建首位员工身份。真实页面验证使用明确的本地测试员工夹具，测试完成后没有把该旁路写入生产代码。
- 所有金额均按币种分组，页面不展示跨币种总金额；积分与金额使用不同投影和文案。
- 数据库查询次数不随币种、活动或权益记录数增长，最近记录、币种数和响应字节均有硬上限，没有前端逐行补查。
- 审查补强了有类型`nil`依赖拒绝以及汇总、金额、时间窗的防御性校验。当前切片未发现未解决的阻断项。
- 接口审查补齐所有响应字段的英文`dc`、真实`eg`和简体中文`apidoc`翻译；`en-US/apidoc`按治理规则保持空对象，英文直接使用 DTO 源文本。

## 规则域影响

- 架构与性能：只读聚合闭环在业务插件内，固定 5 次本地查询且不修改宿主源码，不引入缓存。
- 数据权限与 API：新增独立精确权限和有界聚合接口；客户、代理、跨商家和不支持的数据范围失败关闭。
- 数据库：只读现有营销表，没有新增迁移、Seed、Mock、软删除或生成模型。
- 前端与测试：新增 LinaPro 插件页面、菜单、双语资源和`TC003`，完成真实浏览器验证。
- `i18n`：新增菜单、错误消息和页面中英文镜像；业务枚举通过前端稳定键本地化，不显示原始技术字段。
