# 第十阶段完整独立交付边界纠偏记录

## 用户确认

软件提供方自营环境与购买方环境是同级安装实例。每个购买方获得相同的完整程序并独立运营，包括业务插件、本地合规网关、数据库迁移和第三方适配器；各安装方使用自己的第三方供应商账号、凭据、主体、额度和结算关系。

软件提供方与购买方之间只保留软件授权、升级和支持关系。商业授权码只控制软件使用权、允许版本、插件范围、有效期和升级权益，不得承载实名、合同、发票、支付或其他业务流量。

## 根因

原设计在研究腾讯电子签第三方应用和诺诺`ISV`模式时，把供应商可能存在的平台应用模式扩大成了 LinaPro 自己运营的中央业务服务，并继续派生出销售记录注册、跨客户实例身份、统一主体绑定、业务回调转发、平台预付/后付额度和中央结算。这一推导与“自营加完整程序销售”的产品边界冲突，也把尚未设计的商业授权码与业务网关身份错误地拆成了两个持续依赖。

## 冻结后的交付边界

- 每套系统交付并运行自己的合规网关进程、数据库、迁移、配置和运维能力。
- 每个`IDC`商家配置或授权自己的阿里云、腾讯电子签、诺诺或替代供应商账号，并直接与供应商结算。
- 腾讯电子签由购买方使用自有企业账号、第三方应用、凭据和主体正常对接，腾讯当前官方公开接口作为实现依据；软件提供方不再为全部购买方统一取得腾讯商务确认，购买方实际版本、实名、接口权限、白名单、增值服务和套餐改为每套安装的运行时失败关闭门禁。
- 第三方不允许购买方以自有主体和应用独立接入时，对应适配器保持关闭或更换供应商，不得自动改为软件提供方中央代接。
- 第三方回调直接进入当前商家控制的公开地址或网络入口，不经过软件提供方转发。
- 本地插件与本地网关的进程间身份在安装环境生成，不依赖销售记录、远程注册令牌或软件提供方网络服务。
- 已实现的幂等、防重放、限流、熔断、回调收敛、主动查询、结果未知保护和人工接管可以在本地所有权边界下复用。
- 平台销售绑定、远程实例注册、跨客户路由、平台操作者权威、预购/后付额度、统一价格发布和购买方结算账本停止继续实现。

## 并行存在的用户端交付纠偏

当前仓库仍保留`idc-portal/portal`旧前端源码、`dist`、独立前端构建与锁文件，以及插件内`TC001`至`TC010`测试资产。此前误建的 Nuxt`web-customer`已迁到`apps/lina-websites/sites/default/`作为默认官网迁移基线，`apps/lina-vben/apps/web-customer/`已按`web-antd`母版重建为 Vben/Vite 应用；这些事实只证明结构纠偏和基础构建通过，不证明页面迁移、动态官网包运行时、端到端测试、发布或安装包验收完成。该问题不属于本地合规网关代码改造，但同样影响“每个安装方获得一套完整且一致程序”的交付边界，必须继续由`FB-10`、`FB-12`和任务`15.12`至`15.17`跟踪，不能因本阶段集中处理网关而遗漏。

迁移必须先在`web-customer`完成页面、客户端适配、测试资产和构建发布接线，并通过结构一致性、类型、双语、路由隔离、真实浏览器及迁移回归；官网的服务端渲染和`SEO`门禁单独在`apps/lina-websites/`验证，不适用于 Vben/Vite 客户后台。上述目标全部通过后，才能删除插件内旧源码、生成物、构建配置、锁文件、测试副本和只服务旧静态壳的实现。正式安装包不得同时交付两套可编辑用户端源码，也不得在迁移验证前提前删除旧实现。任务`10.5`的完整交付清单与任务`15.12`的用户端迁移验收必须交叉核对。

## 对既有证据的处理

第十阶段此前关于平台中央部署、销售记录注册和中央结算的验证记录只证明当时实现的技术不变量，不再证明当前产品需求符合性。后续实现和审查必须以本记录、当前`proposal.md`、`design.md`、`specs/idc-local-compliance-gateway/spec.md`和`tasks.md`为准。

在完成任务`10.4`至`10.7`的代码、数据模型、构建、安装和测试纠偏前，不得把原`central-gateway`实现标记为完整私有化交付能力，也不得继续完成原平台结算管理任务。

## 影响分析

- `i18n`：本次只纠正规范和交付边界，不修改运行时文案或语言包；后续配置向导改造需要同步中英文资源。
- 缓存一致性：本次无缓存实现变化；后续本地网关不得依赖软件提供方中央缓存或共享状态。
- 数据权限：本次把业务权威收敛到当前安装商家；后续改造必须删除软件提供方平台操作者和跨客户实例访问路径。
- 开发工具跨平台：本次不修改构建脚本；后续必须验证本地网关随完整安装包在 Windows 与 Linux 构建、安装和运行。
- 测试：本次使用`openspec validate`和静态冲突扫描验证；后续需要补充完整安装包、本地断网、商家自有凭据、直接回调和软件提供方业务服务不可用场景，并由任务`15.12`证明用户端迁移后不存在第二套旧 Portal 源码或构建产物。
