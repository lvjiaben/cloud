# 第六阶段信用管理接口与安全门禁验证记录

## 交付结论

任务`6.11.e`的功能实现和任务内审查已经完成，`idc-core`版本提升至`v0.1.51`。本切片把既有信用政策、申请、账户、账单与客户余额还款权威服务接入后台和客户 HTTP，并保持两个入口的身份、响应和命令边界完全隔离。任务仍暂不勾选：仓库级`i18n`强制门禁被禁止修改的宿主通知预览页 6 个既有缺键阻断；顶级任务`6.11`还另有`6.11.c.2`在线支付与经审核人工收款资金 owner 生产接线缺口。

## 接口与权限边界

- 客户入口提供信用概览、申请列表与提交、账单列表与详情、余额还款凭证和余额还款七组接口。请求不接收`customerNo`，所有权在任何数据库目标查询前从当前活动客户主体派生；返回投影不包含后台客户编号、员工审批证据或私有风险资料。
- 后台入口提供申请列表/详情/复核凭证/复核、账户列表/详情、账单列表/详情、政策凭证/配置十组接口。申请、账户和账单分别使用列表与详情权限，申请复核和政策写入另用动作权限，共八项互不替代的`idc:admin:billing:credit-*`权限。
- 后台授权只接受默认商家内的直接活动员工、非模拟身份和可表示数据范围。权限检查发生在筛选解析和目标存在性读取之前，避免用校验差异探测无权对象。
- 客户和后台列表均使用 AES-256-GCM keyset 游标，游标绑定入口、所有者、筛选条件和页大小；单页最多 50 项。信用概览最多 64 个币种账户，账单详情每页最多 100 条不可变明细，并只返回最多 100 条还款摘要及明确截断标记，不返回昂贵总数。
- 后台账单投影固定隐藏客户可用余额和余额还款资格；客户账单投影只读取同客户、同币种的账本余额，并扣除有效资金占用后再给出可还款判断。

## 高风险命令与业务审计

- 信用政策配置、信用申请复核和客户余额还款均采用“签发精确预览凭证—执行时重新授权并单次消费”的两阶段流程。凭证绑定直接身份、当前会话、默认商家、动作、目标和完整规范化意图，要求宿主最近完整登录；修改金额、币种、日期、决定、证据摘要、请求号或目标都会失败关闭。
- 客户申请的客户身份只从登录态派生，风险材料只接受有界私有引用和小写`SHA-256`摘要。后台申请详情不返回该私有引用和摘要，复核服务继续执行申请人与复核人分离及连续双人审批。
- 政策追加、申请复核及其最终开户、客户余额借记与信用账单还款、对应业务审计均在各自同一 PostgreSQL 事务提交；审计失败会回滚业务事实。幂等重放返回原业务结果，改变预览或证据则冲突。
- 坏账核销、坏账收回和信用账户人工恢复虽然已有内部权威服务，但仍依赖独立审批与账本证据所有者。当前不发布这些 HTTP 写入口，避免用通用后台权限或一次确认替代双人审批。

## 查询与实现边界

- 信用读模型只访问`core`本地 PostgreSQL，不调用 Provider、支付渠道或中央合规服务。详情在只读可重复读事务中分别读取账单头、一个有界明细页和有界还款摘要，没有按返回行逐项回查。
- 账户投影验证额度守恒、条款有效期和逾期摘要完整性；账单投影验证头部金额与付款、核销和应收守恒。异常数据库状态返回稳定完整性错误，不向调用方回显 SQL 或内部主键。
- 金额在 HTTP 中使用规范十进制最小货币单位字符串，拒绝符号、前导零、小数与溢出；时间点统一为 Unix 毫秒。客户余额还款只接受正数，政策允许明确的零违约金上限。
- 运行期依赖均由`backend/plugin.go`在启动装配层创建和传递：信用读模型拥有本地数据库、主体解析器、游标密钥及后台授权器；客户与后台命令复用同一启动期`reauth.Service`实例，并分别注入信用审批、额度使用和业务审计 owner。控制器只接收上述接口，不在请求路径临时创建服务或独立防重放状态。
- 本切片没有修改`apps/lina-core`、`apps/lina-vben`、其他插件、根级构建脚本或永久工具脚本；临时接口文档生成程序在资源生成后已删除，因此无永久开发工具或跨平台影响。前端页面与用户可观察交互继续由任务`6.14`交付。

## 影响判断

- 数据库：无新增迁移、表、索引或生成模型；复用既有信用、账本、审计与重新认证表。真实 PostgreSQL 验证确认事务和现有约束有效。
- API 与数据权限：新增客户与后台版本化接口及八项后台隐藏权限；客户所有权优先、后台精确权限与数据范围门禁均有自动测试。
- 国际化：新增客户与后台信用 API 简体中文文档资源、八项后台菜单中英文资源和五类信用稳定错误中英文资源；英文继续使用 API 源文本。本切片消息覆盖已经通过，完整仓库仍有上述宿主前端 6 项既有缺键。
- 缓存：无影响；信用余额、额度、账单、审批和凭证消费继续以权威数据库为准，不新增缓存事实。
- 外部系统：无新调用。客户余额还款只消费本地正式账本；在线支付与人工收款生产接线仍是`6.11.c.2`缺口。
