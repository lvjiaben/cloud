# 开通资源映射收敛验证记录

## 完成范围

本轮完成任务 8.5.c.2.b.1。同步开通成功和带上游任务号的异步开通成功，现在都必须在 resource owner 事务中先收敛权威资源映射，再保存证据并结案任务。8.5.c.2.b、8.5.c.2、8.5.c 和 8.5 继续保持未完成；跨 owner 回报、参数型能力专用对账、秘密句柄孤儿补偿、具体能力参数编排和生产作业装配仍在 8.5.c.2.b.2。

- 成功开通必须携带经过`ResourceQuery`契约验证的上游资源编号，缺少编号时拒绝结案。
- 映射身份固定核对本地资源、渠道、资源池和上游资源编号。已有`provisioning`映射只能在目的地一致且资源编号为空或一致时激活；已有`active`映射只能接受完全相同的幂等结果。
- 没有预留映射时生成随机业务映射编号并直接创建`active`映射；自增主键和自动时间字段继续由数据库与 GoFrame 维护。
- 同一上游资源已经被其他未释放映射占用时，唯一索引拒绝写入，任务成功、证据和映射全部回滚。
- 同步成功的 Provider 证据记为`provider_resource`，任务查询成功的证据记为`provider_task`；普通响应事实先经过数量、类型、引用、摘要、时间和凭据扫描，再进入不可变证据表。
- 上游返回未知、失败或其他非成功结果不会创建或激活开通映射；合法脱敏证据仍可与对应任务结果同事务保存。

## 依赖与性能

- 没有新增运行期依赖、构造函数参数或启动服务。映射收敛复用`Store`已有的数据库和随机源，调用路径固定为`Executor → resourcetask.Service → Store`。
- 同步写和任务观察都在原有单任务租约事务中完成一次映射锁定查询。不存在随批次增长的数据库装配循环；Provider 证据写入数量继续受 32 条硬上限约束。
- 映射冲突由现有“tenant + local resource”和“tenant + channel + external resource”条件唯一索引保护；查询使用本地资源唯一索引定位当前未释放映射。

## 影响判断

- `API`：没有 HTTP API、路由、DTO、权限标签或公开响应变化。
- 数据权限：这是 tenant 0 resource owner 内部租约任务的持久化步骤，不新增用户可调用的数据入口；映射身份来自已锁定任务和已验证 Provider 结果，不接收浏览器提供的对象编号。
- SQL：没有新增迁移、表、字段或索引，复用现有映射唯一索引与 8.5.c.2.a 的不可变证据表；没有重新生成 DAO。
- 缓存：没有缓存、失效路径或进程内权威状态变化。
- `i18n`：没有用户可见页面、运行时文案、API 文档、菜单、字典或语言包变化。
- 开发工具与跨平台：没有修改构建、生成、CI、脚本或平台入口。
- 测试与 E2E：没有页面、HTTP API 或用户可观察前端行为变化，不触发 E2E 与 Chrome 验收；内部事务行为由单元测试和真实 PostgreSQL 验证。
