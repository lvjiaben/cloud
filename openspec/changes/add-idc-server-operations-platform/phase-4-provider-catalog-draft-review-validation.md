# 第四阶段 Provider 商品草稿审核与物化验证记录

> **`FB-52`失效声明：**Provider 商品草稿审核、物化和第二条发布路径已经被现行通用商品模型废止。下文只记录待删除实现和开发数据的迁移对账范围，不能继续写作当前正确验收，也不能保留旧权限、接口、状态或表结构兼容层。商品只能由商家维护并经唯一通用发布服务发布。

## 结论

原`4.14.d.1`、`4.14.d.2`与`4.14.d.3`只代表旧方向曾经实现，现已失效。原审核证据、`provider_import`来源和物化路径不得进入新运行模型。

仓库级`make.cmd i18n.check`仍仅被禁止修改的宿主通知预览页 6 个既有缺失键阻断，因此两个任务暂不勾选。

## 实现范围

- `012-provider-catalog-draft-review.sql`新增补全、必售币种和逐候选处置 3 张表；草稿的`accepted/materialized`状态通过复合外键绑定同一补全目标，物化商品与版本必须精确等于补全目标。
- 税务、履约、风险、兼容性和候选处置均使用受约束的规范值；必售币种使用大写三字母代码。
- 3 类审核证据通过数据库触发器禁止更新和删除，保留追加式事实；复审发现的“只靠服务不提供更新方法仍可直接改表”缺口已在本轮修复。
- 后台审核服务与来源插件的`catalogcap`创建能力分离。接受、驳回和物化必须先经过直接员工受众、精确权限和全局或单商家数据范围校验，来源插件无法调用审核写操作。
- 接受与物化采用固定数量的有界集合查询，校验分类与商品中英文文案、来源快照号和指纹、逐候选决定、启用配置项、兼容规则、每个计费规则和必售币种的基础价/选项价与续费价、至少一个启用的新单资源池，以及税务、履约和风险结论；没有按候选、配置项、币种或价格循环查询。
- 接受、驳回和物化与业务审计位于同一事务。审计失败会回滚状态和证据；商品图在接受后被改坏时，物化会重新失败关闭。
- 正式发布使用独立于审核的精确权限。发布事务锁定目标版本、商品和唯一物化证据，目标版本行作为所有商品子图写服务必须共同遵守的父级并发栅栏，再重新运行同一完整性检查；旧`published`版本、目标版本、商品当前版本指针和业务审计同事务提交。商品当前指针不一致、新版本号未递增、审核后撤销履约池或审计失败都会拒绝或整体回滚。
- DAO、DO 和 Entity 由插件自己的 GoFrame 代码生成配置生成；可空补全号、原因和税率显式映射为指针。

## 任务级审查

- **已修复**：初始数据底座只能通过外键保留补全主记录，币种和逐候选决定仍可被直接更新或删除。现已增加数据库 append-only 触发器，并以真实 PostgreSQL 反向用例验证更新和删除均被拒绝。
- **已修复**：初始发布事务会查找旧`published`版本，但没有同时证明商品当前版本指针指向该版本，也没有要求目标版本号更大。现已把两项作为锁内状态门禁，拒绝覆盖不一致目录或发布回退版本。
- **已修复**：初始证据不可变触发器函数名超过 PostgreSQL 63 字符限制，会被数据库截断。现已改为明确且不截断的稳定函数名，重复迁移验证通过。
- **严重，外部既有阻断**：`apps/lina-vben/apps/web-antd/src/views/system/message/notice-preview-modal.vue`第 16、42、45 行引用的 3 个宿主键在`en-US`和`zh-CN`均缺失。当前工作区没有`.contributing`，本任务无权修改宿主目录，因此不能把仓库级 i18n 门禁标为通过。
- 未发现越权来源调用、物化自动发布、跨草稿或跨版本证据绑定、候选或价格`N+1`、缺价兜底、浮点金额、审核与发布权限混用、审计后置提交或把可变布尔值当完成证据的问题。

## 影响说明

- **API**：无新增 HTTP API；审核和发布服务当前是插件内部边界，两项精确权限在未来对应后台路由和菜单落地时再登记为可分配权限。
- **SQL**：有影响，新增`012`迁移、3 张表、2 个草稿字段、复合外键、索引、字典和证据不可变触发器；迁移重复执行和测试隔离清理顺序已验证，插件卸载 SQL 仍由后续统一卸载任务处理。
- **缓存**：无影响；审核和商品草稿均读取权威数据库，不使用发布缓存。
- **数据权限**：有影响；审核在参数校验和目标数据库访问前完成直接员工身份、精确权限和可表达数据范围校验，暂不支持部门或本人范围。
- **i18n**：有影响；新增 5 类双语字典和 4 个双语业务错误，插件内覆盖通过，仓库级门禁仍受上述宿主既有问题阻断。
- **开发工具**：仅扩展插件内 GoFrame DAO 表白名单和可空字段映射；Windows 的`make.cmd dao`已通过，配置本身不含平台专属命令，Linux/macOS 继续使用仓库等价`make dao`入口。
- **前端与 Chrome**：无前端改动，本任务不需要页面或 Chrome 验收。
- **Git**：未提交、未暂存、未推送。
