# 第六阶段财务便利操作验证记录

## 完成范围

`6.15`中仍属于通用财务核心的能力已在`idc-core`内闭环完成：账单重发只读取客户已验证的开票邮箱并向后台返回脱敏地址；订单、账单和服务内部备注只追加且用新备注表达更正；保存筛选只属于当前员工；账单、交易、调账和应收只生成私有`XLSX`，不提供`CSV`。

FB-52 审查发现，旧批量续费页面让员工手填权益编号，而正式后端因为通用权益没有续费语义始终拒绝执行；旧 E2E 又用模拟成功响应遮住了这个事实。该入口、客户端调用、后台 API、权限、菜单、DAO、建表、文案和模拟成功证明已经撤下。迁移`095-retire-generic-batch-renewal.sql`只在旧表为空时退役错误存储；发现开发证据时失败关闭并要求先导出后重建，既不静默删除也不保留旧兼容接口。批量续费仍是必需能力，但必须由任务 0.13 中真正拥有续费价格、周期、到期日和状态的长期服务插件，通过可续费权益列表勾选来实现，不能由`idc-core`猜测。

后台页面位于插件`frontend/`，没有向`apps/lina-vben/apps/web-antd`写入 IDC 页面、接口、状态、多语言或依赖。客户读模型没有接入员工内部备注、保存筛选或财务导出表。

## 安全与数据边界

- 创建、生成和下载导出时分别重新检查当前精确权限、员工身份和可表示的数据范围；权限或数据范围变化后失败关闭。
- 导出文件保留`24`小时，下载票据单独短期有效，文件名和媒体类型固定为`XLSX`。
- 账单重发命令不接收邮箱地址，只提交版本化通知意图，不把“已提交”冒充“已送达”。
- 内部备注数据库触发器拒绝更新和删除；更正关系仍保留原备注。

## 问题原因与修复

整插件首次编译暴露两类底层接线问题：公共商品目录与售前支持接口曾被放在同一生成目录，导致控制器接口不匹配；财务操作装配传入了过窄的权限与续费接口。现已拆开`public`和`supportpublic`接口所有权，并让运行时构造函数返回实现本来就具备的完整接口，没有扩大公开 HTTP 能力。

浏览器回归还发现人工收款弹窗测试标记放错位置、确认框依赖不稳定样式类，以及内部状态码直接显示给用户。现已修正稳定定位、弹窗顺序和中英文状态/失败原因显示。FB-52 后续审查又发现通用批量续费属于错误业务所有权和伪测试证明，已按上文撤下并转入任务 0.13。
