# 第十阶段合同状态收敛验证记录

## 1. 任务结论

任务`10.9.b`已完成。每套安装的本地合规网关现在会把腾讯电子签回调和主动查询得到的精确状态，按同一条受保护路由投递给本地合规插件。插件保存只追加状态时间线，并把不同供应商结果收敛为草稿、签署中、完成、拒签、过期、撤销、失败和解除等本地合同状态。

本切片没有实现后台“重新发起”和“解除”操作，也没有归档最终`PDF`、签署报告或证据文件。这些仍分别属于`10.9.c`和`10.9.d`；整组回归属于`10.9.e`。因此`10.9`父任务保持未完成。

## 2. 状态收敛结果

| 腾讯状态 | 本地流程结果 | 普通合同结果 | 安全原因 |
|---|---|---|---|
| `INIT` | 签署中 | 签署中 | 流程已经建立 |
| `PART` | 签署中 | 签署中 | 已有部分签署方完成 |
| `WILLEXPIRE` | 签署中 | 签署中 | 即将到期但尚未终止 |
| `ALL` | 完成 | 完成 | 全部签署完成 |
| `REJECT` | 拒签 | 拒签 | 签署方拒绝 |
| `DEADLINE` | 过期 | 过期 | 签署期限结束 |
| `CANCEL` | 撤销 | 撤销 | 流程被撤销 |
| `INVALID` | 失败 | 失败 | 流程失效 |
| `EXCEPTION` | 失败 | 失败 | 供应商流程异常 |
| `RELIEVED` | 解除流程完成 | 解除 | 只允许合法解除流程收敛 |

`RELIEVED`出现在普通签署流程时不会直接把合同改成解除，而是进入冲突对账。客户接口继续只显示“处理中、已完成、失败”三个安全结果，不向客户暴露腾讯原始状态；因此本任务没有改变已冻结的客户页面文案和交互。

## 3. 回调、主动查询和只追加时间线

- 回调与主动查询都保存腾讯原始精确状态、供应商时间、网关观察时间、来源、路由版本、本地投影、安全原因和处理决定。
- 时间线表禁止更新和删除；数据库唯一约束保证同一路由版本只能形成一条本地事件，同一投递号不能被其他事件复用。
- 同一路由版本重复到达时恢复原结果，不重复推进合同或重复写审计。
- `INIT → PART → WILLEXPIRE`只允许向前推进；迟到的较早非终态保留为“过时”，不能倒退。
- 已有终态遇到相同终态时记为“过时”；遇到相反终态时记为“冲突”，不能按最后到达覆盖。
- 客户主动点击重新检查时，如果本地网关已经掌握终态、但后台定时任务尚未消费投递，网关会返回精确终态快照，插件可以立即补齐本地状态。真实投递仍按网关决定处理，不能借客户请求绕过冲突保护。
- 主动查询失败只保留当前安全状态，不伪造完成或失败，也不调用供应商写接口。

## 4. 本地独立运行和权限边界

- 本地合规插件与本地网关使用安装时生成的进程认证凭据通信。待处理列表使用带精确`limit`查询的签名`GET`，确认已消费使用带独立写范围和业务防重放围栏的`POST`。
- 每次读取都使用新的短期关联号；列表最多返回`50`条，网关使用一次有界关联查询装配页面，插件处理完整页后才一次确认。
- 本地网关只接受当前安装、当前供应商和合同操作范围的数据，确认时再次核对安装、供应商、操作范围、投递号集合和业务围栏。
- 客户主动重新检查前先按当前登录身份和默认租户查询该客户自己的合同，再使用合同已经保存的不透明本地路由；不能通过合同号或路由号读取其他客户数据。
- 没有中央业务网关、中央结算、软件提供方业务回调、平台销售注册或平台操作者接管依赖。每套安装使用同一套组件，自行配置腾讯账号并独立运行。

## 5. 数据库与性能证据

插件迁移`016-contract-status-timeline.sql`完成以下内容：

- 为合同流程增加受约束的腾讯精确状态和网关路由版本；
- 新增完整插件前缀的只追加合同状态事件表；
- 为路由版本、投递号、合同时间线和流程时间线建立唯一约束或索引；
- 使用数据库触发器拒绝修改或删除既有事件；
- 迁移在真实 PostgreSQL 中逐文件执行两次，结果一致；DAO、DO 和 Entity 均由项目代码生成入口重新生成，没有手改生成文件。

本地网关迁移`020-tencent-contract-status.sql`为路由和加密证据保存精确腾讯状态，并更新单调状态保护触发器。审查时发现该脚本直接重跑会遇到已有字段和约束，已经补充存在性保护和安全约束替换；真实 PostgreSQL 测试现在会直接再次执行第`020`号脚本证明可重入。

定时消费每分钟只在主节点运行一次，单批上限固定为`50`。网关列表是一次有界关联查询，确认是一次集合更新；插件按每条法律时间线独立事务提交，规模不会随数据库总行数无限增长，也没有列表逐行远程补查。

## 6. 依赖来源检查

- owner：合同状态时间线和本地合同投影由`idc-compliance`拥有；供应商回调、查询、进程认证和本地投递由同插件交付的本地网关拥有。
- 创建位置：插件启动装配读取当前安装的共享数据库、本地网关客户端和系统审计能力，创建一个合同状态服务实例。
- 传递路径：同一服务实例同时注入客户合同重新检查和主节点定时任务；定时任务不在执行时临时创建服务图。
- 共享策略：本地网关客户端、进程签名器、数据库和审计能力均复用启动期实例或共享后端。没有新增进程内缓存，也没有缓存一致性影响。
