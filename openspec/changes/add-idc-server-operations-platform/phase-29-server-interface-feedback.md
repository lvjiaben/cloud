## 上游商品导入继续实现

用户进一步确认无法完整识别的配置可以导入为未上架草稿，必须列出缺项，管理员补齐且通过既有校验后才能发布。分类必选、名称默认沿用上游、公开地址自动生成可修改；加价填写`10`表示成本增加百分之十，金额按币种最小货币单位四舍五入。上游基础价、配置附加价和未提供完整价格必须分别展示，不能以起步价冒充整机总价。

实现分别由商品拥有方完成原子草稿、绑定、来源证据及幂等保存，由资源拥有方提供只读目录，由财务版和`V10`连接器声明安全投影。参考源码中没有通用硬件字段映射，因此只明确填写上游商品选择，其他字段保留待补。前端两个交付入口共享真实 Vben 导入表单；手填售价保留小数字符串，后端完成金额计算。同一次未改内容的重试复用提交键，不重复创建商品。

新增`TC013`只读分页、搜索、价格及恢复回归，`TC014a/b/c`覆盖分类必填、加价失败重试、多条手填售价及英文缺项。首次浏览器验证发现测试只按回车，而 Vben 默认并未启用回车提交；修正为点击真实搜索按钮，不通过修改业务交互迁就测试。最终整套七项通过，卡片分页和下拉定位最后变更另经定向复测；当前后端、真实隔离数据库及官方门禁通过，`FB-113`按[导入收口验证](phase-29-catalog-import-validation.md)关闭，真实外部供应商门禁不随之关闭。

最终真实目录复核又定位到统计投影错误收紧渠道编号：资源拥有方允许二百五十六字节内的安全不透明名称，但统计只接受`CHN_`，开发库中四条合法名称记录因此使整页失败。修复只将只读统计校验对齐拥有方既有契约，保留员工授权、商家范围、集合上限和参数化查询；不放宽自动化绑定、供应商执行或修改历史数据。增加混合编号及非法字符边界测试，并重新请求真实列表确认。

## 流量包缺口与需求门禁

当前仓库不是完全没有流量包：`idc-core`已有按类型和币种发布附属价格的`GET/PUT accessory-prices`接口，客户服务器详情已有输入`GB`、报价确认、创建待付账单的入口，`idc-zjmfcloud`已有向有限流量实例增加临时流量的适配器。仅这些局部代码存在不能证明功能可用。

只读核实的当前缺口如下。

- 后台前端没有调用`accessory-prices`的配置页面。没有适用的已发布价格时，报价失败关闭，但动作目录没有提前按价格可用性过滤，客户仍可能先看到购买入口再报错。
- `serveroperation_accessory_checkout.go`将付费附属操作停在`awaiting_financial_settlement`，仅免费分支建立执行记录。`plugin.go`正式装配的`fulfillment.NewRoutedConsumer`只调用通用商品结算消费者，没有附属操作分流。
- 附属订单项将`InventoryDecisionCode`设为`manual_confirmation`，通用消费者`validateFrozenItem`要求`available`。当前路径不能推进原流量操作；不得通过把库存标记改成可用来绕过此问题，否则可能误走新商品开通流程。
- 当前流量安全投影只有基础、临时和总额度，客户页尚无真实已用量及重置时间，不能自行推算有效期或承诺永久有效。
- 当前仅魔方云连接器有条件支持临时流量追加。财务版、`V10`、`DCIM`和宝塔不能因为套餐页面上线就被视为已经支持；上游另行购买流量包可能产生另一笔交易，须独立核实契约和收费授权。

魔方参考源码`app/admin/controller/DcimController.php`的流量包管理提供名称、固定容量、总价、启停、库存、适用商品和销售记录；客户侧按服务器与套餐创建账单。它是参考行为，不是本项目已确认规则。其自动解除暂停行为与本项目既有“不自动开机或解除暂停”要求冲突，不予照搬。

用户在本轮回复“可以”，确认采用固定容量套餐、按商品指定可用套餐、有效期跟随上游并在购买前提示。结论已同步用户偏好与生命周期增量规范；不保留客户自由填写`GB`计价的旧入口，也不新增本地独立有效期。库存限量、套餐删除语义和上游无法提供准确重置日期时的售卖处理尚需结合已有规范核对，不得从参考系统隐式继承。

付费结清分流可以独立恢复：按持久化的原附属业务操作、报价、订单和账单关联识别，验证财务拥有方权威结清证据后幂等建立原服务器执行记录；不得通过修改库存判断把附属订单放入通用新购履约。该恢复不依赖套餐页面布局或库存策略，测试只能使用隔离对象，不操作既有客户资金或上游服务器。

进一步核对确认，魔方云已冻结契约只提供基础流量和临时流量，不提供可验证的周期、时区或下次重置时间。目录的五分钟过期只表示缓存新鲜度，不能作为套餐到期；参考系统的`reset_flow_day`推算和主动重置代码不构成上游自动重置承诺。用户已明确允许在此情况下购买，但必须在购买前展示“有效期按上游重置规则执行，暂未提供具体到期时间”。随后用户确认每个套餐可以设置不限量或限量库存，已售套餐下架后保留订单与购买记录；相关销售设置可以继续实施，不提供删除销售历史的入口。

结清恢复采用财务拥有方只读证据契约，复用其现有持久化来源摘要、金额守恒和唯一事件校验；消费者不得通过调用`SettleOrder`创建资金事实，也不得自行削弱验证。只读依赖在插件启动期注入同一数据库后端，原客户或员工身份保留在结账审计中，异步执行追加系统业务事件和不可变交付回执，不伪造员工请求上下文。

用户随后确认限量套餐生成待付款账单时占一份，未付款订单取消或超时关闭完成后释放，已付款订单保留占用。库存释放依赖权威关闭结果，不因发起取消或付款结果未知提前释放。实现复用现有订单和附属操作事实，不另造资金台账或把流量包交给服务器新购库存处理。

用户进一步确认后台填写总可售份数，已占用与剩余由系统计算，剩余最低为零；调低总量不修改或撤销既有购买。实现采用套餐根记录行锁串行化同一套餐结账，按附属操作事实集合统计占用；取消通过原订单完成事件交由附属操作拥有方更新投影，未确认关闭不得释放。价格、容量、名称和适用商品追加不可变版本，旧订单继续引用原版本；列表按页查询并批量装配，不逐套餐查询。

价格配置缺失、付费结清断链和真实执行幂等必须重新验收。旧`phase-8-accessory-pricing-settlement-validation.md`只代表历史版本，不能用于标记当前`FB-114`完成；本轮未付款、未调用上游写接口、未查询或改写实际价格数据。

随后完成了独立的本地结清衔接补丁：非库存快照、财务只读证据、原服务器分流、重复事件幂等、生成模型及查询索引均已通过局部验证。真实隔离数据库链测试从客户结账、余额付款到原服务器唯一执行记录，但该阶段还没有浏览器验收，精确范围见[附属结清局部验证](phase-29-accessory-settlement-validation.md)。

最终收口继续补齐后台套餐管理、客户购买和员工代下单，并在正常重启后完成后台`4/4`、客户`2/2`、员工`2/2`浏览器回归；真实 PostgreSQL 完整`serveroperation`包、取消释放库存直接断言和魔方云连接器`TestTrafficPackage*`全部通过。未执行真实客户扣款或真实上游写操作，完整边界见[固定流量套餐入口验证](phase-29-traffic-package-entry-validation.md)；`FB-114`据此完成。
