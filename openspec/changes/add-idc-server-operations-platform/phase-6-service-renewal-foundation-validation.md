# 阶段 6.5.a 服务与续费数据底座验证

> **`FB-52`失效声明：**本记录依赖旧`service_instance`、通用资源渠道与资源池续费模型，原结论已经失效，不能作为当前续费完成证据。现行权威事实是长期`service_entitlement`及其冻结插件契约；续期支持、到期管理、业务拥有方和模式必须在创建权益时冻结，一次性交付没有续费入口。下文仅用于旧表、旧字段和开发数据迁移对账，不保留兼容层。

## 交付边界

- 在`idc-core`新增服务实例、不可变服务价格快照、价格构成、续费策略、统一业务操作和操作事件六张表。
- 服务实例只拥有客户权益和本地运行投影；渠道、资源池与 Provider 任务仅保存 resource owner 的不透明引用，不复制资源映射或上游证据。
- 新购价格快照冻结已有不可变配置与报价来源；续费价格快照额外冻结原到期日、预计新到期日、续费模式和能力证据。
- 本切片不发布 HTTP、页面或 Provider 调用，手动续费、余额自动续费和跨 owner 执行分别由`6.5.b`、`6.5.c`继续实现。

## 核心不变量

- `provider_confirmed`要求明确渠道和能力证据；`local_entitlement`只允许续费且同样必须携带明确的不支持能力证据；未知能力使用人工处理而不能伪装成本地续费。
- 服务价格头和完整构成必须同事务提交，构成数量以及基础/规格、优惠和税额分别与头部小计、优惠和税额精确一致。
- 服务价格、价格构成、续费策略和操作事件不可修改或删除；业务操作的客户、服务、币种、价格、路由、能力证据和幂等摘要不可改写。
- 原始幂等键不进入数据库，业务操作仅保存 SHA-256 摘要；同客户、同操作类型和相同摘要只能对应一个操作。
- 服务详情、到期扫描、资源投影、操作工作队列和历史读取均有匹配其筛选与稳定顺序的索引，不依赖逐行补查。
- 金额只使用`BIGINT`最小货币单位，币种必须是大写三字符代码，不提供跨币种兜底。

## 数据权限、性能与多语言结论

- 数据权限：本切片没有 HTTP、动态插件或终端用户入口，不产生新的可探测业务数据路径。后续客户续费接口必须只从当前客户主体派生服务所有权；后台入口必须另设精确权限和可表达数据范围。
- 性能：服务历史、价格构成和操作事件分别设置 5000、5000 和 1000000 的持久化硬边界；高频查询均使用服务、客户、状态、到期时间和稳定主键的组合索引。后续列表与调度仍须使用有界集合查询，禁止逐服务访问 resource 或 Provider。
- 多语言：七组数据库字典均有中英文镜像和真实 PostgreSQL 逐值一致性测试；本切片没有运行时用户文案或前端交互。
- 缓存：无影响。服务权益、价格和业务操作全部以 PostgreSQL 为权威源，本切片不引入缓存。
- API、前端与 E2E：无影响。本切片没有新增路由、DTO、页面或用户可观察行为；对应验证由`6.5.b`、`6.5.c`和`6.9`承担。
