# 第八阶段资源 Provider 能力与路由收口记录

## 范围

本记录证明`8.4.b`和`8.4`完成，不代表`8.2`、`8.5`或第八阶段整体完成。

## 完成内容

- `resourcecap`提供精确版本的 Provider SPI、声明期 registrar、不可变快照、最小`ProviderEnv`、参数与结果校验、秘密回调、安全日志指标和安全 HTTPS 客户端。
- 源码 Provider 只在资源拥有方进程内构造。渠道未启用、声明不兼容、秘密范围不符或安全网络环境无法建立时，不创建客户端、不领取新写任务。
- 动态插件只获得`resource-read/v1`的本地只读能力目录，不能取得 Provider、秘密、端点、原始载荷或写方法。
- `pluginhost.HTTP`与`pluginhost.Jobs`各自读取同一份只写后冻结声明；HTTP 只验证并装配运行图，不创建渠道客户端，Jobs 把惰性 Provider 工厂显式注入库存、主体和资源任务 worker。
- 资源拥有方只返回启用渠道下、资源类型匹配的启用资源池候选，并用渠道版本和资源池版本生成不可伪造的修订摘要；提交时精确复核。
- 核心本地路由按优先级与稳定权重选择兼容资源池。开通前允许切到可售备用池，资源已经创建后固定原渠道、资源池和上游编号，不因后台新单策略变化迁移。
- 开通、续费、生命周期和普通服务器操作都冻结完整请求摘要；相同请求重放复用同一任务，改换服务、渠道、池、动作、参数或版本一律冲突。开通终态另保存唯一回执，任务、映射和脱敏证据在资源拥有方事务内收敛。

## 验证结果

- 资源插件`GOWORK=off go test ./backend/... -count=1`：全部通过。
- 资源插件 Provider 契约、bridge、启动装配、候选池和开通终态回报在本机隔离 PostgreSQL及乱序模式执行 10 轮：全部通过，用时约 17 秒。
- 核心库存路由和资源池策略测试随机顺序执行 100 轮：通过；覆盖优先级、稳定权重、未知库存、停新、开通前故障转移、开通后固定和畸形投影拒绝。
- 资源插件独立`golangci-lint`：`0 issues`；生产包`staticcheck`：通过。
- OpenSpec 严格校验在任务更新前后执行，均通过。

## 边界说明

- 没有真实调用 Provider，也没有写入既有魔方用户或实例。
- 没有新增前端、用户可见文案、HTTP API 或 SQL 迁移，因此本收口无新增前端、i18n、API 和数据库变更。
- `8.5`具体服务器能力参数与附属能力编排仍按其子任务继续，不因基础能力与路由收口而提前完成。
