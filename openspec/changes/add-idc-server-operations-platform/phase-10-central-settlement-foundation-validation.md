# 第十阶段中央结算底座验证记录

> 状态：本文件只保留历史技术验证证据。软件提供方与购买方之间的预付、后付、价格和结算模型已被[完整独立交付边界纠偏记录](phase-10-independent-delivery-correction.md)废止，不得继续作为产品实现依据。

## 1. 任务范围

本记录对应`10.7.a`，只冻结并实现中央合规网关的本地商家结算数据库底座。范围包括：

- 逐商家、逐币种的预购或获批后付结算账户；
- 发布后不可变的供应商价格版本和一至十六项连续有序价格明细；
- 绑定商家、实例、已认证业务请求、供应商、操作和价格版本的请求级预占；
- 冻结单位价、预计单位数和预计金额的预占明细；
- 绑定脱敏权威证据的实际用量、实扣和释放明细；
- 保存三个资金桶前后值、变化值和精确业务归属的追加式结算账本；
- 数据库层的金额、币种、归属、生命周期、守恒、不可变和幂等迁移约束。

本任务没有实现平台管理服务、商家查询服务、公共`HTTP API`、供应商生产客户端或供应商路由，也没有把结算服务装配到进程运行图。平台操作者授权、价格发布服务、额度入账、后付审批和供应商可用性开关由`10.7.b`实现；实例请求预占与权威结算编排由`10.7.c`实现。

## 2. 结算模型

### 2.1 账户与金额

`idc_gateway_settlement_account`以“`merchant_ref + currency_code`”唯一。币种只接受原样大写三字母代码；所有金额使用`BIGINT`最小货币单位，并限制在`0..9,000,000,000,000,000`，没有浮点、汇率或跨币种兜底。

账户模式在创建后不可变：

| 模式 | 权威资金桶 | 可用边界 |
|---|---|---|
| `prepaid` | `prepaid_available_minor + held_minor` | 只能从已入账同币种可用额预占 |
| `postpaid` | `held_minor + postpaid_outstanding_minor` | 总和不得超过获批限额，且必须有有效期 |

账户必须从零资金桶和版本 1 开始。每次资金桶变化必须版本递增，并把`last_ledger_entry_no`指向同一事务内完全匹配前后值及数据库时间的唯一账本流水；悬空流水和无流水账户改写都会在延迟约束提交时失败。一个账户事务只允许一个最终资金投影，避免多条隐式变化隐藏资金顺序。

### 2.2 价格与预占

`idc_gateway_price_version`绑定供应商、操作范围和币种；`idc_gateway_price_item`保存费用代码、计费单位和正整数单位价。版本先以`draft`创建，价格项插入会锁定版本行，只允许唯一的`draft -> published`转换封口；延迟约束在发布时要求恰有一至十六项且序号从 1 连续到明细数。发布后数据库拒绝再插入、更新或删除明细，也拒绝改写版本头。预占只能引用已发布版本。

`idc_gateway_settlement_hold`通过复合外键同时证明：

- 账户属于目标商家和币种；
- 实例属于同一商家；
- 业务请求属于同一实例和操作范围；
- 价格版本属于同一供应商、操作范围和币种。

预占只能以`held`、零实扣、零释放、无对账待办和版本 1 创建。预占明细必须全部来自头部冻结的同一价格版本，序号连续，总额等于预占总额；每个预占同时必须存在唯一、金额精确匹配的预购或后付预占账本流水。

### 2.3 权威结算和纠正

终态用量要求每条实际单位数不超过预计单位数，实扣金额精确等于冻结单位价乘以实际单位数，并满足“实扣 + 释放 = 原预占”。全部用量明细汇总还必须与预占头的实扣和释放相等。

部分实扣使用一条终态账本变化同时完成实扣和余量释放：预购账户释放差额到可用额；后付账户只把实际实扣转入未结金额。完整未消费使用`prepaid_release`或`postpaid_release`恢复全部预占。结果未知不创建用量明细、不自动实扣或释放，只允许预占继续保持并推进有界对账状态。

价格、预占明细、用量明细和账本流水均为追加式历史，数据库拒绝更新或删除。每次插入关联预占的账本都会重新校验完整预占账本生命周期，因此不能在已有预占后追加第二条预占或多余终态流水。已提交资金事实的纠正使用`prepaid_adjustment`或`postpaid_adjustment`，必须通过同账户复合外键关联原流水，不能自引用或覆盖历史。

## 3. 数据库与性能边界

- 新增当前迭代迁移`006-central-settlement-foundation.sql`，只包含中央独立产品的`DDL`，没有`Seed DML`或`Mock`数据。
- 中央网关不是随商家安装的插件业务 schema，因此延续既有`idc_gateway_*`命名；没有修改商家插件`manifest/sql`或宿主数据库。
- 资金、价格、预占、用量和审计历史不使用软删除。停用、欠费、终止和法定处置必须由后续显式状态或追加事件表达。
- 价格查找、账户状态、账户预占、对账待办、账户流水和请求流水均有与后续查询顺序匹配的组合索引。
- 当前任务没有列表、导出或聚合读取实现，因此不存在运行时`N+1`查询。后续写服务必须锁定单个账户并用一次有界集合写入最多十六条价格、预占或用量明细；读服务必须使用数据库范围过滤、有界`keyset`和集合投影。
- 迁移使用`CREATE ... IF NOT EXISTS`、`DROP CONSTRAINT IF EXISTS`后重建、`CREATE OR REPLACE FUNCTION`及先删后建触发器；测试会在已应用 schema 上直接再次执行最新迁移，证明安全重入。

## 4. 权限、秘密和运行时影响

- 当前没有公共接口、控制器、路由或查询方法，普通安装实例、商家终端客户和后台员工都没有直接读写结算表的生产入口。
- 商家、实例和请求归属由复合外键在数据库层闭合；后续服务仍必须从已验证实例身份或平台操作者权威推导范围，客户端不得提交商家或余额真相。
- 账本只保存用途隔离操作摘要和规范请求摘要，不保存操作键原文、供应商秘密、身份原文或供应商原始报文。
- 没有新增生产 Go 代码、构造函数、运行期依赖、缓存、共享实例或依赖注入路径。
- 没有修改开发工具、构建脚本或跨平台执行入口。
- 没有运行时用户可见文案、菜单、字典、接口文档或语言资源变化，因此本任务无`i18n`影响。
- 没有页面或端到端可观察行为，本任务不触发`E2E`和截图验证；真实 PostgreSQL 集成测试是与风险匹配的验收方式。

## 5. 自动化覆盖

`settlement_migration_test.go`在每个测试中创建随机`linapro_gateway_settlement_*`schema并在清理阶段删除，只触碰隔离测试 schema。覆盖：

- 预购入账、预占、按冻结价格部分实扣、差额释放和关联调整；
- 获批后付预占、按冻结价格部分实扣和未结金额形成；
- 明确未消费后的完整释放；
- 初始非零账户、无价格项发布、发布后追加价格项、无账本账户改写、悬空账本、额外预占流水和直接创建终态预占拒绝；
- 实际单位数超过冻结预计值的终态结算拒绝；
- 价格、预占明细、用量和账本不可修改或删除；
- 全部迁移首次应用、重复`Apply`和最新 SQL 直接重入；
- PostgreSQL 对象名长度、秘密字段静态禁入和非浮点金额静态检查。

## 6. 验证结果

以下命令均针对包含本任务修改的当前工作区执行：

```text
$env:LINAPRO_IDC_COMPLIANCE_GATEWAY_TEST_DSN=<derived in process from local development config>
$env:GOWORK='off'
go test ./internal/migration -count=10 -shuffle=on

go test ./... -count=1

.\make.cmd lint.go dir=apps/lina-plugins/idc-compliance/central-gateway plugins=1

openspec validate add-idc-server-operations-platform --strict

git diff --check

static scans for floating amounts, secret fields, trailing whitespace,
and production settlement runtime wiring
```

最终结果：

- 真实 PostgreSQL 迁移及结算不变量测试随机顺序连续十轮通过，耗时`9.852s`；每个用例只创建并清理随机`linapro_gateway_settlement_*`隔离 schema；
- 中央网关全模块测试全部通过；
- 官方插件模式`golangci-lint`报告`0 issues`，`staticcheck U1000`通过；
- OpenSpec 严格校验通过；
- `git diff --check`没有空白错误，只报告任务范围外既有`Makefile`和`make.cmd`行尾转换警告；任务文件额外尾随空白扫描通过；
- 金额浮点、秘密字段和生产结算运行时装配静态扫描通过。

本任务不会声称供应商套餐余额、生产计费可用或中央结算网络接口已经上线。

## 7. 任务级审查

审查范围为迁移 SQL、迁移测试、中英文中央网关说明、`10.7`设计与规范拆分以及本记录。第一次审查发现两项数据库完整性问题：已发布价格仍可追加明细，以及新增预占关联账本不会反向重检既有生命周期。根因都是约束触发入口覆盖不完整。现已分别通过带行锁的草稿发布封口和账本插入延迟反向校验修复，并用真实 PostgreSQL 反例测试证明拒绝。

最终任务级`lina-review`结论：严重问题`0`，警告问题`0`。分域结论如下：

- 架构：结算底座闭环在独立中央模块，不污染宿主或商家插件运行图；当前无公共接口和供应商调用；
- 数据库：迁移仅含幂等 DDL，无 Seed/Mock、软删除或浮点金额；价格封口、账户与账本双向证明、预占生命周期和追加历史均由数据库约束；中央独立模块使用`database/sql`嵌入迁移，因此不触发 GoFrame DAO 生成；
- 后端与依赖注入：只新增迁移测试，没有生产 Go 服务、构造函数、共享实例或依赖注入变化；全模块测试和官方 lint 通过；
- 数据权限：当前没有生产读写入口；商家、实例、请求、账户、币种和价格归属使用复合外键闭合，后续服务仍必须从已验证实例或平台操作者权威推导范围；
- 插件与宿主：插件本地`AGENTS.md`不存在；中央嵌套模块保持独立交付，未修改`lina-core`或`lina-vben`；
- 文档：中英文 README 同步，OpenSpec 使用中文并记录范围和未实现项；
- 测试：真实 PostgreSQL 用例自包含、随机 schema 隔离、失败清理和随机顺序验证通过；当前无页面或用户可观察流程，不触发 E2E；
- `i18n`：没有运行时可见文案、菜单、接口文档、错误或语言资源变化；双语 README 属文档同步；
- API、缓存、开发工具和跨平台入口：均无影响。

剩余能力明确归入`10.7.b`至`10.7.f`：当前尚无平台管理权威、生产预占/结算编排、商家账单查询、欠费门禁、SLA 或终止治理。上述缺口不由本数据库底座冒充完成。
