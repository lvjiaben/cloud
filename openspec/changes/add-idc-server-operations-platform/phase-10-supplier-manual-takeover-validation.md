# 第十阶段供应商人工接管验证记录

## 1. 范围与结论

任务`10.6.e.4`实现中央合规网关中唯一安全的供应商人工接管动作。平台操作者只能把仍在运行、结果未知或存在终态冲突的路由推进为`manual_takeover/manual_takeover`并永久停止自动查询；请求、权威结果和存储命令都没有目标成功、目标失败或重发供应商写操作字段。

当前没有开放公共人工接管`HTTP`路由。平台权限、精确目标数据范围和近期完整认证由启动期注入的`SupplierTakeoverAuthority`负责，普通员工、商家客户、安装实例与供应商回调均不能绕过该权威。

## 2. 授权、幂等与乐观围栏

- 请求只接受版本化高熵操作键、中央路由号、供应商代码、预期路由版本、六种封闭原因之一，以及 1 至 16 条既有证据号。
- 证据号在授权前排序并拒绝重复；权威必须逐字段返回相同路由、供应商、预期版本、原因和证据集合，并提供平台操作者引用与完整认证时间。
- 接管操作使用专用类型、独立域和 256 位密钥生成 HMAC；当前构造器强制该密钥不得与决定证据加密密钥相同。未来启动装配 owner 必须再对身份生命周期、路由、回调事件等全部密钥用途执行全局不复用检查；本切片尚无生产装配，因此不把尚未接线的全局检查写成已生效能力。规范请求摘要同时绑定操作 HMAC、权威决定、操作者、完整认证时间和全部证据号。
- 存储层先按操作 HMAC 取得事务级数据库互斥，再查精确恢复记录，并使用 PostgreSQL 权威时间重新核对五分钟完整认证窗口和精确路由版本。并发的相同操作键只有请求摘要完全一致时恢复原接管号、决定证据号与投递号；改原因、版本、证据或操作者必须冲突。

## 3. 证据集合与原子提交

- 存储层以一个`ANY`集合查询按证据号稳定排序读取全部证据，并要求数量、编号顺序、路由归属和不可变来源完全一致；跨路由、缺失、重复或接管后新生成的决定证据均不能作为既有证据冒充。
- 证据摘要绑定路由号及每条既有证据的编号、载荷摘要、来源、规范状态、决策码、路由版本和数据库观察时间。关联表使用单次`UNNEST ... WITH ORDINALITY`批量写入，不按证据逐条查询或插入。
- 平台决定本身被封帧并以证据专用 AES-256-GCM 密钥、`manual_takeover`来源和精确路由 AAD 加密；普通表、错误、日志与实例投递不包含自由文本、原始供应商材料或目标终态。
- 路由停止自动化、接管记录、既有证据关联、加密决定证据和版本化实例投递在一个事务内提交。任一步失败均整体回滚，商家业务请求状态不会被接管动作改写。

## 4. 状态安全

- `running`和`result_unknown`可以进入人工接管；`succeeded/failed`只有在`query_required`终态冲突存在时才允许接管。
- 无冲突的成功或失败终态拒绝接管，不能把正常完成对象重新打开为人工任务。
- 接管后路由版本只增加一次，`next_query_at`与活动查询租约全部清除；数据库触发器禁止人工接管再回到自动状态或改写为成功/失败。
- 接管只表达“自动化已停止并需人工核对”，不代表供应商业务事实，也不解除其他合同、发票、资金或履约门禁。

## 6. 规则域与影响

- 架构与依赖注入：权威、专用操作摘要器、证据保护器与存储均由构造函数注入，没有全局授权器或请求期临时服务图。当前没有生产启动装配或公开路由；后续装配必须由单一 owner 创建共享实例，并校验接管 HMAC 密钥与中央网关其他用途密钥全局不复用。
- 数据权限与 API：没有新增可访问 API。平台权威拥有角色、近期完整认证和目标数据范围，存储只接受权威决定并从既有路由推导实例与业务请求归属。
- 数据库与性能：修改当前未发布的`005`迁移，不含 Seed 或 Mock DML；证据读取和关联写入各为一个有界集合操作，最多 16 条，不存在证据循环中的`N+1`数据库访问。
- 安全：决定证据加密，操作键只保存用途隔离 HMAC，平台操作者引用和稳定封闭原因形成耐久审计事实；不持久化权限令牌、会话、自由文本结论或危险目标状态。
- 缓存、前端、`i18n`与 E2E：均无影响。本切片没有缓存、页面、用户可见文案、接口元数据或公共路由，使用 Go 单元测试和真实 PostgreSQL 集成测试。

## 7. 任务级审查

`lina-review`按任务范围审查了`AGENTS.md`、架构、数据权限、插件、后端 Go、数据库、接口、测试、文档、OpenSpec 与`i18n`规则。审查先发现并修复三项问题：验证文档把尚未进入生产装配的全局密钥不复用检查写成已生效能力；HMAC 写入和证据结果集关闭错误没有完整处理；并发相同操作可能在首个事务提交前错过恢复记录并误报版本冲突。当前实现以操作 HMAC 事务级互斥收敛并发重放，新增八路并发 PostgreSQL 回归，且补充接管后主动查询停止与迟到回调不改变投影的验证。

最终复核确认接管请求、权威结果和存储命令都不存在目标成功、目标失败、重发、供应商参数或自由文本字段；生产启动图与公共路由没有装配本服务，商家业务请求表没有接管写入。SQL 为当前未发布的回调对账迭代`005`，只含 DDL，无 Seed/Mock、自增编号或软删除变化；最新 SQL 在隔离 schema 中可直接重复执行。中英文`README`同步描述相同边界。当前严重问题 0 个、警告 0 个。

本切片没有新增生产运行期依赖、HTTP API、缓存、前端、用户可见文案或 E2E 行为，因此没有 DI 启动来源、接口文档、缓存一致性、运行时`i18n`或浏览器门禁影响；未来装配和平台操作者入口仍必须作为后续任务独立审查。

## 8. 剩余边界

- 腾讯与诺诺生产验签器、查询客户端及业务路由继续受精确供应商契约和商务门禁约束。
- 将来若开放平台操作者入口，必须复用本权威并另行完成 API、权限、审计、双语文案和 E2E 设计；不得直接暴露存储服务。
