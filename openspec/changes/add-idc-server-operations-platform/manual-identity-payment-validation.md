# 人工实名付款反馈验收

## 根因与范围

沿用现有人工实名与首次付款规范。后台人工实名投影允许`verified`且`manual_verification=true`、供应商案件号为空，但付款准备的旧数据库约束仍强制案件号非空，导致在线支付准备报错；统一财务结清读取时遗漏人工来源，同样拒绝空案件号，导致余额支付已入账而订单仍待付款。

本轮只修复`idc-core`及`customer-default`。未修改宿主、未改变金额、未伪造认证案件、未取消实名或金额守恒。现有客户中心会话交接路由缺少类型必需的隐藏页标题，补充空标题以通过类型检查，不改变路由流程。

## 实现与边界

- 新增`135-manual-identity-payment.sql`替换付款恢复上下文的就绪约束，允许真实人工实名没有供应商案件号。恢复上下文没有资金或身份授权权威，每次准备和创建渠道支付仍重新读取当前主体、认证、账单和订单。
- 财务结清锁定读取个人、企业的人工来源，仍验证活动主体、认证状态、时间、有效期、归属、风险及全部不可变资金证据。摘要明确包含人工来源；自动认证未增加序列化字段，已有自动认证摘要格式不变。
- 付款入口发现状态过期时刷新实际账单；余额支付后结清异常也刷新已入账金额。已付款账单提示无需重复支付，隐藏重复付款入口，不伪称订单履约已完成。
- 不新增接口、运行时服务或缓存，复用原资金拥有方、主体边界、锁及事务；查询数量固定，未增加逐行调用。约束修改不涉及字段和生成模型，无须修改或生成`DAO/DO/Entity`。
