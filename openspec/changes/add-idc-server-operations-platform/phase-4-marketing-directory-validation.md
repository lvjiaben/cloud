# 第四阶段营销分群与活动管理目录验证记录

## 范围

本记录覆盖任务`4.10.b.1`：`idc-core`后台分群与活动的有界分页列表、类型化详情、四项独立精确权限和 LinaPro 中英文管理界面。本切片严格只读，不包含分群/活动写入、发券、积分调整、权益调整或效果报表；这些内容仍属于`4.10.b.2`和`4.10.b.3`，所以`4.10.b`及`4.10`保持未完成。

## 实现证据

- `backend/internal/service/marketing/marketing_management_directory.go`定义分群列表、分群详情、活动列表和活动详情四项独立权限。授权在输入校验、游标解析和目标存在性查询之前执行，只接受默认商家中的直接活动员工和可表达数据范围。
- 列表使用独立部署密钥派生的 AES-GCM 游标封装`updated_at + id`边界及筛选摘要。游标绑定资源类型、名称前缀、模式/活动类型、状态、目标分群和页大小；篡改、跨筛选和跨资源复用均失败关闭。单页最多 100 项、游标最多 128 字符、响应最多 1 MiB。
- `backend/internal/service/marketing/marketing_management_directory_persistence.go`的每个列表使用一次围绕当前页的集合化 PostgreSQL 查询完成计数投影，没有逐行补查。分群详情在`READ ONLY + REPEATABLE READ`事务内固定 4 次查询，最多返回 256 个条件、4096 个条件值和 20 个快照；活动详情固定 3 次查询，最多返回 512 个适用范围和 512 个权益规则。
- 服务端防御性校验覆盖分群模式与刷新间隔、条件事实/运算符/值组合、快照终态、活动配额、叠加策略、目标快照、适用范围和金额/比例/积分权益互斥组合。响应不含数据库主键、客户个人信息、任意 JSON、上游载荷、凭据或秘密。
- `GET /admin/marketing/segments`、`GET /admin/marketing/segments/{segmentNo}`、`GET /admin/marketing/campaigns`和`GET /admin/marketing/campaigns/{campaignNo}`只返回业务编号、双语名称、Unix 毫秒时间、类型化规则、整数最小货币单位和显式币种。
- `frontend/pages/marketing-management.vue`在既有总览下增加响应式分群与活动管理卡片，支持中英文筛选、前后翻页、空态、错误态和详情抽屉；前端详情调用对路径参数编码，不做逐行补查或金额计算。插件版本提升为`v0.1.29`。
- `TC003-marketing-operations.ts`扩展覆盖目录分页、总览刷新不触发目录瀑布请求、中英文切换，以及分群条件/快照和活动范围/逐币种权益详情。

## 审查结论

- 四项目录权限独立校验，列表权限不能代替详情权限，营销总览权限也不能代替任何目录权限。
- 查询次数只与接口类型相关，不随当前页条目数、条件数、范围数或权益数增长；所有集合和编码响应均有硬上限。
- keyset 游标经过加密认证且绑定筛选摘要，不暴露数据库 ID。名称前缀中的`%`、`_`和反斜杠按字面匹配。
- 活动金额按自己的币种展示，积分不携带币种；页面没有跨币种汇总、换算或兜底。
- 本切片没有状态写入或危险操作，未复用只读权限作为未来写入授权。

## 规则域影响

- 架构与性能：功能闭环在业务插件内；列表单次集合查询、详情固定查询次数，不修改宿主源码，不引入缓存。
- 数据权限与 API：新增四项精确员工权限和四个有界只读接口；客户、代理、跨商家及不支持的数据范围失败关闭。
- 数据库：在既有营销表上增加匹配工作台筛选和 keyset 顺序的幂等索引，没有 Seed、Mock、软删除或自增主键写入变化。
- 前端与测试：扩展 LinaPro 插件页面、双语资源和`TC003`，完成真实浏览器分页及详情验证。
- `i18n`：新增菜单权限、错误、筛选、枚举、详情和状态中英文镜像；业务枚举由前端稳定翻译键本地化。
