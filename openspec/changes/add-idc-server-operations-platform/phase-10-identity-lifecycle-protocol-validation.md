# 第十阶段身份生命周期协议与账本验证记录

## 1. 任务结论

任务`10.6.c.1`已冻结双密钥轮换、用途隔离操作幂等、撤销与主体人工处置边界，并新增中央身份操作不可变账本。该切片只建立协议、密码学摘要和 PostgreSQL 约束，没有开放轮换、撤销、主体绑定 HTTP 路由，也没有调用供应商；执行服务分别由`10.6.c.2`和`10.6.c.3`承接，因此父任务`10.6.c`保持未完成。

## 2. 冻结协议

- 身份生命周期操作键固定为`liop1_`加规范无填充 Base64URL 编码的`256`位随机值。中央使用独立`256`位 HMAC 密钥和`identity-operation-hmac/v1`固定域计算数据库查找值，原文不落库。
- 密钥轮换固定使用版本化长度前缀二进制帧，绑定操作键、实例、当前密钥、当前代次、新`Ed25519`公钥和`256`位随机数。
- 当前私钥和新私钥必须分别签署同一帧；新旧公钥相同、缺少任一签名、代次/实例/密钥/随机数变化均失败关闭。
- 精确请求摘要包含规范帧及两份确定性签名，用于事务提交后响应丢失的相同请求恢复。
- 活动密钥不允许单独撤销后留下无密钥活动实例；泄露活动密钥必须原子撤销实例。人工动作、原因、目标、操作者和证据均使用封闭值，不提供自由文本强制恢复。
- 腾讯和诺诺主体只能来自后续注入的平台开通权威能力；客户端不能提交主体。主体加密、主体查询 HMAC 和操作幂等 HMAC 使用三个独立密钥用途。

## 3. 数据库账本

迁移`002-identity-lifecycle-operations.sql`新增`idc_gateway_identity_operation`：

- 每个操作保存随机业务编号、实例、封闭操作类型、操作键 HMAC、完整请求摘要、公开结果引用、可选新代次、可选供应商、操作者、封闭原因、证据摘要和数据库完成时间。
- 操作类型只允许密钥轮换、实例撤销、密钥撤销、主体绑定和主体撤销；轮换只能由实例身份发起且没有人工原因，其他动作只能由操作者或系统发起且必须有封闭原因。
- 供应商字段只允许出现在主体操作且只接受`tencent_essbasic`或`nuonuo`；轮换结果代次必须大于一，其他操作禁止伪造代次。
- 操作键 HMAC 全局唯一，所有摘要固定`32`字节；账本禁止更新和删除，按实例、类型、完成时间和编号建立有界历史索引。

## 5. 规则域与审查

- 架构、API 与数据权限：新增公共纯密码学协议和中央内部账本，不新增 HTTP、管理接口、列表或数据存在性入口。
- 数据库：新增独立第二条幂等迁移，无 Seed/Mock、软删除或物理删除语义；索引支持按单实例有界审计读取。
- 安全：操作键原文、私钥、主体原文和自由文本均不进入表、事件或错误；用途密钥和签名域明确隔离。
- 性能与缓存：协议内存和账本单行操作固定有界，无缓存和`N+1`路径。
- `i18n`、前端、宿主和开发工具：无影响；没有运行时文案、页面、宿主源码或工具脚本变化。
