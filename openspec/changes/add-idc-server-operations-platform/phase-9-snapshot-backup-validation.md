# 第九阶段快照与备份适配器验证记录

## 完成范围

本记录对应子任务`9.4.c`，只闭环`idc-zjmfcloud`对快照与备份创建、删除、恢复三类写操作的适配器契约，不宣称客户自助、后台操作、对象列表、配额、对象归属或资源拥有方业务编排已经完成。父任务`9.4`继续保持未完成。

旧魔方财务连接器提供了精确请求证据：创建使用`POST /disks/:diskid/snapshots`并提交`type=snap|backup`和`name`；删除使用`DELETE /snapshots/:snapshotid`；恢复使用`POST /snapshots/:snapshotid/restore?hostid=:cloudid`。旧连接器只按通用成功状态判断，没有消费可供资源拥有方查询的任务编号，因此本适配器不会把普通成功标记当成已受理证明。

## 实现边界

- `server.snapshot`和`server.backup`保持独立能力编码，均声明为`conditional`，公开`action=create/delete/restore`以及可选`disk_ref`、`snapshot_ref`和`name`约束。
- 创建只接受`action + disk_ref + name`三个字段。磁盘编号和资源编号必须是无前导零的正十进制编号；名称必须是去除首尾空白后 1 至 128 字节的有效 UTF-8，拒绝控制字符。
- 删除和恢复只接受`action + snapshot_ref`两个字段。任何跨动作多余字段、未知字段、非法编号或非法名称都在认证和网络请求前失败关闭。
- 创建写入前固定读取一次`GET /clouds/:resource_ref`并从`data.disk[]`核对磁盘编号唯一存在；删除和恢复写入前固定读取一次`GET /clouds/:resource_ref/snapshots?page=1&per_page=9999`并核对快照编号唯一存在且对象类型与当前能力一致。缺失、重复、类型不符、超量或畸形响应都不发送写请求。
- 快照创建固定提交`type=snap`，备份创建固定提交`type=backup`；恢复把当前已经由资源拥有方解析的上游资源编号作为查询参数`hostid`。
- 三类写入都只发送一次。只有 2xx 响应中白名单解码得到真实`taskid`或`task_id`，才返回`accepted`；空响应、仅资源编号、通用`status=success`、畸形响应、`401`、超时或连接歧义都返回不可重试的结果未知。
- 上游响应中的密码和其他非白名单字段不会进入标准化结果、证据、日志或持久化载荷。

## 测试覆盖

可控 TLS 假服务覆盖快照创建、备份创建、快照删除、备份恢复的精确方法、路径、查询和表单；覆盖写前磁盘/快照归属及类型核验、目标缺失、重复、类型不符和畸形列表；覆盖顶层与`data`内任务编号解码、任务和资源编号规范化、未知字段、非法条件组合、中英文名称、首尾空白、控制字符、超长名称、非法资源编号，以及 2xx 缺任务号的失败关闭。通用适配器测试继续覆盖写`401`不刷新重放、传输中断只尝试一次、响应大小、证书与主机名核对和原始秘密丢弃。

## 规则域结论

- 架构与插件：变更闭环在源码 Provider 插件，仅使用`resourcecap`现有公开能力；没有修改宿主目录、运行期依赖或服务定位边界。
- 性能：每次动作固定一次上游写请求，没有数据库读取、列表装配、循环调用或`N+1`路径。
- 数据权限：本切片没有新增 HTTP、对象列表或人工动作入口。`ResourceRef`仍必须先由资源拥有方按渠道和资源池映射；对象归属和公开操作授权未完成前不得开放客户或后台入口。
- API、数据库、缓存、前端、E2E、开发工具与运行时`i18n`：无影响。没有路由、DTO、SQL、缓存、页面、用户可见文案、脚本或工具变更；中英文技术 README 同步维护。
- 安全：所有输入有界且失败关闭；任何已发送写操作都不自动重放；没有执行生产写验证，也没有访问或修改线上已有客户、用户或实例。
