# FB-52 0.13 开发数据迁移、重建与对账验证

## 结论

现有开发数据库`cloud_preview_19120`不包含待迁移的服务器订单、服务、履约意图、资源任务或资源映射。数据库中只有一个通用商品草稿和一个通用商品版本草稿，来源为`manual`，因此本轮不需要删除、覆盖或伪造任何开发数据。

如果其他开发数据库仍有旧服务器数据，应复用已经交付的两段能力，不再增加跨插件迁移表或兼容字段：

1. `idc-core`迁移`090-generic-delivery-entitlement-backfill.sql`把能够由完整冻结事实唯一证明的旧订单服务转换为通用交付记录、长期权益和耐久权益事件。
2. `idc-resource`通过`entitlementcreatedcap`重放耐久权益事件，并只在现有资源任务已成功、资源映射仍有效且履约回执一致时，幂等建立服务器权益投影。

这条路径不调用供应商，不重新开通服务器，不扣款，不发通知，也不创建合同或发票。无法唯一证明归属的数据必须停止迁移并转人工导出、核对或重建，禁止猜测。

## 已有能力与责任边界

| 阶段 | 权威拥有方 | 输入 | 输出 | 失败处理 |
|---|---|---|---|---|
| 通用数据迁移 | `idc-core` | 旧订单服务、履约单元和完整冻结履约意图 | 通用交付记录、长期权益、权益事件 | 缺少唯一冻结事实时立即失败并要求导出后重建 |
| 服务器投影重建 | `idc-resource` | 权益事件、成功资源任务、活动资源映射和成功履约回执 | 服务器权益投影 | 任一归属、插件、版本、摘要或资源证据不一致时失败关闭 |
| 对账 | 各拥有方本地只读核对 | 本拥有方权威表和收到的版本化事件 | 计数与逐项差异 | 差异保留并转人工，不直接改另一插件的数据 |

`idc-resource`不得读取或写入`idc-core`表。两个拥有方之间只通过冻结的`entitlementcreatedcap`事件和收据衔接，避免迁移工具绕过插件边界。

## 安全执行顺序

1. 停止开发环境新写入，记录数据库名称、当前迁移版本和插件版本。
2. 使用 PostgreSQL 原生备份保存完整开发数据库；备份文件校验通过前不得开始迁移或重建。
3. 先在备份恢复出的隔离数据库执行全部迁移两次，确认第二次执行不新增记录、不改变冻结事实。
4. 执行`idc-core`通用交付迁移。若`090`报告旧服务缺少唯一冻结履约意图，立即停止；导出该服务、订单、商品版本、履约单元和资金关联后，由管理员决定补齐来源数据还是重建开发库。
5. 由`idc-core`重放仍为待投递或需要恢复的耐久权益事件。不得手工拼接事件，也不得把商品名或分类当成服务器判断依据。
6. `idc-resource`只对`owner_id=idc-resource`的事件执行投影重建。投影必须同时匹配成功任务、活动映射、原上游资源编号、客户、商品版本、接口实例、插件发布版本和契约摘要。
7. 分别在两个拥有方内执行只读对账，再按事件号和权益号合并报告。任何差异保持原数据不动，转人工核对。
8. 只有隔离演练计数和逐项摘要全部一致后，才允许在目标开发数据库重复同一流程。失败时恢复备份，不运行补偿性供应商动作。

## 对账门禁

通用拥有方必须证明：

- 每个符合迁移条件的旧订单服务恰好对应一个通用长期权益。
- 每个订单项最多一个通用交付记录；按数量拆分只体现在冻结履约意图和权益中。
- 客户、订单、订单项、商品、商品版本、币种、计费规则、开始时间、到期时间和状态与旧冻结事实一致。
- 每个需要业务拥有方管理的长期权益恰好有一个耐久权益事件。
- 重复执行迁移时，交付记录、权益和事件数量及内容摘要不变化。

资源拥有方必须证明：

- 每个已接收的服务器权益事件恰好对应一个服务器权益投影。
- 投影对应的资源任务为`succeeded`，资源映射为`active`，原上游资源编号保持不变。
- 客户、商品、商品版本、接口实例、插件发布版本、履约契约版本和声明摘要与权益事件完全一致。
- 重放同一事件只返回同一收据，不新增第二条投影。
- 清空隔离数据库中的派生投影后，重放同一耐久事件可以恢复相同投影；该验证不得在真实开发库直接删除投影。
- 客户归属或冻结证据冲突时拒绝重建，并且既有投影保持不变。

现有核心测试`generic_delivery_entitlement_backfill_postgres_test.go`覆盖旧服务器服务到通用交付记录、长期权益和耐久事件的两次幂等迁移，并验证无法唯一映射的旧服务失败关闭。

新增资源测试`development_server_data_rebuild_postgres_test.go`覆盖：

- 首次建立服务器权益投影。
- 同一耐久事件重复投递恢复同一收据。
- 隔离测试内删除派生投影后重新建立。
- 服务器投影与成功资源任务、活动资源映射、客户和冻结插件证据逐项对账。
