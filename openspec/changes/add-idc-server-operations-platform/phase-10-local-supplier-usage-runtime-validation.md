# 第十阶段本地供应商用量运行闭环验证记录

## 1. 结论与边界

本记录证明任务`10.7.b.2`已经完成本地网关生产装配、持久调度、原子投影和真实 PostgreSQL 验证。本切片没有实现、模拟或启用真实腾讯/诺诺采集器，也没有增加软件提供方中央回退。本记录形成时两者均等待外部确认；`2026-08-14`后腾讯采集器转由`10.8`按官方用量接口和购买方运行时门禁实现，诺诺`10.4.c`仍受外部证据阻断。

`10.7.b`可以由已经完成的`10.7.b.1`与本任务共同形成技术子项闭环，但父任务仍按当前`tasks.md`保持未勾选，不连带勾选`10.7`或`FB-11`。第十阶段下一项可执行任务是`10.7.d.2`。

## 2. 根因复核

原有`internal/localusage`只包含本地数据模型、固定四次的有界读取和测试存储，没有在生产启动图中构造用量服务，也没有采集调度、租约、证据写入、预算告警、对账或`SLA`写入闭环。旧迁移和只读测试只能证明`10.7.b.1`底座，不能证明生产采集完成。

当前实现把这项缺口收敛在每套安装自带的本地网关内：启动时创建本地读取服务和采集服务，保存两个固定供应商的明确启停状态；只有编译进当前产物并在启动期冻结的只读采集器才会启动工作线程。生产构建当前传入空采集器集合，因此两者均为`disabled`，进程仍可独立启动和就绪。

## 3. 冻结的运行规则

| 细节 | 冻结结果 |
|---|---|
| 调度 | 启用后立即执行一次，之后每 15 分钟执行；一次最多领取腾讯、诺诺两个固定供应商 |
| 并发 | 使用 PostgreSQL 时间、`FOR UPDATE SKIP LOCKED`、60 秒租约和 256 位随机租约原文；数据库只保存`SHA-256` |
| 调用边界 | 单次供应商只读调用最长 45 秒；失败按 1、2、4、8、16、30 分钟有界退避 |
| 输入上限 | 一个套餐、最多 200 条用量、最多八条原币种对账、一个`SLA`观测、最多 256 KiB 权威证据 |
| 原子性 | 加密证据、套餐、用量、预算告警、对账、`SLA`和采集状态在同一事务提交 |
| 重放 | 供应商事件编号使用版本化`HMAC`查重；同编号、同完整规范投影恢复原结果，同编号改变内容必须冲突 |
| 预算 | 只计算当前安装显式启用的供应商加原币种策略；零预算是有效显式策略；未配置时不猜测、不告警 |
| 对账 | 只比较同一原币种最小单位；完整证据产生`exact`或`mismatch`，证据不完整产生`insufficient_evidence` |
| `SLA` | 以本地观测窗口、请求数、成功数和延迟生成百万分比快照；不从软件提供方取得业务数据 |
| 失败 | 只保存固定失败分类，保留最后成功投影；采集失败不调用写接口，也不让供应商状态影响本地进程就绪 |

## 4. 依赖注入、数据和独立运行

- 所有者是本地网关`internal/localusage`；`internal/app.buildLocalSupplierUsage`在启动期使用当前安装的共享数据库池、安装标识和回调证据密钥环构造一次读取服务与采集服务，并保存在`localRuntime`中。不存在逐请求构造或全局服务定位。
- 采集器集合在`NewCollectionService`内复制并冻结。生产装配显式传入空集合；`Run`只在`HasCollectors()`为真时启动工作线程，不存在远程开关、中央注册、授权码或软件提供方业务服务依赖。
- 迁移`017-local-supplier-usage-runtime.sql`只新增当前安装的采集状态表、到期领取索引和预算告警唯一索引。迁移是`IF NOT EXISTS`的 DDL，不含 Seed、Mock、自增主键、中央身份、价格、余额、授信或结算数据。
- 本地采集没有公开 HTTP 路由，也没有用户提交动作；当前安装数据库是唯一数据权威。供应商代码只允许`tencent_essbasic`和`nuonuo_invoice`，测试明确拒绝中央供应商值。
- 组件包继续使用同一程序交付。`windows/amd64`与`linux/amd64`真实构建的清单各含 26 个哈希保护文件，均包含迁移`017`；`productPackageRequired=true`、`localInstallationOnly=true`，且`supplierClientsIncluded=false`、`businessRoutesEnabled=false`。

## 6. 审查与影响记录

- `lina-feedback`根因复核确认缺口位于生产装配和写入闭环，而不是既有只读查询；实现没有借旧 Portal、旧测试或第十五阶段证据宣称完成。
- `lina-review`先发现启动构造函数复杂度超过门禁，以及数据库行游标未按规则关闭；已经抽取本地用量构造函数并补齐关闭处理。随后又补齐摘要构造的显式安全写法、导出契约注释和跨进程租约测试。最终人工审查发现一次同时领取两个租约再顺序调用会提前消耗第二个供应商的租约，已改为一轮最多处理两个、每个供应商在开始前单独领取新租约，并增加双供应商回归测试；正式 lint 与全量测试通过。
- `i18n`：没有新增运行时用户可见文案、API 文档源文本、插件清单文案或语言资源；中英文 README 与部署说明保持镜像。
- 数据权限：没有新增列表、详情、导出或写入 HTTP API；所有状态和证据只在当前安装的本地进程与数据库边界内产生，不暴露跨租户或跨安装查询。
- 性能：单轮最多两个供应商、200 条用量、八条对账和一个`SLA`，领取与投影均为集合化有界操作，不存在按返回行发起数据库查询的`N+1`路径。
