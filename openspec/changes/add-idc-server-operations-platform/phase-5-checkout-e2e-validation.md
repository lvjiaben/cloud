# 第五阶段结账整链路 E2E 验证记录

> **`FB-52`部分失效声明：**浏览器时延、实名恢复、金额和重复提交门禁可以保留；只用`starter-cloud`、旧独立 Portal 和服务器固定配置器验证的路径不能证明通用商品结账完成。当前必须在默认官网与 Vben`web-customer`覆盖服务器、`SSL`和手机三类商品，并使用插件声明配置和商品简单库存。

## 场景归属与编号治理

任务`5.11`要求覆盖公开商品到购物车、实名后恢复付款、重复提交单订单、报价变化确认和后台协助订单不绕过门禁。实施对表发现这些场景已按真实前端所有者分布在两个模块：

- 独立 Portal 的`TC007-commerce-checkout.ts`拥有公开商品、配置器、购物车、客户结账、付款准备恢复和客户订单；
- LinaPro 管理端的`TC005-assisted-quotes.ts`拥有后台协助报价、独立审批和协助下单。

原任务文字指定的核心插件`TC003-checkout-order.ts`已与核心插件现有`TC003-marketing-operations.ts`编号冲突。按照 E2E 用例编号在模块内唯一、测试跟随功能所有者的规则，本轮没有复制一份跨端伪测试或制造重复`TC003`，而是复核并增强现有权威用例，再把任务和覆盖矩阵纠正到实际入口。

## 五项验收覆盖

| 原场景 | 权威用例 | 浏览器证据 |
|---|---|---|
| 公开商品到购物车 | Portal `TC-7a` | 从`/products/starter-cloud`打开配置器，点击加入购物车后落到`/account/cart`并显示所选商品 |
| 实名后恢复付款 | Portal `TC-7a` | 首次准备显示实名阻断，点击重新检查后同一上下文进入“可以选择支付方式” |
| 重复提交单订单 | Portal `TC-7a` | 创建订单后按钮锁定；刷新重试同一报价时两次请求复用同一个随机`portal-UUID`幂等键 |
| 报价变化确认 | Portal `TC-7a` | 连续重新核价从`CNY 108.12`变为`CNY 109.12`并显示价格更新，再允许提交 |
| 协助订单不绕过门禁 | Core `TC-5b/TC-5c` | 决定和结账请求不接受证据、状态或已付字段；下单结果显示“人工审核”，结账入口消失，页面不出现已付款、运行中或已开通 |

Portal 同一文件的其余场景还覆盖客户取消、未登录隔离、移动端无横向溢出和完整英文状态文案。后台协助用例继续覆盖密封游标、精确大金额、服务端审批证据和双人审批提示。

## 本轮增强

后台协助详情此前直接展示订单内部状态码`manual_review`。本轮改为复用现有`plugin.idc-core.commerce.orders.status.*`双语资源，中文显示“人工审核”、英文显示“Manual review”；没有新增平行状态词典。核心插件版本由`v0.1.40`提升到`v0.1.41`。

`TC-5c`在协助订单返回后新增三项可见断言：订单号与“人工审核”同时展示、协助结账按钮消失、详情不出现已付款/运行中/已开通。这样“后台协助下单不绕过门禁”由页面最终状态证明，不再只依赖确认弹窗文案。

后台页面对象的截图目录此前依赖启动命令当前目录，从仓库根运行会写到工作区外。本轮改为从`import.meta.url`解析仓库根，与 Portal 截图 helper 使用同一稳定策略；最终截图还会等待确认弹窗完全隐藏，避免把退出动画中的弹窗当作最终业务状态。

## 浏览器验证证据

1. Portal 以`http://127.0.0.1:9999`真实托管入口运行`TC007-commerce-checkout.ts`：5/5 通过，首个公开商品到付款准备整链路耗时约 1.3 秒，其余场景均低于 1 秒。
2. LinaPro 以`http://127.0.0.1:6670/admin`管理入口、`9999`后端运行`TC005-assisted-quotes.ts`：增强后 3/3 通过，最终场景验证人工审核状态和危险动作消失；等待弹窗退出后的最终场景又定向通过 1/1。
3. 一次错误执行把 Portal 指到 LinaPro 管理端`6670`，5 个用例均等待 Portal 根节点超时，失败截图明确为登录页；纠正到 Portal 的`9999`入口后立即全部通过。该次环境错误不计作产品失败，也没有通过提高超时掩盖。
4. 既有真实 PostgreSQL 回归继续证明协助下单复用正常订单、账单、库存、履约和付款准备服务，浏览器 mock 只验证页面契约，不替代后端状态机证据。
5. 最终视觉证据为[后台协助订单门禁](../../../temp/20260810/194054-idc-assisted-order-gate.png)：详情显示“已创建订单”和`ORD_ASSISTED_0001 · 人工审核`，协助结账按钮已消失，页面没有已付款、运行中或已开通状态。

## 完成边界

任务`5.11`要求的五个 E2E 场景已全部由真实 Chromium 覆盖，且测试文件位于各自功能所有者。真实支付渠道网络、资金入账和开通仍由阶段`7`及资源阶段负责；本轮只允许到付款选择准备或人工审核，绝不伪造支付成功、服务开通或运行状态。

仓库级`i18n`检查中，插件运行时扫描、消息覆盖和插件双语键均通过；完整仓库仍只被禁止修改的宿主通知预览页中英文各 3 个既有缺键阻断。因此任务`5.11`实现和任务内验证完成，但继续保留未勾选。

## 规则影响记录

- 架构与插件：客户流程仍由独立 Portal 所有，员工协助流程仍由核心业务插件管理页所有；没有把 Portal 页面塞入 LinaPro 或修改宿主。
- 数据权限与 API：没有新增或修改接口、DTO、权限或客户所有权输入；E2E 继续断言危险字段不进入请求体。
- 前端与`i18n`：只把已有订单状态双语资源接入协助详情，没有新增硬编码状态翻译；插件版本提升到`v0.1.41`。
- 测试：遵守模块本地唯一 TC 编号，没有创建冲突的核心`TC003`；Portal 5 个和后台 3 个场景均以单 worker 真实 Chromium 通过。
- 数据库与缓存：无迁移、DAO、生产查询或缓存变化。
- 外部系统：所有外部网络继续由后续阶段拥有，本轮 mock 不声称完成真实支付或 Provider 集成。
