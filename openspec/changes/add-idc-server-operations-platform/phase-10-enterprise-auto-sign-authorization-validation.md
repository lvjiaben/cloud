# 第十阶段企业自动签独立授权验证记录

## 结论

任务`10.8.e`已经完成实现、审查和任务范围验证，可以精确勾选。企业自动签默认关闭，只允许有独立权限的员工在最近五分钟完成完整登录后启用；新建授权默认只选择“必须签署的订单合同”，并要求核对准确模板版本、合同来源、到期时间、单一币种、单份合同金额上限和供应商接受的成功发起总次数。生效授权不能编辑，只能一次确认后立即撤销再新建；个人自动签保持关闭。

本项只完成`10.8.e`，不代表父任务`10.8`、`10.8.f`、`10.8.g`或第十阶段完成。客户“我的合同”和订单详情仍由`10.12`直接在`@lina/web-customer`实现；本项没有进入第十五阶段。

## 审查发现与修复

1. 启用确认框原先没有逐项列出模板名称与准确版本、合同来源和准确到期时间。现在完整展示模板、来源、期限、币种、金额和次数，并补充真实浏览器断言与截图。
2. 金额展示原先经过 JavaScript `Number`除法，存在大额精度风险。现在从请求到显示都使用十进制字符串和`BigInt`，不经过浮点数。
3. 自动签状态和来源原先缺少系统字典。迁移现在幂等写入`idc_compliance_contract_auto_sign_status`和`idc_compliance_contract_auto_sign_source`，插件语言包提供中英文内容。
4. “电子合同”父菜单原先绑定模板查看权限，只有自动签权限的员工仍可能被挡在页面外。父菜单现在只承担结构和路由承载；各页签和接口继续分别检查精确权限。
5. 同币种并发创建的数据库唯一冲突原先会被转换成笼统“暂不可用”。现在转换为明确业务冲突。
6. 自动签判断原先没有重新确认准确模板版本仍启用。现在模板版本停用会立即阻止新的自动签，不影响人工签署和已发起合同。
7. 用量计数原先使用应用进程时间判断到期。现在事务内读取 PostgreSQL 权威时间，锁定授权行后追加供应商接受证据并原子增加次数；同一幂等请求不会重复计数。
8. 关联的`idc-core`正式检查发现合同签署人匹配函数复杂度超限，以及两个没有调用方的旧客服辅助函数。签署判断已等价拆分，两个无运行效果的死代码已移除；核心插件全量测试和正式 lint 均通过，没有改变业务规则。

审查收口后，本项范围没有剩余严重或一般问题。

## 实现边界

| 能力 | 所有者与结果 |
| --- | --- |
| 后台页面 | `idc-compliance/frontend/`中的“合规中心 → 电子合同 → 自动签授权”页签；页面、接口客户端和双语资源由插件拥有 |
| 管理接口 | 合规插件列表、启用和撤销接口；服务端重新检查`idc:admin:compliance:contract-auto-sign:manage` |
| 最近登录 | 启用要求五分钟内完整登录；撤销不额外要求近期登录，确保风险出现时可以立即停止 |
| 本地数据 | 授权、准确模板版本关系和供应商接受用量三类表；法律与安全历史不软删除、不覆盖 |
| 并发 | 同币种生效授权由 PostgreSQL 部分唯一索引兜底；计数使用事务行锁、乐观版本和唯一幂等证据 |
| 腾讯门禁 | 启用和新自动签判断都读取购买方本地腾讯网关能力；没有软件提供方中央网关或中央回退 |
| 人工签署 | 任一限制不满足时只拒绝新的自动签；正常人工签署和已发起流程不受影响 |

## 权限、数据、性能与装配

该授权是每套安装实例唯一 IDC 商家的全局法律授权，不是部门或客户拥有的普通行数据，因此固定为`tenant_id=0`，不套用部门行权限。页面和后端同时检查独立权限；授权失败统一按不可访问处理；撤销锁定精确授权和版本，启用锁定同币种状态与准确模板版本。PostgreSQL 测试覆盖无权限拒绝，并断言服务请求的正是独立自动签权限。

列表固定每页 20 条，候选模板最多 50 条；模板关系用一条集合查询装配，不逐行查库。服务在插件路由装配期创建一次，注入宿主数据库、管理运行时、当前会话和购买方本地腾讯网关客户端；控制器不自行创建服务图。本项不新增缓存，也不修改公共构建脚本。
