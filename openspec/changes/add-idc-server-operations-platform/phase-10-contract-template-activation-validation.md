## 启用与停用规则

1. 管理员只能对“已提交腾讯”或“已停用”的完整版本发起启用。
2. 腾讯已停用、腾讯已下线、范围或签署顺序未配置、双方签章位置不完整，或本地正文、预览确认、字段修订不一致时，服务端拒绝启用。
3. 页面点击“启用”后只显示一次确认。确认文字明确说明：同一模板原来启用的版本会自动停用，历史合同不会改变。
4. 取消确认不发请求、不写数据库；确认后只提交一次精确版本和最新锁版本。
5. 服务端在一个事务内锁住同一模板全部版本，先停用其他启用版本，再启用目标版本。
6. 单独停用只阻止新合同继续使用该版本，不删除历史合同或模板版本。

数据库另有部分唯一索引，保证同一个本地模板最多只有一条`status_code = 'enabled'`记录。即使多个请求并发到达，数据库和事务锁也共同阻止出现两个启用版本。

## 权限和审计

- 查看权限为`idc:admin:compliance:contract-template:query`。
- 启用、停用、复制、编辑和同步权限为`idc:admin:compliance:contract-template:manage`。
- 没有管理权限时，服务端在写数据库前拒绝启用；真实 PostgreSQL 验证确认版本状态和锁版本都没有变化。
- 每次成功启用或停用都追加业务审计，记录精确模板编号、操作类型、要求的管理权限、操作前状态、操作后状态和新锁版本。
- 并发测试中的四次成功启用和一次准备性停用都形成完整审计；陈旧锁版本再次提交被拒绝，不形成错误的成功记录。

## 历史版本保护

- 合同表通过外键引用精确的`template_no + version_no`，不能只引用“当前版本”。
- 已提交、已启用和已停用版本由数据库触发器保护，不能修改正文映射、字段映射、范围、顺序、名称或腾讯快照，也不能退回草稿。
- 当前没有模板删除接口或前端删除按钮。
- 真实 PostgreSQL 测试先让合同引用一个版本，再直接尝试删除该版本，数据库按外键拒绝；合同和模板版本都保留。

## 真实 PostgreSQL 验证

`TestElectronicContractTemplatePostgreSQLConcurrentEnableKeepsOneVersion`覆盖：

1. 同一个腾讯模板形成两个本地不可变版本并补齐本地范围与签署顺序。
2. 无管理权限启用被拒绝，目标版本没有任何变化。
3. 先启用版本一，再启用版本二；版本二成功后版本一在同一事务中自动变成“已停用”。
4. 停用版本二，把两个版本都准备为可启用状态。
5. 两个并发启用请求都按事务串行收敛，最终数据库中只有一个启用版本。
6. 并发结束后使用旧锁版本再次启用被拒绝。
7. 成功启停审计的目标、结果、权限、前后快照和数量全部符合预期。

数据库唯一索引继续作为最后一道保护；测试不是只依赖应用层统计结果。

本轮收口时该用例曾在准备腾讯新版本时，先保存供应商字段对应、后保存本地适用范围和签署顺序，触发生产代码正确的状态冲突保护。版本一原本就使用正确顺序，因此根因是版本二测试夹具顺序错误，不是生产并发逻辑失败。修复后统一按“先补齐本地设置，再保存字段对应”准备数据；定向真实 PostgreSQL 用例连续执行`5`次通过，合规插件真实 PostgreSQL 全量测试也通过。

## 双语真实浏览器验证

新增以下插件本地`TC004`子用例：

- `TC-4b-5z`：中文页面先打开启用确认，断言自动停用旧版本和历史合同不变的说明；取消后零请求，再次打开并确认后只提交一次，列表显示“已启用”，按钮切换为“停用”。
- `TC-4b-5e`：英文页面断言`Enable this version?`、自动停用旧版本说明和`Template version enabled`，确认后只提交一次且不显示原始多语言键。

首次运行中文用例时，测试把 Ant Design 中文按钮的无障碍名称严格写成“取消”，而组件实际为带排版空格的“取 消”，因此测试等待超时。根因是测试定位过严，不是产品逻辑或接口失败；定位改为允许中文排版空格后，中文与英文用例都通过。

最终真实 Google Chrome 结果：`TC-4b`共`8 passed`，包括目录、只读权限、中文编辑器、英文暗色编辑器、本地正文流程、复制流程和中英文启用确认。
