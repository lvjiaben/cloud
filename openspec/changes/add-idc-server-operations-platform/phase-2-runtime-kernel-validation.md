# 第二阶段运行内核收尾验证记录

## 验证范围

本记录覆盖任务 2.5 至 2.12 的最终收尾。验证对象只包括 IDC 插件公开能力、秘密管理、审计、缓存、重新认证、托管作业和跨插件边界，不把后续业务阶段的页面或外部供应商验收算进第二阶段。

## 能力边界

- `idccap`同时提供源码工厂、版本与依赖检查、拥有方描述、受宿主授权的调用分发和动态插件 SDK。动态调用只能读取安装实例的非秘密商家上下文，调用方、拥有方、服务、版本、方法、资源、数据表和空请求体均逐项核对。
- `secretcap`提供源码工厂、精确作用域、不可序列化句柄、回调式明文访问和版本依赖检查。按照设计中的保密边界，它故意不发布动态明文描述或 SDK；治理测试会在有人误开该通道时失败。
- `resourcecap`提供版本化 Provider 接口、最小 `ProviderEnv`、严格输入输出校验和只写后冻结的源码声明器。它故意不提供运行期全局 `Resolve/Get`，Provider 工厂只能由资源插件在启动装配时冻结并显式注入。

因此，任务 2.5 中的“描述、分发、宿主授权和动态 SDK”适用于允许动态调用的 `idccap`；秘密和 Provider 能力采用更严格的源码专用边界。这不是缺项，而是避免把明文秘密或上游 Provider 调用暴露给动态插件。

## 通道秘密管理

资源插件新增了后台通道秘密管理接口，覆盖创建、替换、撤销和有界轮换。每次操作都要求：

1. 当前后台人员持有 `idc:admin:resource:channel-secret:manage`；
2. 当前人员对目标渠道具有有效数据范围；
3. 先通过宿主完整登录时间取得短期、签名、单次使用的操作凭证；
4. 凭证精确绑定操作、渠道、秘密名称、秘密摘要、期望版本、轮换上限和幂等键；
5. 业务状态与审计在同一数据库事务中提交，秘密明文只进入回调并在使用后清零。

创建和替换先写入可恢复的准备状态，再调用唯一的 `secretcap` 管理器。秘密已写入但绑定或审计提交失败时，相同业务请求会复用确定性的操作号恢复，不会重复创建秘密。替换保留被替换历史，撤销保留撤销历史，API、数据库审计和日志均不返回秘密明文或不透明秘密引用。

生产装配由资源插件的 `pluginhost.HTTP` 和 `pluginhost.Jobs` 回调完成：同一份冻结的 Provider 工厂、渠道作用域秘密 accessor 和写入器被显式注入控制器、资源编排和托管作业，渠道停用时拒绝构造新的 Provider 客户端。

## 其他运行内核证据

- 业务审计保存可信操作者、客户主体、对象、前后状态、原因、结果和风险；重复键、超限对象和敏感字段会被拒绝或脱敏。
- 核心状态机、异步任务和 Outbox 已覆盖重复事件、并发领取、租约恢复、退避、死信、结果未知与人工接管。
- 版本缓存覆盖单进程和集群修订、最大陈旧时间、后端故障降级、损坏重建与指标；资金、账单和服务状态从不以缓存为真相。
- 最近重新认证使用宿主会话 `LoginAt`，短期凭证绑定用户、会话、操作和目标摘要，并以数据库唯一约束保证单次消费；进程重启和缓存丢失不会恢复已用凭证。
- IDC 的轮询、重试、到期、同步和快照工作均通过源码插件 `pluginhost.Jobs` 注册。宿主测试覆盖重复处理器拒绝、插件停用移除处理器、重启回收孤儿运行记录、非主节点跳过和单节点重叠拒绝。
- 源码扫描覆盖全部 IDC 插件，禁止导入其他插件的 `internal` 或实现包、直接访问其他插件数据表、跨插件外键，以及绕过公开能力直接写入。
