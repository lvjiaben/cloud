# 后台布局复验与修复

## 反馈与范围

用户指出上一轮优化后，大部分后台页面仍然布局混乱。按`lina-feedback`补充当前变更的体验验收缺口。上一轮报告保留为历史记录，其默认入口验收未充分覆盖组合页宽度、分页位置和语言切换后的实际页签，本报告补充这些证据。

本轮以`temp/20261011/192000-before/`为修改前基线，审查插件页面、共用适配样式、布局刷新函数、三个插件的测试及后台使用指南。文件清单见[本轮增量](../../../temp/20261011/202500-review-files.json)，未将其他任务的工作区改动纳入。插件根及上级未发现额外`AGENTS.md`。

## 原因与修复

| 原因 | 处理后的表现 |
| --- | --- |
| 页签内嵌完整页面，重复计算视口高度 | 子页使用父页可用高度，去掉重复标题和第二层留白 |
| 表格外壳在横向布局中收缩 | 表格与外壳同时铺满内容区，列超宽时在表内滚动 |
| 筛选、工具栏、字体变化后高度未重算 | 插件适配层观察布局变化，调用公开表格重算方法，分页可达 |
| 部分列表使用自动高度 | 开放接口和销售列表使用有界高度 |
| 支付配置隐式网格列撑出容器 | 使用可收缩的纵向布局，列表宽度与内容区一致 |
| 三张对账表纵向堆叠 | 分为渠道健康、日对账批次、差异明细；批次操作直接打开对应差异 |
| 供应商概况两张表纵向占满页面 | 桌面按三比二并排，窄屏上下排列并保留单层滚动 |
| 语言更新后表头和筛选仍是原语言 | 资源页重新生成标签和表头，普通筛选按钮紧邻条件 |
| 语言切换重建页面，当前页签丢失 | 当前会话保存所选页签，实际权限继续决定可见内容 |
| 窄屏分页总数和页码重叠 | 分页按可用宽度完整换行，总数、条数和翻页操作仍可见 |

没有修改费用、权限、数据归属、接口或执行结果。魔方云、`SSL`及支付能力仍由安装启用的对应插件提供。样式限于主动采用`plugin-admin-page`的后台插件页面，不改变客户中心和宿主通用主题。

## 三轮页面复验

1. 第一轮使用用户同尺寸截图及[修改前扫描](../../../temp/20261011/192000-layout-audit.json)，确认表格收缩、重复页头和分页裁剪；定位共享适配层及组合页高度链。
2. 第二轮完成布局修复后扫描[三十二个入口](../../../temp/20261011/200200-layout-audit.json)，逐张查看六组截图；自动化覆盖多行数据、失败恢复、准确总数、筛选及双语窄屏。发现加载画面误计为完成、语言切换后截图回到概况、窄屏分页重叠等遗漏，继续修复。
3. 第三轮从入口重新扫描[三十二个页面](../../../temp/20261011/202200-layout-audit.json)，无页面脚本错误及整页横向溢出。补看岗位、企业微信、供应商各页签、支付页签、七类配置抽屉和合同办理；新增断言在截图后仍须保持正确页签，避免隐藏节点让尺寸检查误通过。

营销综合页保留固定高度表格与单层内容滚动，未额外重做其报表组件。动态插件页面只核验实际可达画面，不伪造供应商连接或业务数据。最终实际操作记录[桌面截图](../../../temp/20261011/204700-tasks-final.png)为空列表；资源多行与长文本验证使用测试专属接口场景，不作为真实联调成果。

## 本轮审查

按`lina-review`审查本轮增量，依据前端、测试、翻译、插件、工具、文档和宿主边界规则，以及组合规范完整体验与运营菜单条款。布局函数在页面组件创建，接收公开表格实例，观察布局而不发送查询；卸载后取消动画帧并断开观察器。无后端、数据库、缓存或运行期服务依赖变化，本轮无需重建后端或进行性能审计。

已触发端到端质量审查。新增`TC015f`、`TC034e`、`TC004e`覆盖原截图问题、容器宽度、受控高度、分页边界、当前页签及准确总数；现有场景覆盖失败恢复、权限收回、按需读取和重要操作范围。各用例独立安装自己的测试接口，未执行真实付款、退款、服务器操作或第三方写入。截图已用视觉检查复核，发现的隐藏页签误通过和分页重叠已修复后重新验证。

本轮未发现阻塞问题。外部账号与供应商尚未验证的能力仍保持原限制；额外临时全页面类型扫描的既有诊断保留为验证限制，不声明整个后台全部源码类型无误。未提交、推送、创建`PR`或归档。
