# 第十阶段中央合规网关身份底座验证记录

## 1. 任务结论

任务`10.6.a`已完成中央网关身份协议、PostgreSQL 身份数据模型、嵌入式幂等迁移和公开注册持有证明帧。

本切片不开放注册或业务 HTTP 路由，不签发真实注册令牌，不调用腾讯或诺诺，也不改变中央服务固定失败关闭的就绪状态。

## 2. 已实现能力

### 2.1 身份协议

- 注册令牌格式固定为版本前缀`lreg1_`和`256`位随机值。
- 安装实例公钥固定使用`Ed25519`的`32`字节公钥，注册随机数固定为`32`字节。
- 持有证明使用`idc-compliance-gateway/enrollment/v1`域和四字节大端长度前缀帧，依次绑定协议域、令牌、公钥和随机数。
- 注册签名固定为`64`字节`Ed25519`签名；精确重放摘要对完整持有证明帧计算`SHA-256`。
- 篡改令牌、公钥、随机数或签名均不能通过验证。

### 2.2 PostgreSQL 模型

| 表 | 核心约束 |
|---|---|
| `idc_gateway_registration_token` | 只保存`32`字节令牌摘要；同一销售记录最多一个待消费令牌；显式消费、过期和撤销状态 |
| `idc_gateway_instance` | 销售记录和注册令牌分别唯一；实例显式活动或撤销 |
| `idc_gateway_instance_key` | 公钥和指纹固定`32`字节；代次正数且每实例唯一；每实例最多一把活动密钥 |
| `idc_gateway_subject_binding` | 主体密文与`HMAC`查询摘要分离；每实例每供应商和每供应商主体最多一个活动绑定 |
| `idc_gateway_identity_event` | 只允许封闭聚合类型和操作者类型；事件更新或删除由触发器拒绝 |

所有身份表禁止普通物理删除。模型没有令牌原文、私钥、腾讯或诺诺技术凭据字段。

### 2.3 迁移治理

- SQL 以`go:embed`进入中央服务模块，不依赖商家插件 manifest。
- 迁移使用 PostgreSQL 事务级 advisory lock 和`SERIALIZABLE`事务串行化。
- 迁移台账保存文件名、`SHA-256`和数据库权威应用时间；已应用文件摘要变化时失败关闭。
- 当前迁移可重复执行，所有约束、索引、函数和触发器名称均不超过 PostgreSQL 的`63`字节限制。
- 中央模块固定使用`pgx/v5 v5.10.0`的`database/sql`驱动边界；该版本支持当前 Go 版本并包含上游已发布的安全修复。

## 3. 验证结果

以下中央模块门禁通过：

```text
GOWORK=off go test ./... -count=20 -shuffle=on
GOWORK=off go vet ./...
golangci-lint run --config E:\golang\cloud\.golangci.yml ./...
staticcheck ./...
```

真实 PostgreSQL 验证只使用仓库明确命名的可丢弃`linapro_idc_codegen`数据库，并在其中创建随机`linapro_gateway_test_*`隔离 schema；测试结束后只删除该随机 schema。验证命令与结果：

```text
LINAPRO_IDC_COMPLIANCE_GATEWAY_TEST_DSN=<disposable-codegen-dsn> \
go test ./internal/migration -run TestIdentityMigrationPostgreSQL -count=1 -v

PASS
```

真实数据库断言覆盖：

- 首次迁移和第二次幂等执行。
- 六张中央身份及迁移台账表存在。
- 非`32`字节令牌摘要被拒绝。
- 未知供应商和不存在实例的主体绑定被拒绝。
- 同一实例第二把活动密钥被唯一索引拒绝。
- 实例密钥物理删除被拒绝。
- 身份事件更新和删除均被只追加触发器拒绝。

## 4. 影响评估

- 数据库：只新增中央网关独立模块的嵌入 SQL，不修改商家插件或宿主数据库迁移。
- `API`：新增可复用的 Go 注册协议包，但没有新增 HTTP 路由。
- 数据权限：没有业务查询或写入口，平台销售授权和商家实例认证留在后续服务层。
- 缓存：无影响。
- `i18n`：无运行时用户界面或可见业务文案影响。
- 宿主：未修改宿主代码、页面或构建入口。

## 5. 审查结论

本切片按 LinaReview 检查了密码学域隔离、帧唯一性、令牌与私钥最小化、数据库状态约束、唯一索引、物理删除、迁移幂等、依赖版本和测试隔离。最终没有发现阻断`10.6.a`的`P0`、`P1`或`P2`问题。

本记录冻结`10.6.a`完成时的底座状态。后续`10.6.b.1`已实现令牌签发、摘要密钥注入、原子注册事务和完全相同请求恢复，证据另见[中央身份签发与注册事务验证记录](phase-10-central-gateway-registration-service-validation.md)；密钥轮换、撤销和主体加密服务仍归属`10.6.c`。中央服务在注册传输与运行时装配完成前继续返回失败关闭的就绪状态。
