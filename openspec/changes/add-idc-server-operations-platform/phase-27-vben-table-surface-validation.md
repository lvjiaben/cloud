# 第二十七阶段：全站表格封装与灰白面板

## 状态与范围

本阶段承接`FB-108`、`FB-109`，当前已完成业务表格组件替换和灰白区域的最终综合验收。用户最终确认灰色表头，其余普通表格区域白色，页面外层背景保持原样；此结论覆盖首轮表头也白色的试验。悬停、选中、禁用、焦点及暗色模式继续保留必要反馈。完整数字分页后来由`FB-110`独立完成，不能把本阶段组件替换本身当作分页证据。腾讯电子签、诺诺和其他缺真实供应商条件的验证仍暂停。

按`lina-feedback`归入现有活跃变更：本问题涉及跨应用、插件和独立页面的统一组件边界及长期防回退规则，已先同步用户偏好、前端规则、设计、增量规范和任务。

## 根因

1. 官方 Vben 表格布局令牌使用页面`--background`，客户中心将此令牌设为冷灰；表头另继承`--accent`，客户样式还单独覆盖为`--muted`。因此页面外层与表格区域混为同一底色。
2. 以往盘点只检查普通`Vue`页面，遗漏正式页面导入的`src`组件及`JavaScript`手写节点。财务信用区、下游渠道、SSL 双端仍有原生表格。
3. 独立挂载构建与源码装配是不同入口，不能把源码页面的 Vben 修复当成独立产物已经迁移。原有`vben-adapter`仅校验传入函数，并不包含可供隔离页运行的官方 Vben 组件。
4. 浏览器截图同时发现深色空态文字对比度不足；只检查底色无法发现此问题，因此增加空态文字对比度断言。

| 下游渠道运营台 | 正式入口导入`admin-mount.js`，工厂生成八类原生表格 | 按原有业务字段、动作及分页边界迁移 |
| SSL 管理及客户证书页 | 双端共用`shared/shell.ts`及原生行生成 | 先验证独立安全隔离页的 Vben 运行时，再迁移双端 |
