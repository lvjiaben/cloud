# 第十阶段客户合同签署后端契约验证记录

## 结论

任务`10.8.f`已经完成后端契约、实现、审查和范围验证，可以精确勾选。客户合同目录和订单合同详情只返回当前登录客户拥有的合同；客户可为仍可签署的原合同、原腾讯流程取得一条新的`30`分钟腾讯`H5`链接，也可在从腾讯页面返回后主动重新检查权威状态。

重试不会创建第二份合同、不会重新发起腾讯流程，也不会延长合同原有`7`天期限。重新检查只经每套安装自己的本地合规网关读取腾讯权威状态，浏览器返回参数不能直接把合同改成完成。拒签、撤销、终态失败和过期继续交给后台状态机处理。

本项只完成`10.8.f`后端契约，不代表父任务`10.8`、后续`10.8.g`、客户页面任务`10.12`或第十阶段完成。客户“我的合同”、订单详情、签署按钮和返回后的页面提示仍由`10.12`直接在`@lina/web-customer`实现；本项没有进入第十五阶段，也没有向旧 Portal 或`web-antd`写入业务代码。

## 对外接口

| 接口 | 用途与安全边界 |
| --- | --- |
| `GET /account/compliance/contracts` | 按稳定游标读取当前登录客户的合同，每页默认`20`条、最多`50`条；请求不接受客户号或租户号，不访问腾讯 |
| `GET /account/compliance/orders/{orderNo}/contract` | 只在订单和合同都属于当前登录客户时返回；不存在和不属于本人使用相同结果，避免泄露记录是否存在 |
| `POST /account/compliance/contracts/{contractNo}/signing-links` | 只为仍可签的原合同和原腾讯流程生成新`30`分钟链接；不创建合同、不重发流程、不延长`7`天期限 |
| `PUT /account/compliance/contracts/{contractNo}/authoritative-state` | 经安装本地网关只读查询腾讯权威状态，并按只能向前推进的规则收敛本地状态 |

接口金额字段使用最小货币单位的十进制字符串，避免浏览器浮点数造成大额金额精度丢失。新增接口和字段已经补齐英文接口源文本、中文接口文档翻译和双语运行时错误消息。

## 身份、数据和性能

客户归属由 IDC 核心插件根据当前登录身份和客户主体表得出，控制器和请求参数都不能指定或替换客户号。合规插件在启动装配时取得这一只读身份能力，并注入合同服务；无法取得可信客户身份时失败关闭。

合同列表使用一条集合化 SQL 读取合同和每份合同的最新流程，不逐行查库，也不做昂贵的总数统计。新增`015-customer-contract-directory.sql`幂等索引，按`tenant_id、customer_no、created_at DESC、id DESC`支撑客户合同目录的归属过滤和稳定排序。该迁移只新增索引，没有改表字段，所以不需要重新生成 DAO。

本项不新增缓存。腾讯链接和权威状态查询共用插件启动时创建的一份本地网关客户端；可信返回地址由服务端运行配置装配为客户合同页，不能由浏览器传入。

## 本地网关与重试约束

本地网关增加合同签署链接和合同流程状态的受签名读取路由。链接路由只读取并生成短期入口，状态路由只查询供应商；两者都复用已存在的本地合同和腾讯流程编号，不调用供应商写入接口。

网关请求仍受安装身份、时间窗、随机数防重放、用途权限和本地运行门禁约束。状态刷新只有在腾讯返回可识别的权威结果后才更新本地记录；结果不确定、供应商不可用、合同已过期或流程已进入不可签终态时都失败关闭。

## 审查修复

1. 修复本地网关事务返回值没有正确接住回滚错误的问题，确保事务收尾失败能够真实返回调用方。
2. 修复新增代码中的未检查类型断言、错误文本格式和缺少注释问题，三个相关 Go 模块正式 lint 均为`0 issues`。
3. 将 HTTP 金额从整数改为十进制字符串，并同步控制器断言和中英文接口文档。
4. 补充客户合同目录索引，避免数据增长后依靠状态列索引再额外排序。
5. 插件版本从`v0.1.10`更新为`v0.1.11`，迁移清单和插件清单测试同步更新。

审查收口后，本项范围没有剩余严重或一般问题。
