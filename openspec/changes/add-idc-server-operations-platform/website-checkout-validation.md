# 官网购买与账单支付反馈验收

## 根因与范围

本轮按`lina-feedback`纳入现有结账规范。商品详情由普通局部状态在服务端预取，浏览器接管时却从空状态开始，导致节点不匹配和正文清空；客户购买入口又只提供配置预览，没有完整官网购物车和确认订单。进一步核实账单仅有余额与授信付款，在线渠道只接入充值。

按用户最终确认，官网负责选配、购物车、核价与确认订单，未登录提示登录；只有最后付款进入客户账单。客户旧购买入口跳转官网。同源网关复用完整客户认证和账单模板，交接窗口、来源及随机标识同时校验，令牌不进入地址；第三方模板协议见客户插件双语说明。

范围为两个官网模板、默认客户模板、核心插件游客购物车只读及移除控制器，以及安装工具的官网地址传递。未改变商品售价、支付渠道配置、财务结算、订单所有权或宿主逻辑。未提交、推送或归档。

## 实现与边界

- 商品初始数据通过`Nuxt`载荷传递，列表和详情保持服务端与浏览器初始状态一致；无额外配置商品也能查看价格及购买。
- 新增官网`/cart`和`/checkout`；最终报价、配置快照、库存和幂等订单全部复用核心购买服务。服务端报价有效期及付款准备仍是权威，页面不按缓存金额扣款。
- 游客读取与移除只使用受保护浏览器`Cookie`确定归属，不接受地址中的归属令牌；最多返回一百个公开购买项，排除配置值、文件、客户身份和秘密。该范围是规范确认的公开购买自隔离例外，不绕过员工角色查询边界。移除继续执行已有事务和并发版本校验。
- 公开购物车投影直接复用启动时注入控制器的同一`commerce.Service`，未创建第二套服务或业务缓存；已有集合读取和有界投影保持不变，无逐商品查询。
- 官网会话只存于当前标签页，过期后重新使用客户模板认证，购买项仍在服务器购物车。后台和不同源窗口不因此获得客户或管理员权限。
- 订单确认后打开客户账单支付弹窗，复用付款准备、实名门禁与已验证渠道。二维码、页面及表单跳转仅消费支付拥有方响应；不接受浏览器传入订单总价。未实名、订单不可付款和支付模块不可用均阻止相应操作。
- 客户服务暴露无秘密的官网地址，开发工具传入实际官网端口；仅在本地回环地址之间保留当前主机名，避免跨端口使用不同主机名造成购物车丢失。独立客户开发服务的文件允许范围补入自身应用目录。

## 购物车移除与已有登录追加修复（2026-10-16）

上轮页面用例没有覆盖真实多商品移除，认证也只验证了官网主动打开弹窗的路径，因此上轮“移除、登录已完成”的验收不足。此次以用户实际浏览器和真实数据库重新验收相关路径，不沿用上轮总体通过结论。

根因及处理：购物车投影和最终报价的数量查询都遗漏排除已移除项，删除已经提交后，剩余商品数量校验误失败；两处过滤保持一致。商品重校验查询还遗漏公开地址字段，已补入原有集合查询。配置使用不含值的稳定编号关联浏览器草稿，合并后仍提交到原有订单报价项冻结校验，成功才允许下单；旧项无完整选择时在官网逐项补全，拒绝猜测原配置。配置表单按操作打开，避免同商品多个表单同时加载上游选项。

官网改为从配置的客户服务隐藏认证页读取现有会话，需要登录时在当前标签完成原认证并返回官网；客户中心链接和最终账单跳转使用配置客户来源。消息校验来源、来源窗口和随机标识；客户页只允许配置官网来源，本地仅增加同端口回环别名，生产来源保持精确匹配。令牌只在内存和认证消息中使用，不进入地址。原有客户认证、权限、实名、资金和配置校验均保留。
