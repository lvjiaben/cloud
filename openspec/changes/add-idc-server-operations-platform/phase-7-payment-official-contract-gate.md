# 第七阶段支付宝与微信支付官方契约门禁记录

## 结论

本轮只以当前官方商户文档和官方 SDK 为实现依据。支付宝电脑网站、手机网站以及微信 `Native`、`H5`、`JSAPI` 均按不同产品模式独立冻结能力；商家没有开通相应产品、证书或公众号授权时，对应模式保持关闭。

## 支付宝

官方资料确认：

- 电脑网站支付使用 `alipay.trade.page.pay`。
- 手机网站支付使用 `alipay.trade.wap.pay`。
- 两类产品都提供主动查单、关单、原交易退款、退款查询和账单下载接口。
- 请求使用支付宝开放平台网关和 `RSA2`，页面回跳不能代替异步通知或主动查询的权威结果。

资料入口：

- [支付宝电脑网站支付 API 列表](https://developer.alibaba.com/docs/doc.htm?articleId=105900&docType=1&treeId=270)
- [支付宝手机网站支付 API](https://developer.alibaba.com/docs/api.htm?apiId=1056&docType=4)

## 微信支付

官方资料确认：

- 使用微信支付 `APIv3`。
- 首版产品模式为 `Native` 和微信外 `H5`；`JSAPI` 只有商家完成公众号授权、支付目录、`openid` 与产品开通校验后才能启用。
- 支付成功必须来自验签并解密后的回调，或权威主动查单。
- 支持查单、关单、原交易退款、退款查询和交易账单；退款受理不等于最终成功，必须继续接收回调或查询到终态。
- 请求签名、响应验签、回调验签与 `AES-256-GCM` 解密使用微信支付官方 Go SDK。

资料入口：

- [微信支付 APIv3 官方 Go SDK](https://github.com/wechatpay-apiv3/wechatpay-go)
- [微信支付回调与查单指引](https://pay.wechatpay.cn/doc/v3/merchant/4012075249)
- [微信支付订单退款指引](https://pay.wechatpay.cn/doc/v3/merchant/4013071031)

## 易支付

易支付只采用用户提供的本地文档：`submit.php`、同步返回、异步通知和 `MD5` 签名。`mapi.php`、`api.php`、主动查单、关单、自动退款和账单能力继续关闭；需要退款时进入人工渠道待办，禁止猜测接口。

## 安全边界

- 每套安装只使用当前 IDC 商家自己的商户号、应用、证书、密钥和结算关系，不经过软件提供方中央网关。
- 商户秘密只通过 `secretcap` 的不透明引用保存，调用适配器时短暂解析，页面、日志、审计和证据只保存摘要。
- 回调必须同时核对签名、商户、应用、支付尝试号、币种和金额。
- 页面返回始终只显示“确认中”，不能直接入账。

## 本地契约验证

- 支付宝电脑网站和手机网站下单请求均通过 `RSA2` 签名校验；异步通知同时核对应用、商户、状态、签名和金额。
- 支付宝查单、关单、退款与账单响应必须带有效平台签名；响应内容被修改或签名缺失时拒绝采用。
- 微信 `Native`、`H5`、`JSAPI` 下单、查单、关单、退款和账单均通过官方 SDK 的请求签名与响应验签回归。
- 微信异步通知通过官方 SDK 验签，并使用 `APIv3` 密钥解密后才生成权威结果。
- 支付宝和微信均覆盖平台公钥轮换：切换到新公钥后，旧公钥签发的通知不再被接受。
- 易支付覆盖人民币页面收款、商户匹配、`MD5` 通知验签、篡改拒绝以及未验证查单、关单、退款、账单全部关闭。
- 支付通道秘密只保存 `secretcap` 不透明引用；真实 PostgreSQL 回归确认数据库中没有商户密钥明文。

验证命令：

```powershell
$env:GOWORK='off'
$env:LINAPRO_IDC_PAYMENT_TEST_DSN='pgsql:postgres:123456@tcp(127.0.0.1:5432)/cloud_idc_phase10_e2e_v2?sslmode=disable'
go test ./... -count=1
```

结果：支付插件全部包通过。
