# 第十阶段本地供应商写保护验证记录

## 1. 任务结论

任务`10.6.d.2`已在当前安装环境的本地合规网关中完成 PostgreSQL 权威的安装级与操作级限流、每业务请求单一供应商写租约、按供应商与操作范围持久熔断、半开单探针和`result_unknown`禁止自动重发。

本任务没有实现腾讯或诺诺真实客户端，也没有开放新的供应商业务`HTTP`路由。本记录形成时两者均因外部契约门禁关闭；`2026-08-14`后腾讯客户端改由`10.8`按官方公开契约和购买方运行时门禁实现，诺诺继续受`10.4.c`阻断。缺少客户端时继续失败关闭，不回退到软件提供方网关。旧中央网关限流与熔断验证记录只作为算法迁移基线，不能替代本次本地所有权实现。

## 2. 根因与本地化结果

迁移`004-business-request-guard.sql`曾建立以远程实例为父级的中央限流、写尝试和熔断表，迁移`008-retire-remote-identity.sql`已按独立交付纠偏删除这些表。迁移`009-local-supplier-runtime.sql`后来只留下按供应商保存的简化熔断状态，没有操作范围、写尝试、限流窗口、半开探针所有权或结果未知防重发接线。因此，旧文档中的历史测试通过不代表当前任务完成。

新增迁移`014-local-supplier-write-guard.sql`只使用当前安装标识、本地业务请求、供应商和操作范围，不恢复远程实例注册、平台销售记录、中央主体、跨客户路由或中央结算。最终本地模型包括：

- `idc_gateway_local_rate_limit_window`：安装和操作两个固定窗口，使用数据库时间、行锁和策略版本；
- `idc_gateway_local_supplier_write_attempt`：以业务请求号全局唯一，一个请求最多一条不可删除写尝试；
- `idc_gateway_supplier_circuit`：按供应商与操作范围保存`closed/open/half_open`、唯一探针、到期时间和单调版本；
- `idc_gateway_supplier_health_sample`：最多保留最近 20 条，只保存规范结果、耗时、稳定机器码摘要和数据库观察时间，不保存原始错误或响应。

本地运行时在迁移和供应商主体服务准备完成后构造一个共享`internal/supplierguard.Service`。当前没有真实供应商写路由，所以没有为了演示而接入假的腾讯或诺诺调用；后续生产写路由必须在真正网络调用前取得`Lease.CallSupplier=true`的首次资格。

## 3. 冻结的首个安全策略

- 安装级每 60 秒最多 120 次，操作级每 60 秒最多 30 次；两层在同一事务计数，操作层超限会回滚安装层增量。
- 健康窗口最多 20 条，至少 5 条后达到 3 次真实可用性失败、2 次结果未知或连续 3 次真实可用性失败时开启 5 分钟写保护。
- 确定业务拒绝代表供应商仍可达，业务请求记为失败，但健康样本记为成功；本地认证、权限、参数、映射、配置和限流失败没有健康观察入口。
- 保护到期后只有一个 60 秒探针。探针成功或确定业务拒绝关闭保护；可用性失败或结果未知重新保护。
- 探针超过 60 秒没有观察结果时，下一次准入先把旧尝试和旧业务请求原子记为`result_unknown`，再重新保护 5 分钟。
- 已经取得写租约的请求即使响应丢失，也只能恢复原尝试并得到`CallSupplier=false`；不能自动再次发送。
- 当前不提供商家页面、策略编辑、通知、人工解锁、强制成功、强制失败或危险重发。

## 5. 规则域与审查

- 架构与插件：实现闭环在`idc-compliance/central-gateway`，没有修改宿主核心、管理后台、客户前端、旧 Portal 或软件提供方服务。
- API 与数据权限：没有新增 HTTP 路由或浏览器 DTO；服务只接受已经由本机签名协议登记的业务请求号、服务端操作范围和固定供应商，不接受客户、商家、平台操作者或远程实例归属字段。
- 数据库与性能：单次准入只锁定一个当前安装、一条业务请求、一个熔断行和两个限流行；单次观察只锁定一条业务请求、一个熔断行和一条写尝试，并以最多 20 行的固定有界查询计算健康窗口，无列表扫描或`N+1`。
- 安全：原始供应商错误、响应、凭据、主体、业务载荷和幂等键不进入健康表；稳定机器码在持久化前做用途隔离`SHA-256`摘要。
- 前端与`i18n`：无用户可见页面、交互、路由或文案变化，因此无前端和翻译资源影响。全仓宿主页面既有翻译键失败不属于本任务，未修改宿主，也未宣称全局`i18n`门禁通过。

`lina-review`复核了当前安装所有权、锁顺序、两层限流回滚、全局单写租约、响应丢失恢复、结果未知防重发、熔断代次、迟到结果隔离、并发单探针、探针超时、实例撤销和持久约束。复核补充了安装活动状态锁和撤销回归；最终没有遗留阻断`10.6.d.2`的`P0`、`P1`或`P2`问题。
