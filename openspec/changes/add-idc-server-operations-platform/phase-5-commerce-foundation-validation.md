## 交易事实边界

- 每个客户或游客令牌摘要同一时刻最多拥有一个活动购物车；购物车必须且只能属于其中一方，使用单一大写三字母币种，并保留合并去向、当前报价、过期时间和乐观版本。
- 购物车项目引用不可变配置快照。配置快照头锁定商品版本、来源修订、选择摘要、规格数量和内容摘要；规格行锁定双语名称、组件类型、规范化值及数量，数据库触发器禁止更新或删除。
- 报价由头、项目、费用构成和优惠调整四层追加事实组成。报价锁定客户上下文、币种、有效期、定价、资格、库存和内容摘要；项目锁定商品、配置、计费、税务、路由、库存、合同、履约、风险及金额证据。
- 购物车报价必须与购物车币种一致；报价项目引用的购物车项必须属于该报价的购物车；规格费用必须引用该报价配置快照中真实选中的规格，不能跨购物车、跨币种或借用未选择选项。
- 订单只能引用带客户主体的精确报价，并以“客户 + 结算幂等摘要”唯一。订单项复制报价项目的商业证据并禁止更新或删除；订单状态只表达客户订单生命周期，不代替支付、账单或服务状态。
- 活动库存预留绑定订单项、资源池和完整库存快照，一个订单项同时最多存在一份`held/committed`预留。每个购买数量生成独立履约单元，使两台服务器可以分别成功、失败、未知或转人工，而不把部分履约伪装成整单成功。

## 金额与历史不变量

- 所有金额使用`BIGINT`最小货币单位；报价头、报价项、订单头和订单项均强制满足`净额 = 小计 - 优惠`、`总额 = 净额 + 税额`，且优惠不能超过小计。
- 配置快照、报价头、报价项、费用构成、优惠调整和订单项共 7 类证据由数据库触发器拒绝更新与删除；商品、价格、税率或库存变化不会改写历史商业事实。
- 报价项目通过复合外键证明商品版本、计费规则、配置快照、资源池绑定、库存快照和逐币种税务策略属于同一受约束图；订单和预留继续引用精确报价及库存证据。
- 当前迁移不试图用跨行检查约束库存总量或强制履约单元数量等于购买数量。`5.4`必须在数据库事务中锁定当前库存、集合汇总活动预留并原子创建完整履约单元，避免用不安全的跨表触发器代替事务服务。
