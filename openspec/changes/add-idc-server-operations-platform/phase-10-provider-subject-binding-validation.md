# 第十阶段供应商主体强绑定验证记录

## 1. 任务结论

> 历史说明：本记录描述的是中央网关方向下的早期切片，当前产品所有权已经由完整独立交付纠偏改为每套安装的本地网关。本记录只保留算法与测试证据，不得作为平台中央主体权威的现行依据。

该历史切片完成了腾讯子企业与诺诺纳税主体加密强绑定、精确查重、撤销和回调限域解密。现行实现中主体原文和批准事实的权威属于当前安装的本地网关与购买方供应商授权结果；客户、浏览器、普通后台请求及公共`HTTP`均不能提交或读取主体原文。

本切片不新增`HTTP`路由、不装配腾讯或诺诺客户端，也不放行任何供应商生产调用。`2026-08-14`后腾讯客户端由`10.8`按官方公开契约和购买方运行时门禁实现，版本化业务请求认证与防重放复用后续本地网关能力；诺诺继续受独立外部证据门禁。

## 2. 加密与强绑定

- 腾讯主体只接受规范`ProxyOrganizationOpenId`安全字符投影，诺诺主体只接受规范大写 18 位统一社会信用代码；值只能由注入的`SubjectAuthority`在同步回调中提供。
- 主体加密使用独立 256 位密钥的`AES-256-GCM`和随机 nonce，认证附加数据绑定实例号、绑定号、供应商代码及密文版本。改变任一绑定维度、密文或查重摘要都会失败关闭。
- 查重使用另一把独立 256 位密钥和固定用途域的`HMAC-SHA-256`，不保存可离线猜测的裸`SHA-256`。PostgreSQL 以“供应商 + 活动查重摘要”唯一索引阻止同一主体同时被两个实例占用，并以“实例 + 供应商”唯一索引阻止重复活动绑定。
- 数据库只保存密文、查重 HMAC、密文版本和不透明编号。迁移`003-subject-binding-hardening.sql`把密文长度限制为 32—256 字节、把版本固定为 1，并用触发器禁止修改绑定身份、密文、摘要或版本；唯一允许的更新是从`active`原子进入`revoked`。
- 绑定、撤销、不可变操作账本和身份事件位于同一 PostgreSQL 事务。相同操作键和完整请求精确恢复原结果；同一操作键改变主体、供应商、实例、批准证据或完整登录时间返回`identity_conflict`。

## 3. 权威批准与解密边界

- 绑定和撤销都精确核对动作、实例、供应商、封闭原因、操作者类型与编号、证据摘要和近期完整登录时间。首次执行以数据库权威时间限制完整登录最长五分钟和未来偏差最多三十秒；精确已提交重放可恢复原结果。
- 主体绑定只接受`provider_onboarding_approved`；撤销只接受`provider_revoked`、`merchant_termination`、`subject_replaced`或`security_incident`。不接受自由文本、实例自行批准或活动绑定覆盖。
- 对供应商适配器的读取只提供`WithActiveSubject`同步回调。服务从活动实例的活动绑定加载密文，在回调前完成认证解密和 HMAC 复核，回调返回或 panic 后清零明文，密文缓冲也在服务返回前清理。
- 实例撤销会在同一事务撤销活动/待激活密钥、未消费注册令牌和最多两个活动供应商主体，并逐项写入身份事件。已撤销实例或主体只能得到稳定拒绝，不能从读取路径确认历史主体是否存在。

当前 Windows Go 环境为`CGO_ENABLED=0`且没有可用 C 编译器，因此`go test -race`明确返回`-race requires cgo`，不能伪造竞态门禁通过。并发正确性由真实 PostgreSQL advisory lock、唯一约束和 10 轮并发回归验证；发布环境仍应在具备 CGO 工具链的隔离 CI 追加竞态检测。

## 5. 规则域与审查

- 架构与插件：实现完全位于`idc-compliance/central-gateway`独立嵌套模块，没有修改宿主或其他插件，也没有引入商家运行时依赖。
- API 与数据权限：没有新增 HTTP API、后台页面或客户入口；主体来源、完整登录、动作权限和数据范围由平台受信权威能力负责，内部服务再次逐字段匹配并失败关闭。
- 数据库：新增顺序迁移而不修改既有迁移校验和；迁移幂等、使用`timestamptz`与显式状态，无软删除和物理删除路径。所有列表均为精确单对象或最多两个供应商主体，不存在`N+1`。
- 安全：主体原文、加密密钥和 HMAC 密钥不进入响应、日志、审计或数据库；密文、摘要和操作记录都有用途隔离及数据库约束。
- 缓存、前端、宿主与`i18n`：无影响。全仓统一 lint 仍会被范围外宿主`role`控制器既有重复声明阻断，已按用户指示如实记录且不修改宿主；中央嵌套模块的`golangci-lint`和`staticcheck`均通过。

`lina-review`复核了明文生命周期、AAD 完整性、用途隔离、并发唯一性、精确重放、数据库时间、实例级联撤销、行数上限、密文不可变性和错误投影。审查期间修复了结果集异常路径未使用`defer`关闭、实例撤销未核对主体实际更新行数，以及数据库未限制密文上限和不可变字段三项问题；最终没有遗留阻断`10.6.c.3`的`P0`、`P1`或`P2`问题。
