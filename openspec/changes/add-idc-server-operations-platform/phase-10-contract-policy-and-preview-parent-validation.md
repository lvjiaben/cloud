## 实现核对

### 三级合同规则与页面位置

- `idc-core/backend/internal/service/contractpolicy`保留“沿用上一级”“明确无需合同”“必须签合同”三种不同含义，并按订单、商品、企业的优先顺序计算订单最终决定。逐级没有必须签署规则时默认无需合同；多个商品落到不同模板且订单没有明确选择唯一模板时失败关闭。
- 企业规则只在企业客户详情中编辑；商品规则位于商品新增和商品详情；后台协助报价允许在订单创建前明确最终规则；订单详情允许在付款确认前修改最终决定。付款完成或订单离开待付款、付款处理中、人工审核状态后拒绝修改。
- 商品层只取得全部客户模板，企业层只取得企业或全部客户模板，订单层按订单真实客户类型取得候选。必须签合同时模板必选，模板不可用时失败关闭。
- 页面全部位于`apps/lina-plugins/idc-core/frontend/`，合规中心只管理模板，没有新增集中规则页；`apps/lina-vben/apps/web-antd`工作区与暂存区差异均为空。

### 可选合同、快照与提交边界

- 人工可选合同继续由独立权限`idc:admin:compliance:contract:create`控制；订单取消、关闭或全额退款后拒绝发起，已经付款、正在开通或已经完成的原订单继续履约且不等待可选合同。
- 可选合同预览创建成功后永久锁定订单“无需合同”决定；后续即使合同撤销，也不能把原订单追溯改成必须签署。
- `contractsnapshot`一次冻结订单、服务逐项名称、期限、分项金额、总额、客户、商家和个人已验证主手机号；企业签署人使用合规插件提供的当前有效安全候选，不接收临时手填或普通通知联系人。
- 合规插件在不可修改预览中冻结准确模板版本、语言、签署顺序、签署人版本和固定七天有效期。预览中的签署日期保持空白，最终日期只接受腾讯权威结果；腾讯`H5`链接的三十分钟有效期与合同七天有效期分开计算。
- 生成预览和提交腾讯是两个独立按钮与命令。结果未知时不自动重发，腾讯外部流程号不暴露给普通后台页面。

## 本轮发现并修复的问题

- 客户列表测试替身把值为空的分组、标签查询参数误判为有效筛选，导致“下一页”错误禁用；现已改为只有参数存在实际值时才进入筛选分支。
- 客户详情抽屉的测试标记原先写在不会转发普通属性的自定义抽屉组件上；现已把标记放到真实正文节点，并分别验证抽屉标题与正文。
- Ant Design Select 同时存在可见列表项和隐藏的无障碍代理节点；分组与批量标签用例现只点击当前可见下拉中的真实文字节点。
- 分组和标签候选会并行加载；测试不再假定最后完成的一定是分组请求，而是按`kind=group`精确核对。
- 合同快照 PostgreSQL 测试夹具落后于个人签署人规则，缺少联系人与联系人角色表；现已补齐已验证主联系人夹具。生产查询和业务规则未为测试放宽。
