# 第四阶段供应商容量观测纠偏记录

## FB-52 纠偏结论

本文件原先把供应商计划和资源池快照当成“商品库存”，并把资源插件同步结果描述成商品库存运营能力。该结论已经失效，不能继续作为阶段完成证据，也不能用于恢复旧接口、旧权限、旧菜单或旧页面。

商品库存只是商家新增或编辑商品版本时直接设置的普通商品字段，与自动化插件、供应商接口和资源池没有关系。系统不为库存增加供应商同步、独立审核、确认权限、原因说明或审计流程。

## 当前正确边界

- `idc-core`只保存商品版本自身的简单库存，并在结账时完成本地预留、提交和释放。
- `idc-resource`可以异步读取供应商容量，帮助管理员判断服务器上游是否具备交付条件，但该数据只属于资源插件自己的运行观测。
- 供应商容量不得写入商品库存、自动创建商品草稿、改变商品发布状态或冒充库存确认。
- 后台页面和接口统一使用“供应商容量”含义；旧`inventory`路由、权限、菜单键和测试命名不保留兼容入口。
- 页面只显示渠道名称、容量类别、更新时间、可读状态和可读失败原因，不显示内部编号、供应商原始报文、凭据或技术错误。
- 容量刷新继续使用持久异步任务、有界分页和本地完整快照；失败或结果未知时保留上一份完整观测，不影响商品、订单或履约事实。

## 旧实现处置

旧商品草稿发布桥、资源库存运营路由和对应权限属于错误方向，必须直接删除。开发数据库中的旧发布表、触发器和字典数据由明确迁移清理；供应商容量快照只在资源插件内部保留。新的代码、PostgreSQL、双语前端和真实浏览器验证必须在`FB-52`完成时重新记录，不能沿用本文件原有的服务器库存测试作为通用商品库存证据。
