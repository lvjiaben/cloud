# 第六阶段账单与账本数据底座验证记录

## 实现范围

本轮完成任务 `6.1` 的财务数据库底座。`idc-core` 新增 `023-billing-ledger-foundation.sql`，建立账单、账单明细、账本账户、账本交易、账本分录、余额快照、资金锁定、支付分配、退款分配、调账申请和调账审批共 11 张表，并生成对应 DAO、DO 与 Entity。该切片只建立权威数据模型和提交前约束，不提前实现 `6.2` 的资金服务、`6.3` 的账单状态机或任何 HTTP 接口。

财务域继续闭环在 `idc-core` 内，不修改宿主或建立跨插件外键。所有金额使用带明确币种的整数最小货币单位；客户余额、信用、赠送、佣金和商家现金、应收、收入、税款、清算账户按所有者、类型与币种分层，客户余额和赠送不得提现。

## 数据库不变量

- 原始订单账单按订单唯一，复合外键同时证明订单、客户和币种一致。订单账单明细还必须属于账单头的同一订单和币种，且小计、优惠、净额、税额与总额必须等于不可变订单项，禁止跨订单挂行或结账金额漂移。
- 账单明细、账本交易、分录、余额快照、支付/退款分配和审批决定均为追加式历史；账单、账户、资金锁定与调账申请只允许推进明确生命周期字段，商业身份、原始金额和申请意图不得修改或删除。
- 每笔账本交易声明分录数、借方合计和贷方合计。延迟约束在提交前重新集合计算分录并要求借贷相等，同时要求每个受影响账户恰有一条金额完全对应的余额快照，拒绝无分录快照。
- 余额快照按账户序号和前一快照形成不可断裂链，以账户正常余额方向校验期初、本笔借贷和期末公式。客户余额、赠送与佣金投影不得出现负数。
- `invoice_issuance`、支付、余额支付、退款、调账和冲销使用不同交易语义。支付/退款分配通过“交易号 + 币种 + 交易类型”复合外键绑定正确账本事件，不能把账单开立分录冒充收款。
- 支付和退款分配只追加新记录；冲回必须引用原分配，累计冲回不得超过原金额。退款同时受账单明细可退上限和原支付分配上限约束。
- 冲销交易必须引用同币种非冲销原交易，累计冲销金额不得超过原交易金额。错误历史只能通过新冲销或调账纠正。
- 资金锁定使用原始金额、已消费和已释放非负分桶，活动、部分消费、消费、释放和过期状态均满足金额守恒；同一账户与业务来源同时最多存在一份活动锁定。
- 调账申请精确绑定客户自己的同币种账单或客户余额账户。需要复核时只能由不同员工追加唯一决定；待复核、批准、拒绝和已入账状态与审批、账本引用在提交前一致。

## 迁移与生成结果

- 迁移可在新 PostgreSQL schema 中执行，并可重复执行最后一版两次；字典类型和数据使用幂等写入。
- 11 张表没有 `deleted_at`，所有 `*_minor`金额列均为 `BIGINT`。
- 新增 13 组完整中英文字典；其中账本交易类型单独包含“账单开立”，避免与支付语义混用。
- 插件 `hack/config.yaml` 已把 11 张表加入标准 GoFrame DAO 生成白名单，并为可空外键配置指针类型。
- 标准 `make.cmd dao dir=apps/lina-plugins/idc-core/backend` 已重新生成 DAO、DO 与 Entity；调账账户类型和账本交易类型等可空字段均为指针。
- 插件版本提升到 `v0.1.35`，使 SQL、字典与生成模型通过正式插件升级路径交付。

## 复审结论与未完成边界

本轮按 `lina-review`检查了金额守恒、所有权与币种复合外键、追加式历史、账单与订单一致性、借贷平衡、快照链、冲销、分配、审批隔离、迁移幂等、生成边界和测试证据。自审中发现并修复了三项高风险问题：账单开立误用支付交易类型、账单行可引用其他订单项、订单账单金额未由数据库复核。修复后重新通过全部真实 PostgreSQL 和正式构建门禁，未发现任务范围内仍需修复的严重或高优先级问题。

任务 `6.1` 的实现和任务内验证已经完成，但仓库根不存在 `.contributing`，本业务插件无权修改 `apps/lina-vben/apps/web-antd/src/views/system/message/notice-preview-modal.vue` 引用的 6 个宿主既有缺键，因此父项与子项继续保留未勾选。余额并发消费、资金锁定覆盖可用余额和状态机服务属于 `6.2`；账单状态转换属于 `6.3`。下一切片返回 `5.4`，只消费本轮账单创建能力，在一个事务中组合订单、订单项、账单、库存预留和 Outbox，不在结账时伪造支付或提前写资金账本。

## 规则影响记录

- 架构与插件：财务权威数据全部位于 `idc-core`，无宿主变更、跨插件调用、跨插件外键或新增公共能力抽象。
- 数据权限：本轮没有新增 API 或服务入口，不产生新的可访问数据面；`5.4`及后续账务接口必须分别接入客户所有权或员工精确权限和数据范围。
- 数据库：迁移、索引、复合外键、不可变触发器、延迟约束、幂等字典和标准 DAO 生成均已验证；历史资金表明确不使用软删除。
- 性能：所有提交前校验按单个账单、交易或账户集合查询，没有随列表行数发起应用层 `N+1`；面向列表、详情和导出的查询路径尚未在本切片开放。
- 开发工具：只修改插件自有 `hack/config.yaml` 的 DAO 白名单和可空字段类型，没有修改根构建脚本；Windows/Linux 继续使用同一标准生成与构建入口。
- `i18n`：新增财务字典均有中英文镜像；插件覆盖通过，全仓阻断仅来自上述禁止修改的宿主既有缺键。
- 缓存、前端、API 与 E2E：本轮均无影响。财务表是权威真相，不引入缓存；未新增用户可观察页面、路由或 DTO，浏览器 E2E 不适用。
