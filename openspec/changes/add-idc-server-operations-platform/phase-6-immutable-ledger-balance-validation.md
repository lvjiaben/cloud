# 第六阶段不可变账本与余额服务验证记录

## 实现范围

本轮完成任务 `6.2` 的内部资金服务，代码闭环在 `idc-core/backend/internal/service/billing`。服务只开放已确认充值、可用余额消费、余额锁定创建与消费、锁定释放与过期、完整反向冲销和只读余额投影重建等固定业务语义，不提供调用方可自由指定账户、借贷方向或分录组合的通用记账入口。

渠道验签、主动查单和“付款成功”权威判断仍属于 `idc-payment`。当前资金服务没有 HTTP 路由、控制器或运行时支付装配，普通页面返回、后台请求或调用方自报成功不能直接入账。账单分配与账单生命周期由后续任务 `6.3` 组合，人工收款、减免和高额双人复核属于 `6.4`。

插件版本由 `v0.1.41` 提升为 `v0.1.42`，使本轮后端和双语错误资源通过正式插件升级路径交付。

## 资金与账户不变量

- 确认充值固定借记同币种商家现金并贷记客户余额；普通余额消费和锁定余额消费固定借记客户余额并贷记商家收入。交易头、平衡分录和全部受影响账户快照在同一 PostgreSQL 事务追加。
- 账户号由“所有者、所有者引用、账户类型、币种”确定性派生。余额、信用、赠送、佣金和不同币种使用不同不透明账户号，不相互兜底，也不执行跨币种兑换。
- 每个写入先按业务来源取得事务级 advisory lock，再按账户号稳定排序加锁。余额只从数据库最新快照计算，不接受调用方提供的当前余额。
- 相同来源和相同不可变请求摘要安全复用首次结果；相同来源改变客户、金额、币种、证据或业务语义时拒绝。既有成功结果在客户、账户或商家后来停用后仍可幂等重放，但停用状态阻断新的资金写入。
- 活动且未过期的资金锁定从可用余额扣除。创建、部分消费、全部消费、释放和过期使用一致的账户到锁定顺序；同一来源不能改绑另一客户，任何分桶变化继续满足“原始金额 = 已消费 + 已释放 + 剩余金额”。
- 冲销只能创建引用原交易的完整反向交易。不能修改原流水、部分冲销、重复冲销、冲销一笔冲销交易或在活动锁定后制造负可用余额。

## 流式余额重建与完整性证明

余额重建以账户为边界，从不可变交易和分录使用交易主键 keyset 分页读取，每页最多 `1000` 笔交易；同一交易的该账户全部分录保持在同一页。对应快照按序号分页读取，跨页携带期末余额、前一快照号和序号，逐笔核对：

- 交易顺序、分录摘要和交易摘要；
- 借方、贷方、正常余额方向和整数溢出；
- 快照序号、前序引用、期初、当笔借贷和期末；
- 最终快照数量、活动锁定与可用余额。

重建报告使用流式 `SHA-256` 生成确定性内容证明，内存占用受单页上限约束，不随完整账本线性增长。报告只读，不删除、覆盖或自动修复历史；任何不一致返回完整性错误并转人工核对。

## 独立复审及修正

本轮按 `lina-review` 从资金守恒、并发锁序、幂等身份、账户与币种隔离、不可变历史、查询复杂度、错误本地化和验证证据进行复审。复审过程中发现并修正：

- PostgreSQL advisory lock 文本不能包含空字符，来源锁键改为无歧义的安全分隔格式，并由真实数据库测试捕获回归。
- 幂等成功重放与新资金资格分离，避免商家或客户后来停用后把既有成功请求误报为失败，同时阻断新的写入。
- 锁定来源增加全局客户绑定校验，防止相同来源在其他客户下重建另一份锁定。
- 冲销涉及的账户和最新快照改为集合化查询，移除随账户数量增长的应用层 `N+1`。
- 原先有总行数上限的重建改为 keyset 分页流式重建，既保留失败关闭语义，也能适应长期增长的账本。
- 高复杂度记账函数拆分为聚合、分录准备、快照准备和客户账户保护等可测试步骤；补齐六类账本错误的中英文资源。

修正后重新通过 20 轮真实 PostgreSQL、完整后端、静态分析、插件治理、严格规范与双平台正式构建。任务范围内未发现仍未处理的严重或高优先级问题。

## 未完成边界和规则影响

- 数据权限与 API：本轮没有新增 HTTP API、DTO、控制器、菜单或可访问数据面，因此没有新的终端用户或员工数据权限入口。后续支付、账单与后台页面必须分别接入客户所有权或员工精确权限、默认商家和可表达数据范围，不能直接暴露本内部服务。
- 数据库：复用任务 `6.1` 的 `023-billing-ledger-foundation.sql` 权威表、索引、不可变触发器和延迟约束；本轮没有迁移、DAO、软删除或数据初始化变更。
- 性能：资金写入固定数量集合查询并稳定锁定账户；冲销批量读取账户与最新快照；余额重建按 `1000` 交易 keyset 分页和快照序号分页，没有逐交易查询或无界内存投影。
- 缓存：资金真相和锁定真相只读写 PostgreSQL，不引入缓存或跨节点陈旧窗口。
- 前端与 E2E：没有用户可观察页面、路由或交互变化，浏览器 E2E 当前不适用。客户余额与后台财务页面属于 `6.7`，整链路账本 E2E 属于 `6.9`。
- `i18n`：插件错误消息中英文镜像完整。仓库根不存在 `.contributing`，本业务插件无权修改宿主通知预览页的六个既有缺键，因此任务 `6.2` 及子项按项目既有口径暂不勾选。
- 商业边界：余额不可主动提现、不同币种不兑换；退款入余额、账单支付分配、人工收款、信用和续费均不在本轮擅自实现。
