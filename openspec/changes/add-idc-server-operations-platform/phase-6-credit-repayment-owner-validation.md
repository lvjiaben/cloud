# 第六阶段信用账单还款 Owner 接线验证记录

## 当前结论

任务`6.11.c.2`完成，因此`6.11.c`和`6.11`可以精确收口。商家时区账单日批处理、客户余额还款、经审核人工收款和在线渠道还款均已接入同一信用账单权威服务；佣金、支付清算中间账户或浏览器自报结果不能冒充还款。

## 实现边界

- `core`主节点托管作业每分钟执行一次有界账单批次，按 PostgreSQL 时钟和商家 IANA 时区选择到期账户；重复运行复用同一账期结果。
- 客户余额还款继续由`core`在同一事务借记当前客户同币种可用余额、贷记商家应收并分配信用账单。
- 后台人工收款复用调账申请与双人复核。只有正式`manual_receipt`账本交易提交后才分配信用账单；请求人、复核人、证据和金额受原有门禁约束。
- 在线还款由`idc-payment`创建用途为`credit_statement`的支付尝试。浏览器只能选择本人账单、正数还款金额和可用渠道；`core`重新核对当前活动客户、账单币种、状态和未还金额。
- 渠道验签或权威主动查询成功后，支付插件只提交支付尝试号、信用账单号、币种、金额和证据摘要。`core`原子追加商家现金到应收的正式账本交易并分配信用还款，部分还款和全额还款均恢复对应额度。
- 支付尝试增加不可变用途与用途编号；普通订单和信用账单两类确认由同一租约工作器分发，但各自调用独立的`billingcap`方法，不能把信用还款误作订单付款。
