# 第四阶段逐币种税务策略验证记录

> **`FB-52`部分失效声明：**逐币种税务与舍入策略仍然有效；同一回归中覆盖旧资源池绑定、服务器配置和 Provider 发布门禁的部分已经失效，只能用于迁移对账，不能作为通用商品税务端到端完成证据。

## 结论

`4.13.a`已完成。系统现在要求运营人员为普通来源商品草稿的每个已定价币种明确创建一份税务与舍入策略，不提供默认税率、不换算币种、不覆盖既有策略。策略进入商品详情、商品复制和统一发布门禁；缺失、重复、额外币种或字段组合畸形都会阻止发布。

本切片只建立商品版本拥有的税务事实。权威报价、账单和税务发票的不可变税务输入快照仍属于`4.13`后续切片，因此顶级任务保持未完成。

## 实现范围

- 新增`plugin_idc_core_catalog_tax_policy`表，以商品版本和计税币种唯一，数据库直接约束币种格式、税务处理、税率组合、税收分类和舍入字段。
- 新增独立`idc:admin:catalog:tax:write`权限及`POST /admin/catalog/product-versions/{versionNo}/tax-policies`。授权在输入和目标访问前完成；写入前锁定父版本，只允许`manual/copy/migration + draft`，并证明目标币种已有启用价格。
- 应税接受`0..10000`税率基点，零税率固定为 0，免税不接受税率；所有金额和舍入粒度继续使用整数最小货币单位。
- 商品详情以一次有界投影返回最多 64 份策略；管理端只允许从“已有明确价格且尚未配置策略”的币种中选择，并使用业务字段表单，不暴露 JSON 或数据库主键。
- 商品复制在同一有界复制图中重建全部税务策略，不复用源业务号，不修改源版本。
- 统一发布预览和正式发布新增独立`tax`检查：每个配置价格币种必须恰有一份合法策略，且不能出现没有价格的额外策略币种。发布检查总数由七项增加为八项。
- 插件版本提升至`v0.1.21`，中英文权限、菜单、表单、检查结果和错误消息同步更新。

## 审查结论

- 数据权限：税务写权限不能被商品列表、详情、价格或发布权限替代；授权前不解析输入也不访问目标，目标版本继续受直接员工、默认商家和可表达数据范围约束。
- 性能：详情只增加一次有界集合投影，发布和复制分别一次加载策略集合，不存在逐币种或逐策略数据库查询。
- 一致性：数据库约束、服务校验、复制校验和发布校验共享相同精确枚举与字段组合；前端便利逻辑不构成业务授权。
- 审计复核：初版成功审计缺少税率基点与最小货币单位舍入粒度，终审已补齐完整策略快照，并重新通过后端全量 20 轮和 Go lint。
- 缓存：没有新增跨请求权威缓存，PostgreSQL 仍为税务策略事实源。
- i18n：插件新增文案提供中英文镜像；仓库级检查若仍被无权修改的宿主既有缺键阻断，应作为外部阻断单独记录，不影响本切片插件文案覆盖结论。
