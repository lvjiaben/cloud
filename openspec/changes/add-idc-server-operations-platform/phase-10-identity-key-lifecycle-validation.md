# 第十阶段实例密钥生命周期验证记录

## 1. 任务结论

任务`10.6.c.2`已完成中央实例双密钥持有证明的原子轮换、实例撤销、非活动密钥撤销、精确恢复和封闭人工授权。该切片没有新增 HTTP 路由、商家后台或供应商调用；主体加密绑定继续由`10.6.c.3`承接，因此父任务`10.6.c`保持未完成。

## 2. 密钥轮换

- 服务先计算操作键 HMAC 和完整请求摘要，优先查询不可变操作账本。已提交的完全相同请求可在旧密钥退役后恢复原新密钥编号和代次；同一操作键改变请求返回`identity_conflict`。
- 未命中恢复时，服务读取精确活动实例和当前活动密钥，核对公钥指纹后验证当前私钥与新私钥对同一版本化帧的两份签名。
- PostgreSQL 事务对操作 HMAC 使用 advisory lock，随后重新锁定实例与当前密钥并核对状态、代次和指纹，避免事务外读取被并发状态变化绕过。
- 事务先创建唯一待激活密钥，再退役当前密钥、激活新密钥，并追加不可变操作与三条身份事件；任一步失败整体回滚。每个实例最多一把活动密钥和一把待激活密钥。
- 并发完全相同轮换只产生一个首次结果，另一个调用从账本恢复。实例撤销后即使持有旧操作键和完整旧请求，也不能继续恢复轮换结果或获得活动身份存在性。

## 3. 封闭撤销

- 撤销必须先通过注入的`DispositionAuthority`精确核对动作、实例、可选密钥、封闭原因、操作者、证据摘要和近期完整登录时间；任一字段漂移在进入事务前拒绝。
- 事务使用数据库权威时间要求完整登录不早于五分钟且未来时钟偏差不超过三十秒。首次和恢复请求都绑定完整授权快照；自由文本原因和不匹配动作不能进入存储层。
- 实例撤销原子推进实例、全部活动或待激活密钥、最多两个活动供应商主体和该销售记录所有未消费注册令牌，并追加对应不可变事件和操作记录。
- 活动密钥不能单独撤销；密钥撤销只接受待激活或已退役密钥，避免留下没有活动身份的活动实例。实例撤销是处理活动密钥泄露的唯一入口。
- 相同操作键和授权快照恢复原结果；同一操作键改变动作、目标、原因、操作者、证据或完整登录时间返回`identity_conflict`，不会重复推进状态。

## 5. 规则域与审查

- 架构与插件：实现闭环在中央独立模块的身份服务与 PostgreSQL 存储，不依赖宿主或商家运行时。
- API 与数据权限：没有新增 HTTP 或管理入口；操作者数据权限、动作权限和近期完整登录由注入的权威能力负责，服务再次精确核对其结果。
- 数据库：复用`10.6.c.1`不可变操作账本并新增待激活密钥唯一索引；事务使用数据库时间和行锁，无软删除、普通物理删除或跨库写入。
- 性能：每次轮换或撤销只处理一个实例、最多两把活动/待激活密钥和两个供应商主体，查询和事件数量固定有界，无列表或`N+1`。
- 安全：两把私钥缺一不可；活动密钥不能单独撤销；错误只暴露稳定码，不包含实例、公钥、操作者或数据库细节。
- 缓存、`i18n`、前端、宿主与开发工具：无影响。

LinaReview 检查了精确恢复顺序、并发锁、事务内重新校验、实例撤销后的存在性保护、完整登录时钟、活动/待激活密钥上限、事件操作者类型和错误映射。审查期间修复了“响应丢失后旧密钥已退役导致无法恢复”、实例撤销遗漏待激活密钥，以及系统操作者事件被误记为普通操作者三项问题。最终未发现阻断`10.6.c.2`的`P0`、`P1`或`P2`问题。
