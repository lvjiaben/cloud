# 第十阶段业务请求认证协议验证记录

## 1. 任务结论

任务`10.6.d.1`已经冻结注册后业务请求的`lrp1`签名帧、规范请求目标、业务幂等内容摘要、防重放随机数、持久限流窗口及供应商写熔断数据库不变量。该切片只提供公开密码学协议和顺序迁移，不开放业务 HTTP 路由、不装配供应商客户端，也不执行任何腾讯或诺诺调用。

## 2. 签名与幂等协议

- `Ed25519`签名帧使用固定域和二进制长度前缀编码，完整绑定协议、实例、密钥、操作范围、方法、规范路径、规范查询、载荷摘要、签发/到期毫秒时间、256 位随机数和 256 位业务幂等键，不依赖 JSON 字段顺序。
- 协议只接受`GET/POST/PUT/PATCH/DELETE`标准方法、无点段或转义歧义的`/v1/`绝对路径，以及最多 32 个唯一键、1 KiB 的规范 UTF-8 查询。签名时间窗必须大于零且不超过两分钟，载荷边界固定为 1 MiB。
- 业务内容摘要绑定实际业务内容，但排除可轮换密钥编号、传输时间、随机数和签名。相同业务幂等键可在响应丢失或密钥轮换后使用新传输签名恢复；任何方法、范围、路径、查询或载荷变化都会得到不同内容摘要。
- 业务幂等键固定使用`lbi1_`前缀和规范无填充 Base64URL 的 256 位随机值。数据库只保存后续服务产生的用途隔离 HMAC，不保存原文。

## 3. 数据库不变量

迁移`004-business-request-guard.sql`新增：

- 业务请求表：同一实例内幂等 HMAC 唯一，保存业务内容摘要和封闭状态机；身份、幂等摘要及接受时间不可变，物理删除被拒绝。
- 防重放随机数表：保存随机数`SHA-256`和签名帧摘要，实例与密钥使用复合外键强制同属，更新被拒绝；只允许在签名到期至少 24 小时后由后续有界作业清理。
- 限流窗口表：实例和操作两个维度使用封闭维度约束，保存策略版本、窗口秒数、上限和当前计数，供数据库权威时间下的原子准入使用。
- 供应商熔断与写尝试表：按供应商和操作范围保存`closed/open/half_open`状态；尝试必须属于同一实例、请求和操作范围，只能从`admitted`单向进入一次`observed`，不能删除或改写身份。

当前迁移只建立下一子任务所需的权威存储，不预设真实商家生产限流数值，也不把尚未发生的供应商调用写成健康或故障样本。

## 5. 规则域影响

- 架构、插件与 API：协议与存储完全位于中央网关独立嵌套模块；没有新增 HTTP 路由、控制器、后台或客户页面。
- 数据权限：当前没有可调用入口。后续认证服务必须从服务端路由注入预期操作范围，并在查询业务对象前完成实例、活动密钥、数据库时间、防重放、幂等和限流准入。
- 数据库与性能：新增迁移不修改既有迁移校验和；高频准入使用唯一索引和固定两个限流维度，不允许按历史随机数或业务请求列表扫描。
- 安全：私钥、幂等键原文和随机数原文不落库；载荷只保存摘要。供应商尝试禁止使用本地失败伪造故障观察。
- 缓存、前端、宿主与`i18n`：无影响。

`lina-review`复核了签名字段完整性、规范路径/查询、时间精度、密钥轮换后的幂等恢复、随机数归属、请求/尝试复合外键、状态转换和数据库索引。审查期间补充了无效 UTF-8 查询拒绝、实例与密钥复合归属，以及供应商尝试与业务请求的实例/范围复合归属；未发现阻断`10.6.d.1`的遗留问题。
