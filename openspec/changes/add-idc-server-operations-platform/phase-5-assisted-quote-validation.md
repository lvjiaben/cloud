# 第五阶段后台协助报价与下单验证记录

> **`FB-52`部分失效声明：**协助报价的员工权限、双人审批、金额和幂等边界可以保留；复用旧资源池库存、逐台服务器履约单元或服务器专用配置的部分已经失效，不能作为当前通用协助下单完成证据。协助入口必须与客户入口使用相同的商品简单库存、不透明插件配置和结清后履约意图。

## 实现范围

本轮完成任务 `5.8` 的后台协助报价与安全下单切片。`idc-core` 新增协助报价申请、不可变明细、独立审批、服务端审批证据、`staff` 来源报价和正常结账复用能力，并在 LinaPro 管理端增加“协助报价”工作台。该入口只服务直接员工，不是客户协助会话，也不允许模拟客户、代付、直接标记已付款或直接修改服务状态。

商家可为其权限范围内的客户选择当前公开目录商品和配置，按币种创建最多 8 行的协助报价申请。人工价格只允许表达为权威实时原价之上的固定金额优惠；付款条件只有标准预付款与延期预付款，延期只改变未付款订单的截止时间。申请必须由另一名具备独立精确权限的员工审批或驳回，批准后才能通过普通结账事务创建待付款订单。

## 数据库与事务不变量

- 新增 `026-commerce-assisted-order.sql`，建立协助报价申请和不可变申请明细两张表，并为订单增加协助申请来源与类型化付款条件。插件版本提升到 `v0.1.40`。
- 申请保存客户、币种、项目配置快照、固定优惠、付款条件、原因、内部备注、有效期、摘要、申请人和审批结果；申请商业身份不可修改，明细禁止更新或删除。
- 数据库状态约束要求申请人和审批人不同，并把待审批、已批准、已拒绝、已下单分别绑定完整证据、报价号与订单号组合。后台来源订单必须引用唯一协助申请，普通订单不得携带协助来源或延期预付条件。
- 创建、审批、驳回和下单均在本地 PostgreSQL 事务中写审计。审计失败会回滚业务写入；审批时重新集合校验客户、商品版本、配置、当前价格、税务、库存与优惠上限。
- 审批证据摘要不接受浏览器或 API 调用方输入，由服务端根据不可变申请摘要、审批请求摘要、申请人和审批人生成。调用方不能伪造证据包摘要。
- 协助下单复用既有原子结账，仍创建正常订单、账单、库存预留、逐台履约单元和事务 `Outbox`。结果只能是 `pending_payment` 或既有风险/库存门禁要求的 `manual_review`，不写付款时间、服务运行状态或绕过首次付款实名准备。

## 权限、接口与性能边界

- 管理端分别声明列表、详情、创建、批准、驳回和下单 6 个精确权限；创建还要求客户详情权限。授权只接受直接、活动员工和可表示的全局/当前商家数据范围，拒绝客户主体、模拟、委托、跨商家及未知数据范围。
- 提供 6 条版本化管理 API。写接口 DTO 只包含业务意图、原因和幂等键，不包含 `paid`、订单状态、服务状态、履约状态或证据摘要覆盖字段。
- 列表使用绑定筛选条件和页大小的加密键集游标，不执行总数查询；单页默认 25、最大 100。详情按申请页批量读取明细、报价和订单投影，查询数不随返回行数线性增长。
- 订单管理投影增加协助申请编号和付款条件，客户订单投影继续清除员工协助来源，避免把内部销售流程泄漏给客户入口。

## 管理端与浏览器验证

- 新增 LinaPro 原生协助报价工作台，包含当前页待审批/已批准/已下单指标、密封游标翻页、详情抽屉、公开目录选品、配置数量、实时重算、固定优惠、标准/延期预付、独立审批和安全结账确认。
- 金额从 API 到页面保持十进制字符串，并用 `BigInt` 格式化与换算最小货币单位；超过 JavaScript 安全整数的金额不会失真。未配置币种不会出现，未知状态不展示危险动作。
- 临时独立 `vue-tsc --noEmit` 工程对协助报价客户端和页面完成严格源码类型检查后已删除，检查通过；正式 LinaPro 构建也成功编译该动态插件页面。
- `TC005-assisted-quotes.ts` 在真实 Chromium 以 1 worker 运行 3/3 通过：验证密封游标与精确大金额、客户端不能提交证据摘要或危险状态字段、审批后仅通过正常待付款结账，以及双人审批和安全提示。

## 复审结论与未完成边界

本轮按 `lina-review`复核了权限与数据范围、幂等、并发锁、不可变申请、独立审批、证据来源、实时重校验、金额精度、正常结账复用、客户信息隔离、列表上界和浏览器危险字段。复审发现并修复两类问题：一是浏览器可提交任意审批证据摘要，现已改为服务端权威派生；二是新增线路把 4 个函数推过复杂度门禁，现已按输入校验、投影、付款窗口、预留消费和路由装配职责拆分。修复后重新通过真实 PostgreSQL、浏览器、全包测试、Lint 和正式构建，未发现任务范围内仍需修复的严重或高优先级问题。

任务 `5.8` 的实现和任务内验证已完成。仓库根不存在 `.contributing`，本业务插件无权修改宿主通知预览页中英文各 3 个既有缺键，因此父项与子项继续保留未勾选。`5.9` 继续补并发结算、条件库存、报价变化和部分履约的组合回归；`5.10` 单独负责固定环境性能清单与 `p95/p99`；`5.11` 负责公开目录到付款准备的跨入口整链路 E2E。

## 规则影响记录

- 架构与插件：全部业务代码、SQL、页面、资源和测试闭环在 `idc-core`，未修改宿主核心契约或建立跨插件外键。
- 数据权限：每个读写动作使用独立精确权限；列表和详情只接受可表示的商家级范围，客户存在性与未知资源统一失败关闭。
- API：时间为 Unix 毫秒，金额为十进制字符串，写 DTO 不接受状态覆盖和证据覆盖；列表有界且使用键集游标。
- 数据库：迁移、索引、不可变触发器、外键、状态组合约束和标准 DAO 已验证；审批与下单历史不使用软删除。
- 性能：列表、明细、报价与订单投影使用集合查询和固定上界，无应用层 `N+1`；结账同步事务不调用 Provider。
- 前端与测试：页面遵循 LinaPro/Vben 交互和权限模式，用户可观察行为由真实 Chromium 覆盖；金额不使用浮点数。
- `i18n`：菜单、页面、错误和字典均有中英文镜像；仓库级唯一阻断仍是禁止修改的宿主既有 6 个缺键。
- 缓存与开发工具：本切片不引入缓存，也未修改根构建或测试工具；临时类型检查配置已删除。
