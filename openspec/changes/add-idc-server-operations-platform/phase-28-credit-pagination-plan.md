# 第二十八阶段：信用区域完整分页方案

## 归属与范围

本项归入活跃变更`add-idc-server-operations-platform`的`FB-110`，按`lina-feedback`的`openspec-existing`路径实施。覆盖客户中心信用申请、信用账单，以及后台正式页面和独立插件入口的申请、账户、账单三类表格。不修改信用审批、收费、还款、权限含义、服务器或工单业务。

## 原因

现有列表由`idc-core`的`billing`拥有，仅提供有界游标页。前端固定读取前五十条后关闭分页或在浏览器切页，既无法跳到后续真实数据，也没有准确总数。不能把当前已加载条数当作完整业务集合。

## 实施方案

1. 在已有信用列表请求上增加可选数字`page`，沿用`limit`作为页大小并把列表上限调整到一百条。数字页与游标不得混用；未指定数字页的既有有界游标调用继续按原排序执行，避免破坏其他已存在消费者。页码及乘积必须验证，超出真实末页返回空集合与真实总数。
2. 在同一拥有方列表结果增加`total`。计数与当前页在同一只读一致性快照内查询；总数基于游标和分页条件加入前的同一筛选集合，客户身份由当前登录主体覆盖，员工仍先经过现有精确权限与可表达数据范围门禁。账户总数保留有效条款的关联条件，不直接对基础表无条件计数。
3. 数据库只查询当前页及一次计数，不遍历全部游标、不全量装载后切页、不逐行查询。复用同一个有界查询辅助函数完成三类结果的计数与分页，保留既有排序和字段投影。评估现有客户、币种和时间索引，不因界面统一而改变数据模型或历史业务。
4. 正式页面使用真实`useVbenVxeGrid`分页条；独立插件继续消费唯一的隔离 Vben 运行时，通过普通数据及分页回调跨越 DOM 边界，不传递跨 Vue 的节点。提供总数、每页`10/20/50/100`、数字页码和翻页按钮。只查询正在翻页的表；按当前设计，改变页规模时回到第一页，直接数字跳页不变。暂时服务故障保留已确认数据和页码，重试使用失败请求参数；权限失效按下方补充条款清理。
5. 客户信用概览及后台审批表单保持原行为。新分页没有现存搜索选项时不新增假搜索区；表头灰色，其余表格区域白色，外层布局不变。

## 影响与门禁

- 数据权限：计数与列表共用查询条件，客户不可通过总数看到他人记录；员工未授权时在查询前拒绝。
- `i18n`：分页文案使用 Vben 官方语言；新增请求与响应字段同步插件英文 API 元数据及中文`apidoc`翻译，不改变现有状态翻译。
- 缓存与依赖注入：不增加缓存、持久化分页状态或运行期服务实例；沿用已注入的数据库与身份、权限服务。
- 开发工具：不新增跨平台启动脚本，不重置开发数据库；构建与测试使用现有入口。
- 验证：补充真实 PostgreSQL 的总数、跨页、超出末页、混合参数拒绝、客户隔离、员工拒绝及筛选测试；更新插件`TC011`和客户`TC014`，覆盖每页条数、数字跳页、失败恢复、中文分页和截图。运行所属 Go 包与绑定编译、前端类型与生产构建、`make.cmd lint.go`定向模块、`i18n.check`及`openspec validate`。

本文件记录实施依据，完成情况以配套验证记录为准。使用官方分页控件，并由业务查询层统一页规模变化回第一页的规则；该补充与当前设计保持一致。

## 权限失效补充

本轮复核发现分页错误分支未区分服务故障与授权失效。保持现有权限语义：`503`等暂时故障保留已确认页；`403`清空被拒绝目录的行、总数及对应详情和草稿；`401`清空当前信用工作区全部授权数据。清理时递增读取代次，迟到的列表、详情和材料响应不得重新填入页面。客户概览、还款引用、上传材料及后台审批表单缓存按相同作用域清理，不更改费用、审批或实际写入规则。沿用现有双语错误提示；只失效当前组件的派生状态，不新增服务端缓存或跨实例状态。补充插件`TC011h/i`、客户`TC014f/g`以及组合式函数单测，原有服务故障恢复回归保留。
