# 第七阶段支付确认链路验证记录

## 当前结论

任务`7.7`完成，任务`6.12.b.4.2`及其父项`6.12.b`、`6.12`同步完成。支付插件已经把客户支付创建、渠道回调、本地状态读取、主动查询和异步核心入账接成一条可恢复链路；支付插件不写订单、账单或履约状态，所有资金和统一结清仍由`core`拥有。

## 安全与一致性

- 创建支付尝试前，`core`在同一事务锁定付款上下文、订单和账单，把订单从`pending_payment`推进为`payment_processing`；后续同一付款上下文仍可创建新尝试，客户取消与支付开始共用订单行锁。
- 当前活动客户身份只由`core`的`payment-actor.current`能力返回不透明摘要。支付状态接口不接受客户编号，员工、停用客户或其他客户不能读取支付尝试。
- 页面返回只读取本地状态；未确认的支付保持`submitted/confirming`。只有验签回调或适配器权威主动查询成功才创建不可变确认工作。
- 回调先完成渠道凭据、签名、商户、金额、币种和本地尝试核对，再追加不可变接收记录和唯一工作项；重复通知复用原接收结果，不会重复入账。
- 异步确认只把支付尝试、账单、币种、渠道金额、组合支付总额、余额锁编号和证据摘要交给版本化`billingcap`。`core`重新推导客户、订单和账户，原子完成入账、分配及统一结清。
- 主动查询和核心确认工作使用数据库租约；进程中断后的过期租约可重新领取，达到重试上限后进入人工处理。渠道查询暂时失败会清除当前租约并退避重试，不会卡死工作项。
- 渠道权威查询明确关闭时，支付尝试进入失败并幂等释放同币种余额锁；未配置正式 HTTPS 回跳来源时可以启动插件，但禁止创建支付，避免生成无效地址。
