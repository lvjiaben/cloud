# 第十阶段阿里云个人实人认证状态机验证记录

## 完成范围

任务`10.2.c`完成个人实名认证后端状态机、加密身份快照、阿里云发起与主动查询、30 分钟恢复、人工复核转交以及`core`首次付款实名投影回写。客户中心`API`、页面、回跳路由、定时作业注册、单独同意采集页面和完整浏览器`E2E`归属`10.2.d`，本任务不提前开放运行时客户入口。

## 权威边界

| 边界 | 实现结果 |
|------|----------|
| 客户与同意 | `core`从当前身份推导活动个人客户；发起只接受该客户最新且仍为`granted`的`sensitive_personal_information`同意编号，不接受客户或租户编号 |
| 案件所有权 | `compliance`独占认证案件、个人尝试、服务商编号、掩码和加密快照引用；`core`只保存首次付款消费的案件号、状态、掩码、带密钥查重摘要和通过时间 |
| 跨插件调用 | 新增源码插件进程内`identitycap`，工厂只接受`idc-compliance`；通过状态投影加入调用方默认数据库组的环境事务，没有动态插件描述符、序列化桥、HTTP 回写接口或跨插件 DAO |
| 明文处理 | 姓名与身份证号使用可清除字节缓冲；案件专属`secretcap`作用域保存带随机挑战值的加密快照。认证通过后姓名只另存于`core`受权限保护的法定资料，合规普通案件表只保存掩码和随机挑战摘要；测试断言合规普通行不含姓名明文、身份证明文、身份明文公开摘要或`certifyUrl` |
| 支持范围 | 当前能力矩阵只接受校验通过的中国大陆 18 位居民身份证和年满 14 周岁客户；其他证件、校验码错误、非法日期和未满 14 周岁在本地拒绝且零供应商调用 |
| 权威结果 | `init`只调用一次，结果未知不重放；浏览器回跳复用主动查询。只有`passed=T`通过，且`core`付款门禁投影、合规终态与通过审计在同一事务提交；`passed=F`在有效期内继续等待，`407/408`或本地 30 分钟截止才过期 |
| 人工复核 | 初始化未知、配置代次变化、快照缺失或不一致、同证件其他客户命中均进入`review_required`；系统没有强制成功入口 |

## 状态与恢复

发起顺序固定为本地案件和`preparing`尝试、案件专属加密快照、`core pending`门禁、一次阿里云`init`、持久化`certifyId`与 30 分钟截止时间。任何一步失败都保持失败关闭；远程初始化已经可能受理但本地结果不确定时，尝试进入`initialization_unknown`，恢复扫描只转人工复核而不再次调用`init`。

主动查询先读取案件和尝试，再核对当前服务商配置编号与版本。远程调用期间不持有数据库锁；落库时使用案件和尝试版本围栏。`passed=T`后从`secretcap`回调内校验随机挑战摘要，再以同一环境事务调用`identitycap`、写入合规终态并追加通过审计；任一步失败都整体回滚，付款门禁不会先于审计生效。同证件命中其他客户时，应用层预查直接转人工；数据库唯一围栏竞争先回滚原事务，再以新事务转人工。恢复扫描每批最多 50 条，只对已有`certifyId`的`ready/pending`尝试查询；近期`preparing`保持等待，超出两分钟或初始化未知转人工，超过 30 分钟在本地直接过期。

## 影响分析

- `i18n`：有影响。新增稳定业务错误码已在插件`zh-CN/en-US`资源中提供自然语言映射；客户页面与状态文案在`10.2.d`随客户接口继续闭环。
- 数据权限：有影响。客户发起和主动查询从当前身份派生客户所有权；系统恢复只能处理本地已持久化案件。`identitycap`工厂限制调用插件，写回使用客户号、案件号和状态围栏。
- 缓存一致性：无影响。案件、尝试、配置代次和付款门禁全部以`PostgreSQL`为权威，没有进程缓存或跨节点派生状态。
- 性能：发起和单次查询均使用固定次数点查与事务；恢复每批最多 50 条并按恢复索引读取，不存在随返回行数追加数据库查询的客户接口。远程查询次数受同一批上限约束。
- SQL：有影响。恢复索引加入`preparing`及初始化时间，支持有界超时扫描；`core`新增非空查重摘要唯一索引处理并发抢占；隔离`PostgreSQL`测试对合规`001/002`和核心`001/003/040`迁移连续执行两次通过。
- 开发工具与文档镜像：无开发工具变更；新增的是本活跃 OpenSpec 中文验证记录，不涉及目录级中英文`README`镜像。

## 强制审查结论

本轮按`lina-review`复读了本任务命中的 OpenSpec、架构、数据权限、插件、后端、数据库、测试、i18n 和文档规则，并逐项核对个人实名服务、`identitycap`、迁移、真实数据库用例和验证记录。审查发现并已闭环以下问题：

- 修复`core`通过投影可能先于合规终态审计生效的问题；三项写入现在共享默认数据库组环境事务，审计失败真实回滚付款门禁投影。
- 为不同客户并发提交同一身份证增加数据库唯一围栏，并区分环境事务内的唯一冲突，先回滚再以新事务转人工复核。
- 把合规普通表的快照完整性摘要从身份内容公开哈希改为加密快照内部随机挑战摘要，降低离线猜测风险。
- 去除本地校验阶段不必要的姓名和身份证字符串副本，拒绝姓名控制字符，并保留认证通过后仅由`core`受权限保护法定资料保存姓名的既定边界。

任务`10.2.c`范围内未遗留高、中、低优先级代码审查发现。客户路由、页面、回跳入口、恢复作业装配、敏感信息同意采集和首次付款门禁联调未在本任务伪造完成，继续由`10.2.d`实施；其中恢复作业必须使用运行时拥有的可信系统操作者审计 writer，不能复用依赖登录用户的审计解析器。
