# 第四阶段商品计费与报价规则验证记录

> **`FB-52`部分失效声明：**通用计费周期、逐币种价格和金额约束可以保留；Provider 草稿审核、固定服务器配置价和第二条发布门禁已经失效。现行价格只绑定通用商品版本和插件声明的配置收费，所有来源共用唯一发布服务。

## 结论

`4.3`的插件内实现已经完成。计费规则以原始“周期单位 + 正整数数量”保存，一次性、小时、天、月、一至十年均有精确边界；固定金额、按数量、分段累进阶梯、按量和试用使用同一版本化规则与逐币种价格表。报价计算只使用最小货币单位整数，安装费只进入首购，续费只使用显式续费金额。

插件后端、真实 PostgreSQL、代码质量和插件治理门禁均通过。插件自身运行时多语言、错误消息与新增字典覆盖通过；仓库级`make.cmd i18n.check`仍仅被无权修改的宿主通知预览页 6 个既有缺失键阻断，因此任务暂不勾选。

## 实现范围

- 新增幂等`013-catalog-billing-policy.sql`，在既有计费规则上补充最低新购周期数、单次最高续费周期数、计量单位、分段模式、采集周期、舍入模式与单位、保底、封顶和缺失数据策略。
- 周期约束按单位精确表达：一次性只能是 1；小时、天、月、年分别最多 87,600、3,650、120、10，完整覆盖一小时到十年且不把十年折算成月。
- 一次性只能首购且固定数量；周期规则只能固定或按数量；阶梯与按量只能使用`graduated`分段累进；试用只能首购，期限仍用单位和数量表达，并配置每客户最大试用次数。
- 用量规则必须声明规范化计量单位、小时/天/月采集周期、向下/向上/四舍五入整数舍入、保底、可选封顶，以及“待补算”或“按上一完整周期暂估”策略。缺失权威数据时金额字段保持为空，不能被误解为零金额。
- 上一完整周期暂估结果显式标记`estimated`；待补算结果标记`pending_recalculation`。试用必须由调用方提供权威历史试用次数，缺失、负数或达到上限均拒绝。
- 每个价格维度的阶梯必须从数量 0 开始、边界连续、无重叠、最终区间无上限；固定和按数量只能有一个无上限区间。首个区间可以保存一次安装费，后续区间禁止重复安装费。
- 新购报价使用`amount_minor`，续费报价使用非空`renewal_amount_minor`；安装费只在首购加一次。周期数量会乘到周期收费，不会重复乘安装费。
- 分段结果返回每段范围、计费数量、单位金额和小计；所有乘法和加法在`int64`边界前检查，溢出返回稳定业务错误，不产生环绕金额。
- 商品复制读取并保留全部新增计费字段；统一发布和 Provider 审核完整性门禁都重新校验计费模型及每个基础价、选项价、币种维度的完整阶梯，不能发布畸形或有缺口的价格图。
- 新增阶梯模式、用量采集周期、用量舍入和用量缺失策略 4 类内建字典及中英文资源。计费规则和价格保持显式历史，不使用软删除；本阶段没有新增用户动作、列表或跨插件数据库关系。

## 任务级审查

- **已修复**：首版 SQL 用普通比较验证按量必填字段，PostgreSQL 的`CHECK`会允许结果为`UNKNOWN`，导致缺少完整用量策略的记录通过。现对每个必填可空字段先执行`IS NOT NULL`，真实 PostgreSQL 反例已验证拒绝。
- **已修复**：旧周期约束统一限制为 120，会拒绝长期按小时/按天，同时允许 120 年。现按单位设置精确十年上限，并由 SQL 与领域校验双重约束。
- **已修复**：待补算报价初版使用整数零值承载金额，调用方可能误当成免费。现待补算时收费、安装费和总额均为空；合法零金额试用则返回显式的零金额指针，二者可可靠区分。
- **已修复**：试用历史次数初版是可省略的整数零值，调用方忘记读取权威历史时可能被当作首次试用。现试用报价强制要求显式的权威历史次数指针，非试用报价反而禁止携带该字段。
- **已修复**：初版用量舍入在应用封顶后执行，向上舍入可能再次越过封顶。现先舍入再应用保底和封顶，最终计费数量不会突破政策边界。
- 已确认价格阶梯验证对调用顺序不敏感，但规范化后必须从 0 连续到最终无上限；同一数量不会命中两段，也不会落入空洞。
- 已确认公开发布和 Provider 人工审核都复用同一计费规则与价格阶梯校验；数据库约束不能替代发布时的集合化完整图重检。
- 已确认迁移只含幂等 DDL 与内建 Seed DML，无 Mock、无显式自增主键；计费历史不使用软删除，符合已确定的显式历史策略。
- 严重、外部既有阻断：`apps/lina-vben/apps/web-antd/src/views/system/message/notice-preview-modal.vue`引用的 3 个宿主键在`en-US`和`zh-CN`均缺失。当前仓库没有`.contributing`，本任务无权修改宿主目录，不能把仓库级 i18n 门禁标记为通过。
