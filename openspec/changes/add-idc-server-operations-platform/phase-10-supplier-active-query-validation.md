# 第十阶段供应商主动查询验证记录

## 1. 范围与结论

任务`10.6.e.3`实现中央合规网关的供应商中立只读主动查询核心：成功写入后的首次回调等待截止点、到期批量领取、精确租约围栏、供应商专用只读查询器、加密原始响应、结果未知保护、有上限指数退避，以及与回调共用的单调状态收敛。

本记录形成时未注册腾讯电子签或诺诺电子发票的生产查询客户端，也未开放供应商业务或回调`HTTP`路由。腾讯查询客户端现由`10.8`按已冻结的官方`DescribeFlowDetailInfo`契约、认证、状态、限流和错误语义实现后注入启动注册表；诺诺继续等待精确契约。

## 2. 领取、性能与恢复

- 供应商写成功后立即持久化两分钟首次回调等待截止点；进程重启不会重新解释或延长该时间。
- 单批最多领取 50 条，只处理已绑定加密外部流程号、供应商已注册、到期且未被有效租约占用的路由。
- 领取使用 PostgreSQL `CURRENT_TIMESTAMP`、`FOR UPDATE SKIP LOCKED`和 256 位随机租约；同一路由并发领取最多一个成功，查询回报必须同时匹配路由版本、查询次数和租约令牌。
- 到期扫描固定使用`next_query_at, provider_code, route_no`稳定排序及同序部分索引，不依赖无界全表扫描、精确总数或逐行补查。
- 传输失败、非法响应、引用解密失败以及非终态权威结果按启动策略执行有上限指数退避。失败只保留封闭类别，不保存供应商客户端自由文本错误。

## 3. 密钥与供应商边界

- 查询服务在启动期冻结供应商代码到只读客户端的一对一注册表；领取 SQL 只选择已注册供应商，调用方不能临时替换客户端或提交外部引用。
- 外部流程号仍只以独立 AES-256-GCM 密文和用途隔离 HMAC 持久化；明文只在`RouteProtector.Open`同步消费回调内交给对应供应商客户端，返回后清零。
- 原始查询响应最大 256 KiB，封帧后使用证据专用 AES-256-GCM 密钥和`active_query` AAD 加密；普通数据库投影、错误、日志和实例投递均不包含原始响应或外部流程号。
- 读取查询不会重发供应商写操作。远程调用后若回调已推进路由并清除租约，迟到结果必须以稳定冲突失败且不能追加查询证据或覆盖回调。

## 4. 状态收敛与投递

- 回调与主动查询复用同一基础投影函数。`result_unknown`不被`running`倒退，成功或失败终态不被处理中或未知状态覆盖。
- 权威查询确认当前终态时清除`query_required`并生成新版本实例投递；权威查询返回相反终态时保留既有终态和冲突待办，等待`10.6.e.4`证据驱动人工接管。
- 非终态结果与查询失败只追加加密证据、清除当前租约并安排下一次查询，不创建无状态变化的重复投递。
- 证据、路由投影和版本化实例投递在一个 PostgreSQL 事务内提交；查询不直接更新商家业务请求状态。

## 6. 规则域与影响

- 架构与依赖注入：存储、路由保护器、证据保护器、查询策略和供应商客户端均由构造函数注入并冻结；没有全局客户端注册表或请求期临时服务图。
- 数据库与性能：修改当前未发布的`005`迁移，无 Seed 或 Mock DML；领取是一个有界集合 SQL，单条查询结果各用一个原子收敛事务，不存在按返回行补查归属的`N+1`。
- 数据权限与 API：没有客户或员工`HTTP API`。实例、请求和供应商归属完全来自既有路由复合外键，查询器不能提交客户、商家、实例或主体字段。
- 安全：数据库和实例投递只包含密文、用途隔离摘要、中央编号、规范状态和单调版本；客户端自由文本错误、外部流程号和原始响应不进入普通投影。
- 缓存、前端、`i18n`与 E2E：均无影响。本切片不新增缓存、页面、用户可见文案、接口元数据或可访问路由，因此使用 Go 单元测试和真实 PostgreSQL 集成测试。

## 7. 剩余边界

- 本记录形成时腾讯与诺诺正式只读客户端均关闭；`2026-08-14`后腾讯只读客户端由`10.8`按官方`DescribeFlowDetailInfo`契约和购买方运行时能力门禁实现，诺诺继续等待精确官方契约和外部门禁。
- 平台操作者授权、乐观版本、既有证据集合约束和无强制终态的人工接管由独立任务`10.6.e.4`完成，证据见[第十阶段供应商人工接管验证记录](phase-10-supplier-manual-takeover-validation.md)；这些能力不属于本主动查询切片。
