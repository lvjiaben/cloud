# 第 8 阶段服务器附属能力操作验证记录

## 范围与所有权

本记录收口任务 `8.7.b.4`、`8.7.c` 和父任务 `8.7`。客户页面位于 `@lina/web-customer`；员工页面位于 `idc-resource/frontend/` 并通过插件机制装入管理后台。`web-antd` 没有 IDC 业务页面、接口客户端、路由、状态、多语言资源或业务依赖改动。

## 已实现边界

- 客户和员工都只读取资源拥有方返回的安全目录；Provider 凭据、端点和原始响应不会到达页面。
- 快照、备份、流量、安全组、NAT 和虚拟介质动作由服务端能力矩阵决定。能力不支持时客户按钮隐藏并提供“提交工单”降级入口，员工页面也不暴露不可执行动作。
- 恢复操作必须选择当前服务器自己的对象并输入唯一服务器编号；所有写操作均有明确影响确认。
- 员工动作使用逐动作精确权限、商家数据范围和不可变员工审计，不用总览权限代替写权限。
- 同一服务器的活动操作形成权威互斥；结果未知时所有新写入口关闭，先查询或人工接管，禁止重放 Provider 写请求。
- 收费创建只生成当前客户的待付款账单，结清前不派发 Provider 任务；后台不能替客户选择余额扣款或伪造已付款。
- 客户页面直接实现于 `web-customer`，支持双语和手机布局；工单降级会带入并校验当前服务编号。

## 结论

服务器附属能力已经在客户和员工两端形成能力驱动、权限隔离、结算受控、结果未知失败关闭的完整链路。历史记录中“只有客户迁移基线、员工入口待完成”的结论已被本次实现和验证替代。

资源插件页面的独立构建边界仍按任务`11.0`在进入第 11 阶段页面开发前建立；本阶段只使用现有插件页面装载机制，没有修改`web-antd`源码或依赖绕过该边界。
