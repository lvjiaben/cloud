# 客户钱包、产品和API概览验收

## 范围与实现

本轮沿用`lina-feedback`纳入既有变更，依据客户账户的“客户详情”完整需求及`76-customer-business-openapi.md`最新确认，限定审查客户钱包、统计、产品分页、服务器编辑、渠道接口概览和证书详情入口。不把工作区其他任务或宿主改动计为本轮成果。

原详情只展示服务器，缺少客户钱包和接口授权信息；统计查询曾使用不匹配当前业务的账单和工单状态。钱包改为当前授权客户集合的一次查询，按币种、钱包类型分别展示可用及冻结余额。实际付款、退款和待付采用账务事实，不跨币种合计；工单沿用客服拥有方状态。产品总数、三十天到期和已到期采用同一已购记录投影，排除续费与配置变更重复计数，不把无订单交付混入到期数量。

产品列表展示原购买订单与当前交付，待交付仍可见；服务器与通用权益由后端明确声明交付类型，不凭编号前缀推断。服务器备注使用原版本校验，配置共用原升降级报价、支付及执行流程；不直接改已付款订单。证书进入已安装、已启用且已授权的拥有方管理页面，按指定权益编号读取详情，不依赖当前分页中包含该产品。

渠道拥有方提供客户隔离的授权元信息、全部保留调用分页和原子密钥重置；历史秘密不返回，新秘密仅当前操作展示，重置保留权限、来源、有效期及限流用量。快速翻页和客户切换使用请求代次防止旧响应覆盖；列表失败可重试，重置前确认。

详情宽度固定，产品和调用记录使用官方完整分页、有界表格及内部横向滚动。状态和操作固定在右侧，普通行白底、灰色表头；提示、状态与中英文名称使用短文案，不显示内部配置正文。

## 权限、性能与装配

核心仅查询自身客户、账务、交易及产品表；渠道仅查询自身授权和调用。员工、租户、客户可见范围及精确权限沿用已有边界，服务器编辑新增`idc:admin:resource:server:edit`，读详情保留原查看权限。没有跨插件查表或新增缓存。

钱包一次集合查询；产品客户可见性检查加总数、当前页及配置名称批量投影，访问次数固定，不按返回行发起详情请求。配置名称数量和页大小有上限。渠道调用记录为准确总数与当前页查询。

后台控制器继续复用`backend/plugin.go`启动创建的管理及报价实例；报价实例复用已有数据库、员工身份、授权和业务上下文，客户与后台委托同一私有升降级实现。不模拟客户上下文，不在请求中创建独立服务图。接口方法及控制器骨架通过隔离`make ctrl`生成并填入实现，无宿主修改、手工生成模型或新迁移。
