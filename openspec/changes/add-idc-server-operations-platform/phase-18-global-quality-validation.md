## 隔离故障注入补充验证

本轮用隔离数据库`cloud_codex_fb54b_20260831`和独立配置实际启动接口、管理后台、客户后台三个服务。在服务持续承接公开目录请求期间，主动终止该隔离库的 10 条业务连接；随后连续 40 次公开目录请求全部返回`200`，连接池重新建立连接，没有把数据库瞬断变成永久故障。

之后实际终止后端进程，再通过同一开发入口重新启动完整三服务。后端进程号发生变化，`6030`、`6031`、`6032`重新由三个独立进程监听并全部恢复探活。重复回调、乱序终态保护、队列租约/积压恢复、第三方超时、结果未知、补偿失败及`cluster.enabled=false/true`缓存失效继续由各领域既有自动化测试覆盖；真实进程和数据库故障不再只是模拟。测试结束后已正常停止三个服务，未删除隔离数据库和配置，便于后续复核。基于这些证据，任务`18.6`关闭。

## DAO、CTRL 与接口生成复核

为避免把旧电脑的数据库密码写回仓库，`linactl`新增仅作用于当前进程的`LINA_CODEGEN_DATABASE_LINK`覆盖入口；测试证明它不会修改插件的`hack/config.yaml`。`go test ./internal/goframecli -count=1`和完整`go test ./... -count=1`均通过；需要真实符号链接的测试会在 Windows 未开启对应权限时按已有跨平台策略跳过，不再把操作系统权限缺失误记成工具逻辑失败。

使用专用数据库`linapro_idc_codegen`实际完成以下生成：

- DAO：`content-notice`、`idc-ai`、`idc-baota`、`idc-channel`、`idc-compliance`、`idc-core`、`idc-dcim`、`idc-notify`、`idc-payment`、`idc-portal`、`idc-resource`、`idc-v10`、`idc-zjmf-finance`、`idc-zjmfcloud`、`idc-zjmfmigrate`、`shared-services`、`tenant-core`、`yunsu-ssl`，18 个配置组均成功。
- CTRL：`content-notice`、`idc-ai`、`idc-channel`、`idc-compliance`、`idc-core`、`idc-notify`、`idc-payment`、`idc-portal`、`idc-resource`、`idc-zjmfcloud`、`idc-zjmfmigrate`、`staff-access`、`tenant-core`，13 个含 API 的插件均实际运行生成命令。

当前 GoFrame CTRL 模板默认按单控制器生成，与这些插件已有的多控制器、分组构造和显式依赖注入布局不兼容。生成结果中出现 403 个空的`CodeNotImplemented`方法、重复构造和重复接口；复核后只移除了本轮生成的空壳，保留并校验仓库原有控制器实现，没有用空壳覆盖业务代码。`CodeNotImplemented`扫描为 0；门户品牌控制器方法已按 API 接口命名对齐；魔方云与迁移插件的重复空构造已移除。

DAO 刷新还暴露出服务器操作仍写入已由`086-generic-commerce-shadow-removal.sql`删除的通用交易旧字段。报价、换 IP、变配和附加能力结算现改为通用报价/订单明细加独立数量快照，不再写`product_type_code`、`server_quantity`、`binding_no`或`initial_binding_no`影子列。`idc-core`服务器操作包测试通过；上述 13 个含 API 插件全部执行`GOWORK=off go test ./... -run '^$'`并编译通过。接口时间字段继续沿用既有 Unix 毫秒契约，纯日期继续使用`YYYY-MM-DD`字符串，本轮生成未引入新的时间语义。基于这些证据，任务`18.8`关闭。

## FB-55 迁移菜单双语补漏

真实 Chrome 复核插件开发指南时发现，`idc-zjmfmigrate`已经声明启用`zh-CN`和`en-US`，但插件自己的`manifest/i18n`缺少`menu.json`，宿主只能回退显示`plugin.yaml`中的英文“Migration checks”。本轮为七项迁移菜单和按钮权限分别补齐中英文标题，不修改迁移 API、权限、数据或业务流程。

`make.cmd i18n.check plugins=1`运行时文案、消息覆盖和前端键检查均为 0 违规；`make.cmd plugins.check`扫描 3,387 个文件、0 个治理问题；E2E 治理扫描 246 个文件、17 个范围通过。插件自有`TC002-migration-menu-i18n.ts`使用真实 Chrome 验证中文“迁移检查”和英文“Migration Checks”能够随界面语言切换，`1 passed`。截图为`temp/20260831/20260831-184340-migration-menu-zh.png`和`temp/20260831/20260831-184341-migration-menu-en.png`，人工复核未发现原始翻译键或菜单错位，因此`FB-55`关闭。

本修复只有插件运行时`i18n`资源和测试影响；缓存、数据权限、API、数据库、后端依赖和开发工具跨平台均无影响。
