# 第 7.10 项支付对账验收记录

## 交付范围

- 支付插件新增按商家时区、支付通道和业务日唯一的对账批次，并保存不可修改的渠道来源记录、差异记录、渠道健康状态和补入账申请。
- 自动来源只接受通道已经声明并实现的账单或权威查询能力；没有能力的通道显示“无法自动对账”，结果保持未知，不猜测成功或失败。
- 差异固定分为本地未入账、渠道缺少记录、金额不一致、状态不一致和重复交易。来源、本地候选、批次列表和差异列表都设有固定上限。
- 只有“渠道成功、本地未入账”且支付、客户归属、通道、币种、金额、渠道交易号全部一致时才允许提交补入账。提交人不能复核自己的申请；批准后只进入原支付确认队列，不直接改账，也不直接触发重复履约。
- 后台页面位于 `apps/lina-plugins/idc-payment/frontend/`，没有向 `web-antd` 写入 IDC 业务代码。

## 权限和数据范围

- 查看、提交补入账、复核补入账使用三个独立权限。
- 这些接口只允许直接登录的后台工作人员使用，拒绝模拟登录和代租户操作。
- 当前支付插件是每套安装独立运行的本地商家能力，数据固定属于本安装的商家范围（`tenant_id=0`）；因此本项没有跨租户或跨组织数据，不接入中央平台，也没有中央结算、中央回调或软件提供方业务依赖。

## 第 7.11 项异常回归

- 支付宝、微信支付和易支付适配器测试分别验证旧密钥、错误公钥或被篡改字段不能通过验签。
- 真实 PostgreSQL 回归验证金额不符、币种不符和多付全部进入人工核对且不入支付确认队列；同一成功通知只入账一次。
- 真实 PostgreSQL 回归验证组合支付失败会释放余额锁，订单关闭后的迟到成功款进入待归属异常款，不会复活原订单。
- 退款回归验证重复结果幂等复用，连续权威查询仍无法确定的退款进入结果未知；撤销、退单和结算逆转不会误走普通成功入账路径。
- 设置 `LINAPRO_IDC_PAYMENT_TEST_DSN` 后执行 `go test ./backend/... -count=1`：通过；支付插件 `lint.go`：通过，0 项问题。
