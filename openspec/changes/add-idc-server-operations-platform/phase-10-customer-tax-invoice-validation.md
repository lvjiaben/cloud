## 已冻结的客户流程

1. 客户从自己的有效常用抬头中选择一个；页面优先选中客户明确设置的默认抬头，没有默认时只选择返回的第一个有效抬头，客户仍可改选。
2. 客户选择一张或多张仍有可开票余额的已付款账单，并为每张账单填写本次金额；页面不自动把剩余额度填满。
3. 一份申请只允许同一币种，最多选择`20`张账单；金额按该币种的小数位转成整数最小货币单位，不使用 JavaScript 浮点数。
4. 客户不选择票种，也不能提交税率、税额、税收分类、销售方、供应商或客户编号。
5. 点击提交后直接创建待后台审核申请，不额外增加未确认的二次确认步骤；服务端立即占用逐账单可开票额度并冻结抬头与税务快照。
6. 历史页面只显示当前客户自己的状态、金额、待后台确认或已确认票种、脱敏发票号和七类客户可见原因，不显示后台内部备注。

## 对外接口与安全边界

| 接口 | 用途与限制 |
| --- | --- |
| `GET /account/compliance/tax-invoice-options` | 返回当前客户最多`50`个有效抬头和最多`50`张仍可开票的已付款账单；剩余额度已经扣除现有申请占用 |
| `POST /account/compliance/tax-invoices` | 只接受抬头编号、一至二十个账单编号与逐账单金额、随机重试键；精确重试只恢复原申请 |
| `GET /account/compliance/tax-invoices` | 使用稳定游标读取当前客户自己的申请历史，不返回精确总数、不调用供应商 |

客户归属由服务端从当前登录身份取得，请求没有`customerNo`。新增契约测试确认客户响应没有客户编号、后台内部备注、供应商编号、外部发票引用或加密快照引用；创建请求也没有票种、税率、税额、销售方或供应商字段。

后台已有的供应商中立申请服务继续负责不可变抬头和税务快照、逐账单与逐明细分配、并发防超额、精确幂等和失败关闭。本任务没有新增跨插件查表、站内 HTTP 回环、中央网关、中央结算或软件提供方业务依赖。

## 客户页面

- 页面位于`apps/lina-vben/apps/web-customer/src/views/account/tax-invoices/index.vue`，路由为`/account/tax-invoices`，菜单名为“我的发票”/“My invoices”。
- 页面按“选择抬头、选择账单并填写金额、提交申请”展示，明确提示票种由后台确认。
- 选择第一张账单后，其他币种账单不可加入同一申请；达到`20`张上限后不再允许继续选择，并显示原因。
- 每张账单展示账单编号、订单编号、付款时间、已付金额和剩余可开金额；输入金额为空、格式错误、超过余额时不能提交并显示准确提示。
- 申请历史覆盖待审核、待提交、开票中、结果确认中、已开票、已交付、失败、驳回、取消和红字相关状态，以及全部七类客户可见关闭原因。
- 页面只属于`web-customer`，没有向`web-antd`、旧 Portal 或官网写入页面、路由、状态、接口或双语资源。

- 页面和接口严格执行当前客户隔离，客户请求只包含有权选择的抬头、账单、金额和重试键。
