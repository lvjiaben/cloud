# 资源任务状态矩阵验证记录

## 完成范围

本轮完成任务 8.2.a 和 8.5.a，固化`resource` owner 内部的`Provider`任务状态、转换规则与安全领取，不把尚未实现的`core`权益、运行状态、跨 owner `Saga`或具体服务器操作编排标记为完成。

- 定义`pending`、`submitting`、`accepted`、`running`、`retry_wait`、`succeeded`、`failed`、`result_unknown`、`manual_takeover`和`canceled`十个持久化状态，与资源任务表约束一致。
- 转换只接受“上游接受”“上游明确未接受”“权威查询观察”或“独立人工授权”四种互斥证据类别；证据对象不携带上游文本、秘密、句柄或原始负载。
- `submitting`只有在明确证明未接受时才能进入`retry_wait/failed`；无法确定写入结果时只能进入`result_unknown`，形成禁止自动重放的硬栅栏。
- `accepted/running`遇到查询暂时失败时保持已知接受状态，不得退回重试或猜测结果未知；后续只能由权威查询收敛，或由独立授权并审计的人工流程接管。
- `succeeded/failed/manual_takeover/canceled`均为封闭终态；同状态覆盖、未知状态、无证据跃迁、多证据混用和终态回滚全部拒绝。
- 领取固定为最多 32 条的有界批次，使用`FOR UPDATE SKIP LOCKED`防止并发 worker 重复领取，并在同一事务内递增尝试次数、版本和租约。
- 事务先冻结租约已过期的`submitting`任务，再领取`pending/retry_wait`；崩溃中断的外部写直接进入`result_unknown`，清除租约并保留固定脱敏原因，永不自动重领。
- 可执行时间、租约起点和过期判断全部读取 PostgreSQL 的`CURRENT_TIMESTAMP`，不依赖应用节点时钟。
- worker 的结果转换同时校验任务号、当前`submitting`状态、尝试次数、随机租约令牌和数据库时间下仍有效的租约；迟到或重复 worker 无法覆盖已收敛任务。
- 待领取任务在租约落库前重新经过完整`OperationRequest`秘密与能力校验；被污染或非法的持久化参数在任何上游调用前以“已证明未提交”收敛为失败，并使用固定脱敏原因，不让单条坏记录阻塞同批正常任务。
- 重试、已接受、运行和结果未知都必须给出不超过 24 小时的下一次调度时间；达到尝试上限禁止进入重试，终态禁止携带调度时间。
- 任务创建只持久化调用方幂等键的 SHA-256 摘要；同一渠道重复请求返回原任务，复用同一键修改能力、目标、资源池、策略或规范化参数时拒绝冲突。
- 创建事务以共享锁确认渠道及可选资源池仍启用，停用渠道无法接收新任务；参数必须先通过完整秘密扫描并规范化为稳定 JSON 对象，原始幂等键和秘密均不进入任务表或返回投影。
- 任务秘密输入与任务创建同事务写入独立绑定表，任务领取以一次有界集合查询恢复不可序列化 handle；返回投影没有秘密引用字段。同一幂等键若换用不同 handle 明确冲突。
- 除`retry_wait`外，任务取得提交结果、被本地验证拒绝或执行租约过期时，输入绑定都在同一事务撤销；已证明未接受且允许重试时才保留绑定。
- 异步接受结果必须携带与目标状态一致的上游任务状态，并把渠道、外部任务号、可选资源号和步骤与本地转换原子落库；缺少或状态不匹配均拒绝。

## 验证结果

- 状态矩阵表驱动测试覆盖领取、取消、已接受、同步成功、已证明未接受、结果未知、查询收敛、人工接管和全部关键拒绝路径。
- 终态完整性测试枚举全部声明状态，逐一验证四种终态不能迁移到任何状态。
- 资源任务状态包以随机测试顺序连续运行 20 轮通过。
- 真实 PostgreSQL 隔离 schema 测试以四个并发 worker 领取 16 条任务，连续 20 轮均得到 16 个唯一任务；同时证明活动租约不会重领、过期写会冻结且`result_unknown`不会重领。
- 真实库测试还验证了有效租约可以转为`accepted`并清除执行租约、记录接受/观察时间，而同一租约的迟到重复回报会被完整栅栏拒绝。
- 真实库测试验证首次创建、语义等价参数重放、变更能力冲突、仅保存 64 字符摘要以及渠道停用后拒绝新任务；上述路径同样连续运行 20 轮。
- 真实库测试验证任务领取只返回 handle、接受结果后输入绑定立即转为`revoked`，以及同一幂等键改变 handle 被拒绝。
- 真实库测试验证`accepted`转换与第一步上游任务绑定同事务写入，并由复合外键保证绑定渠道与任务渠道一致。
