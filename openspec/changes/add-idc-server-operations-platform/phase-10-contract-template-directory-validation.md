# 第十阶段合同模板目录与腾讯手工同步验证记录

## 结论

`10.8.c.1`要求的合同模板目录、筛选、分页、权限拆分和腾讯手工同步已经在`idc-compliance`插件内实现，并通过任务范围内的 Go、真实 PostgreSQL、前端类型、插件构建和真实 Chrome 验证。列表只读取本地投影，不会在打开页面、翻页或筛选时调用腾讯；同步失败不会改动原有投影，可以再次手工重试。

此前阻断本项收口的全仓双语检查和全量 E2E TypeScript 编译问题已经修复并重新验证通过。本轮`lina-review`没有发现本项仍存在严重或一般问题，因此`10.8.c.1`可以按当前证据精确勾选；这不代表`10.8.c.2`或父任务`10.8.c`完成。

合同模板页面属于 IDC 管理后台，只存在于`apps/lina-plugins/idc-compliance/frontend/`并通过插件页面机制加载；`apps/lina-vben/apps/web-antd/`没有本项 IDC 页面、接口、状态、语言包或依赖改动。客户合同、签署和开票页面仍按`10.12`直接进入`apps/lina-vben/apps/web-customer/`。

## 问题原因与修复

本轮复核发现并修复了以下实际问题：

- 模板同步和正文写入原来把动态`g.Map`直接交给数据库批量保存，类型不够明确；已改成专用结构，字段和空值规则可由编译器检查。
- PostgreSQL 名称搜索原来的`ESCAPE`写法表示了两个字符，真实数据库会拒绝；已改为单个反斜杠转义，并用真实 PostgreSQL 覆盖名称搜索。
- 一个 PostgreSQL 约束名超过 63 字节，数据库会静默截断；已缩短为稳定名称，避免不同安装或后续迁移出现对象名碰撞。
- 追加式迁移测试中的旧合同模板夹具缺少当前必填的摘要、密钥、PDF 和字段信息；已补齐合法的不可变版本快照。
- 首次真实浏览器测试发现模板表格的固定宽度会撑大整个卡片，导致查询和重置按钮在窗口右侧不可见；已限制卡片和筛选区宽度，并把溢出留在表格内部。

## 性能与安全判断

- 列表使用一条有边界的 PostgreSQL 查询完成最新版本关联、筛选、倒序和 20 条分页，不按返回行数逐条查库，没有`N+1`查询。
- 列表、翻页和筛选都不访问供应商；腾讯只在管理人员手工同步时调用一次。
- 同步使用有类型的暂存数据、一次数据库事务和事务级互斥锁批量更新，避免并发同步产生两个活动投影。
- 查看与管理权限在服务端分别校验；权限拒绝发生在调用腾讯之前。
- 供应商编号、版本号和状态只作为本地投影依据；供应商停用或下线不会物理删除已被合同引用的版本。
- 本项没有新增缓存，也没有新增后端运行期依赖注入；缓存一致性和新的运行时服务装配均无影响。

## 接口、数据库和双语影响

- 接口：模板列表和详情使用查询权限；腾讯同步、复制、编辑和启停使用管理权限。路径和方法维持本阶段已冻结的插件管理接口，没有把 IDC 接口放进框架宿主。
- 数据库：继续使用本阶段的`009-electronic-contract-template.sql`。本轮只纠正数据库对象名和测试数据完整性；安装 SQL 保持幂等，真实 PostgreSQL 安装、重复执行和工作流测试通过。
- 双语：合规插件合同语言包中英文键数量均为`183`，键集合一致；真实 Chrome 已看到中文状态和按钮，没有显示原始翻译键。本轮页面宽度修复没有新增用户文案。
- 数据权限：当前是购买方单套独立安装的后台管理数据，使用默认本地租户边界；查询和管理动作仍分别经过宿主授权接口，没有扩大角色权限效果。
