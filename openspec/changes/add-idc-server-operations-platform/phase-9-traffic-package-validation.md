# 第九阶段流量包适配器验证记录

## 完成范围

本记录对应子任务`9.4.g`，只闭环`idc-zjmfcloud`向当前有限流量实例增加临时流量的适配器契约。流量包商品、报价、账单、付款、权益核销、自动解除暂停和周期重置仍分别归商品、交易、履约与生命周期拥有方；公共动作入口和资源拥有方业务编排尚未完成，父任务`9.4`继续保持未完成。

用户提供的旧魔方财务连接器在`DcimCloud.php`中精确证明：流量包履约执行`PUT /clouds/:id/temp_traffic`并提交整数`traffic`；实例同步通过`GET /clouds/:id`读取`traffic_quota`和`tmp_traffic`，当基础额度非零时以两者之和形成总额度。旧连接器把购买后解除暂停、财务日志和本地流量投影混在同一方法，本适配器不复制这些越界职责。

## 实现边界

- `server.traffic-package`声明为`conditional`，只公开`action=add`和必填`traffic_gb`；数量必须为 1 至 1,000,000 的规范正整数，未知字段、覆盖、减少和`force`在认证前拒绝。
- 写前读取一次实例详情，要求`traffic_quota/tmp_traffic`均为规范非负整数且`traffic_quota>0`。`traffic_quota=0`表示无限流量，增加临时流量没有合法业务语义并失败关闭；相加溢出也不发送写请求。
- 只发送一次`PUT /clouds/:resource_ref/temp_traffic`，表单固定为`traffic=:traffic_gb`；调用内冻结`before_tmp_traffic + traffic_gb`作为唯一后置目标，不接受调用方提交绝对目标值。
- 写响应携带真实`taskid/task_id`时返回`accepted`。没有任务号的 2xx 普通成功或空响应、`401`及传输歧义都只读回查一次实例详情；仅当`tmp_traffic`精确等于冻结期望值时成功，否则保持不可重试的结果未知。明确`400/403/404/405`保持确定失败。
- 每个调用最多一次写入；写`401`只失效旧令牌，回读可以安全刷新令牌但不得重放。Provider 不读取账单、付款或本地权益，也不在增加流量后自动恢复实例。

## 测试与规则域

受控 TLS 假服务覆盖精确方法、路径与表单、任务号受理、同步回读、数量边界、前值加法、无限流量拒绝、详情字段缺失或小数、未知字段、普通成功无法证明、写`401`不重放和传输断线后精确回读。测试自包含且可乱序运行，不访问生产 Provider。

- 架构与插件：实现闭环在源码 Provider 适配器，只消费`resourcecap`既有公开契约；财务、权益与生命周期职责没有倒灌适配器。
- 性能：每个动作固定一次写前实例读取、一次写入，无任务号时一次回读，不存在循环远程请求或`N+1`。
- 数据权限：没有新增公开 HTTP 入口；`ResourceRef`仍必须由资源拥有方按本地资源与渠道映射后传入，客户/后台权限和数据范围入口尚未实现。
- API、数据库、缓存、前端、E2E、开发工具与运行时`i18n`：无影响。没有路由、DTO、SQL、缓存、页面、运行时文案、脚本或工具变化；中英文技术`README`同步维护。
- 安全：没有绝对覆盖、减少、重置、无限流量、批量或强制路径；歧义写绝不重放，只有真实任务号或精确后置状态可收敛。
