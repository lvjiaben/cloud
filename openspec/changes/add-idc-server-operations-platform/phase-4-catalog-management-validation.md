# 第四阶段商品目录管理事务验证记录

> **`FB-52`失效声明：**本记录把分类和商品固定为`cloud_server/bare_metal`并要求类型匹配，原结论已经失效，不能作为当前目录管理完成证据。分类只用于商家整理目录，不决定商品种类或字段；通用商品由商家自由创建，专用配置来自冻结插件契约。下文仅用于旧字段、旧接口、旧页面和开发数据迁移对账。

## 结论

`4.2.b`的插件内实现已经完成。后台手工创建分类和商品分别使用精确员工权限，授权在任何目录表访问之前完成；只接受直接员工、默认商家上下文以及全局或本商家数据范围。创建商品会在同一事务中生成新商品和首个空白的`manual + draft`版本，商品当前版本指针保持为空，不会顺带产生配置、价格、资源池或销售状态。

> **FB-52 纠偏说明：** 本记录证明的是当时服务器专用实现曾经通过测试，不再代表当前正确业务要求。其中“商品类型必须与云服务器或裸金属分类一致”的门禁已经确认错误，必须删除；分类不得限制商品种类。其余事务回滚和多语言证据只能在完成通用商品重写后重新验证，不能直接复用为完成证据。

当时实现要求商品类型与仍启用且未删除的云服务器或裸金属分类精确一致。分类、商品、版本和同事务业务审计任一步失败都会整体回滚。插件自身多语言覆盖通过；仓库级`make.cmd i18n.check`仍仅被无权修改的宿主通知预览页 6 个既有缺失键阻断，因此子任务暂不勾选。

## 实现范围

- 分类创建要求中英文名称和明确的`cloud_server`或`bare_metal`类型；存在父分类时先锁定仍启用、未删除的父分类，并要求类型一致。
- 商品创建要求云服务器或裸金属分类、固定或可配置模式、规范公开 slug、中英文名称及受长度约束的双语摘要；商品类型与分类不一致时返回稳定冲突错误。
- 分类、商品和版本业务号分别使用`ctg_`、`prd_`和`ver_`前缀以及 128 位密码学随机值，不暴露数据库自增主键，也不从名称或上游编号推导。
- 商品和版本同事务写入：商品状态为`draft`、当前版本为空；首个版本号为 1、来源为`manual`、状态为`draft`，发布时间为空；配置组和其他商品子图保持空白。
- 分类创建与商品创建使用不同的精确权限。生产授权器拒绝终端客户、代理身份、跨租户、无身份、非活动员工和无法表达的数据范围；宿主通配权限与平台管理员仍按宿主治理规则生效。
- 两类创建操作都追加同事务业务审计。真实 PostgreSQL 用例证明审计写入失败时商品和版本均不残留。
- 新版本创建时该版本行尚不存在，因此不存在可提前锁定的父行；后续对既有版本的配置、价格、计费、兼容和资源池子图写入，仍必须首先锁定该父版本行。

## 任务级审查

- 已确认授权器在输入规范化、业务号生成和任何目录 DAO 访问前执行；授权失败不会探测分类或商品是否存在。
- 已确认分类创建和商品创建权限互不替代，来源插件的商品草稿创建能力也不能调用后台手工管理服务。
- 已确认商品与版本始终同事务，审计失败会回滚两张表；不存在“商品已创建但版本或审计缺失”的中间状态。
- 已确认新商品没有当前发布版本、配置、价格或资源池，不会因创建动作直接进入可售状态。
- 已确认业务号使用固定长度的 128 位随机值，分类引用只接受`ctg_`命名空间，避免不同业务对象编号误用。
- 已确认每次创建只执行固定数量数据库操作，不存在按配置项、分类树节点或返回行数增长的查询。
- 严重、外部既有阻断：`apps/lina-vben/apps/web-antd/src/views/system/message/notice-preview-modal.vue`引用的 3 个宿主键在`en-US`和`zh-CN`均缺失。当前仓库没有`.contributing`，本任务无权修改宿主目录，不能把仓库级 i18n 门禁标记为通过。
