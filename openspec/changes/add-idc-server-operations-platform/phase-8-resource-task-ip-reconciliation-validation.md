# 换 IP 未知结果专用对账验证记录

## 完成范围

本轮完成任务 8.5.c.2.b.2.a。魔方云换`IP`写接口没有可靠上游任务号时，resource owner 现在使用新鲜资源快照中的白名单数量投影进行参数专用对账。父任务继续保持未完成；重装、变配、重启与重置密码的专用证明、跨 owner 回报、秘密孤儿补偿、具体能力参数编排和生产作业装配仍在 8.5.c.2.b.2.b。

- 只领取具有精确活跃资源映射、没有上游任务绑定且处于`result_unknown`的任务；只调用`QueryResource`，不重复执行换`IP`写请求。
- 数据库事务重新锁定任务后读取权威`sanitized_parameters`，不信任执行器传回的期望值。
- 期望值必须是任务 JSON 中`ip_num`字段的精确正整数，范围固定为 1 至 65535；字符串、浮点数、缺失值和越界值全部拒绝。
- 实际值必须是 Provider 白名单资源投影 JSON 中`ip_count`字段的精确整数，且与期望值完全一致。
- 快照资源号必须匹配活跃映射，观察时间不得早于当前租约；资源状态只允许运行、活跃、停止或暂停，失败、终止、未知和待处理状态不能结案。
- 成功时保存`resourceState`和`ipCount`两条拥有方证据，再与任务成功状态同事务提交；数量不一致时不写证据、不改变任务结果。

## 依赖与性能

- 没有新增运行期依赖、构造函数、跨插件契约或缓存。复用现有`Store`、资源映射和 Provider 只读查询路径。
- JSON 解析只处理已经受 Provider/任务契约大小上限约束的单任务文档；每轮任务数固定最多 32，同一渠道只构造一次 Provider。
- 数据库领取、映射装配和租约栅栏继续使用现有有界集合查询；专用判断不会新增数据库查询或远程调用。

## 影响判断

- `API`：没有 HTTP API、路由、DTO、权限标签或公开响应变化。
- 数据权限：仅处理 tenant 0 resource owner 内部已领取任务；任务参数与映射均从租约事务重新读取，没有新增接受外部对象编号的入口。
- SQL：没有迁移、表、字段、索引、Seed/Mock 或 DAO 生成变化；复用不可变任务证据表。
- 缓存：无影响，不引入缓存或进程内权威状态。
- `i18n`：没有用户可见页面、运行时文案、API 文档、菜单、字典或语言包变化。
- 开发工具与跨平台：没有构建、生成、CI、脚本或平台入口变化。
- 测试与 E2E：没有页面、HTTP API 或前台行为变化，不触发 E2E 与 Chrome；内部行为由单元测试和真实 PostgreSQL 覆盖。

## 剩余门禁

- 重装、变配、重启和重置密码不能复用 IP 数量判断，必须取得各自足以证明结果的专用投影或进入人工处理。
- 当前缺少稳定的服务 owner 幂等回报契约，不能从 resource 插件直接访问其他插件内部实现。
- 秘密 sink 孤儿补偿和`pluginhost.Jobs`启动装配尚未完成，因此执行器继续禁止生产注册。

## 完成后审查

已按`lina-review`完成参数与快照身份、JSON 数值语义、快照新鲜度、证据原子性、查询次数、测试覆盖和未实现边界审查，最终未发现未解决问题：

- 任务参数由数据库租约事务重新读取，资源编号由同一 tenant/channel/provider 维度的唯一活动映射提供，快照编号与观察时间继续执行严格一致性和新鲜度检查。
- `ip_num`与`ip_count`都使用 JSON 整数解码，拒绝字符串、浮点数、缺失值和越界期望值；仅精确数量一致且资源状态属于安全白名单时结案。
- `resourceState`与`ipCount`证据、任务成功状态在同一数据库事务提交，失败与数量不一致路径不会留下部分证据。
- 专用判断复用同一资源快照，不增加数据库查询或远程调用；领取批次仍固定最大 32 条，不引入 N+1。
- 开发过程中真实 PostgreSQL 用例先后暴露了错误的能力代码 fixture 和事务重读未投影`sanitized_parameters`两个根因，均已修正并由 20 次乱序单测、20 次真实 PostgreSQL 回归覆盖。
- 重装、变配、重启、重置密码、跨 owner 回报、秘密孤儿补偿和生产作业装配仍明确保留为后续任务，没有被本轮状态判断错误宣称完成。
