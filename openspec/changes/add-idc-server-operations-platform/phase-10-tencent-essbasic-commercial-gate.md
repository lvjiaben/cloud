# 第十阶段腾讯电子签官方契约与运行时能力门禁记录

> 状态：本文件保留旧“软件提供方中央代接”审计的历史背景，但该架构假设已经废止。当前实现固定为每套安装由购买方使用自己的腾讯企业账号、第三方应用、技术凭据、供应商主体和结算关系独立接入。

## 1. 结论

核验日期：`2026-08-14`；合同模板正文提交能力于`2026-08-15`再次核验。

腾讯电子签集成版官方公开资料已经提供当前实现所需的应用鉴权、企业与员工、模板、合同发起、签署链接、合同查询、下载、企业自动签授权、扩展服务状态和用量查询契约。用户进一步确认：腾讯电子签由购买方自行对接，软件提供方只需正常交付功能，不代持账号、不代理结算，也不承接业务回调。

因此，任务`10.4.b`不再要求软件提供方为全部购买方另行取得腾讯书面商务确认。官方公开接口是开发依据，生产放行改为每套安装的运行时能力检查：

- 每套安装只使用购买方自己的`SecretId`、`SecretKey`、`AppId`、企业主体和操作人身份。
- 软件提供方不提供中央腾讯应用、中央业务网关、中央结算、统一回调或跨购买方主体路由。
- 购买方实际产品版本、企业与操作人实名、应用状态、目标接口权限、白名单、扩展服务、下载授权和套餐逐项检查；不满足的能力单独关闭并显示原因。
- 运行时能力不足不会退回中央服务，也不会阻塞没有强制合同要求的普通个人服务器订单。
- 本记录只冻结公开契约和能力门禁，没有调用腾讯生产接口，也没有创建、修改或删除腾讯对象。

诺诺电子发票不适用本次结论，仍受`10.4.c`和`10.10`的独立外部证据门禁约束。

## 2. 已废止假设

此前审计假设软件提供方使用中央第三方应用代表多个购买方调用腾讯，再从中推导统一书面授权、平台销售注册、跨客户路由、预付或后付结算与中央回调。该假设与完整私有化交付边界冲突，现已全部废止：

1. 购买方不是软件提供方中央腾讯应用下由软件提供方运营的业务租户。
2. 每套安装与软件提供方自营部署同级，自己配置腾讯账号和应用并直接承担供应商费用。
3. 腾讯服务协议中针对中央转售或向第三方开放技术接口的风险，不再构成本项目购买方自有应用模式的统一开发前置条件。
4. 某个购买方账号因版本、权限、白名单、套餐或主体状态不能调用某项接口时，只关闭该安装的对应能力，不改变产品架构。

## 3. 官方公开契约冻结

所有接口使用腾讯电子签集成版`2021-05-26`版本和腾讯云`API 3.0`签名。生产通用端点固定为`essbasic.tencentcloudapi.com`；联调端点与生产端点不得混用。优先使用腾讯云官方 Go SDK，禁止实现允许管理员提交自定义端点的通用转发器。

## 4. 每套安装运行时能力矩阵

| 能力键 | 放行条件 | 关闭时页面行为 |
|---|---|---|
| `tencent.essbasic.base` | 购买方应用配置可用、环境匹配、企业与操作人身份满足腾讯要求 | “暂不可开通”并显示封闭原因和重新检查入口 |
| `tencent.essbasic.template` | `base`有效且模板读取权限、主体和模板状态有效 | 模板列表只显示不可用原因，不允许创建合同 |
| `tencent.essbasic.flow_create` | `template`有效，签署方、变量、顺序、订单快照和本地门禁通过 | 不创建腾讯流程、不消耗套餐 |
| `tencent.essbasic.h5_sign` | 合同仍可签且当前客户匹配目标签署方 | 不生成链接；已有短期链接不得当作永久入口 |
| `tencent.essbasic.flow_query` | 只读查询权限有效并存在受保护外部流程号 | 保持可重试或人工复核，不猜测终态 |
| `tencent.essbasic.flow_download` | 权威状态允许下载且购买方下载授权有效 | 保留合同状态，延后本地归档并显示授权原因 |
| `tencent.essbasic.enterprise_auto_sign` | 腾讯白名单及企业/印章授权有效，本地模板、范围、有效期、金额和次数策略有效 | 默认关闭；任一层撤销后立即停止新自动签流程 |
| `tencent.essbasic.personal_auto_sign` | 首版不放行 | 固定关闭 |
| `tencent.essbasic.evidence_report` | 购买方已购买对应服务且调用主体和接口权限有效 | 不承诺或伪造报告归档 |
| `tencent.essbasic.usage_detail` | 当前用量接口可用且有界采集配置有效 | 停止新采集，保留历史投影和重试状态 |

能力只能逐项启用，禁止使用一个“腾讯电子签已开通”布尔值放开全部接口。运行时检查结果只保存安全状态、时间和封闭原因，不保存供应商原始报文、技术秘密或主体原文。

## 5. 用户可见功能冻结

1. 后台入口固定为“合规中心 → 电子合同”。
2. 开通使用一个分步页面：企业资料确认 → 前往腾讯办理 → 返回后状态检查 → 印章与下载授权。
3. 财务、法务或其他获授权管理员可以发起；法定代表人或超级管理员完成腾讯要求的外部认证。
4. 暂不可用时显示“暂不可开通”、具体原因和重新检查，不显示原始秘密输入框。
   企业资料确认只读显示现有企业法定名称、地区和本地商家编号，不在本系统收集统一社会信用代码、法定代表人身份证、手机号或其他腾讯认证敏感资料；腾讯官方短期办理链接在新窗口打开并保留原向导，办理完成后由发起人回到原页面点击“重新检查”。
5. 模板列表展示名称、适用范围、签署顺序、状态和更新时间；提供预览、复制、编辑草稿、启用和停用，已使用模板版本不可直接删除。
   本地草稿可以继续保存正文、生成并确认`PDF`、设置字段与签章位置；在腾讯公开模板创建契约缺失期间，“提交腾讯”保持禁用并显示普通人能看懂的原因，本地草稿不得因此被标成已提交或可启用。
6. 合同默认可选，可按企业、商品或订单设为必须签约；只有明确要求签约的订单等待签署后履约。
7. 企业自动签独立授权且默认关闭，限定模板、业务范围、有效期、金额和次数，启用要求最近五分钟完整登录与二次确认，并允许立即撤销。
8. 客户从“我的合同”或订单详情进入腾讯`H5`签署，返回后显示处理中、已完成或失败以及重新检查/重试入口。

客户页面最终归属`@lina/web-customer`，但当前第十阶段不得因此提前进入第十五阶段；`10.8`先完成腾讯客户端、管理端向导和领域能力，客户页面由`10.12`在届时已冻结的前端边界内实现。

## 6. 隔离验证要求

真实生产配置启用前，必须使用购买方控制的测试应用、测试企业/操作人和测试流程完成契约验证，不得探测或改写未知生产对象。至少覆盖：

- 配置缺失、错误环境、未实名、无权限、无白名单、无套餐和供应商不可用时逐项失败关闭。
- 模板分页、模板变量缺失、个人与企业签署方不匹配和签署顺序。
- `H5`短期链接、返回后主动查询、重复请求和链接过期重新生成。
- 自动签启用、范围限制、次数/金额上限、腾讯或本地撤销后的新流程拒绝。
- 最终`PDF`下载、本地私有归档、哈希、短期地址过期和下载授权撤销。
- 用量最多`31`天窗口、每页最多`50`条、有界分页和未知套餐类型。
- 超时、`429`、供应商`5xx`和结果未知时不盲目重发外部写入。

## 7. 规范影响

- `API`：`10.8`按上述公开契约实现腾讯客户端和本地管理接口，不开放自定义腾讯端点，也不让浏览器提交原始秘密。
- 数据库：只保存本地不透明编号、安全状态、受保护引用、不可变快照和审计；主体与外部流程原文继续由本地网关保护。
- 数据权限：管理开通、模板、合同策略和自动签分别使用精确权限；客户只能访问自己的合同和订单。
- `i18n`：上述入口、步骤、状态、原因、操作和确认必须提供中英文。
- 外部写入：本记录没有执行外部写入；生产调用必须通过本地网关写租约、幂等、限流、熔断和结果未知保护。
- 后续任务：`10.4.b`已据此完成；`10.4`因诺诺`10.4.c`未完成仍不勾选。腾讯客户端、管理向导、模板、签署方、合同门禁、企业自动签和客户合同后端契约已经由`10.8.a`至`10.8.g`完成，整组证据见[腾讯电子签整组回归验证记录](phase-10-tencent-electronic-contract-regression-validation.md)。客户合同页面仍由`10.12`在`@lina/web-customer`实现，生产腾讯账号验收仍由每套购买方安装自行完成。
