# 第四阶段商品统一发布验证记录

> **`FB-52`纠偏说明：**本记录保存的是第四阶段旧服务器商品模型的历史验证证据，不能再作为当前通用商品模型的完成依据。其中“分类类型匹配商品”“固定配置项规范`JSON`”“所有商品必须绑定服务器资源池”和“保留 Provider 命名发布入口”等结论均已失效。当前权威要求以活跃变更的`design.md`、`tasks.md`、`specs/idc-product-fulfillment/spec.md`和`FB-52`验证记录为准；通用商品发布已经移除旧 Provider 专用适配入口，人工履约可以不绑定接口，插件履约只允许冻结一个兼容接口实例并通过停售准入门禁。

## 结论

`4.2.d`曾在旧服务器商品模型下完成。FB-52 保留了“所有来源共用唯一发布服务”这一正确边界，并已把通用商品发布接入自动化接口绑定与停售准入；旧 Provider 命名发布入口已经删除，不存在兼容适配器或第二条发布路径。其余旧销售完整性结论仅用于定位迁移范围，不代表当前验收通过。

插件后端、真实 PostgreSQL、代码质量和插件治理门禁均通过。插件自身运行时多语言与消息覆盖通过；仓库级`make.cmd i18n.check`仍仅被无权修改的宿主通知预览页 6 个既有缺失键阻断，因此子任务暂不勾选。

## 实现范围

- 发布使用独立精确后台权限，并在读取目标是否存在前完成直接活动员工、默认商家和数据范围授权。
- 事务依次锁定目标版本、所属商品、启用分类和唯一旧发布版本。目标必须仍是`draft`，分类类型必须与商品一致，商品当前版本指针必须与旧发布版本一致，新版本号必须严格递增。
- 统一门禁重新集合校验中英文商品、配置组和配置项销售文案，以及每个选项的规范组件 JSON、固定/可配置共享图不变量和所有启用兼容规则引用。
- 门禁从启用价格推导必售币种，并要求每个启用计费规则在每个必售币种都有基础价、所有启用选项价格和从数量零开始的阶梯；适用续费的规则还必须有显式续费金额。
- 所有来源都必须至少绑定一个启用的新单资源池，避免复制或手工草稿在没有履约路径时进入销售。
- `provider_import`在统一门禁之前额外调用`4.14.d.3`物化审核门禁，重新锁定并验证不可变审核证据、候选处置、币种、政策和权威商品图；其他来源若存在 Provider 完成证据则拒绝发布。
- 成功时唯一旧`published`版本原子转为`superseded`，目标转为`published`，商品状态、当前版本指针和版本号同步切换，业务审计在同一事务提交。任何重检或审计失败都会整体回滚。
- FB-52 已删除 Provider 旧入口`PublishProviderVersion`；HTTP 发布入口只调用统一`PublicationService.PublishVersion`，状态切换逻辑只有一份。
- 图装配采用固定数量的有界投影查询：配置、兼容共享 20,000 行总上限，计费规则最多 256 条，价格最多 100,000 条，资源池以 20,001 的有界计数判定越界；不存在按配置项、币种或价格逐行查询。

## 任务级审查

- **已修复**：统一门禁最初先于 Provider 特有重检执行，会改变既有 Provider 不完整场景的稳定错误语义。现先在相同锁内执行来源特有门禁，再执行公共可售门禁，既不削弱统一校验，也保持 Provider 审核错误的机器码契约。
- **已修复**：价格完整性最初可能从停用计费规则的历史价格推导必售币种。现只从启用计费规则关联的启用价格推导币种，停用历史不会扩大当前销售要求。
- **已修复**：公共门禁补充检查启用兼容规则的两端必须仍引用当前版本的启用配置项，避免孤立兼容边随版本发布。
- 已确认普通来源不调用 Provider 门禁，Provider 来源必定调用；测试以调用计数和真实物化证据共同证明来源分派。
- FB-52 已删除旧 Provider 发布文件；全插件生产代码仅统一服务执行商品版本发布、旧版本替代和当前版本指针切换。
- 已确认锁序与所有子图写服务使用的父版本栅栏一致，发布重检和状态提交之间不能插入绕锁商品图修改。
- 严重、外部既有阻断：`apps/lina-vben/apps/web-antd/src/views/system/message/notice-preview-modal.vue`引用的 3 个宿主键在`en-US`和`zh-CN`均缺失。当前仓库没有`.contributing`，本任务无权修改宿主目录，不能把仓库级 i18n 门禁标记为通过。

## 影响说明

- **API**：无新增 HTTP API；当前为插件内部统一发布服务。后台 API 落地时只能调用该服务。
- **SQL**：无新增迁移；复用现有商品版本、价格、资源池和 Provider 审核约束。真实 PostgreSQL 已验证锁定、切换和事务回滚。
- **缓存**：无影响；当前尚未接入公开商品缓存，发布后缓存失效会在销售读模型阶段统一设计。
- **数据权限**：有影响；所有来源发布都要求直接活动员工、精确发布权限和数据范围 1/2，授权先于目标存在性查询。
- **i18n**：新增`catalog.publication.incomplete`中英文错误消息；插件覆盖通过，仓库级门禁仍受上述宿主既有问题阻断。
- **前端与 Chrome**：无前端改动，不需要页面或 Chrome 验收。
- **Git**：未提交、未暂存、未推送。
