# FB-52 0.14 连接器与 SSL 插件验证记录

## 当前结论

任务 `0.14` 已完成。服务器、SSL 和完全人工非服务器商品三类完整闭环都已经用真实 PostgreSQL 重新执行；服务器连接器多接口与商品版本绑定已经通过真实 Chromium，SSL 独立页面的加载、主题、语言、窄屏、刷新、权限和生命周期场景也已通过。

目前已经完成六个独立托管动态连接器的清单、后端测试、Go 编译和真实 WASM 构建：

- 智简魔方公有云：`idc-zjmfcloud`

每个连接器均声明接口配置可维护多条实例，商品版本只冻结引用其中一条实例。连接器没有把供应商端点、账号或秘密写进通用商品。

## 运行时清单纠正

真实服务启动发现并修正了三项不能靠静态测试发现的问题：

1. `idc-zjmf-finance`曾声明后台和客户页面，但并没有交付对应前端资源。现在该连接器只声明它真实提供的服务器履约扩展点，共用服务器页面仍由`idc-resource`拥有。
2. `idc-resource`旧契约错误要求每个服务器连接器都必须自带后台和客户页面。现在页面声明为可选；连接器若声明页面，仍必须逐项通过宿主治理校验。
3. `yunsu-ssl`的 CSR 最大长度曾超过宿主结构化字段上限。清单和后端现在统一限制为 32768 字节，并有超长拒绝测试。

六个连接器已经重新构建到运行服务实际扫描的`temp/output`目录。旧的嵌套财务插件构建产物没有删除，而是移动到`temp/stale-idc-zjmf-finance-v011`留作核对。

## SSL 独立页面与安全动作

`yunsu-ssl`分别交付后台和客户中心页面，不套用服务器列表。页面只通过版本化宿主桥调用`idc-core`拥有的服务权益接口，不接收宿主原始登录令牌，也不直接调用供应商。

客户中心真实 Chromium 已覆盖：

- 慢资源首次进入立即显示同主题骨架，加载后没有白屏、双页头、双滚动条或横向溢出。
- 第二次进入复用静态资源，不重复完整冷启动。
- 中文、英文、明暗主题、390 像素窄屏、页面刷新和菜单来回切换。
- 停止新业务后保留已有客户证书入口；停用并刷新权限后移除入口。
- 查看证书详情和 DNS 验证资料。
- 签发前切换 DNS/文件验证、重新验证和取消申请。
- 已签发证书先取得短期单次票据，再由宿主完成下载；页面请求中没有登录令牌、供应商秘密或授权头。

后台真实 Chromium 已覆盖管理员独立证书页、客户列、详情和验证资料。页面仍位于无边框隔离容器内，使用宿主标题、标签页、主题、字体和间距；视觉复查没有双页头、双滚动条、技术枚举或内部编号。

浏览器测试曾发现“按钮可见但点不到”的测试时序问题：宿主路由遮罩尚未结束时，测试已经尝试点击 iframe 内按钮。页面对象现在先等待内容加载和宿主遮罩结束；详情打开后，后续动作固定点击抽屉内按钮，不再误点被抽屉盖住的列表按钮。这是实际交互位置修正，没有通过延长超时掩盖失败。
