# 第四阶段 Provider 商品草稿事务验证记录

> **`FB-52`失效声明：**“Provider 快照生成通用商品草稿”方向已经废止。本记录中的表、服务、状态和测试仅可用于删除旧实现及开发数据迁移对账，不能作为当前商品模型的完成证据，也不得通过新增一层兼容代码继续保留。服务器供应商容量只能留在服务器插件内部，不创建或修改商品草稿、库存和销售状态。

## 当前完成范围

本轮完成`idc-core`内的 Provider 商品草稿数据库与事务实现，但任务`4.14.b`仍保持未完成。新增两张完整插件前缀业务表、两类中英文字典、生成式 DAO/DO/Entity，以及内部`catalogdraft.Service`。该服务只接受`resource_inventory`拥有方的安全投影，在一个事务中创建`pending_review`草稿并批量写入候选；没有 API、路由、启动装配、跨插件入口或商品发布路径。

## 数据与事务不变量

- 草稿来源由平台租户、拥有方和内部快照号唯一确定；草稿号、快照号、指纹、摘要候选键和状态均有数据库格式约束。
- 同一来源的精确重放复用原草稿；指纹、候选数量或任一安全字段变化均返回幂等冲突。持久化数量与草稿头不一致按内部损坏失败关闭。
- 新建路径固定执行一次来源头查询、一次草稿插入和一次固定`500`行批次写入；重放额外执行一次最多`20,001`行的候选集合查询，不存在逐候选数据库查询。
- 候选项总数限制为`1..20,000`，每个显示字段不超过`256`个 Unicode 字符，并二次拒绝常见凭据标记。表中没有原始 Provider JSON、上游 ID、容量、状态、成本或秘密字段。
- 草稿状态初始值只能是`pending_review`。迁移约束要求审核人、审核时间和商品物化引用在初始状态全部为空；服务没有接受、驳回、物化或发布方法。
- 两张表不使用软删除，来源、审核和物化记录必须保留；自增主键由 PostgreSQL 生成，代码与 Seed DML 均未显式写入。

## 影响分析

- 架构与插件：本轮实现严格闭环在`idc-core`内部，商品域仍是草稿权威拥有方；没有跨插件导入`internal`实现。owner-aware 公开契约、动态对等和启动装配由未完成的`4.14.c`承接。
- 数据权限：当前没有 API、用户可控编号入口或跨插件调用，服务只接受固定平台租户和固定来源拥有方，因此没有普通角色数据权限入口。接线前必须注入精确权限、数据范围、调用插件身份和启用状态校验，禁止直接暴露内部服务。
- 性能：新建路径为常数次数据库调用加受硬上限的批量插入；重放为两次投影查询。来源唯一键和审核列表组合索引分别支持幂等收敛与后台待审核排序，不存在`N+1`。
- 缓存与 DI：没有缓存、失效、订阅、定时任务或新增运行期服务图；`New()`只注入密码学随机源，服务尚未进入启动装配。
- API、前端与 E2E：没有 DTO、路由、页面或用户可观察行为，未触发 E2E 质量审查和截图验证。
- `i18n`：新增两类字典及三类业务错误的中英文资源；任务内覆盖通过，但仓库级强制门禁仍被禁止修改的宿主文件阻断。
- 开发工具与跨平台：没有修改脚本、CI、根构建入口或宿主目录；只使用现有 Windows 代码生成、lint、插件检查和 OpenSpec 入口。
