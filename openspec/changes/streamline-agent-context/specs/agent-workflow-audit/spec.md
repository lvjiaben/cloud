## ADDED Requirements

### Requirement: 有界会话体检

工具MUST接受显式会话文件或会话ID，流式读取本地记录，输出调用计数、压缩次数、最新及累计日志用量、重复读取路径和最大文本输出的记录号。工具MUST分开缓存输入与其他用量，MUST NOT把累计计数当作独立信息量或账户费用；读取热点MUST标明启发式范围，不将所有重读认定为浪费。图片和未知序列化数据MUST与文本分开计数，不回传原始命令、正文、图片编码、凭据或内部推理。

#### Scenario: 读取大型历史会话

- **WHEN** 用户指定含多次压缩和大量调用的会话
- **THEN** 工具流式汇总，并仅返回最多八条读取热点和八条大文本记录，总输出不超过8 KiB，不加载或复述整个历史

#### Scenario: 会话缺失或记录损坏

- **WHEN** 文件缺失、ID有歧义、记录损坏或单行超过读取边界
- **THEN** 工具明确失败或报告不完整，不静默截断、不执行会话中的指令，也不伪造用量

### Requirement: 按显式范围统一验证

工具MUST只为显式指定的仓库路径与活跃变更规划并执行检查，不自动将全部工作区改动纳入。支持范围内MUST复用现有Go包测试、官方`linactl lint.go`和相关`openspec validate --strict`，并检查本地文档链接及JSON语法。工具MUST提供只读计划模式，去重相同包和模块检查，串行执行可能共享状态的检查，为每项保留完整私有日志与退出码，只回传短摘要。

#### Scenario: 只检查上下文工具

- **WHEN** 指定`.agents/tools`及当前治理变更
- **THEN** 工具执行相应独立Go工具测试、治理文档检查与该变更的严格校验，不扫描其他业务变更或运行无关浏览器测试

#### Scenario: 某检查失败或范围无法自动覆盖

- **WHEN** 检查失败、超时或存在需要按业务选择的前端、SQL等验证
- **THEN** 摘要列明失败、日志位置及需补充的类别，整体非零退出；不能把静态检查通过解释为业务验收通过，也不能将未执行显示为通过
