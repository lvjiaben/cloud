## ADDED Requirements

### Requirement: 按任务读取权威上下文

AI MUST先读取短入口，按修改范围定位相关规则、业务条款、完整Requirement及其Scenario；索引和片段不得替代相关正文，CLI contextFiles不得触发无差别全量加载。

#### Scenario: 修复退款相关问题

- **WHEN** 当前任务仅涉及退款逻辑
- **THEN** AI定位退款拥有者、相关财务边界与当前任务，读取命中条款而不是全量偏好及所有变更

#### Scenario: 发现跨模块依赖

- **WHEN** 已读取条款依赖另一个业务拥有者的确认边界
- **THEN** AI补读该依赖的完整条款，不能因控制上下文而忽略资金或权限约束

### Requirement: 保留业务原文与任务历史

偏好迁移MUST保留全部业务正文与来源证据，允许仅重定位相对链接；现有变更任务和验收状态MUST保持不变。历史流程条款MUST明确由当前治理规则替代，不得重新成为默认门禁。

#### Scenario: 将偏好拆成主题

- **WHEN** 原偏好按章节搬到主题目录
- **THEN** 能按迁移清单恢复原始字节并验证来源哈希，当前入口链接到新主题

#### Scenario: 现有大变更仍未归档

- **WHEN** AI优化上下文入口
- **THEN** 不自动归档、删任务或改现有任务状态，仅新增定位方式

### Requirement: 有界完整读取与有效证据复用

工具MUST限制默认检索输出并返回路径与行号，拒绝越界路径、歧义选择和超过默认正文上限的读取，不静默截断。AI MAY复用同一任务中未变化且正文仍可用的上下文与覆盖当前内容的验证；内容变化、范围扩展或正文丢失时MUST补读或补验证。

#### Scenario: 读取大章节

- **WHEN** 选中正文超过12 KiB
- **THEN** 工具明确拒绝并要求缩小到完整逻辑单元，不输出截断后冒充全文

#### Scenario: 实施转入审查

- **WHEN** 本任务规则正文仍可用且已通过检查覆盖的文件及依赖未变化
- **THEN** 审查复用有效正文与证据，补查新增或未覆盖路径

#### Scenario: 本文档已发生变化

- **WHEN** 已读规范在本任务中被更新
- **THEN** AI读取变化后的相关条款，不用旧证据确认完成

#### Scenario: 大文件含超长任务行

- **WHEN** 目标设计或任务文件过大，普通逐行检索可能返回大段正文
- **THEN** 先通过有界定位或标题确定范围，再读取目标任务和相关完整需求；超限时按完整逻辑单元拆分，不以截断片段确认规范

### Requirement: 技能遵循当前决策与沟通边界

项目技能MUST遵循当前用户确认及项目规则，旧治理条款MUST在所在主题就地标明替代关系并保留历史正文。技能MUST使用模型中性的任务描述，沟通提供结论、关键依据、验证和未决条件，不要求展示内部逐步思考。只有现有资料无法消除且会改变业务结果、权限、费用、数据归属、安全边界或主要操作流程的真实歧义才触发业务澄清；工具实际要求的权限或授权仍须遵守。

#### Scenario: 内部实现有多个等价方案

- **WHEN** 文件命名、代码组织或其他内部实现存在多种不改变已确认业务结果的方案
- **THEN** 代理依据项目约定自主选择并完成必要验证，不因通用技能中的不确定性措辞反复要求用户选择

#### Scenario: 业务决定仍有歧义

- **WHEN** 两种合理方案会产生不同的权限、费用或主要操作流程且缺少用户确认
- **THEN** 暂停依赖该答案的实现，说明具体区别并询问用户，同时继续不依赖答案的已授权工作

#### Scenario: 在既有产品中使用设计技能

- **WHEN** 项目已有设计系统、品牌规范或用户指定的页面风格
- **THEN** 技能优先遵守这些约束，创意建议不得强制更换字体、主题、组件或交互，也不得要求扮演特定模型
