## ADDED Requirements

### Requirement: 质量优先与完整目标交付

AI MUST以用户完整目标、最新确认与未完成项确定工作范围，按需读取MUST NOT缩小目标或替代必要分析和验证。读取是否充分MUST由目标行为、调用与数据依赖、失败原因和验收依据判断；证据矛盾、不足或问题复发时MUST扩大相关排查。当前步骤完成、旧任务勾选或模拟测试通过MUST NOT单独证明完整交付。

#### Scenario: 后续反馈补充原目标

- **WHEN** 用户要求完成可用的交易流程，随后反馈菜单或表单问题，未取消原始目标
- **THEN** AI修复新反馈并保留原目标未完成项，继续处理已授权依赖，不在仅修好菜单后宣称完整流程完成

#### Scenario: 删除能力影响启动与消费者

- **WHEN** 当前任务删除某能力，其注册、启动装配或保留页面仍引用旧结构
- **THEN** AI沿实际依赖检查并修复，即使相关文件在另一模块，也不以局部范围为由忽略；共享文件协调归属，禁止覆盖他人改动

#### Scenario: 已通过证据因环境或反馈失效

- **WHEN** 目标文件未变，但用户报告复发，或并行修改、配置、数据、运行版本变化使旧验证不再覆盖实际结果
- **THEN** AI重新核查受影响链路并补验证，明确源码、构建、运行生效与业务结果的验证层次，不机械复用旧通过结论

#### Scenario: 明确授权接管多个会话

- **WHEN** 用户授权接管既有会话继续任务
- **THEN** AI从原目标、最新确认、未完成项和有效证据恢复任务，摘要不足则定向读取相关历史，协调共享修改并跟进实际结果；发送指令本身不代表完成，授权不扩展到宿主或未获授权的外部写入

#### Scenario: 用户要求多轮复查

- **WHEN** 用户要求继续检查并做多轮优化
- **THEN** AI按未覆盖风险或不同证据来源安排各轮，后轮结合前轮发现验证，不以重复相同测试代替新的检查，也不为凑次数制造修改
- **AND** 旧证据统一按当前实现、依赖、配置、数据与运行版本判断，不让技能中的简写条件覆盖主规则；普通任务不因此自动升级为多轮审计

#### Scenario: 验证构建存在额外输出

- **WHEN** 构建主输出设置在临时目录，但归档插件或结束钩子可能写入禁止修改的宿主目录
- **THEN** AI核对实际生效配置与全部相关输出，在隔离验证配置中禁用或重定向副作用；不把临时主输出或环境变量视为充分证据，不修改宿主构建源码
- **AND** 发现误覆盖既有文件时仅凭可信前快照恢复；无法恢复则记录实际偏差和剩余条件，不以删除原有文件或猜测内容冒充撤回

### Requirement: 按任务读取权威上下文

AI MUST先读取短入口，按修改范围定位相关规则、业务条款、完整Requirement及其Scenario；索引和片段不得替代相关正文，CLI contextFiles不得触发无差别全量加载。

#### Scenario: 仅交流方案

- **WHEN** 用户仅要求解释或讨论且结论不依赖新的仓库事实
- **THEN** AI直接回答并复用当前已提供正文，不自动查询工作区状态、枚举变更或启动实施与审查；用户随后要求修改时再进入必要流程

#### Scenario: 独立目标交接与局部验收

- **WHEN** 已有任务需要交接给新会话，或当前反馈已有明确验收结果
- **THEN** 工具通过`handoff <变更> <任务ID>`生成总量不超过4 KiB的完整选定任务及权威来源，超限明确拒绝；不创建会话、不发送消息、不自动重做完成项
- **AND** 实施、回归和审查围绕当前验收结果，必要依赖继续补齐，独立问题另行记录，不能为节省上下文删除历史或跳过权威条款

#### Scenario: 修复退款相关问题

- **WHEN** 当前任务仅涉及退款逻辑
- **THEN** AI定位退款拥有者、相关财务边界与当前任务，读取命中条款而不是全量偏好及所有变更

#### Scenario: 发现跨模块依赖

- **WHEN** 已读取条款依赖另一个业务拥有者的确认边界
- **THEN** AI补读该依赖的完整条款，不能因控制上下文而忽略资金或权限约束

### Requirement: 保留业务原文与任务历史

偏好迁移MUST保留全部业务正文与来源证据，允许仅重定位相对链接；现有变更任务和验收状态MUST保持不变。历史流程条款MUST明确由当前治理规则替代，不得重新成为默认门禁。

#### Scenario: 将偏好拆成主题

- **WHEN** 原偏好按章节搬到主题目录
- **THEN** 能按迁移清单恢复原始字节并验证来源哈希，当前入口链接到新主题

#### Scenario: 现有大变更仍未归档

- **WHEN** AI优化上下文入口
- **THEN** 不自动归档、删任务或改现有任务状态，仅新增定位方式

### Requirement: 有界完整读取与有效证据复用

工具MUST限制默认检索输出并返回路径与行号，拒绝越界路径、歧义选择和超过默认正文上限的读取，不静默截断。AI MAY复用同一任务中未变化且正文仍可用的上下文与覆盖当前内容的验证；内容变化、范围扩展或正文丢失时MUST补读或补验证。

#### Scenario: 读取大章节

- **WHEN** 选中正文超过12 KiB
- **THEN** 工具明确拒绝并要求缩小到完整逻辑单元，不输出截断后冒充全文

#### Scenario: 实施转入审查

- **WHEN** 本任务规则正文仍可用且已通过检查覆盖的文件及依赖未变化
- **THEN** 审查复用有效正文与证据，补查新增或未覆盖路径

#### Scenario: 本文档已发生变化

- **WHEN** 已读规范在本任务中被更新
- **THEN** AI读取变化后的相关条款，不用旧证据确认完成

#### Scenario: 大文件含超长任务行

- **WHEN** 目标设计或任务文件过大，普通逐行检索可能返回大段正文
- **THEN** 先通过有界定位或标题确定范围，再读取目标任务和相关完整需求；超限时按完整逻辑单元拆分，不以截断片段确认规范

### Requirement: 排查推进与会话读取边界

AI MUST围绕当前待证事实合并独立的定向查询，有依赖的步骤保持顺序；MUST NOT为合并调用加载无关内容。相同查询连续两次没有新增证据时MUST检查任务状态或改换证据来源；真实运行的长任务MAY继续有界等待，已结束、失败或需要外部条件时MUST明确状态与下一步。读取其他会话MUST优先状态和近期结论，再定向提取相关执行证据，不把原始会话或图片编码作为文本全量回传。独立目标建议使用新会话时MUST保留必要交接与权威正文读取，MUST NOT擅自创建会话、跨会话发送消息或中断已授权任务。

#### Scenario: 轮询没有进展

- **WHEN** 连续两次查询没有新增证据
- **THEN** AI检查任务是否仍运行及相关日志、退出码或其他证据；有明确运行信号则继续有界等待，确认已完成或需要登录则说明实际状态，不继续空转

#### Scenario: 检查超大会话

- **WHEN** 用户要求检查另一个会话的耗时或停滞，工具的单项输出限制不能约束整个会话长度
- **THEN** AI先取得当前状态和最后结论，再在工具内提取相关计数或执行片段，不回传整份原始记录，不把已结束会话描述为仍在执行

### Requirement: 有界工作区状态摘要

上下文工具MUST通过`status [仓库相对路径]`返回完整Git状态的计数。默认MUST NOT展开全局文件清单，只列目录分组和活跃变更名称，各最多12条，并明确省略数量；指定范围MUST仅补充该范围总数与最多12条具体状态，不重复全局分组及变更清单。路径展示MUST限制长度并转义换行等特殊字符。工具MUST计入未跟踪文件和生成产物，按重命名的新旧路径匹配范围，并拒绝越界路径。摘要MUST声明省略，不得被视为完整审查证据。

#### Scenario: 大量无关改动

- **WHEN** 工作区包含数百条状态和生成产物，用户只修改一个插件
- **THEN** 默认状态只输出全局统计及有界目录和活跃变更摘要，指定该插件路径后输出该范围总数与最多12条状态，并明确剩余数量

#### Scenario: 文件移出目标目录

- **WHEN** 重命名文件的旧路径属于指定范围而新路径在范围外，或文件名包含空格、中文与换行
- **THEN** 该记录仍计入目标范围，新旧路径被正确解析并转义展示，不拆成多条状态

#### Scenario: 试图查看仓库外路径

- **WHEN** 调用者传入绝对路径、父目录跳转或Git路径表达式
- **THEN** 工具拒绝该请求，不将参数交给Git解释为选项或路径表达式

### Requirement: 技能遵循当前决策与沟通边界

项目技能MUST遵循当前用户确认及项目规则，旧治理条款MUST在所在主题就地标明替代关系并保留历史正文。技能MUST使用模型中性的任务描述，沟通提供结论、关键依据、验证和未决条件，不要求展示内部逐步思考。只有现有资料无法消除且会改变业务结果、权限、费用、数据归属、安全边界或主要操作流程的真实歧义才触发业务澄清；工具实际要求的权限或授权仍须遵守。

#### Scenario: 内部实现有多个等价方案

- **WHEN** 文件命名、代码组织或其他内部实现存在多种不改变已确认业务结果的方案
- **THEN** 代理依据项目约定自主选择并完成必要验证，不因通用技能中的不确定性措辞反复要求用户选择

#### Scenario: 业务决定仍有歧义

- **WHEN** 两种合理方案会产生不同的权限、费用或主要操作流程且缺少用户确认
- **THEN** 暂停依赖该答案的实现，说明具体区别并询问用户，同时继续不依赖答案的已授权工作

#### Scenario: 在既有产品中使用设计技能

- **WHEN** 项目已有设计系统、品牌规范或用户指定的页面风格
- **THEN** 技能优先遵守这些约束，创意建议不得强制更换字体、主题、组件或交互，也不得要求扮演特定模型
