## ADDED Requirements

### Requirement: 单次命令只读诊断订单

开发工具MUST接受一个订单号，通过已有受保护HTTP查询汇总订单、账单付款、履约自动化、资源任务和已记录的上游编号。工具MUST仅发送GET，不读取数据库或调用上游，不登录、刷新凭据或执行重试、开通、回调、状态修复。管理员履约详情MUST仅在已有精确权限和数据范围校验后，提供资源拥有方的本地执行状态、阶段、结果代码、尝试次数和资源任务号；资源详情继续独立验证自身权限。

#### Scenario: 查询结果未知的已付款订单

- **WHEN** 已付款订单的资源任务结果未知
- **THEN** 一次命令展示账本付款事实、履约和资源状态、已保存的上游编号及最近错误分类，明确需要核对且不重复开通，不把调用成功视为资源创建成功

#### Scenario: 权限或登录失效

- **WHEN** 订单、履约或资源查询被拒绝或登录失效
- **THEN** 工具明确报告相应查询未完成，不扫描其他客户或绕过接口读取数据库，不输出令牌、原始错误正文或假报健康

### Requirement: 诊断输出与查询有界

工具MUST只输出白名单编号、状态、精确金额和机器错误代码，不输出客户联系方式、密码、令牌、原始响应或自由文本备注。工具MUST限制响应体、超时、履约任务及资源详情数量，显式声明省略和缺失字段；拒绝跨来源重定向及不安全目标，凭据仅从环境或显式私有会话文件读取。最多检查三条履约任务，最多查询三条不同资源任务，HTTP请求总数最多八次，不随完整订单规模增长；超限MUST报告不完整，不给出完整健康结论。

#### Scenario: 大订单或部分查询失败

- **WHEN** 订单超过三条履约任务，或后续查询失败
- **THEN** 输出省略和失败数量并以非零退出，保留已确认的付款事实，不自动遍历所有任务，也不将缺失证据解释为开通失败或成功

#### Scenario: 上游或接口正文含秘密

- **WHEN** HTTP返回包含凭据、备注、客户信息或异常原始正文
- **THEN** 只保留白名单字段和机器分类，其他内容不进入输出；非法编号、重定向、超大正文和网络超时明确失败
