# 实现设计

## Context

宿主目录严格禁止修改。用户确认新增内置插件并要求分类可扩展，同时扩大范围至各插件开发规范、文档和安装门禁一致性。另一个对话正在修改`customer-tdesign`、`idc-core`、`idc-resource`及`yunsu-ssl`的已购服务表面，本轮不改写这些业务实现和共享运行配置。

## Goals / Non-Goals

目标是插件自己的管理入口、准确分类分页、规范文档与现有安装校验闭环。不创建另一套生命周期引擎，不将展示分类写入宿主领域类型，不伪造尚未支持的动态短信协议。

## Decisions

- 内置源码插件通过清单菜单和`Access().RegisterMenuFilter`隐藏旧入口；旧宿主路由及权限节点保持原有实现，插件不可用时由宿主扩展机制恢复原导航。
- 菜单挂在稳定目录`setting`下，保留插件自有路径`/extension/plugin-manager`。当前后台将`extension`目录内页面转为隐藏配置路由，因此不能把导航入口挂在该目录；通过插件清单适配，不改宿主菜单组织逻辑。
- 分类是`catalog.categories`有序配置，精确标识优先，再按最长配置前缀归类，未匹配使用配置的默认分类。稳定键不限定七种业务；配置校验拒绝重复标识及无效回退。
- 宿主公开`GET /api/v1/plugins`不支持分类查询，公开Go能力不包含运行时摘要。插件通过当前请求的公开HTTP处理器发出普通GET子请求，复用认证、租户与权限中间件，按宿主上限每页100个动态摘要、最多10页，不读取宿主私有服务和表。不采用逐插件详情查询或浏览器全量分页。分类后的结果分页独立保留插件接口的200条上限。
- 目录是平台插件治理投影，数据权威边界仍由宿主公开接口控制；分类聚合只处理已授权摘要。1000项是安装目录上限而非业务行数上限，超限或分页快照改变时整体拒绝，不泄露未授权总数。没有新增数据库、缓存或独立运行期服务实例。
- 生命周期直接消费现有公开HTTP接口。安装和卸载仅按钮一次简短确认，权限范围按需读取并随正式请求提交；安装、重装及上传新包自动启用并开放业务。停用和卸载自动停止销售，缺失业务授权时自动通过公开接口重新校验，无额外人工步骤；更新继续核对目标权限。卸载保留存储数据，业务阻断继续由宿主拒绝，不提供强制入口。
- 开发规范盘点所有插件清单、双语说明、声明的扩展契约与拥有方验证器；采用自动化契约审计验证当前插件，并验证错误声明被拒绝。分类配置只影响展示，绝不能提升安装信任。源码短信适配器与未发布动态短信协议明确区分。
- 新插件使用中文单语言，`i18n.enabled=false`；保持Vben表格、弹窗、授权和状态开关样式，不修改其他插件语言资源。使用`lina-e2e`组织本插件用例和截图。

## Risks / Trade-offs

- 分类聚合增加按目录页数计算的有界摘要调用；宿主摘要缓存仍被复用，无N+1详情查询。目录超过1000项需要以后增加公开批量分类读契约。
- 源码插件需随标准源码插件构建注册后生效；本轮使用独立构建目录、工作区、端口和验证会话，避免覆盖另一个对话的运行实例。
- 文档和测试不能证明第三方真实发送、支付或开通成功，不能将静态契约通过写成外部业务验收通过。
