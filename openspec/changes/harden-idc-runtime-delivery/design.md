## Context

隔离回归已复现支付和财务适配器缺陷。用户最新纠正：参考魔方`MenusController`的`nav_type=2`、`relid`与`service?groupid=菜单ID`，后台配置多个关联商品的服务菜单。`nav_group_user`客户显示偏好不是本次目标；购买页则独立使用销售分类。动态插件源码存在，但SSL缺构建配置，两款魔方插件声明的页面产物未完整交付。

## Goals / Non-Goals

完成已证实的资金状态、CI、JWT与依赖缺陷；完成有效动态插件交付和商品目录的前后端闭环。私人服务分组与真实供应商订单不属于本次授权。既有供应商证据门禁不得因本地模拟通过而关闭。

## Decisions

- 目录由`idc-core`拥有，商家页面放插件前端，客户页面放独立`web-customer`。复用认证、权限、客户主体和已购服务投影。
- 目录关联稳定商品键，与销售分类分离；关联变化实时影响归集，不修改订单快照或服务所有权。目录停用而非删除，避免未经确认引入软删除策略。
- 活动目录作为客户中心菜单，URL选中相应分类/tab，客户无显示偏好入口或写接口，保留全部服务入口。服务列表数据库侧筛选并分页，统计集合查询，避免N+1。
- 支付状态遵循已验签事实和任务租约，提交后未知结果不释放资金；禁用渠道仅阻断新增，不拒绝已有交易的处理。
- 魔方云后台服务器只读投影由`idc-resource`拥有，明确员工权限、数据范围、固定Provider与有界分页；动态页仅经批准page bridge调用，不传宿主token或供应商秘密。迁移已有完整业务API改由独立隔离页通过同样桥授权调用。
- 动态打包缺资源立即失败；自有构建补齐资源，不能以空页面绕过校验。CI显式传数据库并检测必跑测试跳过。
- 前端依赖升级保持必要范围，修复公开已知漏洞并报告暂无补丁的残余构建依赖。

## Risks / Trade-offs

目录重新关联会影响客户当前导航归集，保留全量服务入口。接口分页、版本检查与数据库隔离回归约束并发和跨客户访问风险。供应商真实签发仍依赖有效凭据与授权。

## Migration Plan

新增幂等插件SQL，不清理既有数据；通过仓库生成入口生成DAO和控制器。统一构建与重启后验证菜单与分类选择、动态发现及安装。运行受影响Go测试、lint、前端类型/构建、目录E2E与OpenSpec严格校验，并记录独立审查。

## 集成验证发现

真实宿主发现迁移页面路由被菜单重组丢弃：移除旧 extension 导航时必须保留并隐藏其子路由，保留 PluginSandboxView 与桥元数据供配置中心访问。新增回归覆盖这条真实路径。动态插件升级必须在生命周期锁内外使用一致的有效版本与发现版本，避免预览 pending_upgrade 而执行误判 normal。

数据库门禁还发现资源凭据拥有方校验了Audit依赖却没有追加生命周期审计。审计必须在绑定和不可变接口revision的同一事务中提交，只包含渠道、字段名、状态、版本等非秘密信息；失败保留重试恢复能力。轮换使用有界batch并让密钥拥有方加入ambient事务，使轮换进度与公开审计原子提交。公开错误只保留稳定业务码，禁止携带底层SQL或加密封装cause。

## 动态发现缓存边界

发现包以配置storage根目录中的受验证WASM文件为权威，生效版本以数据库release为权威；path/fingerprint解析缓存和pluginID发现索引不能互相替代。扫描、上传后的既有InvalidateManifestCache、启动和重载继续重建发现索引，读取归档不产生失效或发布事件。生命周期锁内重新读取数据库和目标清单后才允许升级，事务后仍走既有代际/事件失效路径；未新增节点本地替代服务或绕过现有集群协调。可接受的是既有文件发现刷新窗口，不接受把已发现新包错误降为旧包。文件/解析失败保持既有失败关闭，重载或重启可恢复；本次验证涵盖本地版本隔离与失效重建，未部署真实多节点集群。

## 用户反馈修正：商家服务菜单

后台目录名称、排序、启停与商品关联直接投影为客户中心菜单；共享服务页面以路径参数选择tab，浏览器刷新和历史恢复选择。原visibility API撤销，已安装迁移中的历史偏好表不再读写。购买页复用已有销售分类接口与categoryNo过滤，不将服务菜单作为可售分类。
