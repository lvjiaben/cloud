# 商品与客户控制台重写验收

## 实现与部署

商品编辑改为基本资料、用户选配与价格、自动开通三个页签。选配项名称、控件、可选规格和费用放在同一工作区；桌面左侧选配项列表有界独立滚动，避免大量高级字段拉长整个页面，窄屏横向切换。默认开通参数与客户选配分别说明。成本仅在展开后读取。保留税务、代理价格、附加商品和原成交快照。

客户首页重写为服务器、余额和最近订单独立加载；服务器主入口直接使用资源拥有方列表及详情。余额使用准确十进制转换，大金额及窄屏均有覆盖；资源插件停用时不继续读取其服务。已有人工及其他服务仍可进入原服务管理。

资源配置新增共享数据库候选投影和有租约的后台同步。页面只读取本地结果，失效和失败不阻塞资料及价格维护；后台、官网两套模板和管理员重开均有有界刷新，保留已输入内容。缓存按真实连接版本和声明变化失效；候选仅存允许的字段，不保留任意接口属性、认证正文或凭据。

南京魔方连接已按用户明确授权改为同一地址的显式HTTP协议。仍限制目标协议、主机、端口和重定向。此授权不包含真实上游写入。

本地后台、客户中心及两套官网模板已部署当前构建。主后端启用`125600-worker-recovery-connection-lina`，激活记录为`temp/20261021/130300-frozen-connection-activation.log`；后台最终静态资源激活记录为`temp/20261021/131400-bounded-options-assets-activation.log`。客户中心包为`v0.2.22`，两套官网包为`v0.1.15`。

## 本轮发现并修复的业务断点

- 资源声明的地区、线路只有权威接口候选，前端清理时却仅承认静态选项，导致显示已选择但提交缺失。表单及序列化现接受明确返回的权威候选；服务端继续作最终校验。
- 新订单冻结当前连接，商品版本保留旧连接。履约取任务和原单重开却强制二者版本相同，导致任务零执行且长期处理中、重开配置读取失败。现分别读取原成交规格及该订单实际冻结的连接；非资源任务仍保留原匹配条件。
- 用户启用选配后，保存响应与内部可编辑版本先后抵达，价格表单误报冲突。新启用的价格表单在最终可编辑配置读取完成后建立，既有外部修改保护继续生效。
- 冷缓存的重开选项初次为空后不自动更新，现有界重读并保留管理员说明和选择；不自动执行重开、退款或历史未知单核对。

## 审查与剩余边界

按`lina-review`审查本任务新增文件、实现差异和测试；覆盖资源投影的授权及密钥排除、租约释放、版本失效、批量冻结事实、外部修改保护、资金与客户归属、恢复幂等和页面布局。已修复上述阻塞断点。E2E实际操作只到专用模拟上游及独立数据库，不触发第三方创建实例、镜像操作、退款或历史订单重放。

宿主目录`apps/lina-core/`、`apps/lina-vben/`及根`hack/`没有本任务源码修改。没有提交、推送或创建PR。

真实南京魔方的HTTP普通页面、登录与只读接口仍没有HTTP正文，真实商品镜像候选为零，不能验证真实服务器开通。旧订单丢失的响应无法补回，仍须管理员自行核对后按已提供入口选择更正重开或退款。真实外部支付通知还缺可达公网入口，不把隔离结清或生成支付请求宣称为真实收款验收。`V1-CANDIDATES`及真实外部链路保持未完成。
