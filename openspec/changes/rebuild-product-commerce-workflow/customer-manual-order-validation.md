# 客户订单人工状态反馈验收

## 根因与实施

真实订单的履约意图和交付投影均为`manual_pending`，资源任务仍为`result_unknown`，服务权益仍为`pending_activation`。数据库聚合触发器正常；问题在客户订单控制器的公开状态白名单遗漏了已约定的`manual_processing`，重新将其映射为`processing`。原映射测试也错误地期待这个降级值。

本轮修正公开状态白名单及测试，不修改数据库或状态流转。后台订单详情共用该映射，因此同步保留人工处理状态的双语展示。客户订单详情的付款准备提示和重新检查按钮同时服从订单拥有方提供的`canPreparePayment`，已付款订单不再显示过期的“可以继续选择支付方式”。

按`lina-review`限定`UX6`的控制器映射、后台状态展示、客户详情条件及相关测试和截图助手，复用本轮已读的接口、权限、后端、前端、测试和多语言规则。正式规范原已要求停止自动等待并显示人工处理，因此修正实现，不引入新状态或变更生命周期。可信客户访问边界、服务端操作标志、精确金额和原时间戳映射保留，没有新增查询、外部调用、迁移或缓存。
