# 发布构建金额渲染反馈验收

## 根因与实施

真实后台订单详情缺少订单状态、应付金额与商品项目，浏览器记录多次`Cannot convert a BigInt value to a number`。宿主现有发布目标为`es2015`，构建把插件中的`10n ** BigInt(digits)`降成调用`Math.pow`的辅助函数，而该函数不能处理`BigInt`。五处同类写法分别影响订单、运营汇总、合同、自动签额度和批量续费；原生单测和类型检查没有覆盖这个构建阶段问题。

本轮仅修改插件：用十进制字符串构造精确的币种尺度，避免不兼容的乘方转换；合同金额同时移除`Number(minor)`，以整数及余数生成格式化结果，保留完整小数和币种符号。没有改变最小货币单位、价格、币种精度来源或收费算法。订单、合同、授权额度及续费金额列补足宽度，仍在表内横向滚动，操作列保留固定位置。宿主配置和源码没有修改。

按`lina-review`限定五个金额组件、相应客户端替身、三个模块的测试、截图／路由助手和插件版本。复用前端、接口、测试、多语言及财务规则，尤其保持金额字符串及既有拥有方操作权限。没有新增服务、公共包装层、迁移、缓存、查询或供应商写入。

触发构建后行为的`E2E`质量审查：先复现旧构建失败，再验证实际发布包；断言既覆盖精确金额及币种精度，也覆盖被渲染错误连带丢失的订单状态和商品内容。只读合同与预览测试明确断言没有提交；运营验证使用本地真实读取。最终视审合同详情、订单详情、完整授权额度和续费金额，未见本次范围的翻译键或数字裁切。未发现阻塞问题。
