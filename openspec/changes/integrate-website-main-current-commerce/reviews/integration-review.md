`website-main`为独立动态模板，只消费现有拥有方公开HTTP接口，没有私有跨插件导入；当前依赖为`idc-portal >=0.1.14`、`idc-core >=0.1.0`。后端公共列表复用原controller注入的catalog reader和同一数据库、cursor codec，不新建服务图。既有内容服务复用原数据库及存储，未新增表或手写生成工件。

关键交易价格、商品状态、归属、配置版本和秘密均由后端实时校验。公开身份缓存只存公开字段，最多三十秒陈旧，可配置共享目录，失败保留正常页面及重试，不缓存客户权限或价格。客户会话只在页面内存，账户代理带原Bearer、请求来源及方法限制；一次性交接失效可回退现有客户中心会话桥。

## 2026-10-29完整结算、配置与视觉反馈复查

本节替代前文初次迁入时“客户中心付款”“不补公共配置后台”的阶段结论。当前安装`website-main v0.4.6`，后台静态产物与源码插件后端也已更新至本轮实现；无提交、推送、PR或归档。

### 根因与当前实现

- 原会话按一次性交接处理，页面跳转需要重新跨域桥接；加购响应未复用且购物车无条件匿名合并。现以同源`HttpOnly`会话保持页面连续性，桥接后只验证最小用户资料；真实`401`清理身份及Cookie，业务实名与审核状态分别提示。会话无进程内持久状态，跨网关实例及重启仍由后端JWT校验约束。
- 实际运行还发现官网与客户中心网关因断连竞态退出：客户端先离开、上游稍后才返回头部，`pipeline(fromWeb(body), 已关闭响应)`同步失败后留下无错误监听的`Readable`，延迟超时触发进程退出。三个实际入口均已在`Node 24`子进程重现相同堆栈，改为Web流`pipeTo`并清理断连资源，不吞全局异常。官网默认网关与客户中心网关已替换重启，独立官网交付同步重建。
- 加购响应在同一标签页按身份摘要保存一次，最多15秒，消费即删除，身份变化或过期重新读取；后续报价、冻结和下单仍使用拥有方版本及金额，不以浏览器快照定价。优惠与渠道读取不阻塞有效报价。真实两台加购的点击至报价显示，初次旧链路约8.0/4.0秒、修正源约2.4/1.6秒，正式安装实测约3.1/1.7秒；单次加购接口约0.3秒，正式链路不再匿名合并。计时是本地观测，不作为上游或所有环境的时延承诺。
- 付款在原结算子区域选择当前渠道和模式，使用现有订单、账单、付款准备、余额与支付接口；不检测插件或跳转客户中心替代官网付款。GET/POST付款页、原地本地二维码和权威查单分别处理；提交前保存锁，响应未知后不重发金融POST，刷新只查订单、账单和已知付款尝试。用户主动实名可打开现有认证页，保留付款上下文。
- `idc-portal`补齐独立头尾Logo、版权、QQ、地址、企业微信及公众号二维码、许可证号与链接的保存、回读和公开投影。旧`logoUrl`及公安备案字段保持原名；其他模板配置桶保留。导航来自模板内置默认项及当前后台配置，未复制分支运行数据库；后台头尾导航编辑、保存、排序和英文名称已验证。
- 已声明但未消费的首页四项配置接到原首张轮播节点；清空恢复当前商品及原素材。默认导航相同英文译名的中文身份单独保留，避免切换语言后“生态合作”变成“合作伙伴”。没有改变菜单目标、DOM组件层级、CSS或页面布局。
- 全部455个原HTML、CSS、图片、字体及原注入样式保持来源摘要。当前包531资源与项目外独立构建的清单及资源完全一致；实际HTTP样式字节与`text/css`类型正确。独立Go二进制路径元数据可能不同，不要求整包散列相同。
