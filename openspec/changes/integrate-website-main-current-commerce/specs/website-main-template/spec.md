# 官网模板与当前业务衔接

## Purpose

将官网交付分支的独立动态模板接入当前系统，保留其页面素材、布局和双语表现，并以当前拥有方的公开接口提供可用的商品选配、购物车、内容和认证交接，避免旧后端及环境状态覆盖本地业务。

## ADDED Requirements

### Requirement: 官网源码选择性引入

系统`MUST`仅引入选定官网插件的完整源码和必要资源，不以整分支合并覆盖其他业务；官网外存在内容冲突的文件`MUST`先列出本地和分支差异并按用户逐项决定或后续明确的代理决策授权处理。

#### Scenario: 分支包含旧业务和官网

- **WHEN** 远端官网分支同时修改商品、客户中心、公共配置及测试环境
- **THEN** 官网插件独立迁入，其他改动逐项审计；冲突文件在明确确认或授权代理决定前保持本地内容，旧完成记录不作为本地验收证据。

### Requirement: 官网使用当前拥有方契约

官网`MUST`通过当前公开品牌、商品、内容、认证、购物车和订单接口展示真实资料并办理购买，全部原页面、样式、图片和字体保持分支原文件，新增业务控件复用原样式，保留双语页面；不恢复退役路由、公告可见范围或手工发布流程，不依赖供应商写入完成本地验收。

#### Scenario: 旧官网购买链路接入

- **WHEN** 客户选配并加入购物车
- **THEN** 官网识别当前客户会话，未登录保留配置并复用客户中心认证；已登录以当前账户购物车契约提交，每次配置一台，官网内编辑、核价、选择支付方式并确认付款，复用当前拥有方的账单、付款准备、付款创建及状态查询，不以跳转客户中心代替官网付款。

#### Scenario: 服务器配置与登录信息

- **WHEN** 当前商品提供系统、区域、数量展示语义并开启服务器登录输入
- **THEN** 官网提供分类系统、独立区域及精确数量控件，按当前约束与权威价格提交原候选；主机名密码允许自填、空值自动生成，各自绑定独立项目，密码不写入普通配置或浏览器持久存储。

#### Scenario: 失败与双语页面

- **WHEN** 读取、保存或报价失败，或客户切换语言、窄屏访问
- **THEN** 官网显示当前语言的可操作反馈，保留可恢复输入，避免重复提交或错误价格；公共品牌与内容适配当前字段，不显示旧接口错误或未翻译键。

#### Scenario: 官网跨页面会话与结算性能

- **WHEN** 已登录客户加购后进入购物车及结算
- **THEN** 同源受保护会话在页面间保持，真实失效才重新认证；复用当前身份下加购响应的权威购物车，避免重复匿名合并和完整读取，独立支付方式及优惠信息不阻塞有效报价。

#### Scenario: 官网付款与未知结果恢复

- **WHEN** 客户在现有结算区选择支付方式并确认订单
- **THEN** 通过当前渠道能力及拥有方付款接口办理，按GET/POST/QR的真实结果交互；业务阻断区别于未登录，网络未知时保留当前订单和尝试状态并查单，不能重复创建付款。

#### Scenario: 官网公共配置完整接入

- **WHEN** 管理员维护导航、公共Logo、联系及备案资料和模板内容
- **THEN** 通过当前拥有方保存并公开投影，在原官网组件展示，头尾独立Logo为空时沿用原公共Logo，切换模板保留公共信息及各模板配置；已声明的首页标题、说明、图片和首张按钮配置作用于原首张轮播节点，清空恢复当前商品内容及原素材，不重组轮播。

#### Scenario: 商品标记与翻译文档取舍

- **WHEN** 选择官网相关及独立修复
- **THEN** 所有官网商品固定显示`NEW`，不增加后台开关；翻译补缺失键且同键本地优先，文档与规则以本地为主，分支历史只用于追溯。

#### Scenario: 原方案卡片使用有界批量商品读取

- **WHEN** 官网配置至多24个本方关联商品
- **THEN** 使用可选`publicSlugs[]`精确集合筛选一次读取当前公开投影，与既有名称、分类、币种、可售范围及分页约束相交；集合绑定游标，原无集合请求行为保持不变，按商家关联顺序填入原卡片，不逐项请求详情。

### Requirement: 官网可独立动态交付

插件`MUST`从源码独立构建合法`WASM`包，通过已有官网模板发现与安装能力工作，不修改宿主或依赖仓库私有实现。

#### Scenario: 本地交付验收

- **WHEN** 构建并安装官网插件
- **THEN** 核对实际包、页面资源及已安装身份，真实页面与本地业务请求通过，测试数据单独清理，代码验证和运行生效分别留证。
