# 设计

工单域保存组织部门`ID`关联，不复制组织成员、不推断角色名称。当前人员通过已发布`Org`能力读取直属部门，通过`Authz`精确检查操作权限和主管权限；全部数据角色本身不等于超级管理员。普通部门角色仅可访问直属组织关联队列，本人范围继续收缩。

部门队列只允许人工领取，跨部门转派清空原处理人并返回空成功，避免成功后读回已失权详情。旧队列未关联时禁止领取，保留历史并由管理员显式关联；不按名字猜测部门。旧资格不自动转角色，避免扩大授权。

不修改`apps/lina-core`、`apps/lina-vben`或根`hack`；菜单归并使用`org-core`清单，帮助使用已发布`layout.header.actions.before`插槽。组织禁用时拒绝员工依赖该组织的访问、领取及内部建单，保留历史数据。客户及匿名工单继续使用现有已配置的问题分类路由，不自动更换其归属；管理员仍可将待处理工单转到有效队列。构造依赖由`plugin.go`传入同一`Services.Org`与`Authz`，无新增缓存。组织名称按固定500队列上限分批装配，遵守200批量上限，无逐行查询。

菜单与帮助、接口说明需中英文资源。验证涵盖部门关联、角色范围、领取冲突、转派后权限、无资格插件启动以及真实页面帮助。

## 用户确认的后续收敛

升级和低评分仅在队列标记需要跟进、记录历史，移除员工内部定向通知；重开清空处理人回队列，客户通知不变。帮助入口采用仅五个权限相关页面显示的右下角圆形悬浮问号，背景跟随当前主题并带阴影与悬停效果，点击展开说明。工单全局设置需要广域数据范围，部门客服不授工单配置权限。历史员工授权表和成员表仅保留历史数据，不再读取或授权；独立插件源码和成员生成模型删除。

旧工单队列的`org_dept_id`默认零，管理员明确选真实组织后才参与领取。迁移不按名称关联、不给既有员工资格自动增角色。原自动分配字段历史值保留，但运行时不消费；编辑只能保存人工领取。
