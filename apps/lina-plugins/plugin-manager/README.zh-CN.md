# 内置插件管理

`plugin-manager`是平台级内置源码插件。通过公开菜单过滤隐藏旧插件管理菜单，在“系统设置→插件管理”下提供`/extension/plugin-manager`工作区；菜单挂载到稳定目录`setting`，避免前端对扩展中心目录的统一隐藏，不修改宿主源码。

## 分类与列表

默认提供支付、短信、服务器、云产品、官网、用户中心、系统功能。配置位于`manifest/config/config.yaml`的`catalog`，部署也可通过插件的`catalog`配置覆盖。`categories`按顺序定义`id`、`name`、精确`plugins`与可选`prefixes`，精确标识优先，前缀取最长匹配；`fallback`指定未知插件归属。新增分类不需要修改前端。七个初始分类使用对应图标，其他分类使用通用图标。工具栏“开发文档”提供完整开发指南，复用宿主公开语言资源，由插件自己的抽屉承载。

列表只显示动态托管插件。标识和名称是仅有的搜索条件；名称与标识合并一列，另有版本号、状态、业务、运行时状态和安装时间，操作仅安装、更新、卸载，操作列按按钮内容自适应宽度。状态开关仍使用现有启停权限。停用或卸载时先自动停止新销售，再提交对应操作；已停止则直接继续。停止失败不会继续，后续失败保留真实停止状态并允许重试，不自动恢复销售；仍受原有依赖、权限和业务影响检查约束。停止新业务保留已有服务访问。

## 安装与校验

遵守[开发规范](../README.zh-CN.md)。分类不会授权安装。宿主公开接口继续校验拥有方契约、依赖、权限、授权范围及业务影响。安装和卸载只在按钮上一次简短确认。安装及重新安装自动启用并开放新业务；上传新包后也自动完成，不再二次确认安装。动作按需读取详情，更新读取目标版本权限并显式确认。卸载保留数据；依赖或业务阻断时不提供绕过入口。

源码随标准`plugins=1`构建注册；重编前须刷新官方临时工作区，不能复用过期的注册聚合模块。交付时核对二进制包含`lina-plugin-plugin-manager`，并验证分类接口及新导航，数据库启用记录不能代替实际装配。`plugin_embed.go`嵌入清单、配置及页面。插件使用中文单语言。自定义角色需在现有角色授权页勾选新插件菜单，接口继续使用原有`plugin:list`及各动作权限，不自动扩大角色授权。目录聚合调用相同服务器的公开HTTP处理器，重走认证与权限，仅转发必要会话、语言和租户头；最多1000个摘要，分类后在服务端分页，无逐行详情查询、私有表或额外缓存。

## 验证

从仓库根执行`GOWORK=off go -C apps/lina-plugins/plugin-manager test ./backend/... -count=1`、`make lint dir=apps/lina-plugins/plugin-manager`。`hack/tests/e2e/TC001-plugin-management.ts`验证页面交互，`TC002-live-navigation.ts`通过真实登录、菜单导航和目录接口验证部署结果，不注入路由或模拟接口；通过仓库标准插件测试入口执行。规范审计用例位于`hack/tests/contracts/`，需要包含源码插件的独立Go工作区。共享运行实例在其他对话使用时不重启。

## 业务授权恢复

停用或卸载缺少业务授权时，在原操作中自动通过公开启用接口重新校验后继续，不再展示长说明或要求额外勾选；不恢复新销售，不直接改写授权快照。权限、依赖及业务影响仍由服务端校验，失败时刷新真实状态并允许重试。该流程适配宿主同步可能清空授权快照的情况，不宣称修复其内部根因。
