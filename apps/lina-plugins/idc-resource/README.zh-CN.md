# LinaPro IDC 资源插件

## 范围

该源码插件拥有上游资源渠道、标准化库存、资源映射、资源分配和可审计异步操作边界。

服务器详情、附件、续费和产品任务从对应客户产品管理中使用；原服务器及运维独立路由退役，原授权节点仍保留。动态服务器以权益编号限定本地资源投影和续费候选，旧服务器任务继续支持服务编号。任务详情与接管校验传入的产品或接口范围；续费预览和确认校验产品范围。

无产品归属的概况、健康、容量、任务和调用记录收在供应商接口配置中，各页签按原权限加载；仅有运维权限时不会读取配置目录。接口详情内的任务和日志固定该接口；无法可靠关联到产品的日志不会展示为产品日志。

## 运行基础

插件已提供版本化 Provider 契约和启动声明、加密渠道秘密绑定、渠道、资源池、权威上游映射、资源任务、能力与库存快照、成本/余额/到期观察以及健康观察。渠道读取器固定使用两次有界查询，并且只允许已启用渠道构造 Provider；停用渠道不会构造客户端或接收新任务。

本插件不保存秘密明文。数据库只保留由`core secretcap`加密秘密对应的不透明引用；该引用只能在 resource owner 的构造边界内恢复为不可序列化的`secretcap.Handle`，不得返回、记录日志或写入审计正文。

Provider 登录会话同样属于 resource owner 状态。PostgreSQL 权威保存渠道代次、到期时间、刷新租约摘要和不透明`secretcap`引用，令牌明文始终加密。新建的 Provider 实例和不同应用节点会收敛到同一次登录；按代次失效可以防止旧`401`误删更新后的令牌。刷新网络调用在数据库事务外执行并受 150 秒租约保护，租约到期后允许恢复，但不会因此把任何业务写操作变成可重放操作。

Provider 网络访问由 resource owner 统一控制：请求只能访问渠道显式配置的同一HTTP或HTTPS origin，不自动降级，禁止重定向；HTTPS按已确认接口策略保留加密并跳过证书验证；每次拨号都会重新解析 DNS，并直接连接本次校验通过的公网 IP。私网、回环、链路本地、共享地址、基准测试、文档、组播、保留地址以及公私混合 DNS 结果全部拒绝。

Provider 写任务只保存调用方幂等键摘要，使用 PostgreSQL 权威时间和有界`SKIP LOCKED`批次领取，并以任务号、尝试次数、随机令牌、状态和有效租约共同约束结果转换。执行中的外部写一旦租约过期便冻结为`result_unknown`，永不自动重放。

Provider 写健康同样以 PostgreSQL 为权威源。每次已完成的上游调用都会追加不可变、非敏感观察，并推进一个按渠道隔离的有界窗口。五个样本内出现三次失败、两次未知结果或三次连续失败时，系统开启五分钟的仅写保护；受保护任务保持待执行且不消耗尝试次数，精确任务和资源对账仍然可用。worker 以一次有界集合查询核对整批渠道，不引入逐任务数据库读取。

精确任务/资源查询和库存分页只在拥有方已经持久收敛或重新调度本地操作后追加各自健康观察。畸形响应只保存规范分类而不保存原始载荷；合法但尚未收敛目标状态的资源读取仍属于健康查询；认证分类失败会在同一事务中同时记录原操作和认证两个维度。

Provider 库存只允许由本资源拥有方暂存。每个收集中快照都持久化固定页大小、精确不透明续传游标、页计数、条目计数和链式指纹。每页经过校验后使用一次有界批量写入；只有终页事务可以取代最后完整快照。任何失败、重复、跳页、带筛选、超限或畸形同步都不会改变当前可发布库存。

资源观察使用独立的 PostgreSQL`observation_claimed_at`业务时间作为新鲜度下界，并把完全相同的值作为`ClaimedAt`返回；不得为此复用 GoFrame 自动维护的`updated_at`。

上游客户账号由本插件以耐久状态机收敛。状态机始终先执行精确用户名查重，只有明确不存在才允许一次有界创建；未知写入永不重放，明确拒绝也必须重新查重后才能再次创建。用户名和密码只以渠道作用域的`secretcap`句柄传递，创建响应必须经精确查重核验后才发布上游用户编号；成功后撤销两个句柄，人工核对前先撤销随机密码。

Provider 任务后台只读取本地有界投影。队列使用键集分页且最多返回一百行；详情固定读取一个任务、最新标准化上游绑定和最多五十条不可变脱敏证据。只有`accepted`、`running`或`result_unknown`状态允许人工接管，并且必须提交任务乐观版本、一个受控原因和一至十六条属于同一任务的既有证据。事务会关闭自动化、撤销保留的任务输入绑定、追加不可变责任记录与业务审计并清除观测领取信息；不会调用 Provider、重试写入、接受自由文本或判定成功失败。

## 依赖

插件依赖 LinaPro 和版本范围为`>=0.1.171 <1.0.0`的`idc-core`，只导入核心插件公开能力契约。`v0.1.60`提供部分回收残留资源的版本化生命周期安全投影；资源插件继续使用核心插件的 Provider 任务权限和秘密拥有方能力。其他 IDC 插件可以导入`resourcecap`，但不得导入本插件内部实现。

## 同系统连接器生命周期恢复

供应商配置页面为拥有`plugin:query`和`plugin:business-impact`权限的员工提供明确的同系统连接器检查。重新确认还要求`plugin:enable`，连接器已安装且启用、运行正常、生效／发现／当前版本非空且一致、没有待升级版本。确认后重读详情，调用现有启用接口，核对版本和新业务状态，再请求正式业务影响报告；失败或状态变化时清空结果。这是已有启用与授权操作，可能刷新当前同版本构建，不是冻结工件摘要的专用修复接口。

不修改宿主代码或私有授权表。宿主重启或其他连接器状态变化后可能需要再次确认；报告仅作参考，正式停用仍重新核对业务排空，未完成业务必须拒绝。此操作不恢复已停止的新业务，不停用连接器。

## 交付与阶段边界

版本`v0.1.8`以仅平台、全局、项目内建源码插件交付，并提供中英文资源。它提供有界 Provider 健康页和任务核对页、最新标准化非敏感观测，以及使用精确权限和乐观并发的证据驱动人工责任转移。已开启的熔断不能手工关闭或通过放宽策略缩短，人工接管也不能强制判定结果或重放 Provider 写入。其余能力专用对账、跨拥有方回报和完整资源编排仍是后续受门禁约束的实施任务。

资源连接器元数据可声明`apiPathPrefix: /v1`。拥有方校验该单一版本段，将其冻结在仅拥有方可读的配置中，为登录及业务请求统一解析根地址，并避免重复版本；动态插件不能取得该传输策略或秘密原文。

地区、线路和镜像选项通过共享数据库投影提供，页面不等待上游网络。投影按当前接口、连接修订及连接器证据隔离，异步同步使用共享租约；只持久化白名单选项，缺失、过期或停用时不构造选项。新购买使用当前资源连接，历史订单保留原冻结连接。

上游目录刷新失败时，同一有效连接继续展示最近成功同步的地区、线路和镜像，不再因十五分钟过期隐藏已有选项。目录只作配置参考，不代表实时容量或保证可开通；后台持续重试，连接修订与连接器证据保持隔离，停用接口不得读取旧目录。

已付款服务器修正重开仍保留原成交身份。权益投递分别验证原成交接口证据，以及成功任务实际执行的接口、连接器版本和声明。兼容版本的声明摘要可以不同；所选渠道仍须符合原供应商及资源协议、本次冻结修正和本地成功回报。归属绑定保持幂等，不重新发送上游开通请求。


## 原生转售商品采购

公开 `resourcecap.NativePurchasePlan` 是独立的 `provision.parameters.build` 输入，只携带商品拥有方冻结的 `channelcommercecap.Purchase`。它没有服务器硬件、上游客户身份、主机名、密码、回调秘密或采购权限。`BuildNativePurchaseParameters` 双向校验计划和映射器的有界 JSON 输出；执行与重试继续由资源拥有方持久化关联关系并注入秘密令牌。

财务原生转售准入要求精确版本显式声明 `native_finance_v1`、真实商品与配置版本身份、可逆源字段映射和合法导入快照；不放宽原 `ServerFulfillmentContract`，也不按插件 ID 猜能力。每个原生意图的商品数量及购买周期数均为 1；版本化导入契约保留 `MaximumPurchaseCycles=1`，旧读取方会明确拒绝不支持的协议版本，不能静默丢弃上游限制。新财务快照使用 v3 远程核价，不携带公开组件金额。目录小时及天周期使用公开计费契约按单位确定的上限，支持财务默认的 720 小时月周期。

V10 通用模块使用显式 `native_v10_common_v1` 与导入协议 v3 的 `remote_evaluation`；拥有方只将合法远程视图转成源配置及无金额的周期元数据。内部 `ImportedBillingSource` 桥校验冻结商品与接口版本、精确商品及资源声明和当前源配置后，只调用固定 `catalog.billing-terms`，不借用员工权限，不接受任意方法。原生采购计划必须携带明确协议。

员工拥有方的商品读取显式设置 typed `CatalogProductQuery.IncludePricePreview`，只为合法默认选配请求账号价示例。冻结商品的内部核价读取不设置该标记，只核算已选值；缺少必填客户信息时不生成零价示例。

托管魔方云连接器的`resource.query`仅可通过无附加请求参数的认证`GET /clouds/{正整数编号}`读取已审核的客户机主机名与登录用户名。其他路径、方法与连接器继续执行全局秘密字段限制。既有结果策略继续保留归一化运行事实`Data`，密码、令牌和私有路径不进入客户事实。

## 已购服务器页面

`customer-ui`包维护服务器列表列、生命周期圆点、到期日期与剩余天数颜色、系统图标、服务端搜索、分页及独立版本的客户备注。插件在`customer.products`声明一个带`purchased-services.customer.v1`的表面，客户模板承载该页面，不自行定义服务器列。标准前端构建先生成管理端资源，再安装锁定的客户页面依赖并构建至`frontend/dist/customer`，通过同一公开资源声明发布；只构建客户页面可在仓库根运行`pnpm --dir apps/lina-plugins/idc-resource/frontend run build:customer`。页面使用公开的`Vben`隔离适配器，认证信息留在父页面，资源事实采用批量读取。`idc-core >=0.1.171`提供已支付目录与插件过滤；空菜单显式展示插件需要`idc-core >=0.1.172`。服务器页使用紧凑的行内搜索，不显示重复标题或刷新工具栏，表格随容器可用高度调整。


## 资源快捷导航

服务器与资源下的供应商运维快捷入口进入既有配置页面的运维页签，只加载当前获权内容。快捷菜单使用现有概况查看权限，不授予配置读取或写入权限；其他运维权限仍可从原配置容器使用。
