# TDesign 用户中心

[English](README.md)

基于`React`和`TDesign React`的独立中文用户中心模板，注册`idc-portal`的`customer-template/v1`扩展。不替换`customer-default`，不导入宿主前端源码。

## 功能

- 完整加载商家配置后一次显示导航，按客户任务分组，只显示后台定义的产品入口，不自动补全部服务，支持手机抽屉菜单。
- 登录、邮箱验证注册、找回密码、首次修改密码、核对当前密码后修改登录密码与独立会话恢复。
- 购买与购物车衔接独立官网；费用内提供订单、付款准备、充值、余额和信用付款、浏览器支付交接及真实结果查询。
- 已购服务、原生服务器支持的操作、明确确认查看密码、续费报价、账单和收支明细。
- 工单、附件、回复、关闭、重开与评价。
- 真实用户头像及更换、昵称编辑、登录联系方式状态与安全处理入口、通知联系人、地址、公钥、个人与企业认证、发票抬头、税务发票、退款、信用申请和还款、通知记录与偏好、免打扰设置及推广记录。
- 数据导出与注销申请，由服务端检查授权、最近登录和保留条件。

可选功能依赖相应业务插件。此模板实现声明的页面；第三方插件自带页面仍需匹配的模板适配器。界面操作不能代替后端授权。

## 构建与验证

需要`Node.js 20.19+`或`22.12+`、`pnpm 10.30.3`及支持`WASI reactor`的`Go 1.25+`。

```sh
pnpm install --ignore-workspace --frozen-lockfile
pnpm test
pnpm run build
GOWORK=off go test ./... -count=1
pnpm run package
node scripts/verify-package.mjs
pnpm run test:e2e
```

产物为`dist/customer-tdesign.wasm`。验证脚本在独立`WASI`运行时初始化插件，检查描述符调用、拒绝路径和嵌入资源。浏览器测试使用受控接口响应，不进行真实扣款或外部服务器操作。

```sh
CUSTOMER_API_ORIGIN=http://127.0.0.1:6032 pnpm run dev
```

开发地址为`127.0.0.1:16742`。生产资源调用同源公开接口。插件内不得写入凭据或商家支付配置。

## 安装

通过部署实例已有插件管理流程上传产物，满足声明的`idc-portal`依赖后启用。准备好切换时，在已有用户中心模板设置中选择新模板。本地已通过正式上传、安装及启用流程加入候选列表，活动模板仍保留原选择；旧模板继续保留用于回退。

## 官网与头像接口

模板的`websiteurl`设置官网源地址；`websitecatalogpath`、`websiteconfigurepath`、`websitecartpath`分别配置商品列表、配置页与购物车路径，配置路径使用`{product}`占位。官网需提供`POST /__website/session`并校验用户中心来源；用户中心通过`/auth/website-session`提供限定来源的登录桥。配置缺失时页面显示明确提示。独立预览可用`CUSTOMER_WEBSITE_CONFIG`注入同一组公开设置。

更换头像使用`idc-core`的客户专用`POST /account/customer/avatar-uploads`，再调用公开本人头像更新接口；需要同时部署本轮业务插件后端。不会授予客户后台文件管理权限。

## 验证边界

已实现页面通过本地真实接口读取及隔离浏览器流程检查；专用本地测试账户已验证资料保存、地址／联系人／发票抬头新增编辑移除，以及修改密码后重新登录。第三方支付到账、供应商动作、认证与税务开票需要在商家配置的测试环境继续验收。浏览器付款支持网页跳转、表单提交和二维码；原生应用及微信`JSAPI`付款需要对应环境适配器。任意第三方页面嵌入仍需专用适配器。

## 登录联系方式改绑状态

手机号与邮箱不再通过普通资料直接保存。配套`idc-core`中间件在身份认证后拒绝客户绕过验证改写，保留员工全量资料表单、昵称、头像和既有密码流程；该保护要求部署并启用匹配的业务插件后端。

用户中心提供“验证原联系方式→验证新联系方式→自动保存”的自助流程，无需人工审批。原联系方式由服务端读取；首次绑定验证另一项已有联系方式。原方式无法接收验证码或两项均未绑定时，用户自行进入已有工单页面。

配套的 `idc-core` 与 `idc-notify` 使用现有公开本人资料接口和插件中间件完成保存，不修改宿主源码或直接访问宿主私有表。验证码绑定账户、登录会话、字段及原始资料，10 分钟有效，错误尝试受限，成功后不可重复使用；联系方式保存与验证码消费处于同一事务。部署须安装通知插件的 `010-login-contact-change.sql`，并在后台配置可用邮件／短信渠道及对应验证码模板。

## 资源工作台

首页显示已认证账号`ID`及最多五条近期资源。后台定义的产品标签支持服务端搜索和带独立版本的客户备注。运行状态、`IP`地址及系统信息通过每页一次有界本地资源查询取得；没有确认的信息保持未知。费用列展示当前生效价格记录，不冒充实收金额或续费报价。

管理页按实例信息、系统与连接、快照备份、网络安全、操作记录和费用分区，使用资源拥有方的能力、精确候选、当前会话确认与持久化操作状态。密码及控制台输出只在明确点击后一次领取，关闭弹窗立即隐藏；救援使用客户输入的临时密码，不伪造生成密码。收费操作要求部署匹配的资源及核心实现，前端构建成功不代表这些业务已可用。部署时通过正式插件生命周期安装核心迁移`150-customer-service-workspace.sql`并满足清单中的配套依赖。

商业操作使用独立报价资格、权威最终含税价格、明确确认及真实付款单据。变配重新求值当前权益完整的类型化字段，冻结专用目标后计算差价，不修改官网购物车。商业历史与真实对象账期采用有界游标分页，服务暂停后仍可读取；对象就绪状态未知时不能恢复。

站内消息同步当前客户的真实宿主投递记录，并以纯文本显示正文。登录和页面重新可见／聚焦按三十秒边界更新提醒，没有持续轮询。同会话刷新失败保留最后确认的未读数，身份变化立即清除；发送状态与实际消息正文分开展示。

供应商限制保持真实：当前魔方适配不能证明修改`IP`数量即为更换地址，因此不开放该动作；无法核实快照／备份就绪状态时不开放恢复。监控和修改启动顺序需要已经核实的供应商合同，不使用虚假控件代替。
