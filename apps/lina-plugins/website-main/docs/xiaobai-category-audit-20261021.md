## 核心关系

一级商品分类 → 二级商品分类 → 具体商品 → 商品配置项 → 配置选项。配置页“产品型号”切换同二级分类的兄弟商品，目标是不同商品ID，不是商品下面又建第三级分类。只能证明公开页面结构，不能据此声称查看了对方后台数据库。

例如：弹性云ECS（`fid=2`）→ 湖北襄阳弹性云（`gid=32`）→ 两款商品（`pid=178/183`）→ `CPU`、内存、操作系统等 → 2核／4核、4G／8G、系统版本等。

## 页面实现对应

- 顶部下拉：`.Submenu-product-name`为一级；四个`.Submenu-middle-product`分别装各组二级入口；`a.list-product-content`跳分类页。
- 左侧目录：`.sky-cart-menu-item`包括一级`.sky-cart-menu-title`和二级`.sky-cart-submenu-item`。当前二级和对应一级带`active`，当前分组展开。
- 右侧目录：二级标题和说明，下面`.shopping-cart-product` `.product-card`展示一张或多张商品卡，含名称、说明、库存、月起价、购买入口。
- 购买地址：`/cart?action=configureproduct&pid=商品ID`；配置页`.basicConfigurationItems`列同分类型号，`.sky-form-group`显示配置项。
- 售罄卡仍展示，购买按钮无`href`；配置页对应型号也可无`href`并提示库存不足。
- 默认/cart线上当前显示四川成都分类，并非全部商品。

## 本方当前差距

只读源码核对：`idc-core`管理分类创建契约已有`parentCategoryNo`，管理侧有父分类信息；但公开`CatalogCategoryItem`未带父分类或子节点，`website-main`的`renderMenu`逐项将分类作一级标题，并额外加入全部商品。因此本方官网目前没有完整呈现参考站的一级折叠分组＋二级入口。

源码位置：`apps/lina-plugins/idc-core/backend/api/admin/v1/catalog_category_create.go`；`apps/lina-plugins/idc-core/backend/api/public/v1/catalog_types.go`；`apps/lina-plugins/website-main/frontend/public/lina/catalog-page.js`。

本次只审计，不把竞品分类与商品写入本方后台、不修改公开接口；后续实现应消费本方真实父子分类、排序、商品归属，并保留已确认的分类独立购买提示。
