# TC011 隔离同系统协议测试

`TC011b`自行创建两个随机命名的本地测试数据库，通过已有官方初始化命令建立宿主表结构和必要种子数据，正常启动自动安装源码插件并建立插件必要数据，再启动两个独立后端。它不会复制部署安装元数据、客户、交易、订单或服务数据，也不会修改当前开发库。测试结束（包括失败）停止自有进程、删除自有数据库和包含密钥的临时目录。

测试用正式构建工具构建当前`idc-peer`和测试专用提供方，以正式接口安装、创建客户、开放API、保存密钥、验证连接、发布商品、导入商品并余额付款。一次性商品通过上游正常人工交付，下游正常查询完成且不能生成服务。长期商品由测试专用提供方正式返回接单和完成状态；仅上游该测试商品的本地有效期属于受控前置，下游服务映射、扣款和续费必须通过正式协议与任务完成。

`TC011c`复用同样的官方初始化和清理能力，自行创建一套隔离实例。它通过其他插件的正式启用操作复现同系统连接器授权丢失，再通过已启用连接器的正式重复启用操作恢复检查；验证停止新业务状态保持、列表与详情读取后仍可检查、空业务正式停用成功，以及在售导入商品阻止正式停用。连接、商品与导入均走正式接口，仅客户实名和平衡充值为既有受控前置，不创建客户订单、不伪造业务状态或宿主授权。首次由停用转为启用可能再次丢失授权，需要使用已启用状态下的重新确认入口；本测试不宣称消除宿主同步缺陷。

运行条件：本地PostgreSQL、`python3`及`PyYAML`、`openssl`、`ip`、Go和已构建的`temp/bin/lina`；测试二进制须由当前源码构建。使用测试运行器已有的`E2E_DB_*`或`E2E_PG_URL`，不要把凭据写进脚本。插件使用已有本地开发安全配置，临时复制目录权限为`0700`，配置和证书私钥为`0600`。

正式出站策略要求公网HTTPS。测试从本机网卡选择公网地址，或通过`E2E_PEER_PUBLIC_IP`明确指定本机公网地址，绑定临时可信HTTPS代理转发至测试上游；不会放宽私网、回环或证书校验。没有适用公网地址时测试明确失败。它不调用远端第三方服务。

```bash
pnpm -C hack/tests test:module plugin:idc-channel -- --grep 'TC-11b'
pnpm -C hack/tests test:module plugin:idc-channel -- --grep 'TC-11c'
```

测试只输出固定步骤、净化后的接口路径和结果，不输出AppSecret、访问令牌、数据库密码、SQL参数、供应商原始响应或配置。启动失败的后端日志可在本次日期临时目录保留为`0600`诊断文件，不能作为公开交付物。
