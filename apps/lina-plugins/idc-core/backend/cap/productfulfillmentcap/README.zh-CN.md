# 商品交付连接器契约

[English](README.md) | 简体中文

新增云商品通过`idc-core`拥有的`product-fulfillment@v1`扩展接入。不在交易核心添加商品类型枚举，也不复制服务器表。平台负责商业配置、报价、订单、资金结清与冻结的成交事实；连接器负责真实供应商协议及明确支持的操作。

## 声明商品

| 声明 | 职责 |
| --- | --- |
| `interface_configuration` | 供应商连接设置，凭据使用受保护的秘密字段 |
| `product_configuration` | 商家维护的供应商参数及真实限制 |
| `customer_configuration` | 类型化客户输入、候选项及关联条件 |
| `provider_metadata` | [接口声明](declaration.go)、交付粒度、持续管理及续费事实 |

商家编辑器维护商业名称、顺序、可售子项及价格。本地未绑定的信息字段保留在订单；发送上游必须明确填写参数名；声明内的对应继续校验类型和边界，自定义原生名称与标量内容通过[自定义参数契约](custom_parameters.go)冻结在`custom_parameters`中。直接开通连接器必须将该结构转换为最终外发表单，不支持时明确拒绝，不能静默丢弃。认证信息、上游账号身份与已付款单位数量仍由所属服务控制。`productChoiceFields`允许支持的商品文本参数进行纯批量校验；商家的`productChoiceBindings`将商业子项标识对应到实际接口值。`customerProductFields`声明客户输入对商品参数的替换。单位转换由连接器负责，核心不能推断某个数值代表内存、带宽或证书数量。

候选项及关联必须来自供应商事实，采用有界请求与字段白名单。后台、预览和购买表单使用这些声明的关系；保留的目录不代表实时容量保证。[服务器](../../../../idc-zjmfcloud/plugin.yaml)与[证书](../../../../yunsu-ssl/plugin.yaml)声明展示不同配置形状，不能据其存在宣称供应商已完成生产验收。证书连接器目前在供应商域名能力未确认时阻止自动发布。

## 交付已付款商品

按[请求与结果契约](contract.go)实现不同的提交与查询方法。使用传入的不可变成交配置和幂等标识，不能用今天的商品配置重建旧订单。区分`per_order_item`与`per_quantity_unit`交付粒度，异步受理保留外部编号。只有供应商确认后才报告成功；超时或受理结果不确定必须保留`result_unknown`，不能静默重发或伪造明确拒绝。

持续服务必须声明真实权益拥有方及[服务操作契约](service_action.go)支持的操作。一次性交付不能虚构可续费服务。续费沿[计费与续费声明](billing.go)选择上游确认、本地权益或不支持；试用必须明确支持暂停、恢复及转正式续费。安装了插件不代表已具备这些能力。

[纯配置校验](configuration_validation.go)不能读取凭据、访问上游或写入状态，每次结果必须明确返回`valid`。未知或无效结果不能批准保存。共享[入场辅助方法](../provideradmissioncap/provideradmissioncap.go)只等待业务回调尚未进入时的类型化宿主拒绝，不代表上游写入可以重发。

## 验证接入

在仓库根目录使用已准备的插件工作区运行契约测试：

```text
go -C temp/output/.build test lina-plugin-idc-core/backend/cap/productfulfillmentcap -count=1
```

随后通过专用本地假上游验证实际连接器及其拥有方：商家保存、客户选配与价格、资金结清、最终供应商参数、查询恢复、服务归属及管理入口就绪。必须包含明确拒绝和结果不确定场景。现有通用表单与已付款服务器样例位于[核心插件端到端测试](../../../hack/tests/e2e/)。模拟通过不代表真实供应商可用、收费或生命周期能力已验收；第三方写入仍需独立授权。

## 原生商品转售

`ProviderDeclaration.saleImportProtocol`通过`native_finance_v1`或`native_v10_common_v1`显式声明原生财务或V10通用模块商品由资源拥有方执行转售。准入仍精确匹配插件发布包、声明、接口修订和拥有方生成的目录读取证据，不能凭插件名称获得此能力。协议要求按数量单位交付，并由资源拥有方管理持续权益。

冻结的`provisionresourcecap.TaskRequest.NativePurchaseProtocol`精确标识协议，`NativePurchase`携带一份已付款的`channelcommercecap.Purchase`，与服务器方案独立。资源拥有方持久化原生任务、回调关联和`downstream_token`，不创建服务器资源池、上游客户账号或登录密码。原生通用商品权益不投影成服务器。

`ImportFulfillment.maximumPurchaseCycles`表示可跨层转售保留的源购买周期上限，零保持旧快照行为。原生财务商品明确限制为一个周期，后续导入和导出均保留此限制；购物车解析及结算报价在收款前拒绝超过上限的购买。


带源周期上限或显示与默认值策略的静态导入使用快照协议`2`，旧连接器会拒绝，避免静默剥离限制。动态计价使用协议`3`及`pricingMode=remote_evaluation`，周期没有静态金额；财务原始价表也不能替代账号实际成交价。配置报价、购物车和接受结算报价前，通过冻结的接口证据调用资源拥有方只读核价，再应用商家加价或整件定价。价格或配置证据变化时拒绝旧报价，已接受订单重放不重新核价。当前明确拒绝再次导出动态计价商品，不支持多层动态转售。
