# 客户联系方式身份验证

本源码契约只允许`idc-notify`调用。核心插件保存加密的客户联系方式投影及按用途隔离的查询摘要，不保存密码，不读取宿主身份私有表，不签发令牌，不通过登录查询创建账户，也不向访客提供账户搜索接口。

邮箱或手机号登录先解析出独立用户名，再由调用方使用宿主公开登录接口校验密码；返回令牌前必须读取宿主签名身份的真实个人资料。重复、陈旧、停用或不属于客户的身份失败关闭。用户名登录保留宿主既有语义。联系方式更新与原已认证个人资料写入在同一事务刷新投影；直接开户使用宿主账户拥有方刚接受的原值，成功领取客户身份后读取公开个人资料刷新。

`POST /x/idc-core/api/v1/admin/account-login/contact-index-refreshes`按固定页大小处理。真实工作人员必须通过客户更新权限及宿主公开用户查询权限，不保留管理员令牌。默认仅刷新派生索引并返回权限修复候选摘要；只有明确传入`repairCustomerAccess=true`才修复平台内有效、没有任何角色且归属有效`admin_direct`开户路径的客户。已有角色、员工、停用账户和受限客户均排除。修复另外使用操作员公开角色查询与批量授权权限，确认内建`user`角色启用且范围仅限本人；新直接开户通过`usercap.Create`分配同一角色。

核心身份引擎只支持通知插件拥有的已验证联系方式提供方。找回密码先验证绑定用途、账户、联系方式、浏览器与修订号的一次性验证码，再调用宿主公开的已验证身份登录`SPI`。临时令牌只留在服务端；原密码写入与验证码消费共用事务。响应前将旧会话的精确编号写入插件共享拒绝记录；宿主撤销失败时，可使用独立且只允许清理旧会话的凭证重试，不影响新签发会话。

派生索引由`149-customer-contact-login.sql`维护，模型通过官方`DAO`工具生成；不修改宿主源码，不使用宿主身份私有存储、签名密钥或伪造请求上下文。
