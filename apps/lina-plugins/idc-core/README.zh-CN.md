# LinaPro IDC 核心插件

## 范围

该源码插件负责 IDC 平台稳定的客户、商品目录、订单与账务、服务支持协同、商家设置以及共享公开契约边界。

## 依赖

该插件仅依赖 LinaPro 宿主。其他 IDC 插件可以依赖其 `backend/cap` 下的公开契约。

## 运行时安全密钥环

启用插件路由与秘密信封服务前，部署环境必须以单个规范 JSON 对象提供`LINAPRO_IDC_CORE_SECURITY_KEYRING`：

```json
{"active_key_id":"v1","reservation_key":"<32 字节安全随机数的规范 Base64>","keys":{"v1":"<另一个 32 字节安全随机数的规范 Base64>"}}
```

每个根密钥必须使用密码学安全随机源生成，并与源码库、数据库行、日志和支持包隔离。`reservation_key`必须保持稳定。有版本根密钥通过 HKDF-SHA-256 分别派生审计重放、审计完整性和秘密信封密钥。轮换时先添加新版本、保留旧版本用于验证已有审计证据和解包装，再修改`active_key_id`，并在退役旧版本前完成有界信封重包装。变量缺失或无效时插件失败关闭，不使用随机、数据库或硬编码回退。

源码消费者通过`secretcap/spi`的单 owner 声明和冻结接缝取得只回调秘密访问能力。资源拥有者为每个渠道派生稳定且不可逆的独立 scope，只把对应 accessor 和加密输出 sink 注入 Provider。scope manager 只通过同步且仅调用一次的 producer 接收生命周期明文，不提供列表或 handle 发现；其可选的生成式凭据扩展只支持固定的 256 位 URL-safe 策略，由秘密拥有方仅生成并加密一次，相同重放只能恢复原句柄。registrar 不提供运行期查询，也不发布动态插件明文 bridge。

资源拥有方的商品接口会把不透明的`pfi_*`接口标识和不可变的`rci_*`资源配置修订投影到商品自动化。核心把每个`rci_*`映射成一条只追加的接口配置修订；已发布商品版本冻结这条映射，付款后的履约请求再把精确`rci_*`写入规范摘要。商品配置修订与资源端点、账号、秘密引用修订是两件不同的事；编辑资源渠道不能让历史订单悄悄改用最新供应商配置。

## 商品目录基础

商品拥有方把商家自定义分类树、通用商品身份和不可变的已发布版本历史分开保存。分类只用于整理商品，不能决定商品种类。通用核心只负责名称、介绍、计费规则、HTTP 边界上的精确十进制字符串金额、逐币种价格、税务策略、发布状态和冻结的商业快照，不写死服务器、证书、CDN、域名、手机、发货或物流字段。

从 FB-52 0.10 开始，未发布商品版本可以通过商品履约扩展点绑定至多一个兼容的供应商接口实例。被选插件声明接口配置、商家商品配置、客户购买字段、校验、履约动作、状态和受治理的前端页面。服务器的 CPU、内存、操作系统、磁盘、带宽、地区、线路、IP、资源池和服务器操作归服务器插件；SSL 和手机插件分别拥有自己的字段与页面。更换供应商必须创建新商品版本，不能改写历史订单。价格不使用浮点资金或跨币种兜底，供应商原始响应、凭据、成本和内部编号不得成为公开商品内容。

开发期“资源或 Provider 快照生成商品草稿”路径已经退休，不保留兼容入口。`089-retire-provider-catalog-draft.sql`只在不存在`provider_import`商品版本时原位清理；如果仍有这种旧版本，迁移会失败关闭。此时应先导出必须保留的测试数据，再用当前迁移重建开发数据库，只恢复不依赖旧路径的数据，禁止把旧版本改写成手工或迁移商品。

## 交付边界

该稳定业务拥有方是强制内置源码插件，并提供中英文资源。可替换的供应商连接器单独作为托管动态插件，通过唯一一套 LinaPro 插件管理完成安装、升级、停止新销售、停用和卸载；具体业务配置仍回到商品或对应业务页面。内置业务拥有方不出现在可卸载的托管插件列表中。
