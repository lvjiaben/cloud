# 插件自有已购页面

商品所属插件维护列表字段、内容与操作。商家可在产品菜单的“展示插件”中按顺序选择内容块；即使没有商品或已支付权益，已选择的插件仍展示自己的搜索与空表格。配置列表与实际有权益的插件合并，不能因配置遗漏隐藏已购买服务，也不能根据菜单名称猜测插件。客户模板消费已有治理后的`customer_surfaces`，只负责菜单、分类与页面容器；同一菜单中多个插件在同一页分块展示，不能把服务器列套给其他商品。

## 声明

插件在`customer.products`插槽的一个客户页面声明`purchased-services.customer.v1`，表示这个页面可作为已购内容块；页面`key`、入口和界面由插件自己决定。每个插件只能有一个有效的已购页面，重复声明、停用、异常运行态或未安装时不选择任何页面。复用已有页面即可，不必新增重复导航。

```yaml
customer_surfaces:
  - key: certificates
    version: v1
    title: Certificate services
    slot: customer.products
    route: certificates
    entry: customer/certificates/index.html
    bridge_capabilities:
      - purchased-services.customer.v1
      - service-entitlements.customer.v1
    status: active
```

入口必须属于当前插件版本的公开资源。动态插件使用宿主返回的`entryUrl`；源码插件只支持在`public_assets`中发布的独立`HTML`入口，不能把宿主组件路径当作页面。模板以保留沙箱隔离的`srcdoc`承载公开页面并设置可信资源基址，避免本地地址空间限制；不授予`allow-same-origin`，不在父页面执行插件脚本。容器设置`linapro-surface-key`元数据，复用页面可据此使用当前有效表面标识。

## 上下文与请求

沿用`linapro.plugin-page-bridge`的`1.0`信封，验证窗口、方向、插件、表面及请求编号。`host.context.v1`只传语言、主题和`services.directoryNo`、`services.pluginId`等公开上下文，不传令牌或客户身份。`host.view.v1`承载就绪、尺寸、标题和受限站内导航。

`purchased-services.customer.v1`由已购容器提供受控适配，不是新增宿主全局服务，也不通过宿主页面授权接口申请令牌：

| 请求 | 结果与边界 |
| --- | --- |
| `GET account/purchased-services` | 适配至`idc-core`的当前菜单已购接口；容器固定菜单及插件，只接受分页和关键词。 |
| `PUT account/service-entitlements/{entitlementNo}/customer-note` | 仅当前页面读到的权益可提交，后端继续验证当前客户、独立版本与审计。 |

源码页面的其他请求只发往自身插件的`account/`公开接口；批量权益引用必须来自当前块已读取的记录。动态页面的其他能力必须先取得宿主为准确表面、能力、方法及路径签发的短期授权，所属后端由授权方返回，不能由页面选择。已有`idc-core`受管服务列表同时固定当前菜单和履约插件；详情、任务及下载只接受该页面已有记录产生的引用。业务插件自身仍负责私有接口的数据权限和业务校验。

请求有并发、次数及超时边界。菜单、页面版本或登录身份变化后取消旧请求；旧页面结果不能写入新页面。外部插件页面不可读取父级会话。模板不得用通用列或伪造数据替代不可用的插件页面。

## 支付和性能

已购权益要求同租户、同客户、同订单存在`paid_at`。此条件同时约束列表、总数、菜单计数及插件分组；已支付待开通保留。分组来自同一数据库边界，按管理拥有方归集；通用管理拥有方为`idc-core`时使用履约插件。每个内容块在数据库分页前应用`providerId`，不能在浏览器筛选整页冒充真实分页。

目录查询使用固定次数集合查询，不按权益逐个探测插件。模板复用导航已取得的运行态快照；各插件只请求当前有界页面及必要的批量事实。资源页面自身采用`Vben`官方适配器，维护服务器生命周期、到期提醒、系统图标和备注；证书页面维持证书插件的域名、验证及证书操作规范。

## 空菜单配置

管理员目录接口的可选`pagePluginIds`最多16个、去重且保持顺序，仅适用于产品菜单。不传保留当前选择，传空列表清除；同目录乐观版本、事务及审计一起保存，不改变商品归属或任何服务权限。客户目录服务结果的`providers`包含显式配置的零条内容块及当前客户实际已支付权益所属插件，`total`仍为真实支付行数。读取采用目录键上的集合查询，不按权益逐行探测插件。
