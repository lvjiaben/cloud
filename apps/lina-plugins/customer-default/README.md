# Default customer center template

An independent dynamic template with shared branding (logo, name, title, company and contacts) and separately retained template settings.

Copy this entire directory anywhere. With Node.js 22+, pnpm 10.30.3 and Go 1.25+, run `pnpm install --frozen-lockfile`, `pnpm run build` and `pnpm run package`. Upload `dist/customer-default.wasm`. No host source, external source symlinks or repository build tools are required.

`frontend/customer/vendor/` contains only the 29 required Vben package dependencies and customer integration source closure. See `DEPENDENCIES.json` and the retained `vben/LICENSE` (MIT). Business features consume public HTTP APIs. These copies are maintained independently.

Run `node frontend/server.mjs` with `LINAPRO_BACKEND_PROXY_TARGET` and `CUSTOMER_PORT`. The framework-independent gateway resolves the active template and forwards API/authentication/assets, including deep-link refreshes. Third-party templates may use vanilla JavaScript, jQuery, Vue or React.

Select the installed template under System settings / Customer center configuration. Template switches preserve shared and per-template settings and all customer business data. Some host versions have an owner authorization defect in disable/uninstall impact checks; this plugin does not bypass those checks or modify the host.

Product configuration, cart, and checkout belong to the website. Legacy customer purchase links redirect to `WEBSITE_PUBLIC_ORIGIN`, defaulting locally to `http://localhost:6680`; the official development launcher supplies the actual website port. `/auth/website-session` delivers the existing session through an iframe only to the operator-configured website origin; explicit login uses the current tab and `/account/website-purchase` returns to the verified website destination. Confirmed orders open customer invoices with verified channel QR or page-redirect payment options. Existing identity, cancellation, and payment-readiness gates remain in force.

Authentication handoff is framework-neutral: `/auth/website-session?nonce=...` sends `{type:"lina-website-session",nonce,accessToken}` only to the website origin obtained from `/__website/configuration`. The website validates the configured customer origin, iframe window and nonce. `login=1&returnTo=...` is an explicit current-tab login request; after complete customer authentication, `/account/website-purchase` returns only to that configured website. Tokens never enter URLs. `probe=1` checks an existing session in the current tab without starting login, then submits it in a form body to the approved website gateway; this supports browsers that partition embedded storage. The configuration includes `origins`: only local loopback websites add their same-port loopback alias; production origins remain exact. Other customer frameworks can implement the same protocol without sharing private stores.

Common interface icons (Lucide, Fluent MDL2, and Element Plus) are bundled with the template and do not require an external icon API. Their original licenses and sources are retained in `frontend/customer/public/icon-licenses.txt` and included in the build.

The console independently loads all purchased services, cloud servers, recent orders, balances and unpaid invoices, with retries for individual panels. Service totals and a five-item preview come from the current customer's paginated API; `/account/product-directories` lists all services without requiring a server plugin, and the purchase entry covers all products. `/account/servers` retains the resource owner’s paginated server list and direct access to delivered server status, addresses, power operations, renewal and explicit credential disclosure. Other server services retain their own entry. Server entries are hidden when the resource plugin is disabled, while ordinary purchased services remain available.

Orders, the console and the complete service list show local management preparation separately from delivery and lifecycle. A pending or interrupted management link keeps the original paid service and order visible; native server navigation waits for the confirmed link. Historical services without this notification keep their existing navigation. This progress display never authorizes another provisioning request or refund.
