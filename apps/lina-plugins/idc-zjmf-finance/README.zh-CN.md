# idc-zjmf-finance

`idc-zjmf-finance`是魔方财务原生接口的托管动态服务器连接器。它与魔方云、魔方 V10、DCIM 是不同插件，不使用旧的`modules/addons/idcsmart_api`或任何`/v1`兼容接口。

[English](README.md) | 简体中文

## 接口实例

管理员可以在`idc-resource`中为本插件建立多个接口实例。每个实例独立保存地址、账号、密码和非机密登录策略，商品版本只冻结所选接口投影和上游商品配置，不复制账号或密码。

本连接器不重复声明一套服务器菜单或空白页面。后台接口管理、服务器列表和客户服务器页面统一由`idc-resource`提供；只有连接器以后交付了真实的独立业务页面和对应静态资源时，才允许声明自己的页面入口。

原生登录固定调用`POST /zjmf_api_login`，提交`username`和`password`。宿主从成功响应的`jwt`字段取令牌，并仅在机密出站代理内写入`Authorization: Bearer`请求头。令牌、账号、密码和完整原始响应不会进入 WASM 内存、页面、日志或履约证据。

资源渠道必须使用`login_session`认证策略，令牌路径为`["jwt"]`，请求头为`Authorization`，令牌格式为`Bearer`，刷新判断路径为`["status"]`，刷新值为`["405"]`，并启用`serializeInvocations: true`。资源插件会校验这些固定设置，认证最多重试一次，并用 PostgreSQL 租约保证同一接口实例的完整调用过程串行执行。

## 商品和配置候选

`upstream_product_id`从`GET /cart/all`加载。后续配置只读取`GET /cart/get_product_config?pid=<已选商品>`。不同上游商品编号会形成不同请求，缺少上游商品编号时直接拒绝，不会复用另一个商品的配置结果。

魔方财务允许商家自定义配置项名称，所以插件不会按“地区”“线路”“系统”等文字猜测含义。管理员先明确选择上游地区、线路和操作系统配置项，再把对应子项冻结到商品版本。服务器专用字段仍由`idc-resource`契约拥有，不进入通用商品核心。

## 开通和后续操作

首次开通使用源码可证明的原生流程：读取`/user_info`，在同一接口实例串行保护下处理购物车，再调用`/cart/add_to_shop`、`/cart/settle`和余额或信用支付。结算前的明确拒绝可以安全失败；结算提交后若超时且没有取得订单编号，结果必须进入“未知、人工核对”，不能自动重新下单。

当前代码已经接通首次购买流程。资源插件只把受治理的 HTTPS 回调地址和数字履约编号交给连接器；连接器只接受`downstream_token`这一个操作机密槽，明文仅由机密代理注入供应商表单，绝不进入 WASM。每次重放都先调用`/cart/clear`，已有服务器就直接恢复，已有账单就继续余额支付，不会重复加购物车或结算。只有上游返回有效服务器编号后才会报告开通成功。续费和变配会产生新的上游财务交易，现阶段明确标为不支持。

## 验证

在插件目录执行：

```powershell
$env:GOWORK = "off"
go test ./... -count=1
go vet ./...
go build ./...
$env:GOOS = "wasip1"
$env:GOARCH = "wasm"
go build -o idc-zjmf-finance.wasm .
```

生产写入验证只能使用专门创建的测试账号和测试商品。不得拿已有客户订单或服务器做破坏性验证。
